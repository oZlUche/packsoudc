# 神明总表（信仰体系的核心配置）

> **源文件是 [`docs/gods.xlsx`](gods.xlsx)**（作者 2026-10-01 定：核心配置做成 xlsx，便于修改）。本页是同一内容的只读镜像，改设计改 xlsx，再改 `data/authoring/faiths/<id>.json`（与信物 / 赐福道具），再跑导入；镜像之后由工具重生成（待定 5）。
> 来源：`data/authoring/faiths/*.json`（main，a38bbac）、报告 081 / 082 / 093 / 095、`docs/worldview/`。表里每个数都对过内容文件；「作者设计」= 093 作者表格定的四位，「游戏里既有」= 082 时按占位数做的四位。

## 怎么读这张表、怎么改

| 表里的列 | 落在数据里的字段 | 改了要跑什么 |
|---|---|---|
| 阶数与阈值 | `thresholds`（非递减正数；阶 = 过了几道阈值） | `tools/import_content.gd` |
| 升级途径（信力行为） | `deeds[]`（`FaithDeed` 构件，13 种见下） | 同上 |
| 献祭 | `offerings[]`（`OfferingRule`：`tags / min_cells / exact_grade`，`multiplier` 默认 ×2，`per_cell`） | 同上 |
| 等级效果 | `perks[]`（`FaithPerk` 构件，`tier` 默认 1；16 种见 `EffectRegistry.FAITH_PERKS`） | 同上；新效果要加构件 |
| 赐福模板 | `blessings[]`（`Blessing`：圈哪些道具、名字前缀、`rarity_up` 默认 +1、`value_mult` 默认 ×1.5、按阶 / 激活即 / 按信力的 `faith_bonuses`） | 同上 |
| 包内转化 | `convert_chance`（默认 3%）+ `convert_per_tier`（默认每阶 +1%）：激活时每走一步，包里每件能被赐福的道具独立掷一次 | 同上 |
| 信物 | 道具标签 `faith:<id>` + `faith_anchor`（最后置入的信物决定激活，3.8） | 道具 JSON |
| 道具按阶功能 | 信仰道具的 `faith_bonuses[]`（`tier` 从 1 起） | 道具 JSON |

信力只记**此刻激活**的信仰；各神各一个池子，切换不清（继承还没做，082）。神坛只在休息点、只在激活信仰时出现；常规献祭不限次数，特殊操作与献祭共享休息点的这一次机会（093 七）。
