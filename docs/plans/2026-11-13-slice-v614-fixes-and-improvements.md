# v6.14 切片体验：运行修复、开局一致性与发现引导执行方案

> 日期：2026-11-13。仅方案，未修改或复测游戏。
> 主依据：[v6.14 体验报告](../reports/testing/2026-11-13-slice-v614-experience.md)，实测 c1b1de036786724f7ca1418655dd0f21104f76c2；对照[313](../reports/313-vertical-slice-s1.md)与当前 changelog v6.15。
> 当前合成已经是“拿起→拖到搭档→确认”，不恢复旧接缝小锤或拖上即消耗。v6.15 已移除砧和82条升级，历史方案不再作为恢复旧入口的依据。

## 1. 判断与执行顺序

切片正常获得装备可以通关，但首局曾被脚本错误中断；原S3的守卫通过含测试补装，不能与本次自然配装混为一种证据。两份记录都保留，分别证明流程可达与一次自然通关，不宣称新人理解或整体平衡已通过。

| 批次 | 问题 | 目标 |
|---|---|---|
| A / P1 | B01 悬浮回调生命周期 | 消除悬浮链脚本错误与失效对象调用；找到可验证根因 |
| B / P2 | B02 预设越界、U02 开局预览、仓库提示 | 可见预设、清单、出发实物和审计同口径 |
| C / P1～P2 | 首次合成机会教学、U01 多重覆盖 | 不知道合成的玩家能发现操作；不因尝试配方拆散装备 |
| D / P2～P3 | D01 绕行、D02 无来源交易、地图/角色说明 | 明确路线风险收益，清理无效内容 |
| E / 后续实验 | 有限携入、第二角色 | 独立验证连续成长与角色差异，不混入缺陷修复 |

A/B/C 是下一轮陌生玩家试玩前的重点。D先明确规则再调数；E不阻塞稳定性修复。执行时重核最新main并附问题状态表，已修项目只复测。

## 2. A：悬浮回调与面板生命周期

### 2.1 事实及定位边界

B01 已确认：inventory_panel.gd 的闭包调用 is_open 时目标被报告为 Vector2，伴随 slot >= slot_max 对象查询错误与 Debugger Break。短步骤未再次退出，不能关闭问题；退出码0也不能掩盖SCRIPT ERROR。

当前 _quiet_tip 仍捕获 fuse_note、_quiet_uid 和 prev，并将闭包安装到可能跨面板复用的HoverTip。这是优先定位方向，不是已证明的唯一根因；不能仅加一个类型判断就宣称修复。

### 2.2 排查与修复要求

1. 在隔离用户目录保留 before-restart.json、首会话与重启日志；原版本复核后在最新版本重走。存档不保存旧闭包，必须执行合成、挤出、关背包、场景切换和地面悬浮才能覆盖生命周期。
2. 给临时诊断记录面板/ground/tip标识、注册与解绑、回调调用、销毁时机、当前owner与fuse_note有效性。不要每帧刷全量日志。
3. 查清谁拥有hover抑制条件，谁复用GroundLayer，销毁面板时谁清理；检查嵌套prev闭包是否无限保留旧面板。
4. 优先最小改成可显式注册/解绑的抑制条件，或由存活owner统一查询。若采用回调恢复，须保证只有当前仍持有注册权的owner能恢复，不能把后安装的回调覆盖掉。多owner乱序销毁要正确。
5. 使用明确类型/弱引用/有效性检查作为防线，但仍要断开生命周期错误的引用；不能吞掉错误或把失效链永久返回false掩盖问题。
6. 关闭确认窗、移出物品后，正常悬浮应恢复；现有“关闭后仍停在目标上先不弹，换物品再恢复”的交互保持。右键、双击和地面回收不被静默拦截。

### 2.3 验收

自动测试覆盖注册幂等、重开面板、共享ground tip、多个owner顺序/逆序销毁、确认/取消、场景释放后再次输入。运行压力序列建议至少100次开关/切换，检查注册量不随次数线性增长。

真实UI从报告档与全新档各走长序列：商店→背包→合成阔剑/绷带卷→长物挤出→关闭→调试抽屉开关→背包→地面悬浮/回收；无调试抽屉的普通路径也要测。DEBUG与实际导出运行方式分别验证，不能从DEBUG退出推导所有包必崩。

通过标准：无SCRIPT ERROR、无该悬浮链slot对象查询错误、无残留回调增长，且所有悬浮/确认/回收功能正常。若仍无法稳定复现，交付已证实的生命周期修正与覆盖限制，不能写“B01完全解决”。

## 3. B：统一开局范围、预设与整备预览

### 3.1 当前事实与推荐落地方案

当前manifest允许19件物品且不含longsword，但免费强攻可带入长剑；章节额外发放knife、bandage、ration。SliceAudit.walk以空kit开局，未覆盖玩家能选的实际入口。allow_carry_in=false是设计限制，不是仓库保存故障。

本轮推荐保留固定补给基线，**停止复用正式版免费预设，新增显式的切片预设白名单**。默认固定补给先作为可靠回归基线；希望保留强攻/坚守选择时，配置切片专用方案，通过审计与对打后再启用，不把longsword简单塞进允许清单来掩盖越界。

预设候选按用途设计：进攻取向保留组件组合空间，防御取向用盾/甲取舍输出与负重；不要开局直接发终点答案套装。两套均只用合法清单内物品，具体数量由总开局表与bench结果确定，不在此凭DPS拍数。

章节定义所有开局来源的合并规则：包、角色固定物、章节补给、预设、携入。以来源标签区分“固定包含”和“预设替换项”，不能按item_id粗暴去重，因为两把knife可能是合法合成资源。每个实际可选预设提供完整输入数量表，并注明是否已含章节三件补给。

### 3.2 预览与真正开局同源

提取或复用纯开局计划函数，给出具体物品、多重数量、来源、预计摆位/落地去向；整备和RunState.start消费同一份计划。不通过“预览时真的开局再撤销”实现，不提前扣仓库/资金、不推进随机流。

整备棋盘显示最终装备，若暂不便摆入固定补给，至少在同屏明确展示“出发补给”及其数量、重量和落地情况；能力预估包含实际入包会参战的装备，待落地件不能虚算战力。最终允许自动摆放时说明其规则，截图对账预览与出发后的实物。

切预设A→B→A、取消/后退/恢复档，不叠加补给、不重复收费、不丢原仓库件。UI隐藏预设还不够，开局后端也拒绝不属于本章节的preset_id；旧配置选中非法预设时明确回到合法默认，不静默带入。

### 3.3 提示与仓库闭环

首次进入预设区短提示“任选一套，点击可预览”，说明互斥替换，并用已有耐力/负重与装备变化反馈。简述“强攻：偏输出、耗耐力较高”“坚守：偏防御”，具体措辞以最终配装事实为准。

no_preset_tip按章节条件生成；禁止仓库携入时不再写“其余从仓库拖”。明确“本试玩每局使用固定补给，仓库装备暂不带入”，同时只说明真实用途：物品保存、收藏与已存在知识记录。不承诺未实现的科技或未来继承。

这只是第一轮修复基线，并未解决长期收集动机；如果用户希望展示连续搜打撤成长，按§8单独试有限携入，不能打开allow_carry_in就称UI修好。

### 3.4 审计补齐

SliceAudit必须通过与UI同一入口枚举章节、角色、每个可见预设及不选预设，而不再只用空kit。核对总数量、来源、最终背包/地面、允许清单与可合成闭包，含新增的两件同名原料可能解锁清单外配方。

每种开局组合跑固定开发种子与独立验证种子，20个种子只能作为初筛。正式版章节验证无影响；非法预设后端拒绝；旧run里已存在longsword不静默删除，记录旧配置例外，新开局按新规则。

在审计输出注明覆盖了哪些入口与路径。原0问题仍是历史结果，不能改写成历史已覆盖预设。

## 4. C：首次真实合成机会的教学

### 4.1 触发条件

当前小锤只在拿起物品后出现，所以需要在“玩家尚不知道该拿起什么”时给一次短引导。

复用正式FusionResolve/可消费检查，对当前可见且玩家有权使用的容器查合法配对：
- 背包、地面、已揭示的战利品/搜索收获；
- 未揭示物品、未成交商店货物、锁定/扎根/随身受保护件、pending禁忌组合不算可执行机会；
- 同id配方要求不同uid，候选完整且当前可操作，不能只按两种名字存在触发；
- 若容器必须先取出才可拖合，提示“先取出这件”，不指向不可操作背景地面。

首战掉刀与背包初始刀、搜索磨刀石与刀都必须可触发。等待当前揭示/战利品动画和视图布局完成后高亮两件，用稳定uid定位；移动/销毁/转场时重新校验，不能挂着失效坐标。不要用固定延迟保证“应该显示好了”。

### 4.2 展示与状态

一页短引导：“拿起一件，拖到有小锤的搭档上，确认后合成。”不泄露未知产物，不自动移动/消耗。指引不得拦住必要拖拽或遮住搭档。

切片独立档案记录shown/dismissed/completed三个意义，completed只由实际合成成功写入。首显一次，取消不记成功；关闭后保留可主动重看的帮助入口，未完成者不在每个容器重复弹窗。保存重启不重复刷教学，也不因只显示过就被计作完成。

测试未知/已认识结果、全新/回流档、已会合成的人、多候选优先选简单组合、首次机会退出、满包、重复揭示、确认取消和失败回滚。UI观察记录玩家是否能自己拿起、找到搭档、理解消耗，不能用模型已知配方的操作成功替代。

## 5. U01：长短物品覆盖与合成意图

本次问题源于覆盖多件时退回一般挤出，配方本身无错。建议首轮最小调整为**识别合成意图后阻止多重覆盖误挤出**，暂不立即改成任意光标命中就合。

- 当前光标命中合法搭档，或高亮明确指向该搭档，但拖拽物覆盖其他道具时：不移动任何被覆盖物，提示“还压到其他物品，请换一侧或反向拖动”。
- 存在多个可合搭档时不自动选一件；提示调整目标。
- 没有合法合成意图的普通摆放/挤出保持原规则，别把所有多覆盖一律禁掉。
- 松手失败后拖动件按既有安全取消规则回原位或继续拿取；无空间时不能复制/消失，不改其他物品布局。

若体验仍难操作，再单独实验“光标明确命中的唯一搭档优先”，只影响合成选择，不强行用拖动物形状覆盖的位置放成品；产物按正式落点规则验证。先给两方案相同场景对比，不同时上线两套不一致判定。

验收覆盖linen_bolt→bandage、反向、旋转、额外覆盖皮甲、两位合法搭档、包体、地面↔棋盘、搜索面板开关、锁定、取消/确认、最终成品放不下。必须验证普通摆放意图仍能完成。

## 6. D01：绕行不是自动判Bug，先查真实前置关系

当前可从商店→补衣人→休息→搜索二绕过盾卫取毒药和圆盾。313却将搜索二解释为盾卫后的奖励；对打表又表明盾卫往往需要这些装备才能稳定战胜。

**不要直接加“先赢盾卫才能开搜索二”的锁**：可能把唯一可行配置锁到它要打败的敌人后面，形成软性循环前置。

本轮推荐先保留双向绕行作为合法时间换风险路线，修正文档的“战后奖励必经”说法，按实际所有可达路径重算收益：
- 战斗支路：更短路线、盾卫实际掉落与败战风险；
- 商业绕行：额外步数、交易/机会成本、是否实际可免费拿齐同样装备；
- 两条路径都保留提前撤离，不全面禁止回头。

若实测商业支路完全支配战斗支路，做独立候选：提升盾卫胜后独有但受控的收益，或让搜索二部分物资随盾卫胜利额外开放。原先用于克制盾卫的必要组件必须在战前另有合理渠道，不能唯一供给后置。每个候选单独与当前比较，不同时改敌人生命、掉落、费用与地图连边。

工具需要检查带状态的路径而非纯图连通：战斗是否胜利、首次搜索/重复搜索次数、倒计时、资金、当前可达材料和退出条件。给出节点id路线、步数（含原地搜索）、关键收益、最低必要资源。候选资格有来源不代表在需要时拿得到。

至少对比70060实走路线、盾卫正面路线、节点9提前撤离、第三搜遭遇屠夫；利用最新v6.14逃跑失败直接开打规则，不用历史扣体力/虚弱规则重测。

## 7. D02与低成本说明优化

- 补衣人熟皮革在切片无来源：在切片专用事件/章节适配中隐藏该项；不改正式版通用事件。亚麻布有来源但已被消耗属于正常取舍，保留禁用及原因。
- 若只剩一项交易和离开即可，不为填选项增加无意义材料来源；全无可用交易仍能免费离开。
- 首次路线选择轻提示现有全图F/缩放操作，按输入绑定生成键名；避免重复新增地图教学页。不同窗口下能发现屏外终点和两个出口。
- 角色卡已有数值、求饶、偷袭，不再列为“缺少角色介绍”。补一句准确打法概括与试玩角色范围，不承诺未开放的角色。

遵守既有“图能说明不重复加字”定调：不恢复已撤销战后得失告示，不重做已改善的护甲/格挡文案，不回滚v6.10拖放确认。

## 8. E：有限携入与第二角色，独立可选实验

当前任务授权制定方案；以下是产品优化候选，不算修Bug的必需项。A～D稳定后才做。

### 8.1 有限携入

目标是让上一局收获影响下一局，同时避免成套终点装备跳过发现过程。建议实验“一件仓库道具”与既定带入价值预算的组合约束，具体预算依据19件清单实际价值分布制定。允许清单、独一/特殊件排除、负重和空间继续约束，预设与携入如何替换必须显式定义，不能在最强预设上无代价再叠加。

先列普通材料、基础武器、合成成品、防具/盾的合法携入样本，再做首次/成熟仓库对照。携入物按真实实例转移，取消出征不扣、出发扣一次、带回不复制、失败照既有规则处理；预览与开局同源。

若预算无法防止一件成品跳过全部选择，应调整可带类别或把携入展示留下一版，而不是削弱全部旧装备。正式存档与切片档仍隔离。

### 8.2 第二角色

复用正式版现有且能力已完成的角色，先比较耐力、负重、体力、能力与当前切片内容的适配；不新造角色、不无条件开放全池。选一位与安德烈乌斯有实际决策差异的候选，提供两卡对照。

加入后审计角色固定物品、预设、章节补给及携入的组合入口；求饶/偷袭与候选能力分别测试。仅数值不同但路线选择相同则暂不扩充。E两个实验分开跑，避免把角色差异误归因于仓库成长。

## 9. 测试、指标与再验收

### 9.1 必须新增的覆盖

| 范围 | 测试 |
|---|---|
| 生命周期 | 跨面板共享tip、销毁后悬浮、注册解绑数量、无调试抽屉路径、DEBUG与导出运行 |
| 开局 | 每个可见预设+默认、切换取消重进、章节补给多重数量、非法preset拒绝、预览与实物/能力一致 |
| 教学 | 已揭示容器与包组合、不可见货不触发、一次首显、完成事件、退出再进与知识保存 |
| 拖放 | 长短双向/旋转/多覆盖、普通挤出不退化、确认取消守恒 |
| 路线 | 绕行与正面、两出口、搜索遭遇、倒计时耗尽、战败/求饶/逃跑失败 |
| 档案 | 新档/报告恢复档/旧越界预设档；正式档无字节变更，切片知识独立 |

报告中的首局种子70060从全新档复测自然通关，不注入终点装备；同档第二局验证预设与仓库说明。节点9完整撤离、正常失败/死亡和v6.14新逃跑规则补测。中文/英文×默认/大字号按实际最新版本跑，不沿用v6.12结果。

定向通过后跑适用全量test.sh、warnings和内容一致性。记录真实数量、退出码与日志；330断言/8套件是历史定向结果，不当全量或本轮成绩。

### 9.2 工具与体验指标

扩展SliceAudit而非另建平台：枚举入口矩阵、每种开局实际物品、可合成闭包、带条件路线及反例。记录检查coverage，失败给具体角色/preset/seed/来源链。

复用slice_bench，比较合法开局与实际可达中途配置，不再用默认初始DPS5.3代表所有玩家；29.4强攻只作为已观察的越界配置证据，不是调数目标。

首次合成记录：机会出现、提示显示、拿起、确认/取消、成功、求助。UI工具等待不作玩家耗时；未合成分为没机会/未理解/主动放弃。B01日志错误与清理泄漏、Fontconfig/V-Sync环境警告分栏，不用白名单吞脚本错误。

4～6名新玩家观察在运行稳定后安排；能自主选预设、理解固定补给、找到第一组合、解释一次撤离选择。无人可测时交专家复测与候选包，标记S4未验证，不宣称已具备公开发布条件。

## 10. 完成门禁与Git交付

下一轮候选包必须满足：
1. B01有根因/修复证据和长序列回归，无同类运行错误；
2. 所有可见开局均入清单、预览一致，审计覆盖真实入口；
3. 首次合成机会可见且不泄露未知成品，多重覆盖不造成误挤出；
4. 分支奖励可达性按明确设计验收，无把克制组件锁在目标后的循环；
5. 无来源事件适配仅影响切片；旧档/正式档安全；
6. 自然通关、提前撤离、失败与第二次出征均有新证据。

按批次交PR，报告用docs/reports下一编号或testing惯例，更新索引、manifest版本和必要架构说明。原体验报告保留原样，逐项关联B01/B02/U01/U02/D01/D02与用户四项反馈，写明设计选择、代码改动、实测和未覆盖。

按用户约定提交、推送、创建PR并合并默认分支，遵守检查与保护。仅方案合并不代表这些问题已修复；无需为候选仓库/角色扩展阻塞已明确的安全与教学修复。
