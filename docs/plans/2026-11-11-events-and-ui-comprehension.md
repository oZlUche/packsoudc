# 常规事件补充与 UI 信息理解验证：执行方案

> 日期：2026-11-11。本文为设计与执行指导，尚未实施事件或进行本次游戏走查。
> 来源：本地源码审阅、GitHub main 的 standard 节点规则核对、世界观已定内容、玩家反馈「对于胜负没有实际感受」。
> 与 `2026-11-10-balance-diagnostics-and-statistics.md` 配套。实施前拉取最新默认分支，重核已完成工作，不重复实现。

## 1. 判断与前置机制审阅

当前已有道具说明、战前对手、战记、状态、倍速与结算等信息入口，但“字段存在”不等于玩家能及时发现、理解并据此行动。现阶段不能断言 UI 信息已经足够，也不能根据一名玩家的反馈断言需要增加大量信息。需要一次聚焦理解链条的专项测试，而非再次泛泛检查所有页面。

建议先由独立审阅线程完成机制核对，再由测试线程复现重要结论。模型首选 GPT-6.1 Sol，high 推理强度；首轮工作以阅读代码、追踪调用、核对数据与文案为主，不需要默认启用 Astra。复杂跨系统因果、存档与随机性难题可选取具体证据交 Astra 二次复核。模型选择不代替实际运行证据。

机制审阅需交付矩阵：机制 → 作者定案 → 数据配置 → 正式调用路径 → 玩家入口/反馈 → 测试覆盖 → 缺口 → 优先级。关注：

- 背包、邻接、武器升级是否真的改变战斗，以及变化能否被看见。
- 信仰、耐力、负重、倒计时之间的规则是否一致。
- 战斗胜败、物品带出、托付和局外成长是否形成可解释后果。
- 事件交易和战斗分支是否原子结算，旧档与重入是否一致。
- 区分“已实现但无内容”“有数据未接流程”“实现正确但表达不清”“规则尚未定案”。

每个问题必须给代码/数据位置、触发条件与影响；无法确定的写待验证。报告只给可执行缺口，不为追求完备而提议新大系统。该审阅不阻塞本文件中的内容草案；涉及其发现的规则缺陷先修复再上线相应事件。

## 2. 本次核对到的事件基础

`data/authoring/node_rules/standard.json` 的常规事件池为 cache、stranger、marked_reward、rest_spot、ambush、rift、altar 七个事件；free_mode 和 clockwork_hourglass 均引用 standard。它们有基础功能，但多数正文很短。已有特殊任务/钟房事件不能当作通用内容随意替换。

已存在条件：can_afford、has_item、vitality_at_least、faith_active、has_map_buff 等；后果包括 change_money、give_item、lose_item、restore_vitality、spend_vitality、pass_time、start_battle、teleport、next_event 等。

必须注意的实现边界：

1. `set_flag` 是局外旗标，不能直接作为仅本局的人情或事件链状态。
2. `give_random_item` 走搜索抽取，不等于主题奖励池。需核查并补最小的主题池抽取入口，复用既有物品资格与发放逻辑；不能直接用全局搜索结果冒充本方案的奖励。
3. `start_battle` 只请求战斗，本身不绑定文案中的某种敌人，也不保证胜利专属奖励。必须显式绑定合法敌人内容与胜负分支。
4. `pass_time` 不只是扣一个界面数字，会推进相关世界逻辑；选项必须明确耗时，测试猎手、侵蚀、倒计时耗尽的结算顺序。
5. GiveItem 给到地上，不承诺自动进包。背包满不能让文案说“已装好”。
6. HasItem 与 LoseItem 的可扣实例集合需统一；核查锁定、收藏、任务/独一道具与数量，避免“条件通过但扣除失败，奖励仍发”。
7. EventPlacer 的现有权重选择不是完整的事件重复抑制系统，不能只在设计表写“每局一次”却不接实现。

## 3. 内容设计规则

- 首轮增加 8 个事件，第二轮 4 个；同时修补旧七事件，不追求一次扩到几十个。
- 正文说明为什么产生这项成本或收益；按钮写行动与确定的机械代价；结果文本说明实际发生了什么。
- 不新造神明定案，不把独立魔法写成必须信仰某神，不擅自扩写破晓、寂灭等特殊任务。
- 每个事件有无代价离开选项；不得让“离开”也偷偷扣资源。受既有世界规则影响的时间成本除外，但必须事先显示。
- 明确数值为首轮测试建议，不是最终平衡值。本文中的数字落地后从配置生成 UI，不在多处写死。
- 药物交易得到道具不等于自动治疗；体力和战斗生命不能混称；一段安静剧情不能写成停止倒计时或冻结猎手。
- 旧档既有 event id 保留。新事件只铺新生成内容，不能覆盖玩家已经做过的选择。

## 5. 第一批八个事件：正文、选项、结果

以下中文为可编辑初稿；英文翻译在实施时与中文同批交付，不允许中文上线后英文仍显示旧事件含义。

### E01 油布下的补给 / event_supply_bundle

**正文**：断墙下压着一捆军团的油布，木牌上还刻着领用人的姓名。外层缠着可以回收的绳布，里面是防潮包好的食物。要保住内层的包装，得慢慢拆开。

- 「拆开内层（耗时 1，食物补给 ×1）」：从 food_supply 池抽 1 次，pass_time 1 后按合法结算流程发放。结果：“你剥去受潮的外层，取出了{reward_name}。四周的滴水声没有停过。”
- 「回收外层（绳布材料 ×1）」：从 wrapping_material 池抽 1 次。结果：“你收起还能使用的{reward_name}，留下没有拆开的内包。”
- 「保持原样」：无收益。结果：“你把刻有姓名的木牌翻回正面，继续赶路。”

**功能**：即时基础材料与耗时食物补给二选一；类别确定，具体物品随机。food_supply 仅收符合包装叙事的食物，不混入药瓶；两池价值按实际数据校准。

### E02 墙根的药摊 / event_herbalist

**正文**：一名药贩把封好的药品摆在墙影里，摊布上压着半截帝国路税木牌。“想便宜些，就拿干草药来换。”他指向其中一份，包装仍然完整。

- 「购买{reward_name}（支付 P 币）」：从 medicine 池预抽 1 次，具体物品、数量、用途与 P 在点击前显示并保存；扣 P 后发放。
- 「用干草药束 ×2 换{reward_name}」：扣 dried_herbs 2，发同一份已抽出的药品，不能另抽一次。核算交换价值，不满足锁定/数量条件时禁用。
- 「不买」：无变化，不承诺返回后刷新商品。

**结果**：购买：“他收好钱，将封好的{reward_name}放到你面前。”交换：“药贩闻了闻草束，把{reward_name}推了过来。”

**功能**：玩家看到真实商品再比较两种成本；P 按实际抽中物品报价形成并冻结，材料换药也需核对不同档位的经济成本。领取药物不自动治疗。

### E03 陷住的货车 / event_stuck_cart

**正文**：货车斜陷在碎石里，车主正收拢散落的货物。“帮我抬起轮轴，金属货里分你一件。”他指向车底卡住的货箱，路旁另堆着已经顾不上收的绳布杂物。

- 「抬起轮轴（体力 -1，金属货 ×1）」：当前体力至少 2；从 metal_cargo 池抽 1 次并预览具体奖励、尺寸与重量，扣体力后发放。
- 「收拢路旁杂物（轻便材料 ×1）」：从 light_salvage 池抽 1 次。结果：“车主摆摆手，你收起了路边的{reward_name}。”
- 「离开」：无变化。

**重货结果**：“轮子滚回石面，车主把答应的{reward_name}搬到你脚边。”

**功能**：体力换较高价值的金属材料；轻货池限制真实重量与体积，不能只凭名字认定轻便。剧情不预先保证铜锭。

### E04 倒墙后的担架 / event_field_stretcher

**正文**：两名随军医工把担架架在倒墙后。水壶在小炉上冒着热气，绷带按干净和用过分成两堆。“坐下就慢慢处理；若赶时间，我们还有一份现成的。”

- 「坐下处理伤处（耗时 2，体力 +1）」：pass_time 2 + restore_vitality 1。结果：“绷带重新收紧，你起身时脚下稳了些。炉里的水已经烧开。”
- 「支付 P 币快速处理（体力 +1）」：扣 P + restore_vitality 1，无额外 pass_time；P 用测试配置。结果：“医工拆开预备好的敷料，很快处理完伤处。”
- 「继续赶路」：无变化。

**功能**：时间与资金换续航；满体力时两个恢复选项禁用并说明，不能收钱后回 0。若没有“尚可恢复”条件，新增最小条件而非用 vitality_at_least 反推。

### E05 冷却的铸槽 / event_cracked_foundry

**正文**：旧王国的铸槽已经冷透，炉渣间还露着金属余料。旁边堆着旧支架和工具柄，有些木料仍然结实。你可以花些时间拆出其中一类。

- 「撬出金属余料（耗时 1，金属材料 ×1）」：metal_salvage 池抽 1 次。结果：“炉渣裂开，你从灰里取出了{reward_name}。”
- 「拆取结实木料（耗时 1，木材料 ×1）」：worked_wood 池抽 1 次。结果：“你卸下锈钉，留下腐坏的部分，收起{reward_name}。”
- 「不拆」：无变化。

**功能**：玩家选择制作方向，具体材料按主题、深度、难度抽取；不保证指定 id。worked_wood 可纳入已落地且合资格的风干木料、硬木板，未实现物品不能先填入正式池。只出废墟，不变成新锻造设施。

### E06 停转的油槽 / event_clock_oiler

**正文**：供油臂停在半空，传动机构夹着碎石。检修槽里还留着可用的活动零件，侧边固定架上也有能回收的材料。拆开其中一侧，失去支撑的余物便会沉入油泥。

- 「拆取传动零件（耗时 1，机关零件 ×1）」：mechanism_parts 池抽 1 次。结果：“轴心松开，你取出{reward_name}，支架缓缓伏了下去。”
- 「回收固定架（耗时 1，固定件材料 ×1）」：mechanism_fasteners 池抽 1 次。结果：“你取下{reward_name}，余下的零件随支架沉进油泥。”
- 「不碰机关」：无变化。

**功能**：传动件与固定件两类主题选择，只出沙漏。候选可分别审计齿轮/发条、铆钉/支撑金属，必须满足当前物品标签、叙事与阶段限制。一次性的是这个事件实例，其他事件仍可从相同池抽到同物品。不承诺地图机关因此停止。

### E07 补衣人的针 / event_refugee_weaver

**正文**：避风处挂着几件补过许多次的外衣。补衣人指了指断开的腰带：“皮子或者布都行。我不缺针，缺的是能缝上去的东西。”她打开钱袋，让你看见里面确实还有零钱。

- 「交出熟皮革 ×1，换 P₁ 币」：tanned_leather 1 → 固定 P₁。
- 「交出亚麻布卷 ×1，换 P₂ 币」：linen_bolt 1 → 固定 P₂。
- 「保留材料」：无变化。

**结果文案**：皮革：“她先试了试皮子的韧性，才数钱给你。针线随后穿过了第一道接缝。”布卷：“她展开布边，看过没有霉斑的部分，把钱放进你手中。”保留：“你收好材料，她低头继续缝补那条旧腰带。”

**功能**：制作资源与即时资金竞争。P₁/P₂ 建议高于普通出售所得、低于可反复买入套利的价格；先核算真实报价。事件一次成交关闭，不能逐件无限卖；拒收锁定件。

### E08 铜灯下的凹龛 / event_ward_recess

**正文**：凹龛的铜灯早已熄灭。墙边散着工匠留下的磨料和小工具，底座后还压着几件金属旧物。要搬出后面的东西，得先清开碎石。

- 「收起工匠材料（工坊材料 ×1）」：workshop_supplies 池抽 1 次。结果：“你抹去细灰，收起{reward_name}，它还能用在下一次加工上。”
- 「清开底座（耗时 1，金属旧物 ×1）」：metal_curios 池抽 1 次。结果：“你清开碎石，把{reward_name}放到脚边，余物滑入了更深的缝隙。”
- 「留下它们」：无变化。

**功能**：制作用途与带出价值/占格取舍，只出废墟。前者只入合格工坊材料，后者可入普通可交易金属旧物但排除任务、独一、特殊解锁物；两者不混称制作材料。不自动添加武器增益。

## 6. 第二批四个事件：需要小型流程支持

### E09 还在运转的检修仓 / event_gear_cache

**正文**：检修仓的门只开了半扇。一具维护造物守在敞开的零件匣旁，听见脚步便转过身。匣内还留着完整的机关备件；要靠近它，得先让这位守卫停下来。

- 「查看守卫，准备迎战」：显示实际绑定敌人的战前信息，确认才开战；胜利后额外从 guarded_mechanism 池发放预抽的机关备件 ×1，失败不发；正常战斗后果照旧。
- 「离开检修仓」：不战、不额外扣资源。

**胜利结果**：“守卫终于停住。你打开零件匣，取出了里面的{reward_name}。”**失败**：由实际退败/终局流程显示，不编造你一定成功逃出。

**功能**：让战前判断和胜利所得建立联系。只出沙漏，绑定已有适档机关敌人，实施时选定真实 id；不能用任意池敌人却描写机械守卫。额外奖励通过战后成功分支发一次，存读档不可重复领取。

### E10 桥洞里的收路钱者 / event_toll_watch

**正文**：桥洞里有几个人，盾牌斜靠在装满杂物的木箱上。“想进来翻货，就先交看守钱。”说话的人站起身，却没有追出桥洞。外面的道路仍然通着。

- 「付 P 币进入货堆」：从 trade_materials 池有放回预抽 2 次形成货包，允许同物品重复；扣款前预览具体物品、数量、价值与价格。购买与战胜共用同一个已保存的货包结果。
- 「查看守卫，争夺货物」：同一份货物只在胜利后发放，普通战败规则照旧。
- 「沿外面的路走」：无额外损失，不锁地图道路。

**结果**：付钱：“钱落进箱子，他们让开了货堆前的位置。”获胜：“看守离开了货堆，你找到了先前看见的那包货。”离开：“你沿桥洞外绕过，身后没有追来的脚步。”

**功能**：钱买确定性与战斗风险的比较；正式地图可用不同人类敌人配置，不能在无桥场景配图里硬画跨河地形。首轮货包为两次低中档材料抽取，不增加橙红、票券或任务物品。抽中后冻结的是该实例的结果，不是给所有事件固定相同物品。

### E11 走散的传令者 / event_lost_runner

**正文**：一名传令者靠着石柱，手里攥着磨破的靴带。“我还能走，只是不能再让这只靴子散开。”他看了看你带着的东西，又望向回程的方向。

- 「交给他麻绳卷 ×1」：扣 rope_coil 1；写本局待回报状态。
- 「帮他重新绑好（耗时 1）」：pass_time 1；写同一待回报状态。
- 「指明来路，继续走」：无机械奖励、不立旗标。结果：“你指了指自己走来的方向，他点头记下。”

**救助结果**：“他试着走了几步，终于站稳。‘若前面还有我们的补给，我替你留一份。’”明确是条件式承诺，不保证当局一定得到回报。

**功能**：材料与时间换潜在后续价值。不得使用局外 SetFlag 污染下一局；本局状态需进入存档。本局最多出现一组，不发现金即时奖励。

### E12 石墙上的绳结 / event_runner_return

**正文**：低墙上挂着一个熟悉的绳结。先前的传令者从墙后探出身：“补给只剩这些。我留了一份，你挑一样。”他摊开两份包好的东西，一份是食物，另一份是药品。

- 「拿食物：{food_name} ×1」或「拿药品：{medicine_name} ×1」：E12 激活并首次形成有效奖励上下文时，从 food_supply 与 medicine 各预抽 1 次并保存、展示；只发所选的一份，消费本局回报状态。
- 「留给后来的人」：无资源奖励，同样消费状态，防止回来改选重复领取。

**结果**：拿食物：“他把{reward_name}放到你面前，将药品留在墙后的阴凉处。”拿药：“你接过{reward_name}。他收好食物，又指了指前面的路。”留下：“他把两样东西重新包好，郑重地向你点头。”

**功能**：让前一次选择在世界中得到一次具体回应；不授予隐含善恶分或新成长货币。

**链条实施**：为 E11/E12 预留有先后可达关系的节点，E12 激活前用合理中性正文，不提前出现“熟人”；不得覆盖搜索/商店/主线任务点。若当前生成器无法稳定支持，先不上线这两项，不用全局旗标或随意改变已访问节点凑数。

## 7. 旧七事件修补要求

| 旧事件 | 保留的功能 | 必须修补 |
|---|---|---|
| cache | 体力换战利品 | 说明撬锁为什么耗体力；收益范围与实际抽取一致；与专用宝箱节点区分 |
| stranger / marked_reward | 人情与回应 | 审核 marked 的真实作用和持续期；文案不能承诺必见后续；不与 E11 链混用状态 |
| rest_spot | 恢复机会 | 补具体环境与结果；免费恢复若保留，就作为低强度喘息，不强行让所有事件都有代价 |
| ambush | 突发威胁 | “上去看看”不能隐藏立即开战；明确接近会遭遇，逃跑概率与失败后果可查 |
| rift | 位移风险 | 文本明确目标不确定与行动成本；没有合法落点时不能照扣款并说成功 |
| altar | 物品换恢复、破坏引战 | “最值钱的一件”高风险，必须预览具体实例；刀断掉需明确消耗；不允许误扣锁定或独一道具 |

先检查所有普通事件是否空标题、空正文、无图或图片路径无效。特殊任务动态生成文本要单列，不能直接补写剧情覆盖任务逻辑。

## 8. 分布、收益与图文落地

### 8.1 事件池与次数

两图共用 standard，直接把地图专属事件加进去会串场。优先复用已有章节覆盖能力；如果没有，新增薄的章节事件池覆盖，不复制整份经济/节点规则制造双份维护。

第一批公共 E01/02/03/04/07，加废墟 E05/08、沙漏 E06。旧七事件保留并调权；初始同权作为测试起点，按实际出现率复核，不把常规休息、商店、搜索全替换为事件。

每个新增事件每局最多一次，E11/E12 算一个链组；生成与随机揭示统一去重，状态存档。这是事件模板的出现频率限制，不消耗任何奖励池。新模板都达到出现上限时，继续选择符合条件的可重复普通事件；不得生成不可交互空点。不能用 `event_groups` 抢占所有事件节点、挤掉现有 faith_call。

### 8.2 原子性与耗时

交易提交前再次检查完整成本与候选实例；扣款失败不能继续给物品。按成本、世界推进、奖励的真实流程验证；耗时导致终局后不得复活或额外发奖励。向玩家说明会推进倒计时及世界活动，临界条件测试必须覆盖。

满包收益落地明确显示并可整理；离开清理规则照旧。离开、Esc、重复点击、重入、存读档不得重复发奖。每个事件一旦选定终结分支，记录完成状态。

### 8.3 文案与美术

正文建议 60～130 个汉字，结果 20～60 字，每屏 2～3 个有效选项加离开；超出时优先压缩文字，不靠缩小到难读字号。费用/数量由配置占位符生成，名字走现有 item 模板，多语言同批。

先用 5～6 张共享场景图覆盖补给、行商/医工、废墟工坊、机关检修、人际援助、伏击；检查现有资产再列缺图。无定稿图片时保留可测试布局并明确素材缺口，不能用不相关图让正文与画面矛盾。方案中的地点与人物是事件草案，不改写神话定案。

### 8.4 主题奖励池：永不抽空的加权表

**数据与抽样**

- 上述 pool_id 为建议名称，先核查已有抽取组件，再补最小作者配置与生产入口；沿现有 JSON → 资源导入流程，不另造一套独立搜索系统。
- 池包含候选 item_id、正的基础权重、合法阶段/章节、数量范围及深度/难度权重配置。事件选项引用 pool_id、draw_count、reward_key。首轮除 E10 抽两次外均抽一次、每次一件，避免同时扩大数量与品质。
- 先按实际章节、深度、解锁和剧情主题筛选，再按“基础权重 × 深度倍率 × 难度倍率”归一化抽取。所有倍率有限且非负；各支持上下文至少一个正权重合法候选。难度沿当前游戏档位，数值通过实验确定，不能臆造新档位。
- **每次抽取不删除候选，不递减权重，不记录库存/剩余数量；同一事件多抽和不同事件都允许重复抽到相同 item_id。** 每次发放创建独立物品实例；共享配置不可被存档或运行时修改。无需补货、重填、枯竭或跨局库存系统。
- 高难度/深层可适度增加同主题较高档候选的权重，不能突破解锁、主题与事件成本上限。低难度保留基础制作供应，不能靠断供制造难度；免费轻货与守卫奖励分开预算。机关池不出草药，食物池不出矿石，不用全局 crafted 标签代替主题清单。
- 候选资格全部被排除属于配置缺陷，不是“抽空”。导入与审计覆盖所有支持上下文；可配置同主题、符合解锁的基础候选作兜底，禁止循环回退。仍无候选时禁用收益选项、保留免费离开并记录错误，不先扣资源再给空结果。

**结果冻结与 UI**

- 事件实例生成有效奖励上下文时预抽并保存具体 item_id、数量、pool/config 版本、上下文快照；E12 在激活时形成上下文。奖励随机流由本局种子、节点/事件实例 id、reward_key 派生，与无关战斗/搜索随机流隔离。
- 同一事件重入、Esc、读档或切换选项不重新抽取，不因后续难度/深度变化改写已保存结果。不同实例继续独立抽取同一池；旧档已存在的具体奖励保留。没有新字段的旧事件按旧语义兼容，不能加载即刷新。
- 交易、互换及明示货物的选项预览实际物品、数量、用途、占格与成本；搜索/拆解可只展示类别、档位范围和数量，结果揭示实际物品。隐藏结果不能在正文预先写死物品名。
- E02 两种支付共用 reward_key，E10 付钱/战胜共用 reward_key。发放成功与完成状态一并持久化；战败不发，重复回调不得再发。E04 恢复与 E07 收购不必随机化，支付材料也不随机扣除。
- “每个事件只能领取一次”只限制该事件结算，不意味着池内某个物品已被取走。正文里的“余物埋入油泥”描述现场选择后果，不影响其他节点。

**检测和统计工具**

1. 静态检查池/物品引用、主题和材料资格、正权重、所有上下文非空、解锁限制、回退无环，以及预览和结果模板的占位符。普通旧事件的物品收益同样审计；特殊任务确定奖励不强制改随机。
2. 以固定种子抽取至少 10,000 次，确认配置摘要完全不变；用单候选池与抽数大于候选数的夹具证明可重复抽、数量足额、物品实例不同。只重复读取同一已冻结事件不算新的抽样样本。
3. 按池 × 深度 × 难度统计资格、归一化理论概率、实际命中与置信区间、档位/价值/重量和制作可用比例。用预先确定的容差或统计检验判断偏离，不能凭“随机样本必须严格单调”判失败。
4. 验证保存/加载、未领取重入、无关随机操作、支付方式切换、战斗胜负/重复回调、满包落地、临界终局、旧档兼容、空候选不扣费；交易预览与实际奖励逐项对账。
5. 供给报告分开“事件出现率”“给定事件的选项选择”“给定选项的物品概率”“实际获得并用于升级”。进入候选池不等于保证取得；将材料方案的升级可达性测试接入同一生产抽取函数。

## 9. 给测试线程的专项 UI 任务

### 9.1 测试目的

验证信息能否支撑“看见威胁 → 作准备 → 看见过程 → 解释结果 → 调整下一次行动”。本方案提供任务，不代表已派发线程或已完成测试。

| 场景 | 测试者需要回答 | 证据 |
|---|---|---|
| 战前遇到高爆发或耐力战敌人 | 对方主要威胁是什么？我可改变什么？ | 首屏和必要悬停截图，查找路径与次数 |
| 换一件回复道具或改变摆放 | 哪项能力变化？变化是否被明确反映？ | 前后数值、布局、说明与真实战斗对照 |
| 以当前倍速观看战斗 | 能否看到关键出手、状态或耐力不足？ | 录像、倍速、暂停/跳过、事件时间线 |
| 胜利/失败后 | 为什么赢/输？具体得失？接下来怎么改？ | 玩家自由回答与日志分开记录 |
| 事件钱/材料/体力/时间选项 | 点之前知道付出什么，得到什么吗？ | 按钮、禁用原因、实际扣除与结果 |
| 满包、锁定材料、临界倒计时 | 能否理解不可选或收益落地？ | 无条件吞资源、无法返回等异常记录 |

### 9.2 覆盖与方法

中文/英文，默认/大字号，项目支持的最小窗口及常用分辨率；战前、战中、战后和事件屏均覆盖。使用隔离存档与固定种子，记录构建和数据摘要。

先以玩家视角操作，不看源码寻找答案；再用源码/日志核实。测试模型能判断可见性和一致性，不能代替真人感受。作者/原玩家可进行短场景自由回答，先回答再看诊断，避免提示正确答案。

分开报告：信息不存在；信息存在但难找；信息明显但难懂；说明与规则不一致；能理解但后果缺乏意义。不要把这五类统一改成“加说明文字”。

### 9.3 UI 通过标准

硬标准：无遮挡/截断/错语种；数值与实际后果一致；不可选原因可见；损失对象明确；胜负揭示不早于当前设计规定时机；掉落与扣费可对账。

理解标准：记录是否独立说出主要威胁、一个可行调整及实际得失；小样本只报告观察，不造百分比结论。玩家说不清时保留原话与操作证据，提出最小改动后复测。不要把“看过 tooltip”当成“已理解”。

按 AGENTS.md 将真实游戏问题、测试工具问题、预期负向日志与未覆盖范围分栏；测试完成后提交报告、必要证据和索引并创建 PR 合并，遵守保护规则。

## 10. 实施顺序与验收

1. 机制审阅与 UI 初次走查，建立现状证据；补正文/图片缺口清单。
2. 先实现并验证 §8.4 的最小主题奖励池、结果保存与导入校验，再实施第一批八事件及旧事件必要安全修复；补地图事件分布、锁定一致性、禁用原因和一次性结算测试。
3. 用至少 100 个固定地图种子检查可达性、事件频率、重复限制、地图专属限制和 faith_call 保留；记录节点不足导致的未放置，不宣称每局出现全套。
4. 对每个选项验证成功、成本不足、满体力/满包、锁定物品、重复点击、读档和临界终局。对经济交易检查有无购买→事件换钱的套利路径。
5. 专项 UI 复测后才安排第二批战斗奖励与人情链。没有战后条件分支/本局状态支持时先完成依赖，不以剧情假装实现。
6. 全量 `bash tools/test.sh`、静态警告检查、导入一致性和字体覆盖检查，报告实际结果；游戏测试证据按约定提交合并。

每批报告包含新增事件 id、配置成本、物品引用、出现规则、文案与机制对照、截图、测试结果和未覆盖范围；更新开发报告索引及 status。设计规则变化同步 architecture。
