# 赐福异体参与合成：308 审阅后的执行方案

> 2026-11-12。仅方案，未实施。依据[308](../reports/308-blessed-variants-in-fusion.md)与用户最新决定。
> 本文优先于 308 中的异神优先级、“不新增任何提示”及无条件预览表述；异神双武器的【禁忌】独立记入[待办](../todo/2026-11-12-forbidden-cross-faith-fusion.md)。
> 与[体验整改](2026-11-12-v585-experience-improvements.md)及[306](../reports/306-fusion-reform-batch-a.md)配套，不重复实现已完成的 Lore、锁定和相邻确认窗。

## 1. 本轮规则

| 输入 | 处理 |
|---|---|
| 两件普通道具 | 原配方、普通成品 |
| 一件赐福一件普通 | 匹配原件，输出同神的既有赐福成品 |
| 两件同神赐福 | 输出该神的既有赐福成品，仅一份成品赐福，不叠加输入加成 |
| 两把武器分别属于不同神 | 转入异神双武器策略接口；未来产生【禁忌】特殊效果，本轮仅预留，不按价格或当前信仰抹掉另一位神 |
| 其他异神组合（武器+材料、非武器） | 采用下面的稳定择神规则，保留独立分支，不能误触发禁忌 |

“属于某神”本轮指派生赐福的来源神，不是角色当前信仰，也不是任意带 faith 标签的道具。“双拼”按两件实际输入均有 weapon 标签且是赐福异体识别，不要求两者原件 id 相同，也不依赖产物名字含“双”。此为本轮范围解释，不扩展到所有泛材料制造。

其他异神组合择神：当前激活信仰若在输入两神之中则优先；否则取固定 ItemValue 定义价值较高的输入；仍相等按稳定神明 id 文本排序。不能使用商店报价、背包位置、uid 或拖动方向。“配方靠前”不作兜底，因为 knife+knife 无法区分两件。

禁忌接口未实现前，异神双武器返回结构化 unavailable，UI 明确“此组合暂不可合成”，不显示可执行合成按钮，不消耗、不记知识。此为临时上线策略建议，用于避免假装已有禁忌效果；后续接入正式规则后移除此限制。普通和同神组合可独立上线。

## 2. 匹配和产物解析

复用 blessed_of 获取原件 id，配方仍按固定两个原件匹配，不复制 23 张配方。不要用截断下划线解析原件或神明；通过派生元数据/正式信仰注册表查来源，缺失或不一致报诊断错误，不能静默按普通件吞掉。

单一纯解析入口接收 recipe、两件定义、当前信仰与数据库，返回：
- recipe_id、base_output_id；
- status（ready / unavailable / invalid）；
- output_id（仅 ready 时有真实现存定义）；
- inheritance_kind（normal / single_faith / conflicting_faith / forbidden_pending）；
- selected_faith、排序去重的 source_faith_ids；
- warnings（如 blessing_lost）、reason_code。

字段名为建议，可沿项目类型规范落地，不为占位构建插件框架。预览、执行、拖合 output_of、相邻结果均用同一解析函数；将数据库和上下文显式传入，不让底层 Fusion 访问 UI 或全局游戏状态。

产物直接取 Blessings.variant_of 对应既有 ItemDef，不复制输入 faith_bonuses，不叠双份、不动态创建新赐福模板、不改变随机替换概率。原料仅决定使用哪份成品定义；品质、附魔、成长等实例状态继续按已定合成规则处理并提示损失。

选定神的成品异体不存在：允许普通成品，返回 blessing_lost。导入/审计列出所有此类配方与神，不自动补模板。原件成品缺失属于错误，应拒绝交易而非普通回落。禁忌 pending 不得走这个回落，不能消耗两种信仰后出普通品。

## 3. 可见性、损失告知与确认

未知成品继续显示统一问号，不泄露名称、稀有度、属性、配方 note。仅基础成品已认识或配方已发现时可显示具体产物，不能因解析成功直接揭露未知配方。

只有发生损失/冲突时加短提示：
- 缺异体回落：“本次合成不会保留赐福。”
- 非双武器异神择神：明确保留哪位神、另一份不叠加。
- 禁忌待办分支：仅告知暂不可合成，不写未实现的伤害或惩罚。
这些只描述输入信仰后果，未知状态也可显示，不必暴露成品。

一般单物品悬浮窗只列已发现的基础配方关系，不能假设另一件的信仰并承诺最终前缀。两件实际形成组合后才显示解析后的精确结果。

相邻确认时重查 uid、相邻关系、锁定/扎根/随身保护、配方和信仰上下文。相较已显示预览结果变化时刷新并要求重新确认，不悄悄扣物产出另一件。

9 条拖合若仍无确认窗，赐福损失/异神选择路径必须有知情确认；优先与既定相邻迁移复用统一窗口。迁移未完成时可在这类有损拖合处复用同一确认流程，确认前不消费悬挂物，取消恢复原操作状态。不能只改拖动预览文字却松手立即吞赐福。

## 4. 认识、发现和旧档

按原件共享“认识”是主动设计规则，不是认为异体只有外观差异。赐福还影响标签、信仰加成、稀有度和价值。

双向成立：认识普通件后认识其赐福家族；只获得异体也认识原件和同家族异体。限定在 Lore/合成可见性，不擅自改变图鉴收藏计数、成就和交易物品身份。

旧档仅存异体 seen id 时，读取/查询按原件归一并兼容原 id；不抹除真实物品 id，不把 seen 推断成发现过配方。派生缺失条目记录兼容诊断，不能根据后缀猜测。

所有异体组合成功只记录原 recipe_id 一次。预览、失败、禁忌 pending、取消不记；实际生成的是哪个异体，回执仍记录真实 output_id。沿 306 的局内 Lore 随 run 保存、结算并入 meta 机制，不另建存档系统。

## 5. 教学联动

新教学固定普通 knife 与 poison_vial 照做，旧档的 knife_brute 能合成 poisoned_knife_brute。取消对此类已有兼容原料的补发；真正缺料的恢复仍按体验方案处理。

守卫条件和提示要分别检查：
1. 玩家是否实际成功完成指定配方（recipe_id）；
2. 当前持有的普通/赐福成品是否适合继续教学；
3. 已丢弃/锁定/缺少材料是否需要整理或明确跳过。

不能合成出 poisoned_knife_brute 后仍精确要求 poisoned_knife 而再次卡住。教学专用条件可识别原件家族，不要全局修改所有 has_item/lose_item 的精确语义。有成品不自动记合成成功，反之有知识也不代表现在有成品。

## 6. 审计与测试

先拉最新 main，检查 308 是否已有实施；复用代码而非重写。输出完整配方×合法赐福来源矩阵，分类 ready、loss、forbidden_pending、invalid。

覆盖：
- 普通、单神、同神；同原件不同神（knife+knife）；不同武器原件不同神；
- 非双武器异神：当前神属于两输入/为第三神、价值同/不同、神 id 兜底；
- 左右交换、拖向反转、旋转摆位、uid 创建顺序、存读档均不改相同输入/信仰上下文下的结果；
- 同神不叠倍；缺成品异体普通回落提示；真正缺输出拒绝；
- 禁忌 pending 所有入口不扣物、不记知识，不落普通回退；
- 锁定/扎根/随身、满包及地面全满、取消、重复点击、预览后信仰/输入改变；
- 旧 Lore 仅普通/仅异体两种存档，知识与图鉴计数隔离；
- 71888 旧教学存档实合异体成品并通过守卫条件；新档普通教学完整走通；
- 中英、默认/大字号、未知预览与有损确认可见性。

审计低价值赐福组件将高阶成品变成赐福品的成本：列合法配方、原料获得渠道/价值、成品价值/信仰效果、是否新增利润回路。概率不变不代表获取成本不变；先报告差异，不无依据削弱赐福。对高影响案例调用现有战斗工具，不只比较 DPS。

## 7. 范围、交付与关联文档

本轮不改铁匠/砧的材料规则，不将归一化泛化到精确任务消耗。打造如何继承赐福另议，308 的“按同口径对齐即可”不作为授权自动扩展。

实施时同步更新 308 为“已由本方案修订”，保留历史，不继续要求旧的异神价格优先规则用于双武器；更新体验方案中的旧排除条款。禁忌单独待办，不写成已实现。

提交定向/全量适用测试、warnings、导入一致性、UI 证据和新报告，区分真实问题、工具问题、预期负向和未覆盖。按用户既有约定提交、推送、创建 PR、合并默认分支，遵守检查。本文及待办合并不代表游戏功能已上线。
