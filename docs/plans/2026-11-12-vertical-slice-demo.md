## 1. 产品目标与边界

第一阶段是可交陌生玩家实际玩的内部切片：有开始、探索选择、合成机会、战斗反馈、撤离或失败、结算与再次出征。第二阶段才是公开 Demo 的包装、平台验证和发布准备。

不是把整个正式版锁几个菜单后称为切片，也不是另做一份演示战斗。切片使用正式的背包、配方、战斗、交易、地图和存档逻辑，通过单独内容配置限制范围。修复进入共享代码，测试场景和资源筛选不侵入正式模式。

体验时长目标暂定一趟 15～25 分钟，不含首次启动/问卷；这是首轮预算假设，不是已经测得的节奏。不要为了达标加敌人生命或拖慢回放。实际偏长时优先删重复教学、节点和操作往返。

通过切片要能回答：
1. 玩家知道为什么保留/丢弃/移动一个物品吗？
2. 至少一次合成是主动选择，并能说明它改变了什么吗？
3. 玩家能用战斗证据解释一种威胁、一次防御或关键反应吗？
4. 撤离与继续探索之间有真实可见的取舍吗？
5. 玩完后是否愿意尝试另一条路线？只记录自愿行为与回答，不许用代理评价代替真人结论。

| 内容 | 第一阶段范围 |

| 角色 | 安德烈乌斯一个角色；一个基础预设，第二个防御取向预设仅在首轮后加入 |

暂不展示不等于删除正式资源。对外界面不出现开发占位、“待实现功能”菜单或不可解释的死链接。固定说明“试玩内容范围”即可，别让玩家判断实现阶段。

## 4. 一趟远征的结构

采用约8～12个可到达节点的受控路线模板，首轮不是直接拿现有小图随机结果赌关键内容。复用已有手绘地图/布局加载能力；若接口不足，补最小章节/场景配置，不另写生成器。具体节点数随首轮时间调整。

| 阶段 | 场景安排 | 玩家要感受到的结果 |
|---|---|---|
| 起步 | 简短出征目标，放入一把武器，查看一个邻接效果 | 摆放真的影响可用装备或已存在的效果 |
| 基准战 | 一个威胁简单的对手，可预览，战后可回看 | 理解生命、防御和实际胜负 |
| 收集 | 两个可选来源，提供一条可完成配方所需组件 | 物品除了卖钱，还有组合用途 |
| 第一次合成 | 未知结果允许取消；准备一条保守继续路径 | 发现而非被强制交作业，知道会消耗什么 |
| 分支 | 商店/事件的低风险支路，对比精英的高风险收益 | 资金、体力、背包空间共同影响路线 |
| 撤离决定 | 安全出口与终点挑战都可理解 | 带回现有收获本身是有效成功 |
| 终点 | 现有机制守卫，战前看得到威胁 | 战胜的收益和失败后果明确 |
| 回营 | 带出、损失、知识保留、入库及再次出征 | 一趟经历有持续后果 |

不要强制必须合成才能离开，不把忽略配方写成测试失败。第一条机会由来源保证，结果仍按知识规则隐藏；首次体验原料成本低，合成不能消耗唯一可用武器后让玩家无合理继续能力。

至少保留一条不依赖随机金币的可达撤离路径。付费撤离若保留，费用来自配置、提前可见；不要照搬50币导致第一次试玩必然凑不齐。终点战胜后同样走实际撤离/结算，不凭开发脚本直接写成功。

守卫只作为切片终点挑战，不冒充正式最终Boss；选择真实enemy_id并核对战斗身份，不新增一套专属战斗系统。

## 5. 首版配方与来源清单

候选优先使用已存在定义，正式启用前核对C批是否改变配方：

| 配方候选 | 展示价值 | 内容条件 |
|---|---|---|
| knife + knife → twin_blades | 两件武器换一件，空间与作战方式变化 | 需要两个不同uid；第二把刀是明确探索收益 |
| shortsword + whetstone → broadsword | 磨刀石用途可推理，展示另一武器方向 | 与匕首线路形成选择，不保证所有原料同局全拿齐 |
| knife + poison_vial → poisoned_knife | 通过持续伤害回应有格挡的对手 | 等C批相邻+确认落地；不为切片保留松手直接合的旧教学 |
| bandage + linen_bolt → bandage_roll | 非武器组合也有价值 | 同样依赖C批交互统一；实际效果和供给按现有数据核对 |

前两条可先作为内部骨架，完整陌生玩家首版需四条都使用统一确认流程。第五/六条只在测试支持时从既有路线选择，不为展示高档而加入长链。

P0生成 slice_manifest（建议放项目既有内容配置体系中）：章节/模板、角色与预设、allowed_item_ids、recipe_ids、enemy_ids、event_ids、各来源及权重、确定教学供给、出口条件、版本。名称仅为建议，执行者先复用已有schema。每个可获得的成品及其所需资源逐项标来源，不把候选资格当保证获得。

来源保证不等于所有掉落固定：第一条发现机会的关键组件确定存在；其余从狭窄主题池抽取，保留轻微变化。事件池有放回，结果实例冻结；测试抽样不能靠反复进同一事件刷新。

首轮普通原料不引入赐福冲突。若赐福系统仍能替换候选，必须在切片来源配置明确排除或先完成赐福兼容，不可放任玩家遇到不可解释组合。该限制仅作用于切片，不全局修改概率。

## 6. 内容裁剪的技术边界

一个切片入口/配置驱动正式GameFlow；开发启动参数可用于内部选择，公开包使用普通可见开始入口，不要求玩家输入种子或开开发菜单。

采用独立存档命名空间或经过验证的独立用户目录；profile_id与版本随档保存。不得加载正式仓库、把切片知识写入正式档或切换模式后改写玩家资产。是否向正式版继承进度暂不承诺。

筛选要覆盖整条来源链：搜索、事件池、商店、敌人装备/掉落、起始物品、合成、信仰赠物与特殊保底。不能只藏图鉴和菜单。敌人所需内部道具可以另列依赖集，玩家掉落遵守可得清单；不可因删内部资源导致敌人无法编译。

隐藏不开放的砧升级入口，仅在切片模式；不连带删除附魔/恢复等正式功能。不等待全库82条迁移才制作骨架，但发布切片的四条配方必须完全使用最终交互；若共享C批仍在重构，只做内容表、布局和测试，不另建临时分叉实现。

保留生产逻辑和美术资源，按内容白名单限制玩家接触范围。打包裁资源需追踪动态加载的依赖；第一阶段宁可包体稍大，也不要复制脚本和资源制造双份维护。

自动检查无未知id、缺依赖、空池、不可达出口、配方无来源、过滤后敌人空装、非法奖励。切片结束后回营只呈现开放功能，不触发正式后续章节/NPC任务。

## 7. 教学与反馈

本切片授权范围为**新的切片引导配置**：首次可操作前最多一段简短引导，不直接重写三张正式序章。行动完成条件来自真实事件；关闭说明不当作动作已完成。

第一课只教摆放和开战；容量、合成、反应、交易在第一次真正遇到时提示。长风味文字仍可自愿查阅，保留书本风格。未知合成沿v5.90纸条和问号样式，成功后输入和成品悬浮窗显示已发现关系。

战斗反馈优先使用现有日志/回放：
- 格挡与护甲分开；生命与地图体力分开。
- 关键反应的教学指向当时可见反应，不是任意状态行。
- 战后列实际得失与下一步入口，治疗参与时不将末血差当总伤害。
- 不自动给未经证实的“失败主因”，不增加综合评分面板。
- 回放正常倍速为默认参考，已有倍速/跳过尊重玩家选择，不强制延长短战斗。

玩家要能看见合成前后差异；未知成品不提前泄露属性，成功后再明确展示。不得用不同敌人的战斗结果直接声称升级提升了百分之多少。

| 里程碑 | 交付物 | 验收 |

| S0 基线与内容锁定 | 最新SHA、实现状态、manifest、布局与出口图、资源缺口、任务工量估计 | 四条配方与所有来源可解释，明确C批依赖 |

| S2 核心体验 | 关键组件供给、统一合成、交易、简短动作教学、战后反馈 | 玩家能在真实UI完成，数据守恒、知识正确 |
| S3 回归与内部候选包 | 自动化、真人前专家走查、可分发玩家包、版本清单 | 关键功能门禁通过，未覆盖明确 |

工期在S0之后估算：分别给代码、内容、UI、QA工作量与依赖；不得把模型生成代码时间当成整个制作工期。优先级为稳定循环→理解→选择→画面细节。

### 功能硬门禁

- 关键原料不会被祝福或来源过滤破坏；四条配方生产路径确实可完成。
- 未知预览、取消、已知结果、保存重启后知识一致；无吞物/复制/死锁。
- 至少一条实际可达退出路线，错误选择不会陷入无任何结束入口的界面。
- 物品、货币、交易、撤离和失败结算可对账；独立存档不污染正式档。
- 默认与大字号、中文与英文的关键流程可操作，无截断遮住关键按钮。
- 测试通过不等于无异常日志，SCRIPT ERROR、未预期错误必须处理，退出资源告警单列归因。

## 9. 测试与观察方法

### 9.1 三种验证不混写

1. **功能测试**：配方/交易/存档/地图可达性/筛选依赖。
2. **专家可见UI走查**：提示是否出现、文字是否对齐规则、实际窗口能否操作。
3. **陌生玩家观察**：理解、发现意愿与重玩兴趣。只有第三类能提供相应体验证据。

固定开发种子做复现，另留独立种子做验证；模板下也检查奖励变化。首轮可用20个种子筛基本断路，发现随机依赖再扩大，不把20当统计充分。记录配置摘要，避免同种子不同版本被误称同一场景。

复用现有战斗工具做输入成对比较，至少覆盖基础/合成后、快攻/防御、缺组件、低体力和背包紧张。固定敌人与上下文比较，不套全游戏统一胜率目标，不直接引用历史2.2秒为节奏指标。

### 9.2 最小本地记录

复用现有runs/calibration/教程日志，缺字段时小幅扩展，不搭分析平台。记录build、profile版本、seed、真实玩家操作/游戏时间区分、关键步骤、候选配方与实际合成、取消/跳过、交易、战斗结果、撤离与失败、退出重进。

计算“到首次操作/首次合成/结算”的时间、首次合成机会到完成的比例、选择哪条路、放弃原因、求助次数。自动化等待与云端卡顿剔出玩家耗时解释。无合成者保留在样本中，区分没遇到、没看懂、不愿合成。

日志默认本地，测试者自愿提供脱敏证据；不加默认联网遥测。

### 9.3 陌生玩家任务

邀请4～6名没玩过项目的人，先不给配方答案。让他们自主玩，结束后询问：
- 为什么留下这件、丢掉那件？
- 刚才合成得到什么，为什么值得/不值得？
- 指定战斗里护甲或格挡做了什么？
- 为什么选择撤离/继续？实际带回或失去了什么？
- 是否愿意再试不同路线，具体想试什么？

逐人记录，不把小样本百分比当总体转化率。成功并非每人都打赢守卫；能理解并主动撤离也是有效结果。若多人在同一节点求助，先修该节点。没有真人时可交内部候选包，但不能宣称S4通过或公开展示已验证好玩。

## 10. 阶段二：公开 Demo 打磨与发布条件

S4确认核心体验有可重复的正面证据后再启动。默认先准备桌面鼠标键盘玩家包；首发平台建议Windows，执行时核实模板和目标机，Linux云端仅作开发验证。Web、手柄、移动端不隐含纳入。

### 必做

- 正式导出包，关闭开发入口和调试注入，独立存档；无需编辑器可首次启动、暂停、退出、恢复、结算和重开。
- 目标设备上测启动、地图/战斗帧时间、峰值内存、首次加载卡顿与长时间重复开局；记录机器配置和构建。以拟定最低配置实测后再公布，不用llvmpipe或30FPS工具限帧推断性能。
- 已有美术与纸条风格统一；首屏、合成、战斗、结算四个关键画面打磨，不全库返工。
- 真实音频设备验证音量、静音与切场景；使用现有合规音效。若配乐仍缺，选择经授权的小范围素材或如实采用无配乐版本，不能依赖Dummy音频验收。
- 中文/英文、支持窗口和字号矩阵；未知配方、多页说明及输入提示全部可读。
- 清晰的试玩范围、版本、退出入口、反馈渠道说明；发布文案只承诺包内实际可玩的内容。
- 保存旧候选包回滚能力、资源许可清单、已知问题、安装/运行说明、构建校验值。

公开包硬阻塞：崩溃、档污染、关键操作不可达、无法结束、明显吞物/复制、关键文字遮挡、素材无合法使用依据。普通内容少不是阻塞；未做红武/禁忌不应伪装成缺陷或承诺即将上线。

制作候选包与发布是不同动作。本文授权制作与验收方案，不自行上传公开商店、发公告或联系测试者；需要发布时交付具体候选包、渠道与文案供用户决定。

## 11. 控制成本与扩范围规则

优先复用：正式UI、现有敌人/武器/事件、未知图标、地图主题与结算。第一阶段不新增角色、完整Boss机制、动态材质贴图、复杂神明争夺或全面经济改造。

遇到范围超预算，按顺序砍：额外配方→第二预设→局外打造展示→可选事件。不能砍存档隔离、真实失败/撤离、合成知情确认和关键反馈。内部骨架不等全游戏改革完成；公开候选不使用临时旁路来掩盖共享核心缺陷。

如果新玩家已经理解规则却仍不觉得选择有意义，优先调整组件机会成本、敌人差异和路线收益，再考虑加内容；不要默认增加说明页或更多武器。

## 12. 交付与Git约定

每个里程碑交付配置/代码、可复现命令、commit、资源摘要、测试结果与截图/录像；报告使用docs/reports/下一可用编号或testing惯例，更新索引。设计文档与实施状态分开，不把本方案合并标记成Demo完成。

定向检查后运行适用完整test.sh、warnings.sh及导入一致性；日志隔离，真实存档不受影响。分类列出游戏问题、工具问题、预期负向、未覆盖。保留历史证据，不覆盖v5.85报告。

按用户约定提交、推送、创建PR并合并默认分支，遵守检查与保护；内容选择与修复进main，切片只是受限配置，不长期维护独立产品分支。

下一执行者从S0开始：核对最新C批及赐福计划状态，列具体manifest与路线，随后实现可玩骨架。不可直接跳到宣传、美术扩充或全量武器重平衡。
