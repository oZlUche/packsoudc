## 1. 目标与边界

优先确保玩家能完成教程所教的动作、理解战斗中真实发生的事，并知道胜负后实际得失。保留已成立的背包空间取舍、敌人预览、交易天平、付费撤离和书本表达，不扩大制作系统或重做交易系统。

此次是内部垂直切片的前置整改，不是公开 Demo 发布计划。两局专家走查不能证明总体难度、留存或长期经济；不因数场 2～13.8 秒战斗直接提高生命、改伤害或强制延长播放。

执行前拉取最新 main，记录 SHA、版本与引擎。将 E01～E05 逐项标成“仍可复现/已修复待验证/无法确认”，附当前证据。status.md 顶部仍有历史版本信息，优先核对代码与 changelog，不能据旧状态重复施工。

## 3. E01：教学合成必须能完成

### 3.1 已知问题与处理选择

报告种子 71888 第一战得到 knife_brute，后续 poison_vial 只与普通 knife 精确匹配。备用入口让玩家通关但结算 crafts=0，不能当“合成教学成功”。

采用最小修复：**只对序章关键教学供给保证普通 knife 与 poison_vial**，普通地图的祝福替换与精确配方规则保持既有语义。追踪教学物品最终进入玩家可取容器前的全部转换，不能只把初始数据写成 knife，随后又被祝福管线替换。

优先在教学专用来源上指定确定物品；不全局禁用祝福、不将 blessed_of 自动降格成普通原料、不复制一整套祝福配方。不回收或替换玩家已经取得的异体。

> 2026-11-12 修订：赐福版按原件参与合成已由[赐福异体合成方案](2026-11-12-blessed-fusion-review-actions.md)实施（报告 312，v6.02），本段「不将 blessed_of 自动降格成普通原料」只指教学来源，不再排除赐福合成；旧档 knife_brute 直接能合，不再补发普通匕首。

新档标准流程应能自给足完成该配方；额外补给只服务确实缺少兼容原料的教学状态，不能每次重入无限领取。

### 3.2 教学状态与旧档恢复

- 区分“有成品”“实际成功合成过指定 recipe_id”“教学选择跳过”。仅持有成品可允许继续，但不能声称完成合成动作。
- 旧档已有 knife_brute 时，提供一次性的兼容原料补教入口或明确跳过；不清空旧存档、不修改异体实例。若已有普通 knife，只缺毒药，不再送第二把刀。
- 满包时允许教学供给按生产规则落地并给出可整理提示；容器都无法接收则不标领取完成。领取状态和物品发放一起保存，重复进入不复制。
- 输入被锁定时提示解锁或换用合法实例，不能绕过 Fusion.spendable；玩家已丢弃/出售教学材料时允许明确跳过并保留可重看的操作说明，避免无限补领套利。
- 跳过提示建议为“当前没有可用的合成组合，直接准备战斗”，不要断言没有匕首；有合法材料但未合成时继续给操作指引。
- 指引引用实际操作：若 poisoned_knife 仍是拖合，教现有拖合；若改革已迁相邻，统一为“将两件相邻放置 → 点击合成标记 → 查看消耗 → 确认”。对应更新中英文事件、帮助与测试，不能两种口径并存。

### 3.3 测试

复用报告的隔离合成前存档与 recipe-probe，先在原版本复核，再在最新版本测试兼容加载；不能直接覆盖正常 run.json。

夹具覆盖：普通刀、knife_brute、其他由正式生成器产生的祝福异体、缺刀、缺毒药、已有成品、锁定、满包、取消、重复领取、保存重启。正常种子 71888 走完整序章，另选实际触发普通/祝福路径的种子并记录。

验收：指定合成实际消耗正确两个实例、产出 poisoned_knife、对应知识/计数仅增长一次；未完成者明确记 skipped 或未完成，不自动写成功。全程没有静默消耗祝福武器。

## 4. E02：防御与战后结果必须可解释

入口：core/battle/battle_narrator.gd 的 stopped 分支、守卫事件 tut_elite.json、相关词条/中英文教学。

### 4.1 防御语言

优先修表达，不改变结算顺序：

- 仅护甲：明确“护甲吸收 X”，必要时显示剩余护甲池。
- 仅格挡：明确“格挡抵消 X”，按当前正式格挡规则描述。
- 两者都有：分别列实际贡献及最终生命损失，不能把两部分重复算进总减免。
- 毒、流血及穿透/其他伤害类型：依据事件里的实际处理，不把通用文案“毒无视所有防御”写成新规则。

从真实伤害解析事件读取数值，别在 narrator 里重新实现减伤计算。覆盖吸收恰好耗尽、超出护甲池、完全阻挡和零值场景；存在其他修正时按真实伤害流水对账，不用简化公式漏掉其他修正。

守卫教学按真实圆盾解释格挡，替换“披着甲”叙述；不要为了迁就旧文案给敌人添加护甲。静态教学数字优先引用配置；若敌方装备允许变化，使用条件文本或固定教学敌人装备契约。

### 4.2 生命、体力与胜败所得

首次相关场景短句区分“本场生命”和“地图红心体力”，下一战恢复生命按当前规则说明；不将正常重置列为恢复 Bug。

利用现有结算与回放展示：本场结果、实际体力变化、获得/失去物品或货币、回放入口。胜利不等于从未受伤；累计受伤与战末血量之间可能有治疗，不能相减后认定日志错误。报告焰狼战可作为已有治疗参与的复核案例。

首轮只校正文案与关键现有信息，不新建综合战力评分面板、不猜“最主要败因”。能验证的归因再展示，缺少数据则保持事实陈述。

验收：仅护甲/仅格挡/混合/毒与流血的日志与实际状态一致；下一战生命与地图体力变化可解释；中文英文用词一致。

## 5. E03：先呈现反应证据，再暂停讲解

报告仅证明教学出现时目标区未显示相应状态，不能据此改底层反应计算。

先复现同一守卫回放，记录反应事件时间、状态视图更新完成时间、暂停与遮罩创建时间。修复采用事件驱动：状态视图应用该战斗时刻的数据且目标可见后再展示教学，不用固定 sleep 或“多等几帧”掩盖竞态。

优先锚定毒/流血或实际反应展示项，而非整个状态行。如果反应结算已消费状态、对应图标不再存在，显示从真实事件生成的短暂反应提示“毒 + 流血触发菌血”，锚定该提示；不要伪造仍存在的状态图标。关窗后正常继续，不重复结算反应。

首句只讲发生了什么，机制细节保留可展开说明。目标不存在、战斗已结束、回放跳转时取消或重新定位提示，不能指向盾牌或悬空位置。

验收：正常播放、支持的倍速、暂停/继续、拖动回放、同刻多事件、终结一击；不同窗口和字号下锚点正确。反应教程的首次完成标记与回放重看分开，不每次拖回都强制弹窗。断言实际伤害/反应结果修复前后不变。

## 6. E04：教学改成动作驱动的小步骤

先盘点第一轮强制说明：触发点、页数、阻断操作、目标动作、可观察成功条件。不是只删字，而是减少玩家第一次行动前必须记住的内容。

建议流程：

| 阶段 | 本次只教的动作 | 完成证据 |
|---|---|---|
| 初次整理 | 把一把可用武器放入背包 | 实例实际在有效格位，现有能力信息更新 |
| 第一战 | 查看对手并开始战斗 | 玩家进入战斗；战后能找到结果与回放 |
| 首次容量冲突 | 留下或重新摆放物品 | 合法摆放或主动放弃，不把点击“知道了”当会整理 |
| 首次合成 | 对兼容原料完成真实合成 | 生产合成回执含指定 recipe_id |
| 首次反应 | 看见真实反应并理解一句因果 | 教学锚定证据；不强制玩家背公式 |
| 首次撤离 | 看清费用与带出结果 | 确认后实际结算与入库 |

已完成的动作不重复强制解释；可选长文保留入口。多页时给明确进度，提示下一步可点击位置，不强制等待无意义动画。搜索与背包切换检查可否减少一次无信息的往返，不顺带重做整个地图 UI。

动作条件不能因满包、误放、锁定、关闭窗口或存读档永久卡住；允许退出当前说明、重新查看。知识/教学标记与“跳过教程”分开，普通流程不假称已做过三趟。

此项属于专家建议，先用改前/改后记录验证打断次数和自主动作机会，不把代理工具延迟或文字总量当真人理解度。

## 7. E05：商店只补首用提示

沿用现有交易天平与确认逻辑。首访短提示建议：“双击挑选商品；点自己的钱袋补差；确认后成交。”按实际输入绑定与本地化模板生成，不把键名写死。

给可点击钱袋明确悬浮提示；差额为零时不诱导继续加钱，资金不足时说明不足。离开未成交仍按原规则撤销挂账。不要把报告中尝试单击/拖动视为交易故障，除非最新版本独立复现操作契约错误。

验收：首次购买、已有足额交换物、缺钱、取消、离开、重入和读档；货币与物品守恒。初访提示不在每次进入弹出，帮助仍可重看。

## 8. 复用既有合成改革，补真实 UI 覆盖

306 已完成锁定保护、Lore、未知成品遮挡、相邻合成确认与寂灭检查；本任务不重复建设，也不要求再引入新的跨文件事务系统。核对已采用的“局内知识随局内档保存，结算并入局外”规则及回归结果。

v5.85 报告没有触发相邻确认窗，因此需专门实际走查：
- 未知成品为问号，无图标/颜色/属性泄露，消耗明确；
- 已认识但配方未发现时可预览，取消不记录；
- 窗口移动鼠标不意外关闭，确认和取消可点击、不挡必要操作；

- 地面/棋盘跨容器、锁定、满包和保存重启。

## 9. 验证、统计与内部切片门禁

### 9.1 自动化与诊断

复用现有配方探针、教程状态测试、战斗日志测试、回放 UI 测试及合成 Lore 测试。补缺失断言，不用“相关 305 套件通过”代替整个教程链走通。

建议最小结构化记录：build/seed、教程步骤 id、触发/展示/关闭、成功/跳过/失败原因、合成 recipe_id 与成功事件、播放时刻与锚点、交易完成/取消。只记录本地诊断需要的字段，不上传玩家数据；复用现有日志设施，避免新建分析平台。

E01 原始失败档与新档分别测试；UI 截图加关键连续录像，日志时间与画面能对齐。运行适用的定向测试、完整 test.sh、warnings.sh、内容导入一致性；记录真实退出码与断言数量。

ObjectDB/资源退出告警单列工具治理：定位夹具释放、静态缓存或运行实例，给前后计数。不能简单加入 expected_errors 白名单使测试变绿，也不能未调查就声称玩家每局泄漏。V-Sync 云端警告与帧率限制不作为性能优化依据。

### 9.2 实际游戏复测矩阵

- 主回归：新档种子 71888 完整序章；普通小图种子 780613 完整出征→购买→撤离→入库。
- 合成：补一场真正走到相邻确认、未知发现与已知预览的独立路线。
- 防御与反应：使用固定战斗夹具 + 原生回放，确认逻辑及显示时序。
- 中文/英文 × 默认/大字号，项目支持的最小窗口和常用分辨率；关键弹窗/长文优先覆盖。
- 补至少一次失败后的实际体力与物品结果，以及退出重进；正式自由局未打到耐力耗尽，长战用独立真实规则场景验证，不把原报告当已覆盖。
- 音频、真实设备性能、第二三章完整内容与长期经济仍需专门测试；缺环境时写明不覆盖。

内部切片门禁：标准教学路径可完成合成；没有无法继续的步骤；防御叙述、反应锚点、交易和撤离结算正确；失败与成功至少各有一条完整可解释证据；关键数据保存无复制/丢失。通过这些不等于公开 Demo 已可发布。

### 9.3 小规模新玩家观察

有条件招募 4～6 名未接触项目的人，不由代理替代。任务是完成合成、说明护甲/格挡区别、区分生命/体力、购买一件商品、自选撤离；先让其自由操作，再询问判断依据。

记录是否求助、误操作、错误预测、原话与任务结果；不要在测试前教正确答案。不用小样本造留存率或总体难度结论。暂无玩家时继续功能验收，报告真人理解度仍未验证，不阻塞 A/B 修复。

## 10. Git 交付与完成判定

每批新报告放 docs/reports/ 或现有 testing 目录惯例下，更新报告索引与必要状态；原始 v5.85 报告及证据保持历史完整。表格逐项关联 E01～E05、修改 commit、复现结果、测试与图片，区分游戏问题、工具问题、预期负向、未覆盖。

按用户约定提交、推送、创建 PR 并合并默认分支，遵守必需检查和保护。不能把方案提交写成修复完成，不能把全量测试通过写成真人已理解。与合成改革并行的变更先核对接口和教程操作，不恢复旧实现来迁就旧测试。
