## 4. 单局阶梯结算

### 4.1 已确认规则

按最终结算总分 S 发放：

| S | 见识 |
|---|---|
| S < 1000 | 0 |
| 1000 ≤ S < 2000 | 1 |
| 2000 ≤ S < 5000 | 2 |
| S ≥ 5000 | 3 |

达到即领取；每档额外1点，5000分总计3点，不是只领取最高档1点。阈值1000/2000/5000是首轮测试配置。

- 成功、失败使用相同阶梯；成绩不同可自然导致奖励不同。
- 分数不跨局结转，不做固定比例兑换；已获得见识跨局保留并可消费。
- 不新增另一套隐藏“有效积分”。先修正可被利用的计分来源，再以屏幕显示的最终总分判档。
- 历史总分不扣减、不追溯换点；满树后点数保留，不兑换金币/属性。
- 正常保存退出不结算；现有“放弃本局”若作为结束，只计实际有效行为，不奖励放弃本身，不额外新增放弃入口。
- 菜单回看、重复读取、结算重试不得重新发奖。

### 4.2 计分审计先行

必须复核携入物品、商店购买、托付物品、合成计数、图鉴发现和出生点。历史成绩原本用于展示，不能假设可直接承担经济发行。

重点回归：
- 带高价物品进图立即带出，重复获得战利分。
- 同一物品从棋盘/托付/容器反复流转而重复计分。
- 买入卖出循环、反复操作同一节点、可逆制作重复刷分。
- 用难度倍率放大出生或低风险重复操作得分。

建议战利分只计本局新增、实际带出的合格价值；携入本金、购买本金不可反复计入。实施前选择并记录统一的来源/价值归因规则，包括合成成品承接投入价值、托付与背包合并去重，不能仅靠最终物品id判断是否新增。若采用更简化规则，必须解释取舍并用反例验证。

有效探索按唯一内容/节点事件计数，出生点不产生可刷成长分；首次发现按存档级去重。保留正常重复游玩的奖励，不做每日上限或反复游玩惩罚。

新计分规则使用版本标记，旧历史记录不重算；必要时区分历史最佳和新规则最佳，避免不可比成绩混用。

### 4.3 结算与存档

复用最终 MetaState.absorb/结算提交边界：物品、图鉴、最终积分计算完成后才判档，不能在 compute_score 每次调用时发点。

建议持久化：
- 见识余额、累计获得/花费/迁移补偿。
- 稳定的 run_id（不能仅使用随机种子）、结算提交标记。
- 本局最终总分、奖励规则版本、已达档位、实际发点。
- 存档迁移版本。

结算记录与余额变更使用同一次原子存档提交；重试可恢复且不重复发奖。避免无限增加无用记录，沿用现有历史归档策略，但已结算状态不能因清理历史而失效。

## 5. 额外保底奖励

1. 精英额外1件稀有及以上；BOSS额外1件史诗及以上。BOSS不再叠领精英科技奖励。
2. 原生BOSS保底、正常掉落照常；科技奖励单独追加。信仰额外奖励作为不同来源独立处理，不能挤占或覆盖科技奖励；记录各来源并联合评估总产出。
3. 掉落后进入战利品，玩家仍需拿取和带出，不直接发仓库。
4. 使用有放回池；一次抽取不消耗池成员，允许跨次重复。
5. 池配置明确最低/最高稀有度、各档权重、章节和难度资格。首版上限为合法普通金色档，排除红武；“以上”不意味着均匀概率。
6. 排除唯一/任务/合成专属、其他BOSS身份专属、票券、金银及不适合通用奖励的特殊道具；沿用内容获取权限，不单靠稀有度判断。材料是否入池由明确白名单决定，界面不得误称必出装备。
7. 禁止复用向下回退的 rarity_guarantee 语义。内容导入时验证所有可触发组合均有合格池。运行时异常使用预先验证的同下限备用池；备用池仍为空应报明确诊断，禁止偷偷降低品质或抽取禁品，并将其视为发布阻塞错误。
8. 使用持久化且确定的随机结果；重进战利品界面、读档不重抽。
9. 敌人预览/期望掉落沿用同一解析入口，显示科技额外来源，不维护另一套近似规则。

## 6. 讨价与局内商店刷新

### 6.1 讨价修正

当前购买价格倍率参与收购价计算，存在买便宜同时卖便宜的问题。将购买价与收购价计算解耦：
- bargain只影响符合条件的商人货物购买价。
- 玩家物品收购价以不含讨价折扣的基准与出售比例计算。
- 金银、回购、损坏物品、随身技能等按各自现有规则处理并明确例外。
- 不全局改写通用 shop_price_mult 的全部语义，先检查所有调用者，避免改变其他事件或信仰效果。
- 验证折扣叠加、取整和回购不产生稳定套利；不得以重新压低玩家卖价掩盖问题。

### 6.2 刷新首版规格

每家商店一次；科技只解锁能力，刷新另付局内金币。刷新价格配置化，先以当前常见商品价格和钱包分布给出测试值及依据，不在代码硬编码。

刷新前必须：交易台没有未确认交易/金币报价/随身格报价，没有进行中的拖拽，金币足够，次数未用，科技已生效。

刷新只更换可刷新商人库存：
- 玩家卖入物品不删除；归属/来源标记跨离店和读档保留。
- 商人钱袋不重置。
- 首版不刷新随身技能报价；按钮说明清楚。
- 已购买物品和玩家物品不参与回滚或重抽。
- 在保留格位之外生成合法可放置新货，物品不能丢失、重叠或复制。
- 完全无法生成有效新货时不扣钱、不耗次数，提示原因。
- 生成新棋盘、扣费、刷新次数和随机结果统一提交；异常时全部不生效。
- 刷新次数按节点存储，退出/重进/读档不重置；相同输入与随机状态可复现。

不能直接套用局外 Market.refresh：局内有交易台、回购与棋盘物品归属。

## 7. 旧档迁移与生效时点

迁移先备份，版本化且幂等；保留迁移清单以便核查。默认实施策略：

| 原状态 | 处理 |
|---|---|
| 数值树节点 | 等级、已交材料保留 |
| 原机制节点（除bargain/luck） | 等级与能力免费保留，不再要求补交见识 |
| bargain 1或2级 | 迁为新单级固定9折；退还旧第二级额外投入（按版本映射核算） |
| luck任意已购等级 | 删除旧科技幸运buff，退还已购等级对应的原金币/材料成本；不自动发两种新奖励 |
| 机制节点未完成的材料提交 | 退还已交材料，清空旧提交账 |
| 尚未购买 | 采用新成本与前置 |
| 历史总分 | 不自动兑换见识 |

注意：上表bargain第二级成本应以原版本表为准；已核对旧表为1000金币及1银锭。实现使用版本映射，不通过当前新表推算旧成本。此处退款是一次性迁移补偿，不是开放日常退款系统。已经保留的有效机制等级不再全额退款，以免重复补偿。

退回材料若仓库放不下，使用现有安全领取/暂存方式；若没有，则增加最小迁移领取账，禁止静默丢弃。金币/材料补偿不是见识发行。

开局冻结科技效果与规则版本；进行中旧对局保持原效果至结束。旧对局结束后完成迁移，奖励按明确记录的版本结算，不能中途切换掉落/计分规则。局外仓库等设施更新也须在安全的局外状态完成。

正式档与slice档分开迁移，不能将正式档科技、余额或历史导入slice。切片新点数展示与科技入口维持原范围，除非之后另立切片成长展示任务。

| 商店 | 无科技、报价中、拖拽中、钱不足、一次限制、卖入物品保留、钱包不重置、无空间失败原子性 |
| 经济 | 讨价只改买价；损坏/回购/金银/折扣组合无新增套利 |
| 迁移 | 空档、各级旧luck/bargain、部分提交、满仓、满树、进行中旧局、重复迁移、slice隔离 |

统计每局：run_id、规则版本、种子、章节/规模/难度/角色、科技快照、结局、有效战斗/探索事件、战利计分来源、最终分数、档位与见识、活跃游玩时间与行动数、净财富、购买顺序、额外掉落来源、刷新成本和使用情况。测试注入资源必须标记并排除正常成长统计。

实验至少覆盖新档/部分成长/满成长、不同章节与规模、D1–D5、成功与失败；同种子配对对比。行为策略包括认真探索失败、快速刷第一档、满档即撤/放弃、继续挑战、正常撤离。先做小样本发现问题，再针对异常扩大样本，报告种子和样本量。

输出：
- 各组0/1/2/3点比例、首次购买和首次机制解锁局数。
- 见识/活跃分钟与见识/行动数，兼看净财富和风险。
- 第一档与满档后的主动结束收益。
- 各节点购买率、购买后实际触发/使用率。
- 满科技对掉落、净收入、胜率与成长速度的影响。

自动模拟不能证明有趣；人工体验验证玩家能说明：本局为何得这些点、下个目标是什么、买后下局有何变化。初始阈值与成本通过以上证据再定，不宣称未经验证的时长目标。

发布阻塞：重复发点/扣费、旧档物品或权益丢失、非法掉落或违反下限、可复现稳定套利、跨档污染、配置与运行效果不一致。性能/随机测试报告区分游戏问题、工具问题、预期负向日志和未覆盖范围。

## 11. 后续机制候选（不进入首版范围）

分别考虑等预算出征补给选择、商店类别采购委托、撤离情报、单次奖励二选一。目的在增加选择，而非继续叠加产量。需扩展时在 docs/todo 下逐项建独立idea文件，说明触发、效果、成本、接口与验收，不合并成一个无边界的大任务。
