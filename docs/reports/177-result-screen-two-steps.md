# 177 · 结算屏拆两步：先看账（大字总价值 / 图鉴 / 金币），再进背包与仓库

> 作者 2026-10-16 13:57（附截图）：「将撤离界面分为两部，第一步显示这个，用更大的文字显示总价值，点亮图鉴数、金币数，下方有继续按钮。第二步才是现在的背包和仓库」。性质：界面 · 实施。待定按推荐。关联 058（结算屏）、092（保险箱、遗落一键出售）、156 §16 / 157（战败时保险箱居中放大）、164（仓库面板两种用法）。

## 1. 现状

`ui/game/result_screen.gd` 一屏到底：标题、一行模式 / 种子 / 出口、一行行动点 / 踩点 / 胜负、（信力节奏行）、一行「背出来 N 件、值 N 币、带出 N 币；图鉴新点亮 N 条」小字灰色、遗落提示、保险箱格、然后 `WarehousePanel`（带回来的棋盘 + 仓库分页）塞在同一个竖向滚动里，「继续」钉在底下。账在进屏之前已经记好（`GameFlow._settle_run` → `flow.result`、`flow.last_absorbed`），这一屏只是展示 + 置入仓库。

## 2. 方案

同一个 `Screen.RESULT`，屏内两步 `_step`（1 账 / 2 仓库），不加枚举、不改 `GameFlow`：`open()` 建第 1 步，第 1 步的「继续」在屏内重建成第 2 步，第 2 步的「继续」才调现在的 `proceed()`（一键出售遗落、去局外或进下一张教学图）。

### 2.1 第 1 步 · 账

石板居中一块（`_slab_screen`，深色，158 的 tone 规矩），内容竖排居中：

1. 标题「撤离成功」28（现有），下面一行灰字模式 / 种子 / 出口（现有）。
2. 一行行动点 / 踩点 / 胜负（现有，14）。信力节奏行与开发版的导 CSV 按钮留在这一步（它们是读数）。
3. **三块大数**，一行并排、等宽，各自上数下名：
   - 「总价值」= `r.value + r.safe_value`（背出来的 + 保险箱里的，待定 1），数字用 `UiPalette.display_font()`（马善政）**48**，颜色 `HEAL`；名「总价值」13 灰。
   - 「图鉴点亮」= `flow.last_absorbed.lit`，数字 **32**，名「图鉴新点亮」；0 条时数字灰色。
   - 「带出金币」= `r.balance`，数字 **32**，颜色 `STAMINA`（金币色），名「带出金币」。
   - 数字是结算读数，按 TextLint 的例外（界面运行时拼的数不是内容文案）。
4. 一行小字：「背出来 N 件、保险箱 N 件」13 灰（件数不进大数）。遗落提示（092 那句「地上还有 N 件……离开这一屏时会一键出售」）放在这里，颜色不变——玩家在第 1 步就知道账里没算的那部分会怎么处理。
5. 底部「继续」16 PRIMARY（`_to_step(2)`）。**没有**「跳过」：第 2 步是置入仓库，不能跳。

### 2.2 第 2 步 · 背包与仓库

现在的下半截原样：保险箱小格（撤离时的小号版）+ `WarehousePanel`（棋盘 + 仓库分页，格子 60，拖拽、双击、一键置入、整理都不动）+ 底部「继续」/「进入下一张：X」（现有逻辑，`proceed`）。标题行只留一行小字「置入仓库」+ 右侧灰字「总价值 N · 带出 N 币」做回看（待定 2）。没有「返回」：账只是看的，不需要回去。

### 2.3 战败

不拆：战败没有棋盘与仓库，一步到底和现在一样（保险箱居中放大，156 §16），大数只画「保险箱带出」一块（`safe_value`，48，HEAL），图鉴 / 金币那两块不画（战败钱为 0、图鉴仍按带出的保险箱件数记——`lit` 有就画「图鉴点亮」）。「继续」直接 `proceed`。

### 2.4 实现要点

- `result_screen.gd`：`open(payload)` 保存 `_r`、`_extracted`，`_build_step(1)`；`_to_step(n)` 清掉石板内容重建（和现在重建仓库面板一样便宜）。`_wh` / `_safe_view` 只在第 2 步存在；`store_all()` / `safe_view()` 测试入口不变（第 1 步时 `_wh == null`，测试先 `to_step(2)`）。
- 大数一块 = 竖向盒：`LabelDisplay`（数字）+ `Label`（名）；三块放 `HBoxContainer`，`alignment CENTER`、`size_flags EXPAND` 等分。字号常量 `BIG_NUMBER_PX = 48` / `NUMBER_PX = 32`。
- 回放 / 教程不涉及。`flow.stash_sale_preview()` 照旧只在第 1 步算一次。
- 截图金样：`/mnt/project-files/screenshots/177/` 两步各一张 + 战败一张。

## 补充一（2026-10-16 13:58 / 13:59，作者）· 一键置入卡住就跳过；一键出售按标签筛选

> 作者原话：「关于一键置入，当某个道具卡住时跳到下一个」「【一键出售】加入按标签筛选」。两条都是局外 / 结算的小改，并进 177 一起派。

### 补 1.1 一键置入：放不下的跳过，继续放后面的

- 现状 `MetaState.store_all`：按棋盘从上到下、从左到右逐件 `InventoryService.transfer_auto` 进仓库，**第一件放不下就 `break`**（当初作者定的「中途停止并提示」），返回 `{moved, left, stuck}`。
- 改：放不下的记下名字、`continue`，后面的照放。返回 `{moved, left, stuck: 第一件的名字, stuck_names: 全部放不下的名字（按棋盘顺序、不重复）}`，`stuck` 保留给老调用。
- 提示行（`WarehousePanel.store_all`）：「放进 N 件；仓库放不下 M 件（名甲、名乙、名丙……）—— 挪一挪仓库，或者不要了」，名字最多列三个、多的写「等」；一件没放下仍是现在那句。基地「家」页的一键置入走同一个入口，自动跟上。
- 顺序仍是棋盘顺序，不改成先大后小（放不下的多半是大件，先大后小也救不了，保留玩家能预期的顺序）。
- 测试：三件里中间那件放不下 → moved 2、left 1、stuck_names = [它]；全放不下 → moved 0、名字全列；搬空后棋盘留着（作者 2026-10-13 那条不变）。

### 补 1.2 一键出售：稀有度档之外再按标签筛

- 现状：出售页一个稀有度下拉（白 / 绿及以下 / … / 全部）+ 预览「会卖 N 件得 N 币」+「一键出售」。`MetaState.sell_where / sell_preview / _sellable(max_rarity)`。
- 改：下拉旁再加一个**标签下拉**，第一项「不限标签」，后面只列**仓库里现有道具带的、会显示的标签**（`TagRegistry.shown`，内部标签不列），按 `TagDef.category` 分组（用途 / 材质 / 元素 / 来历 / 来源，组间一条分隔），组内按注册顺序；仓库变了下拉重建（选中的标签若没了回「不限」）。
- 筛选 = 稀有度 ≤ 档 **且** 带该标签（单选，待定 补 1）。`sell_where(max_rarity, ratio, tag := &"")`、`sell_preview` 同款、`_sellable(max_rarity, tag)` 多一个条件；预览与「这一档没有可卖的」提示照旧。双击卖一件不受筛选影响。
- 铸牌（175：固定价 3）带不带标签都按现在的规矩卖，不特判。
- 测试：仓库有「材料」三件、「武器」两件，选「材料」+「全部」→ 预览 3 件；选「白色」+「武器」只卖白色武器；下拉只列仓库里有的标签、不列内部标签；卖光那类后下拉回「不限」。
