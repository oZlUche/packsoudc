> 阶段 4 · M3 ｜ 对应架构文档第 5 节（5.1–5.9）｜ 状态：**计划，尚未动工**
>
> 2026-09-21 第二版：生成逻辑按 5.4 的新规则（配置逐环声明、必须型、撤离点覆盖、
> 高危区、先隔离后断边）对齐；校验只剩「全图连通」这一条连通性要求。
> 第三版：加 M3-3b 手绘地图（网格脚本）与文本往返；撤离点由叠加改为覆盖；

> 第六版：路线改为风险/收益两个分数各在风格区间内、性价比相当；换乘点与路线尽头进骨架。

> 敌人预览的槽位在 M3 留好、内容归 M4。

第 5 节已经把地图系统设计完了。这份文档不重复设计，只回答三个问题：
**分几步做、每步做完怎么算过、哪些事现在必须定下来。**

## 一、先划清边界：M3 做到哪儿为止

这是最容易失控的地方。地图一旦画出来，「顺手把战斗接上去」的诱惑极大，
而那会让 M3 拖成半个游戏。

| 属于 M3 | 不属于 M3 |
|---|---|
| 生成一张图、校验它是好图 | 节点里发生什么（战斗、商店、休息、事件） |
| 单步移动、行动点累加 | 掉落与搜刮（M4） |
| 图的存档往返 | 整局存档（M5） |
| 画出来、点得动 | 场景流与转场（M6） |
| 生成器写 `erosion_band` | 侵蚀推进与惩罚（第 7 阶段） |
| `MapNode.content` 这个槽位，以及「节点内容在生成时就定好」这条规矩 | 敌人是谁、背包长什么样、预览界面（M4，架构 5.10） |
| `MapGraph.routes`，沙盒里开局挑出生点 | 体力、战败、战斗输了扣多少（M5，架构 7.1） |

**M3 的验收是一句话**：从入口走到核心再走回来，行动点数对得上，走过的节点
标成 `VISITED` 且不再产生任何东西，换个种子是另一张图、同一个种子是同一张图。

节点事件的接缝已经在设计里了 —— `MapNode.type` 与 `MapNode.seed` 都已就位。
M3 只负责把「你踩到了一个 type 为 battle 的节点」这件事报出去，**谁接不管**。

## 二、六个步骤

每一步一个提交、一份报告，顺序不能换 —— 后面的每一步都依赖前面的能跑。

### M3-1 拓扑无关的数据层

`core/map/`：`map_node.gd`、`map_edge.gd`、`map_graph.gd`，外加 `to_dict` / `from_dict`。

**做完算过**：

- 手搓一张三节点小图，`to_dict → from_dict` 之后逐字段相同 —— 包括 `routes` 与每个节点的 `content`。
  敌人在地图上看得见（5.10），所以节点内容是图的一部分，得跟着图存、跟着图读
- `edges_of` / `neighbors` 在无向边上对称：`b in neighbors(a)` ⇔ `a in neighbors(b)`
- **`MapGraph` 的属性名里不出现 `ring` / `angle` / `radius` / `floor`**

最后一条要写成**测试**，不是写成注释。第 13 节把「地图形态硬编码」列为已知风险，
而一条靠人记住的约束，在第二章开工时必然已经没人记得。
扫 `core/map/map_graph.gd` 与 `map_navigator.gd` 的源码找这几个词，
命中就红 —— 一条 grep 换一个第二章不用重写的数据层，很划算。

### M3-2 生成器抽象 + 注册表 + 通用校验

`map_generator.gd`（`@abstract`）、`map_generator_registry.gd`、`MapGenerator.validate()`。

注册表照 `EffectRegistry` 的样子来：**`generator_id → 脚本路径` 一张表，新增一种形态
只登记一行**。这套在效果系统上已经验证过，不再另发明。

**失败重试的次数要现在定死**：换种子重生成，上限 **32 次**，用尽了
`push_error` 并返回 `null`。**不要降级产出一张坏图** —— 一张连通性有问题的地图，
表现是玩家走到一半发现无路可走，而那时已经离生成现场很远了。

### M3-3 环形生成器：拓扑与骨架

`generators/ring_map_generator.gd` + `ring_map_config.gd` + `ring_spec.gd` + `route_style.gd` +
`danger_zone_spec.gd`，按 5.4「骨架先行」的十步走。这一步只做到**拓扑**：
槽位、路线骨架、候选边、高危区隔离、断边、入口、连通性校验。节点类型全部先填 `battle`，
留给 M3-3c。

拆成两步是因为拓扑与类型分配各有一套不变式，混在一起出了错分不清是路没铺好还是类型填错了。

**这一步的测试方式与别处不同：测的是不变式，不是具体形状。**

| 不变式 | 为什么 |
|---|---|
| 同种子 → `to_dict()` 逐字节相同 | 确定性是存档、回放、平衡跑批的前提 |
| **全图连通**：每个节点都从某个入口可达 | 唯一的连通性要求。可以走回头路，死路无妨 |
| **骨架完整**：每条路线是入口→核心的一条简单路径 | 路线是生成之初就有的东西，不能被后面的步骤弄断 |
| `converge_after_ring` 之前各路线互不相交 | 太早合流风格就没意义了 |
| 每个高危区：区内连通，与区外**恰好一条边**，不含骨架节点 | 单入口是它的全部意义；横在必经之路上就不是诱惑是路障 |
| 槽位数随环单调不增 | 环越靠里越短 |
| `tier` 与 `erosion_band` 随环数单调 | 越内越难这条不能靠巧合成立 |
| `MapGraph` 属性名里没有 `ring` / `angle` / `radius` | 见 M3-1，同一条 grep |

跑 **64 个种子**。再加一组极端参数（一个环、`tangential_break_chance = 1.0`、
高危区尺寸等于整环、`route_drift = 0`、`entry_count` 大于最外环槽位数）确认要么生成出合法图，
要么在 32 次内干净地失败 —— 不能吐出一张半对的图。

**故意不测的：「每个 `erosion_band` 内部连通」。** 侵蚀绝不封路（5.7），
被侵蚀的节点照样能走，只是有代价；幸存区被切成几片困不住人。
为它加校验，等于在生成器里偷偷禁掉一类本来合法、而且更有张力的地图。

### M3-3b 手绘地图：网格脚本的解析与导出

`core/map/map_grid_text.gd`（`parse` / `render`）+ `generators/grid_script_generator.gd`。
格式见架构 5.4.1，两张图 `data/authoring/maps/chapter01_v0.txt`、`chapter01_v0.1.txt` 已从作者的电子表格转出
（`tools/map_xlsx_to_text.py`）。

**做完算过**：

- `chapter01_v0.txt` 解析出的图通过 M3-2 的通用校验（全图连通）
- **往返**：`render(parse(text)) == text` 对这张图逐字节成立 —— 与内容管线的往返测试同一个道理，
  往返不掉字，才说明解析没有丢信息
- 随机生成器产出的图 `render` 出来再 `parse` 回去，`to_dict()` 一致
- `\|` 落在 `-` 上得到一个 `junction` 节点，把那段弧一分为二；连续 `\|` 得到一条 `layout.span = 2` 的径向边
- `[danger]` 层逐格对上 `[map]`：字母格的等级写进 `MapNode.danger`；同等级相连的一片得到同一个 `zone`
- `chapter01_v0.1.txt` 解析出来：红区那一片只有一条边通向区外，且那条边挂在精英上 —— 作者画的和 5.4 的高危区规则一致，验证一下

**为什么排在随机生成器之后而不是之前**：解析器很小，但「生成图能导出成同一种文本」
是它最值钱的部分 —— 生成器调参时，看一张文本图比看一堆坐标快十倍。
两边共用 `MapGridText`，格式只定义一次。

这一步也是 5.1「可插拔」的**第一次兑现**：第二个生成器不是第二章的事，第一章就有了。

### M3-3c 类型分配：风格、配额、覆盖、均衡

`generators/ring_type_assigner.gd`，按 5.4 步骤 5 的 a→g 顺序。单独一个类，
输入是已有拓扑的 `MapGraph` 加配置，输出是填好 `type` 的同一张图 ——
手绘图解析出来也能喂给它做校验（只告警）。

| 不变式 | 为什么 |
|---|---|
| 路线独占节点的类型比例与其 `mix` 偏差在容差内 | 风格得看得出来 |
| 每环每类落在 `quota` 的 `[min, max]` 内 | 作者写的规则得成立 |
| **覆盖**：每个节点距最近 `rest` ≤ K_rest、距最近 `shop` ≤ K_shop | 玩家走的是路径不是环 |
| 死胡同末端也满足覆盖 | 最容易漏的就是这种地方 |
| 高危区里没有 `rest` / `shop` | 岔出去的诱惑，不该能在里面喘气 |
| `no_adjacent` 成立 | 作者写的规则得成立 |
| 每条路线的风险分、收益分落在其风格区间；各路线收益/风险之比差 ≤ `ev_tolerance` | 风格不同、性价比相当 —— 作者的第三点加上取舍 |
| 相邻路线每 `pivot_every_rings` 环至少一个换乘点 | 退路是拓扑不是提示，否则风格成了开局定终身 |
| `ends_at = "extract"` 的路线末端是 `extract`；`bailout_every_rings` 的路线上有撤离点 | 偏搜索可以不打 BOSS，偏战斗打不动能撤 |
| `graph.routes` 每条的 `entry_id` 互不相同、`node_ids` 是图上一条真实路径、`risk` / `reward` 与重算一致 | 开局给玩家看的那份摘要不能和图对不上 |
| 搜索点按 `reference_searches` 计分 | 搜几次是玩家的旋钮，生成器只按基准定档 |
| 每 N 环至少一个 `extract`，覆盖的不是必须型 | 出口吃掉休息区，玩家就没地方喘气了 |
| 高危区内 `elite` ≥ `min_elites`、`search` ≥ `min_search` | 没有收益的高危区只是惩罚 |

再测两件事：**修正不破坏前序**（覆盖修正之后环配额仍成立，均衡之后覆盖仍成立），
以及一组故意冲突的配置（配额把休息区限死为 0 而覆盖要求 4 步一个）在 32 次内干净失败。

**批量统计脚本**在这一步之后就该写（照 `bench_battle.gd`）：跑 200 个种子，
打印每条路线的风险分、收益分、比值与类型构成、覆盖的最大步数、重试次数分布。
重试次数一高，说明配置与约束在打架，与其调种子上限不如改配置。

### M3-4 run 层：行动计数与单步移动

`core/run/action_clock.gd`、`core/run/move_intent.gd`、`core/map/map_navigator.gd`。

注意 `ActionClock` 与 `MoveIntent` 放在 `core/run/` 而不是 `core/map/` ——
行动点是整局的设施，将来事件、战斗、商店都会花它。

**这一步真正要守住的是结算顺序**（5.6）：

```
校验合法 → ActionClock.spend → ErosionField.on_action → 结算目的地惩罚 → 触发节点事件
                                └── 第 7 阶段才有，现在留空钩子
```

即使侵蚀还没做，**这个顺序现在就要固定下来并写进测试**，用一个假的侵蚀钩子记录
调用次序即可。顺序反了的表现是「玩家走进一个刚好在这一步被侵蚀的节点却毫发无伤」,
而那是三个阶段之后才会有人发现的 bug。

同样，**一切移动必须经过 `MoveIntent`**，哪怕现在只有 `kind == "step"` 一种。
第 14 节把这条列为「容易被无意堵死的接缝」——
任何地方直接读 `edge.action_cost` 加进 `ActionClock`，就是在给传送挖坑。

`distance_map` 这一步就实现，但**只允许只读查询**（HUD 的「距最近撤离点 N 步」、
生成期校验）。加一条测试断言 `MapNavigator` 不提供任何多步移动入口。

### M3-5 章节定义走内容管线

`ChapterDef` + `RingMapConfig`（含 `RingSpec[]` 与 `DangerZoneSpec[]`）的作者数据。

**推荐：走现有的内容管线，不另开一条路。**

`RingMapConfig` 是一个纯 `@export` 的 `Resource`，导入器的 `_fill` / `_coerce`
是反射驱动的，**不认识任何具体类型**，所以它天然就能处理。代价只有三处：

- `ContentPaths.KINDS` 加一行 `chapters`
- `ContentPaths.ORDER` 里排在最后（章节引用敌人池与掉落表，得先有它们）
- `ContentImporter` 加一个 `import_chapter` 入口，约八行

收益是整条链免费到手：命令行导入、往返测试、**以及可视化编辑器自动认得章节配置**
—— 表单是反射生成的，新类型不用改编辑器一行代码。

不走的话就等于开第二条内容通路，而「界面不是另一条通路，只是同一条通路的另一个
入口」这条原则已经在第 10 节立过。手写 `.tres` 调环数与抖动参数，
调到第三次就会想要一个界面。

> 这一步也是对内容管线通用性的**第一次真实检验**：它此前只喂过道具、增益、套装
> 三种同源的东西。章节配置结构完全不同，喂得进去才算证明了「导入器不认识具体类型」。

### M3-6 渲染与地图沙盒

`ui/map/map_layout_strategy.gd`、`ui/map/layouts/ring_layout.gd`、`ui/map/map_view.gd`，
外加 `ui/map/map_sandbox.tscn` 与启动选择器的第四个入口。

**布局策略是形态相关的唯一表现层**。`MapView` 主体按 `graph.layout_kind`
从注册表取策略，其余（节点按钮、点击导航、镜头平移缩放）全部共享。

**角度是解出来的**（架构 5.9）：数据层只有环序、环内次序和连接。`RingLayout.solve`
先把径向边做并查集，同一分量共用一个角度；最外环均匀铺满，向内逐环定角，
没被径向边钉住的点在次序上插值。

**做完算过**：

- 每条径向边两端角度相等（容差 1e-6）—— **异环通路垂直于切线**，这是唯一硬目标
- 每一环按次序角度单调递增（循环意义下）；不单调的图要有告警而不是静默画歪
- 同一张图解两次结果逐位相同（求解器无随机，抖动用图的种子）
- `chapter01_v0.txt` 解出来每条 `|` 都是竖直的，用截图确认一次

一个节点接着多个角度不同的外环节点时取圆周均值并告警 —— 这种图本来就画不出
全部垂直，告警让作者知道该改哪一笔。

切向边**必须画弧**，沿圆弧采样若干点用 `draw_polyline` —— 画直线会把同心环的
视觉语言破坏掉，玩家看到的就是一张普通的网。

沙盒要能演示的：生成 → 显示 → **挑一个出生点**（每个出生点旁边标出它那条路线的风格、
尽头、风险与收益档位，整条路线高亮）→ 点相邻节点走一步 → 行动点读数变 →
节点变灰但仍可点 → 换种子重生成。

出生点的选择是这一章第一个真正的决策，沙盒里就该长得像个决策：三条路线同时亮着各自的颜色，
悬停哪个出生点哪条路线加粗。敌人预览的浮窗 M3 不做（内容归 M4），
但节点上要留出「这里有可看的内容」的标记位，`random` 节点没有 —— 那是地图上唯一看不透的点。

**`VISITED` 必须与「不可通行」有明显区分**（去饱和但连线清晰）。这是 5.9 点名的
视觉要求，因为「可以走回头路」正是这一章的核心规则，看不出来就等于没有。

## 三、现在要定下来的四件事

### 1. 生成失败重试上限 = 32，用尽则失败，不降级

见 M3-2。

### 2. `erosion_band` 由生成器写，现在就写

侵蚀系统排在第 7 阶段，但 `erosion_band` 是**地图的属性**，不是侵蚀系统的属性。
设计已经明确「子类有义务为每个节点写入 `tier` 与 `erosion_band`」，M3 照做。
（不校验 band 内部连通，理由见 M3-3。）

这条也顺带守住了 5.2 的硬约束二：`erosion_band` 与 `tier` 是两个独立字段，
第一章里数值相等，但不要合并。

### 3. M3 不碰节点事件（junction 也不是事件）

`junction` 是手绘图里「径向边接在弧中间」产生的拐点，没有事件。走过它花行动点、
标 `VISITED`，但**不报出去** —— 它不是给 M4 接的东西。

### 3′. 撤离点是覆盖不是叠加

节点被进入时只做两件事：标 `VISITED`、把 `{node_id, type, seed}` 报出去。
接这个信号的人是 M4。

每 N 环挑一个非必须型节点，把它的 `type` 改成 `extract`。那个位置原本的事件没了。
第一版写成 `is_extract` 叠加属性，作者纠正为覆盖 —— 出口就是出口，不兼做别的。

### 4. 章节配置走内容管线

见 M3-5。这是本次规划里唯一一个**新的设计决定**，其余都是把第 5 节已有的设计
拆成步骤。落地时要回写架构文档第 10 节并在变更记录留痕。

## 四、风险

1. **「环」的概念泄漏到通用层。** 第 13 节已列。对策是 M3-1 里那条 grep 测试 ——
   把口头约定变成会红的东西。
2. **生成参数与地图规模强耦合。** 某一环的 `node_count` 改一下，入口到核心的
   最短路、高危区能摆在哪、撤离点密度全都变。建议 M3-3 做完就写一个**批量统计脚本**
   （照 `bench_battle.gd` 的样子）：跑 200 个种子，打印节点数、平均度数、
   入口到核心最短路分布、高危区尺寸分布、重试次数分布。最后一项尤其要看 ——
   重试次数一高，说明配置与校验在打架，与其调种子上限不如改配置。
   第 7 阶段调侵蚀节奏时要靠它，第 13 节风险 4 说的就是这件事。
3. **沙盒容易长成游戏。** 地图一画出来就想接战斗。守住第一节那张表。
4. **布局策略的接口可能定窄。** `node_position` 现在只吃 `(node, meta, view_size)`。
   六边形或分层图可能需要知道邻居。这条不预先设计 —— 等第二种形态真的来了再拓宽，
   现在猜等于给一个不存在的需求写代码。
5. **高危区扩张可能凑不够 `size`。** 环太小、或几片高危区互相挤，扩张会卡住。
   对策是把「凑不够」当作生成失败换种子，而不是缩小 size 将就 ——
   将就出来的高危区三个点一个精英，既不高危也不诱人。
