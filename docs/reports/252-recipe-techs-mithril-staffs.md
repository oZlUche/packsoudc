# 252 配方机制：科技解锁配方、秘银锭、法杖配方线

作者 2026-10-25 14:29（架构设计线）：「秘银锭素材增加，在铁匠铺里用银锭和金钱加工（该配方要科技解锁），法杖配方用木棍和魔法素材加工（不同等级法杖要科技解锁），250不再带晶石。249甩东西的先实装，我在游戏里试试。关于科技，目前除了升级基地建设和获得开局加成外，也将解锁有用的配方（配方用在铁匠铺里合成和制造高稀有度道具），具体的配方机制要理顺，好好头脑风暴一下」

本篇只写方案，不改代码。数字全是占位，作者改表。

## 〇 先回三件事

1. **249 甩东西已经在主干上**（v4.32，PR #325，`DragLayer` / `GroundLayer._begin_throw` / `ItemStash.landing_vel`）。本地说一声「同步」拉主干就能试。手感常数集中在 `DragLayer` 顶部：`THROW_WINDOW_SEC` 0.09、`THROW_SAMPLES` 8、`THROW_MIN` 0.15、`THROW_VMAX` 1.6、`THROW_DENSITY` 2.0（密度除数，越大受密度影响越小）。试完报一句「太飘 / 太沉」，执行调数。
2. **「250 不再带晶石」照现状**：250 落地后 raider / ragpicker / apothecary 与 `carry_rules/standard` 抽不到晶石（它们写的是 material，晶石已归 crystal）。作者定了不加回去，§七 第 5 条的待定关掉，什么都不用改。晶石只从法杖敌人（247）与 `CrystalRoll`（246）来。
3. **秘银剑的占位配方**（`smith_mithril_sword`：银锭 ×2 + 钢锭 + 下品火晶石，批注写着「秘银没有对应素材」）随本篇换成真配方（§三 3.6）。

## 一 现状

| 处 | 现状 | 问题 |
|---|---|---|
| 铁匠铺配方 `SmithRecipeDef` | 14 条，字段 output / inputs（id → 件数）/ funds / group / level（1～3）/ note | **唯一的门是铁匠铺级数**：级数到了全部开。没有「知不知道」这一层，科技树和配方不相干 |

## 二 头脑风暴：一张配方要过几道门

把「能不能打」拆成三道门，每道门各管一件事，互不替代：

| 门 | 管什么 | 谁开 | 现状 |
|---|---|---|---|
| **铺子** | 这间铺子打得了多高档（稀有度上限） | 科技「铁匠铺」的级数 | 有（251） |
| **会不会** | 知不知道这张配方 | **科技**（本篇） | 没有 |
| **有没有** | 仓库里的素材与钱 | 搜打撤带回来、集市买、铁匠铺炼 | 有 |

### 2.1 「会不会」怎么写进数据——三条路

| 路 | 写法 | 好 | 坏 |
|---|---|---|---|
| 甲 配方写在科技上 | 科技效果构件 `tech_recipes` 列 `recipes: [[一级开的 id], [二级开的 id], …]` | 一张科技卡就是一张清单，说明好生成 | 配方 json 不知道自己被谁锁；配表要两边对；每加一条配方要动 techs.xlsx |
| **乙 配方写在配方上**（推荐） | `SmithRecipeDef` 加 `tech: StringName`（空 = 不要科技）与 `tech_level: int`（默认 1）；科技构件 `tech_recipes` 不带参数，说明文字反查「哪些配方写着我」 | 一张配方自己说全（铺子几级、哪个科技几级、要什么料）；加配方只改配方 json；导入器查得到「写了不存在的科技 / 级数超过它的级数上限」 | 科技卡的说明要扫一遍配方表（几十条，启动时一次，不算事） |
| 丙 配方图纸是道具 | 图纸是局内掉落，带回基地交给铁匠 | 搜打撤味道足，给局内多一种值钱货 | 不是作者这次要的「科技解锁」；可以**以后**叠在乙上（图纸 = 一次性把某条配方的 `tech` 门视作已开） |

推荐 **乙**，丙记在待定里。

### 2.2 一张科技开一条配方，还是一条「工艺线」开一串

树的守门是「每列同深度最多并排两个」。一条配方一个节点，列 0 铁匠铺上面只能再放两个，第三条配方就要挂到更深，树会长成一根竹竿。所以**科技按「工艺线」立节点，一条线几级，每级开一档**——正好对上作者的「不同等级法杖要科技解锁」：

- 「秘银冶炼」一级：开 **秘银锭** 与用秘银的配方。
- 「法杖工艺」三级：一级开 **魔法杖**，二级开 **法师杖**，三级开 **魔导杖、大魔导杖**。
- 以后的线同样加：「精工护甲」「附魔」「拆解」……一条线一个节点，级数就是梯子。

### 2.3 配方有哪几种形

inputs 本来就是「道具 id → 件数」，任何道具都能当料，所以下面几种形**不用加字段**，只是配表的习惯：

| 形 | 例 | 用处 |
|---|---|---|
| 打造 | 素材 + 钱 → 武器 / 防具 | 现有 14 条 |
| 冶炼 | 素材 → 更好的素材（银锭 + 钱 → **秘银锭**；银矿石 → 银锭） | 让素材有链，低档素材不再只能卖 |
| 改铸 | 低档成品 + 素材 → 高档成品（长剑 + 秘银锭 → 秘银附魔长剑；魔导杖 + 上品晶石 → 大魔导杖） | 高稀有度道具的正道：先有低档那件，再往上铸；也让铁匠铺一级打出来的东西不浪费 |
| 附魔（以后） | 武器 + 晶石 → 带元素的同件 | 晶石多一条出路；需要「同件带元素」的道具定义，另篇再议 |
| 拆解（以后） | 成品 → 素材若干 | 另一个方向，另篇 |

**配表的两条规矩**（写进 `docs/balance-json-guide.md`）：
- 产物稀有度 ≥ 紫（3）的配方**必须**挂科技；白～蓝的可以只靠铺子级数。
- `level`（铺子级数）按产物稀有度填：白 / 绿 1、蓝 2、紫 / 金 3。科技开的是「会」，铺子管的是「打得了」，两个门都要过。

### 2.4 法杖梯子

对着 247 的四阶法师起名，玩家手里的杖与敌人手里的杖是同一套：

| 杖 | 稀有度 | 形 | 装载格 | 基础伤害 | 节拍 | 对应 247 敌人 |
|---|---|---|---|---|---|---|
| 魔法杖 `magic_staff`（已有） | 1（绿，不动） | 1×3 | 杖头两侧 2 | 6 | 1.2 s | 魔法学徒 |
| 法师杖 `mage_staff`（新） | 2 | 1×3 | 2 | 8 | 1.1 s | 熟练的魔法师 |
| 魔导杖 `magus_staff`（新） | 3 | 1×3 | 3（两侧 + 杖头上方） | 10 | 1.0 s | 魔导师 |
| 大魔导杖 `grand_magus_staff`（新） | 4 | 1×3 | 3 | 12 | 0.9 s | 大魔导师 |

- 都带 `staff` / `magic`、`material: wood`、`free_when_loaded`（装晶不耗耐力，247）。档次差在装载格数与节拍，不在晶石品级（晶石品级由玩家装什么决定，246 的「次数不绑稀有度」照旧）。
- 247 的四阶敌人各拿对应的杖（§四 待定 2，推荐改）：杖本身成了法师的掉落，是玩家拿到高档杖的第二条路，配方是稳的那条。

## 三 推荐方案

### 3.1 数据

- `SmithRecipeDef` 加 `tech: StringName = &""`、`tech_level: int = 1`。导入器：`tech` 非空时要在科技表里有，`tech_level` ≤ 它的级数上限，否则报错。
- 新科技构件 `TechRecipes`（`"type": "tech_recipes"`，登记 `RunRegistry.TECH_EFFECTS`）：`derive` 什么也不写（配方直接查 `TechService.level(meta, tech)`，120 的派生规矩不破）；`describe_level(k)` = 「会打：」+ 所有 `tech == 我 且 tech_level == k` 的配方产物名，按配方文件名排。
- techs.xlsx 加两行节点（列 0，前置 `smithy`）与各级：

| id | 名 | 英文 | 级 | 钱 | 材料（占位） |
|---|---|---|---|---|---|
| `mithril_smelting` | 秘银冶炼 | Mithril Smelting | 1 | 1500 | silver_ingot ×2，crystal_shards ×3 |
| `staffcraft` | 法杖工艺 | Staffcraft | 1 | 600 | crystal_shards ×3 |
| | | | 2 | 1200 | fire_crystal_low ×1（任一元素下品亦可——表里只能写一个 id，先写火） |
| | | | 3 | 2000 | silver_ingot ×2，fire_crystal ×1 |

两个节点并排在列 0 深度 4（守门允许同深度两个），树高一行，面板滚。说明一句不写数字：「学会炼秘银：银锭加钱炼成秘银锭，再用它打更好的刀剑」「学会做法杖：级数越高，做得出的杖越好」。

秘银锭按作者原话只要银锭和钱。晶石当料会被吃掉（它们是 crystal 类别、按 id 计件，`Smithy.have` 现成可用）；碎晶、晶石就是作者说的「魔法素材」。

### 3.4 铁匠铺界面

- `Smithy.recipes_for` 分三桶：`ready` / `level_locked` / `tech_locked`；`can_forge` 多一句 `smithy.need_tech`「要先点出「{科技名}」」。
- 格子（`RecipeCell`）：科技没开的**照样列出来、灰掉**，悬浮窗第一句写要哪个科技几级（待定 4，推荐显示——玩家在铁匠铺就看得见科技买的是什么）。铺子级不够的照旧。
- 科技卡「现在 / 下一级」两行由 `TechRecipes.describe_level` 生成：「会打：秘银锭、秘银附魔长剑」。

### 3.5 冶炼配方放哪一列

左列大类是 blade / hammer / bow / staff / shield / armor（251 补充一）。冶炼出来的是素材，不属于任何一类。加第七个大类 `smelt`「冶炼」（`SmithRecipeDef.GROUPS` 末尾，木牌大类键照 251 的做法，键图先占位）。

注意 UI替换美术 10-25 的定稿：铁匠铺 `keys` 区（x 48、y 190、宽 212、高 366）**正好只容六块木牌**（六 × 56 + 五 × 6）。加第七块有两条路：请美术把 keys 区放高到 428（底图砖墙那一段是纯墙，拉得开）；或先不加大类，冶炼配方并进「斧锤」一列、格子上标「冶炼」。推荐**前者**，执行落第一批时先走后者，键图到了再分出来。

**已定（美术设计 10-25 14:48）**：keys 区挪成 x 48、y 128、w 212、h 428（上到砖拱下沿，下到 556，铁砧顶之上；七块 56 高、间隔 6 正好 428），`base251/final/smithy/layout.json` 与 `cut_final.py` 已改；木牌皮通用、字由代码写，所以第七块「冶炼」**不用新图**——执行第一批就直接加 `smelt` 大类，不必并进「斧锤」。科技树节点没有图字段，两张科技图不画。

### 3.6 集市

`wooden_stick` 白、`crystal_shards` 白自然进集市一级的货；银锭蓝在三级。秘银锭不进（白名单按稀有度 ≤ 2，紫自然挡住；再加一道「只从铁匠铺来」的保险：`MarketRules.excluded_ids` 加它）。

### 3.7 测试

- 导入器：配方写了不存在的科技 / 超过级数上限 → 红。
- `Smithy.recipes_for` 三桶：铺子三级、科技未点 → 秘银锭在 `tech_locked`；点出科技一级 → `ready`；法杖工艺一级只开魔法杖，三级开两根。
- `TechRecipes.describe_level(1)` 含「秘银锭」。
- 配方把晶石当料吃掉、产物进仓库、钱扣对。
- 科技树守门（宽 ≤ 792）仍绿；列 0 深度 4 两个并排。
- 快照：新道具 + 改配方要 `bash tools/snapshot_content.sh`（173）。

## 四 待定（都按推荐走，作者不说就是同意）

1. **银矿石 → 银锭 的冶炼配方**（不要科技）：推荐**加**。银矿石现在只能卖，有了它银矿石→银锭→秘银锭成一条链。
2. **247 四阶法师换拿对应的杖**（熟练→法师杖、魔导师→魔导杖、大魔导师→大魔导杖）：推荐**改**。敌人掉的杖是高档杖的第二条路，也让四阶看起来真有差别。
3. **「任一元素下品」的料**：配方 inputs 按 id 计件，写不出「任一下品晶石」。推荐**先写火**（三份配方各写一元素太多、加「任一标签」字段太重）；要真想任一元素，再加 `inputs_any: [[id…], 件数]`。
4. **科技没开的配方显示还是隐藏**：推荐**显示灰掉**。
5. **配方图纸（丙）**：推荐**以后**，叠在乙上。
6. **贵重品熔铸**（银块 / 银条 → 银锭）：推荐**不加**。244 定了金银是卖的，熔了会把它们的卖价和素材价搅在一起。
7. **114 局内两件拖合的配方要不要也能被科技解锁**：推荐**不动**，另一套机制。

## 五 不改

- 铁匠铺级数 = 稀有度上限（251）；集市规则；三列树；114 局内合成；250 的「杂兵不带晶石」。

## 六 美术

## 七 执行顺序

1. 数据层：`SmithRecipeDef.tech / tech_level` + 导入器校验 + `TechRecipes` 构件 + 登记。
2. 表：techs.xlsx 两行节点 + 各级，跑 `techs_xlsx_to_json`。
3. 道具五件 + 配方七条（占位图）+ 快照。
4. `Smithy.recipes_for` 三桶 + 界面灰格 + `smelt` 大类 + UiText。
5. 待定 1 / 2（冶炼银锭、法师换杖）。
6. 测试 + 落地回写 §八。

## 八 落地（v4.45，2026-10-25）

- 数据：`SmithRecipeDef.tech / tech_level`；导入器在科技全部导完后查（`validate_smith_recipe_techs`：科技在、级数不超上限、`tech_recipes` 构件写的是自己的 id）；冶炼类（`smelt`）的产物得是素材。
