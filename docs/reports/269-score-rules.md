# 269 方案：计分规则 —— 总分不再只是带出价值，击败与探索也计分，战败不再是 0

作者 2026-10-31 11:44 / 11:45（小修线，附战败结算截图：走过 14 点、32 步、击败 8 + 精英 1、打输 2、搜索 5、带出 0 件、总分 **0**）：「战败为什么总分是 0？击败敌人不算分数吗？检查计算公式」「要改计分规则」。

## 〇 一句话

现在「总分」= 带出的东西值多少钱（棋盘上的 + 保险箱里的），账单其他十行只是列着不算分，所以战败除非保险箱里有东西就是 0。建议改成 **战利 + 战绩 + 探索，再乘难度**（A）：击败普通 10 / 精英 40 / 首领 200，走过一点 2、翻一个搜索点 5、合成一次 5、图鉴新点亮 25；战败照记战绩和探索，只是没有战利。截图那局会从 0 变成 **173**。

## 一、现状（读码）

| 哪里 | 怎么算 | 代码 |
|---|---|---|
| 结算账单「总分」行 | `r.value + r.safe_value`（带出价值 + 保险箱价值） | `LedgerView.rows_for` |
| 军功碑账行「出征 N 次 · 总分 N · 图鉴 N / M」 | `meta.score += result.value`（撤离）、`+= result.safe_value`（都算） | `MetaState.absorb` |
| 军功碑「最佳一局」 | 按 `result.value` 挑（`best_value` / `best_run`） | `MetaState.absorb` / `best_run_of` |
| 成就 | 只有「满载而归」读 `best_value ≥ 300`；没有成就读 `score` | `AchievementDef.progress` |
| 对局记录（261） | 列表与详情写 value / balance，没有分 | `RunRecordsWindow` |

账单十一行里，走过的点、步数、击败三行、打输、搜索 · 合成、图鉴新点亮、带出金币都不计分（224 补充三当时说「以后有对应系统再把分数转成经验」）。军功碑碑额已经另写仓库总价值（260），所以「总分 = 价值」和碑额是重复的。

## 二、三种计分

### A　战利 + 战绩 + 探索，乘难度（推荐）

总分 = （战利分 + 战绩分 + 探索分）× 难度系数，向下取整。

| 项 | 算法 | 截图那局 |
|---|---|---|
| 战利分 | 带出价值 + 保险箱价值（撤离）；战败只有保险箱价值 | 0 |
| 战绩分 | 普通敌人 **10** / 精英 **40** / 首领 **200** 一只；打输不扣（局已经输了） | 8 × 10 + 40 = 120 |
| 探索分 | 走过的点 **2** / 搜索点 **5** / 合成 **5** / 图鉴新点亮 **25** 一个；步数不算（走得多不是功） | 14 × 2 + 5 × 5 = 53 |
| 难度系数 | 1 + 0.25 × 难度档（普通 0 → ×1，进阶三 → ×1.75） | ×1 |
| **总分** | | **173** |

撤离一局大约：战利 500 ～ 1500 + 战绩 100 ～ 400 + 探索 60 ～ 150 —— 战利仍是大头，撤离永远比战败划算，但战败不再是 0，打得多的一局死了也有分。

### B　纯军功：价值不计分

总分 = （战绩分 + 探索分 + 撤离奖 100）× 难度系数，带出价值完全不算分（钱与仓库价值碑额已经写着）。军功碑的「总分」就真是军功。缺点：带回一包紫装和空手回来分一样，和「满载而归」的直觉相反。

### C　最小改：撤离照旧，战败记战绩

撤离 = 现状（价值）；战败 = 战绩分（10 / 40 / 200），不加探索、不乘难度。改动最小，但两种结局用两把尺，战败 120 和撤离 1200 没法比。

## 三、A 的改动清单（执行）

1. 新 `ScoreRules`（`data/authoring/base_rules/score.json` → `core/run/score_rules.gd`）：`kill` {normal 10, elite 40, boss 200}、`explore` {visited 2, search 5, craft 5, lit 25}、`difficulty_step` 0.25、`extract_bonus` 0（B 用 100）、`loot_counts` true（B 用 false）。
2. `RunResult.score` + `score_parts` {loot, battle, explore, mult}，在 `from_state` 算（图鉴新点亮那一项要等 `MetaState.absorb` 记完 `got["lit"]`，所以 `absorb` 里补算 `lit × 25` 再乘系数；账单拿到的 `lit` 同源）；难度档从 `DifficultyDef.level` 读（普通没写 = 0）。
3. 账单：「总分」行 = `score`；总分行下面一行小字（思源宋体 14，灰墨）「战利 N · 战绩 N · 探索 N · 难度 ×1.25」（普通难度不写难度段）；战败一样写。十一行不动。
4. `MetaState.absorb`：`score += result.score`（撤离、战败都加一次，取代原来两处 value / safe_value）；`best_value` 仍按价值（成就「满载而归」不动）；**军功碑「最佳一局」改按 `score` 挑**（`best_run["score"]`，老 best_run 没 score 就按 value 比，等新局超过）—— 待定 1。
5. 历史行 `to_dict` 加 `"score"`；261 对局记录列表加一列「分」、详情一行「总分 N（战利 N · 战绩 N · 探索 N）」，老行没 score 写「—」。
6. 存档：`meta.score` 累计不重算（老分照留）；没有版本号变化。
7. 文案：`ledger.score_parts`「战利 %d · 战绩 %d · 探索 %d」+「 · 难度 ×%s」；`records.col_score`、`records.detail_score`。
8. 测试：战败局 score = 战绩 + 探索（截图那组数 = 173）；撤离局 = 价值 + 战绩 + 探索；进阶三 ×1.75 向下取整；`meta.score` 一局只加一次；最佳一局按 score；对局记录老行「—」。
9. 校准：`tools/` 沙盒跑 96 种子三档难度，报每档的撤离 / 战败均分，看战利与战绩的比例在 3 ～ 8 : 1 之间，不对就调 `score.json`，不动代码。
