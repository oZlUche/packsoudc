# 035 · 路线是生成规则，不是合格条件；单条路径的长度上限

> 阶段 4 · M3 ｜ 架构文档 5.4（v1.34）｜ 接[报告 034](034-map-editor-and-source.md)

## 起因

作者看了编辑器之后问了一句、指正了一处、提了一条新规则：

1. 编辑器里蓝色、橙色的连线是什么？
2. 战斗路线、搜索路线这些，**本质是用来生成地图的规则，不是检验地图是否合格的必要条件**。
3. 单条路径不要太长：最多 ±1 环位偏移、±1 槽位偏移。

## 那几条彩色粗线

是生成器留下的**路线标注**（`graph.routes`）：每个出生点一条，红 / 橙 / 蓝按路线下标轮流取色。
我画了却没给图例，这是界面的疏漏。现在右栏（没选中点时）有图例 ——
「出生点 12 · mixed → core」各自带颜色 —— 和一个「描出生成路线」的开关。关掉它，图一点不变。

## 路线从校验里拿掉

033 / 034 里我把路线当成了图的一部分来验：骨架是否仍是一条简单路径、相邻路线之间有没有换乘点、
高危区有没有占骨架节点，计划里 M3-3c 还要验每条路线的风险收益区间。

这是错位。路线决定地图**怎么长出来**；长出来之后，一张图合不合格只看它自己 ——
连不连得上、出生点间隔、高危区单入口、边有没有超长。路线留在图上只是标注，
开局给玩家挑出生点时看的。手改过的图、手绘的图可以没有路线，或者对不上。

拿掉的规则：`skeleton`、`pivot`、`zone_skeleton`。生成器照旧按这些规则长图（骨架边受保护、
高危区避开骨架、换乘弧受保护），只是不再拿它们判一张图的死活。
对 M3-3c 的影响：路线风险收益的校准仍然做，但做成**生成时尽力拉回区间**，不进校验。

## 单条路径的长度上限

`RingMapConfig.edge_max_ring_offset` / `edge_max_slot_offset`，默认各 1，写进 `layout_meta` ——
校验和编辑器从图上读，不必手上有配置。

**槽位偏移怎么量。** 同环就是隔几个槽位。跨环时两环槽位数不同，得把一个点按比例投到另一环上。
第一版投到内环上量，截图一看不对：内环只有六个槽位，一格 60°，「± 1 格」等于没限制。
改成投到**外环**上量（外环的槽位更细）。留半格余量，因为投影是小数。

这条上限牵出三处连带改动：

**正对空白区的点可以没有向内的边。** 以前每个点至少向内连一条、多远都连，
于是空白区对面会拉出横穿半张图的长边。现在够不着就不连，它靠同环的弧连到别处。

**路线撞上空白区时横着挪。** 034 里的做法是「绕到最近的点」—— 那正是一条长边。
现在沿当前这环向两边找最近的、能向内走的点，挪过去经过的点和弧也进骨架。
路线因此不再是严格的「一步一环」，测试里的不变式放宽成「每步要么向内一环，要么同环横挪」。

**断边不许断出孤岛。** 「每个点都有向内的径向边」是原先连通性的根基，现在不成立了，
所以断边那一步每断一条之前先查两头还连不连得上，连不上就留着。
顺带的好处：断边概率拉到 1.0，第一次尝试就连通（有测试）。

`route_drift` 默认 2 → 1，并且不会超过边长上限。034 里「漂移量按环长缩放」的做法作废 ——
有了统一的边长上限，它是多余的。

## 验证

```
bash tools/test.sh
通过  1752 项断言，26 个套件
```

- 64 种子不变式里加了「每一条边都在长度上限之内」（上限从配置读）。
- 新增：清掉 / 改乱路线标注，图照样过校验；手拉一条超长边 → `edge_length`；
  断边概率 1.0 时 16 个种子第一次尝试就连通。
- 换乘点的测试改在**没有空白区**的配置上跑：换乘是尽力而为的生成规则，弧上横着空白区时
  连不过去是合法的；没有空白区时它就该条条走得通。

重试次数（各 64 个种子，全部成功）：

| 环数 | 平均尝试 | 失败原因 |
|---|---|---|
| 3 / 4 | 1.00 | 无 |
| 5 | 1.77 | 只有 `zone_missing` |
| 6 | 1.25 | 只有 `zone_missing` |
| 7 | 1.22 | 只有 `zone_missing` |

5 环比 034 的 1.50 略高：边长上限让高危区能长的方向变少了。仍然全是配置层面的那一条。

## 遗留

- 编辑器里手动连边不拦超长的，只在校验栏里黄字提醒 —— 形态规矩对手绘图是提醒不是禁令。
- 朴素布局下，1.5 个外环槽位的边在内圈看着仍有 60° 左右。这是槽位本身粗，不是上限没生效；
  M3-6 的布局求解会让径向边更接近垂直。
