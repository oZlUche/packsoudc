# 279 武器网状升级清单（五类 × 五档 × 材质分支）

作者 2026-11-04 16:12：「关于武器的进化，我想的是不仅局外铁匠铺，局内收集到对应道具后，也可以在休息点的铸造区升级，为此，需要设计一套比较通用的武器网状升级路线，比如绿色武器+骨素材=蓝色骨质武器，后续可以根据加入的素材呈现更多种不同的状态：纯骨制，骨+金属，骨+木等等。这种设计都可以应用在短兵、单手、双持、长柄、双手武器中，另外基础武器（白色品质）可以在包内直接通过拼接变成绿色武器，比如匕首+匕首=双刀，木棍+短剑=长枪等等（参考背包乱斗）」。
16:22 更正：「不是组装武器词条，而是生成足够多的不同稀有度和不同类型的武器，对应各种等级」。

本版（v2）按更正写：**每一把都是一件有名有画有自己效果的具体武器**，网只是它们之间的升级来路；不拼部位、不拼词条、不用脚本生成。取代 276 的 25 把清单（战锤 50 → 36 保留）。

## 〇 一句话

五个类别（短兵 / 单手 / 双持 / 长柄 / 双手）× 五档（白 / 绿 / 蓝 / 紫 / 橙），共 **69 把新武器**（武器 19 → 88），每把有名字、形状、数值和自己的那一句效果。升级来路是一张网：白 + 白（或白 + 材料）在包里**拼接**成绿；绿 + 一件某类材料（骨 / 金属 / 木 / 石）在**砧**上升成蓝，不同材料升成不同的蓝；蓝 + 另一类材料升成紫，两条路可以汇到同一把紫；紫 + 一颗魔晶升成橙。砧在休息点铁炉旁和基地铁匠铺都有。档位对应章节：白绿 1 章、蓝 2 章、紫 3 章起、橙 4–5 章。

## 二、规则（只有四条）

1. **拼接（白 → 绿）**：两件在同一棋盘上贴着（任一格相邻，转向无关）且配得上 → 接缝浮一枚小锤徽，点徽合成，成品落在两件的并集脚印上（放不下进手里）。不自动合（待定 2）。任何棋盘都行，不花钱。配方表 `data/authoring/fusions/*.json`：`{inputs: [a, b], output}`。
2. **砧（绿 → 蓝 → 紫 → 橙）**：武器槽 + 材料槽；配方 = 上一把 + 一件某类材料。材料按 **类**认：`SmithRecipeDef` 加 `material_inputs: [{material: bone, min_rarity: 1}]`，任何 `material` 字段匹配且稀有度够的材料都行（蓝要绿材料、紫要蓝材料、橙要紫魔晶；待定 3）。休息点砧免费、每个休息点一次；基地砧收工钱 60 / 150 / 300，铺子级数照旧是档次上限。
3. **每档一句**：同一把升上去的武器保留上一把的句子，再加自己的一句；材料决定加的那句的方向（骨 → 流血 / 暴击，金属 → 直伤 / 格挡，木 → 省耐力 / 快，石 → 震慑 / 坚韧，魔晶 → 元素），但每把的句子都是单独写的，不是模板套出来的。
4. **DPS 阶梯**（伤害 ÷ 冷却）：白 5–8 · 绿 10–12 · 蓝 14–17 · 紫 20–24 · 橙 28–32；耐力 / 秒 ≈ DPS × 0.45。落地后 242 估力台跑全表，顺带把 273 段 2 的 r3 近战拉齐。

## 七、补充二：高级材料顶替低级材料时，属性怎么算、怎么显示（作者 2026-11-04 16:53）

作者问：「高级素材理应可以替代低级素材且给予更多属性，因此也许要考虑让道具的属性不再是固定值？或者是让最终显示的道具属性不是初始值而是各种加成后的结果，考虑一下哪种方案」。

### 1. 现状（读码）

| 事实 | 在哪 |
|---|---|
| 「这一件独有」的数据已经有地方放：`ItemInstance.state`（锁定、不参战、钉住、磨损剩余次数、铸牌附魔 `enchant`），存档逐字节往返，`from_dict` 回读时把数值键归一 | `core/inventory/item_instance.gd:43–150, 195–215` |
| 铸牌附魔就是「实例覆盖定义」的先例：`state.enchant` 压过 `ItemDef.enchant`，编译战斗时挂成一条规则（origin `enchant`） | `core/forge/forge.gd:128, 148`；`core/battle/compiled_item.gd:28` |
| 定义级倍率也有先例：273 的 `combat.power_mult`（法杖 1 / 1.15 / 1.3 / 1.45），提示框写成一行「威力 ×N」 | `ui/inventory/item_tooltip.gd:148` |
| 提示框里**非伤害**的基础属性（格挡、护甲……）直接打印定义里的 `base_stats` 原值；**武器句**则用编译后的 `stats_with_opening`，所以伤害已经算进了邻接 / 开局 / 装填，格挡护甲没有 | `ui/inventory/item_tooltip.gd:136–146, 323` |
| 279 的砧配方 `material_inputs [{material, min_rarity}]` 本来就按「≥ 最低稀有度」认材料，所以「高级材料顶替低级材料」**配方层已经成立**，缺的只是「顶替了要多给」 | 本报告 §二.2、待定 3 |

### 2. 两种写法

**A. 定义仍是固定值，多出来的部分记在这一件上（推荐）。** 定义（JSON）不动，仍是平衡 / 台架 / 图鉴 / 敌人池的锚点；砧上升级时，材料稀有度每比配方要求高一档，这一件的 `state.quality` 加 1；编译战斗时按品质乘上去。这和铸牌附魔是同一个口子（实例改定义），只是附魔挂规则、品质乘数字。

**B. 定义本身不再固定。** 要么给每个「武器 × 材料档」生成一份定义（69 把 × 2–3 档 ≈ 200 个 id，图鉴、美术、敌人池、存档对账全跟着膨胀，正是作者 16:22 否掉的那种组装式膨胀），要么让 `ItemDef` 可按件改写（破坏「定义只读、实例可变」的分层，存档得存整份定义）。两条路都比 A 贵得多，不推荐。

**显示**：无论 A 还是 B，作者的第二个想法都该做：提示框 / 战前 / 商店只显示**算完加成的最终值**，不显示初始值（奥卡姆：一个数字够了，两个数字反而要解释）。A 方案下这就是把 `base_stats` 那几行也走一遍编译后的 `StatSet`，而不是打印定义原值；武器句本来就已经是最终值。

### 3. 品质（quality）怎么定

- **来源**：砧上升级时取「所用材料稀有度 − 配方最低稀有度」；升下一档时**取新旧两者较高的**，不累加（否则橙武器能叠到 +60%）。拼接（白 + 白 = 绿）和铁匠铺买来的默认 0。
- **幅度**：每档 **+10%**，上限 **2 档（+20%）**。对着 §二.4 的 DPS 阶梯：蓝 14–17 用橙材料做出来是 16.8–20.4，刚摸到紫的下限 20，而紫还多一句效果——高一档材料值得用，但不顶掉下一档武器。
- **作用面**（作者 17:00：非伤害句子也该随材料升）：这一件身上**每个带数的东西**都按品质走，分三种单位——
  - 伤害、格挡、护甲：×(1 + 0.1 × quality)，写法就是实例级的 `power_mult`，和 273 的定义级 `power_mult` 相乘；
  - 句子里的**个数**（流血 / 中毒 / 迟缓层数、直伤点数、开局刺的点数、元素层数）：每档 **+1**；
  - 句子里的**百分比**（耐力消耗 −10%、速度 +10%、暴击 +10% 这类轴偏移）：每档 **+5 个百分点**（−10% → −15% → −20%）。
  武器自己的耐力价（`costs`）不动——那是价钱不是效果。实现上是编译第 7 步「按件修饰」的位置多一道：按 `state.quality` 改这一件编译副本里的规则数值，定义不碰；提示框的句子从编译副本读，所以显示自然是最终值。
- **敌人 / 台架 / 图鉴**：全按 quality 0；台架另跑一遍 quality 2 看阶梯是否被打穿。
- **存档**：`state.quality` 整数，缺省 0；173 对账层对未知 state 键是原样带过的，不用改；读回时和磨损次数一样归一成 int。
- **标记**：提示框和背包里的这一件要让人看出「不是普通的一把」——推荐在名字旁画 1–2 个小菱形（一档一个），不写字；样式归 UI替换美术 出样。

### 4. 待定（续）

12. 幅度每档 +10%、上限两档 —— **推荐如上**；也可每档 +15% 上限一档。
13. 升下一档时品质取较高还是重算 —— **推荐取较高**。
14. 品质标记：A 名字旁小菱形 / B 不标（只看数字） —— **推荐 A**。
15. 卖价是否随品质涨 —— **推荐不涨**（268 卖价表按定义算，省一处）。
16. 句子数值的单位：个数 +1、百分比 +5 点 —— **推荐如上**；也可统一 ×1.1 取整（小数会被四舍五入吃掉，不推荐）。
