## 结算顺序一处落地

```
校验合法 → ActionClock.spend → erosion.on_action → 结算目的地惩罚 → 触发节点事件
```

`MapTravel.apply(intent)` 是**唯一会改地图状态的入口**。`step_to(to_id)` 只是造个 step 意图交给它；
将来的传送、定点移动造好自己的意图也走它，顺序、计数、惩罚、事件一处不用改。

侵蚀还没有（第 7 阶段），但顺序现在就定死：测试里一个假侵蚀钩子和假事件钩子往同一个日志里记，
断言日志是 `["spend", "erosion", "penalty", "event:N"]`，而且侵蚀看到的累计已经是花过这一步之后的。
顺序反了的表现是「玩家走进一个刚好在这一步被侵蚀的点却毫发无伤」—— 那是三个阶段之后才会有人发现的 bug。

钩子都是鸭子类型：`erosion` 有 `on_action` / `move_penalty` 就行，`on_node_event` 是一个 Callable。
`MapTravel` 不认识 `ErosionField`，也不认识战斗 —— 这一层是开发期就能跑的，不用等它们。

## 几个决定

- **一切移动经过 `MoveIntent`。** `MapNavigator.resolve_step` 是唯一一处把 `edge.action_cost` 变成行动点的地方；
  别处直接读 `action_cost` 加进时钟，就是在给传送挖坑（第 14 节）。`teleport` 意图现在被拒绝，不是当 `step` 走。
- **导航器没有多步入口。** 测试断言它的公开方法就是 `available_moves / edge_for_step / resolve_step / distance_map / nearest_of_type`
  这五个，多一个「走过去」就红。自动寻路是有意不做的（5.6）：每一步都得是一次独立决策。
- **出生点开局就算踩过了。** `start_at` 直接标 VISITED，它不该再触发一次事件。
- **节点什么时候算「用过」由事件系统说。** 接了 `on_node_event`，`MapTravel` 不动 state，等事件系统 `mark_visited`
  （战斗打完才算）；没接，到点即标 —— M4 之前的占位。已访问的点只能穿行：折返照样花行动点，不再触发事件。
- **拒绝要说得出原因。** `refused(intent, why)`：不相邻、意图过期（它以为人在 A，人在 B）、不认识的移动方式。
  拒绝的一步不花行动点、人不动。
- 存档 `{current, history, clock}`，图另存；读回来接着能走。

## 画布不随视口缩

作者中途说图看着太挤：保持环间距不变，增大画布。

以前布局把整张图缩进控件：六环的图和四环的图画得一样大，六环就挤。现在布局按**固定环距**
（`RING_STEP` = 110 像素）算出画布大小 —— 六环 1440 像素见方 —— 不随视口缩。`MapView` 加了拖动（中键）
与缩放（滚轮围着鼠标缩，`F` 缩到刚好放下、`1` 回原比例）。换图之后先 `fit()` 看全，要看细节再放大。
坐标分两套：布局给的是画布坐标，命中测试与信号都用它，屏幕坐标只在输入处理里出现一次 ——
测试直接用画布坐标调 `press`，不用管视口。

节点画成**固定的屏幕大小**：缩小整张图看全貌时，边和环跟着缩，点和字不缩，还看得清；
命中半径按缩放换算回画布尺度。编辑器两边的栏各窄了三四十像素，中间的图多一点。

## 验证

```
bash tools/test.sh
通过  3337 项断言，29 个套件（73 秒）
```

- 时钟：只加不减，0 与负数不花不发信号，存读。
- 导航器：公开方法清单；相邻 = 能走；距离表全图连通；最近的核心；`resolve_step` 的花费 = 那条边的 `action_cost`。
- 结算顺序（假钩子记日志）；侵蚀惩罚扣在体力上；接了事件钩子由它标 VISITED。
- 已访问只能穿行：同一个点只触发一次事件，`first_visit` 只有头一回是 true，穿行照样花行动点。
- 拒绝：不相邻、原地、不存在的点、过期意图、`teleport`；每次一条原因；不花行动点、人不动。
- 6 个种子各随机走 40 步：计数 = 走过的边的 `action_cost` 之和，永远有地方可走，存读回来接着走。
- 视图：位置在画布内、四环的画布比 800 宽、`fit` 之后画布右下角在控件内、画布 ⇄ 屏幕来回一致。
