## 二、v0.1 比 v0 多的三条规则

### 1. 节点类型用字母

| 符号 | 类型 | 作者原话 |
|---|---|---|
| `A` | `battle` | 普通战斗点 |
| `E` | `elite` | 精英战斗点 |
| `S` | `shop` | 商店 |
| `R` | `rest` | 休息区 |
| `V` | `search` | 搜索点（一种特殊事件），可以搜索至多 N 次并发现战利品（但有可能遭遇敌人，遭遇概率随搜索次数上升），或者离开。有一定概率出现第三种选项，目前占位 |
| `Q` | `event` | 常规事件，目前占位，可以获得奖励道具或者恢复，或者剧情 |
| `?` | `random` | 随机事件，在 A/S/R/V/Q 中按概率挑选 |
| `B` | `core` | 最终撤离点，这里有当前地图的最终 BOSS，是地图终点 |

两处值得记：**`?` 不会变成精英或 BOSS**（挑选池里没有 E、B），所以随机点不会突然要人命；
**终点从 `E` 改成 `B`**，`E` 让给了精英。图例里还留着 `1` = 缺省事件点，
第 12 行有一个没改完的 `1` —— 解析时按 `?` 处理。

### 2. 危险区域用底色，不用数字

v0 里 `2` 同时表示「高危区」和「某种类型」，两个维度挤在一个格子里。v0.1 把它拆开了：
数字/字母只表类型，**区域刷底色** —— 红 = 高危（敌人/事件难度上升，奖励更高），
黄 = 中危（略微上升，略高），没底色 = 常规。

文本没有颜色，所以转出来的文件分两层：`[map]` 符号层、`[danger]` 危险层（`.` / `1` / `2`），
行列逐格对齐。底色刷在 `-` 上也没关系，只有节点那一格算数。

数据层因此多一个字段：`MapNode.danger`（0 / 1 / 2）。它**叠在 tier 之上**，两者独立 ——
tier 由环决定、danger 由区域决定，内容层选敌人池与掉落表时两个都看。
一个外环的高危区可以比内环的常规点更难，这正是它存在的意义：危险不只随深度递增，
也会横着摆在你面前让你绕或者闯。

### 3. 作者画的高危区，恰好符合我写的规则

第 4 行红区 `V-E-V-Q`：一个精英、两个搜索点、一个事件；与外界的连接只有一条 ——
`Y` 列那根 `|`，从精英 `E` 通向第 6 行。**单入口，而且入口挂在精英上。**
这和 5.4 里 `DangerZoneSpec` 的 `min_elites = 1`、`min_search = 2`、`gate_prefers_elite` 一字不差，
而作者画的时候并没有看那段。

黄色的中危区有五片，都不是单入口 —— 中危区只是难度修正，不做拓扑隔离。
随机生成器目前只造高危区；中危区要不要随机生成、按什么规则，等有了第一版手感再说。
