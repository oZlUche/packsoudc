# 301 元素反应的伤害要记进战记、结算页左下角信力记录对玩家隐藏

> 作者 2026-11-11 13:32（架构设计线程）：「目前元素反应造成的伤害不会被记录，需要记录」；13:33：「结算计分界面左下角的信力记录对玩家隐藏」。直接指派，派执行。

## 一、元素反应的伤害

### 现状（读码）

- 反应结算（`core/battle/reactions/reaction_resolver.gd` `_resolve`）：先发一条 `effect_resolved`（`effect = reaction`，`uid 0`），再以**对手**为主人跑反应的效果；其中的 `deal_damage`（如燃毒的那一下火焰伤害）发出的伤害事件 `uid = 0`、`source_side = 对手`，事件上**没有标是哪种反应打的**。
- 战记（`core/battle/battle_narrator.gd`）：反应本身有一行「某某身上引发了【燃毒】」；紧跟的那一下伤害因为 `uid 0` 且来源是对手，被当成对手的「天生」出手，写成「对手使用天生造成了 N 火焰伤害」—— 读起来不是反应的伤害，等于没记。
- 反应挂上去的持续伤害（如灼血每秒的火焰伤害）走身上状态自己跳的那条，按状态名写，没问题。
- 末行战报的双方总伤害是把全部伤害事件加起来，反应伤害**算在内**；别处按道具分账的地方（属性条的每件秒伤、记录板、计分）有没有漏，执行逐个核。

### 做法

1. 反应效果里发出的伤害事件带上 `reaction: <反应 id>`（`ctx.reacting > 0` 时由反应结算把当前反应 id 放进上下文，`DealDamage` / 伤害结算写进事件）。
2. 战记：带 `reaction` 的伤害写在反应那一行下面、同一组，缩进一行：「造成了 N 火焰伤害」（被护甲 / 格挡挡掉的照现有写法）；不再出现「使用天生」。反应没有伤害的（如火冰只剥护甲）不变。
3. 执行把吃伤害事件的地方过一遍并各补一条测试：末行战报总数、属性条秒伤、记录板的最高伤害、269 计分里和伤害有关的项、平衡导出（`battle_metrics`）。归属规则：反应伤害算**引发方那一边**的伤害，不记到某一件道具头上（两件道具各出一个元素，记给谁都不对）；按道具分账的地方单列一行反应名。
4. 回放界面：反应伤害的飘字照常（现在已有），不改。

## 二、结算页左下角的信力记录

- 现状（`ui/game/result_screen.gd` 约 245 行）：`r.faith_pace` 那一行调表用的量尺只判了 `GameSettings.dev_build()`，作者从编辑器里跑就是开发环境，所以一直看得见。
- 改成：默认不显示；只有开发者开关（186 的 `DevGate`）打开时才显示。每局信力记录照旧随对局记录写进 `calibration/runs_faith/`，不受影响。
- 测试：开发环境、开关没开时结算页没有这一行；开了才有。
