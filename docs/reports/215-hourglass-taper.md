# 215 沙漏中段逐步收窄：`HourglassMapConfig.taper`

作者 2026-10-20 14:46（答 213 落地差异里的「蝴蝶结看不出来」）：「中间逐步收窄，确实要这样」。

## 1 现状

- `HourglassMapGenerator.shape()`（078）：每半边 `half_rows` 层都是**满宽** `0～width-1`（`fill` 只决定抽几成格子），颈部 `neck_rows` 层只有 `neck_lanes` 条线段（`lane_cols()`，宽 5 两条在第 1、3 列），颈部两头那层强制全填。
- 所以第二章（宽 5、每半 4 层、颈 2 层）的格子表是 5 / 5 / 5 / 5 / 2 / 2 / 5 / 5 / 5 / 5：长方形 + 两条线 + 长方形。局内衬底每层一条横线、213 的预览每层一条虚线，都是等长，看不出沙漏。
- 塔（`TowerMapConfig.widths()`：底宽 7、每层收 1 → 7 / 5 / 3 / 1，居中偏移 `(base_width − w) / 2`）已经有「逐层收窄 + 居中」的现成做法与测试。

## 2 方案

### 2.1 配置
`HourglassMapConfig` 加一个字段：
- `taper: int = 0`：每半边从外层往颈部**每层收几格**。0 = 现状（老配置、老测试不变）。
- 第 k 层（k = 0 是最外层，到 `half_rows − 1` 紧挨颈部）的宽 `w_k = max(neck_span, width − taper × k)`，`neck_span` = 线段最小列到最大列的跨度（宽 5 两条线 = 3）。居中：`offset = (width − w_k) / 2`，允许的列 = `offset … offset + w_k − 1`（和塔同一条偏移规则；偶差时偏左一格，塔也是这样）。
- 出口半边对称：第 `half_rows + neck_rows + k` 层用 `w_{half_rows − 1 − k}`。
- 校验：紧挨颈部那层必须盖住所有线段列（`lane_cols()` ⊆ 允许的列），否则 `build_note` 报「颈部线段落在收窄的层外」。线段用 `_spread(n, 1)` 对称放时这一条天然成立。
- `cols` 不变（仍是 `width`），画布宽度、底图 `safe_area`（210 按宽 5 的画布对的）都不动。

### 2.2 第二章数据
`clockwork_hourglass.json` 的 `generator_config` 加 `"taper": 1`：格子表变成 **5 / 4 / 3 / 3 / 2 / 2 / 3 / 3 / 4 / 5**。按 `fill 0.75` 估点数 40 → 30（第 0 / 最后层与颈部两头照旧全填）；`step_limit 40`、`danger_by_row` 十项不变。
预览（213）与局内衬底不用改：层线按 `cells[r]` 的最小 / 最大列画，自己就短下去了。

### 2.3 编辑器与快照
- `free_slots` 用 `cells` 判空位，自动跟着收窄。
- 存档里的图带 `layout_meta.cells`，老存档照旧；`tools/snapshot_content.sh` 跑一遍（章节配置变了）。

## 6 落地（v3.56，2026-10-20）

按 3.1～3.3 推荐落地，没有偏差。补充两点：

1. 每层的格由 `HourglassMapConfig.half_cols(k)` 给出（生成器和测试共用），线段跨度比宽度还大时（比如线段贴两边）收窄停在满宽，照样生成；只有收窄后紧挨颈部那层盖不住某条线段才报错。
2. 213 的预览测试里「蝴蝶结」那条从「真收窄才验」改成必验：左半往颈部一层比一层短、两半对称。210 的测试按 `cells` 验宽度序列 5 / 4 / 3 / 3 / 2 / 2 / 3 / 3 / 4 / 5。
