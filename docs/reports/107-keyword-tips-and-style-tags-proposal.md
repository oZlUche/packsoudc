# 方案：关键词弹窗按字段开关、删掉「打法」类标签（107）

> 架构 thread，2026-10-03。作者拿「狩猎之神赐福的长弓」的悬浮窗举例：关键词太多太冗长 ——
> ① 【快攻】是武器的特色不是标签，删；以后类似的也删。② 【近战】/【远程】游戏里没有特别体现，将来可能用到，保留，但不要弹窗说明。
> ③ 足够直白的词不需要弹窗：【耐力】【耗耐力】【冷却】【信力】同理。④ 给关键词加一个新字段决定是否弹窗，上面这些全改 FALSE，**说明文字保留不动**。
> 本文只写方案，不实现。

## 一、现状：三类词条，命中即弹

悬浮窗（`ui/inventory/item_tooltip.gd`）的侧边词条由 `Glossary.terms_in(主文字, extra)` 收：

| 来源 | 在哪 | 怎么进侧窗 |
|---|---|---|
| 固定词条 | `core/text/glossary.gd` 的 `TERMS`（22 条：自发、冷却、急速、防护、护盾、耐力、耗耐力、信力、休眠……） | 主文字里出现这个词就收，并在主文字里标色 + 下划线 |
| 标签词条 | 每个 `TagDef.description`（`data/authoring/tags/*.json`，40 个标签） | 道具带这个标签且标签有说明就收（`Glossary.tag_terms`） |
| buff 词条 | 道具规则里施加的 `BuffDef`，说明由 `describe_buff` 生成 | 道具会施加就收 |

没有任何开关：有说明 = 一定弹。例子里 13 个侧窗，其中「赐福 / 远程 / 快攻 / 耗耐力 / 耐力 / 冷却 / 信力」七个对玩家没有信息增量。

## 二、方案

### 2.1 一个字段：`tip`，默认 true

- `TagDef` 加 `@export var tip: bool = true`（「要不要给这个标签弹词条」）。JSON 里写 `"tip": false`；导入器 / 导出器 / 编辑器走 10.4 的反射，自动认得，往返测试自动覆盖。
- 固定词条 `TERMS` 的值从「一句话」改成 `{"text": …, "tip": bool}`（没写 `tip` 按 true），和标签同一个字段名，读表的地方（`terms_in`、编辑器的词典、`FieldText`）统一用 `Glossary.term_text(name)` 取文字。
- buff 词条不加开关：它们的说明是按数据生成的效果（「标记：防护 −3，持续 8 秒」），就是玩家要看的东西。

**语义**：`tip = false` 的词**不进侧窗、主文字里也不标色不下划线**（标了色玩家就会去找解释；找不到比没有更糟）。说明文字一字不动：编辑器的词典、`docs/` 的词表、将来的图鉴 / 帮助页照用。标签行「标签：信仰、信物、武器、远程」照样列出名字。

### 2.2 删「打法」类标签

作者定：打法是武器自己的数（冷却 0.8 秒、伤害 10 已经说明了「快」），不是标签。

| 标签 | 说明 | 用到的道具 | 代码 / 内容引用 | 处置 |
|---|---|---|---|---|
| `rapid` 快攻 | 出手快、单下轻的打法 | 9 | 无 | **删** |
| `burst` 重击 | 出手慢、单下重的打法 | 6 | 无 | **删**（同类） |
| `heavy` 重型 | 笨重的大件 | 2 | 无 | 待定 1：体积已由格数表达，推荐删 |

删法：删 `data/authoring/tags/<id>.json`、从 15 件道具的 `tags` 里去掉、`tools/import_content.gd` 重导、`check_content` 绿；搜 `tests/` 里有没有按这两个标签断言的夹具。导入器对**未登记的标签**现在是否报错要确认（若不报，这次顺手加：道具引用了不存在的标签 → error，防止删了标签还有道具挂着）。

### 2.3 首批 `tip = false` 的词（数据，作者随时可改）

**固定词条**（作者点名 + 同类）：

| 词 | tip | 理由 |
|---|---|---|
| 冷却、耐力、耗耐力、信力、自发 | false | 作者点名，直白 |
| 休眠 | **删词条** | 作者定：不用词条，用灰 / 亮区分（2.5） |
| 急速 | **true** | 「越高冷却越短」是玩家不一定知道的换算，留 |
| 开战时、出手时、受伤时、层数够时、资源低于时 | true | 时机词，决定一条规则什么时候动，留 |
| 防护、护盾、中毒、流血、直接伤害、永续、叠层、合成、增益槽、受益槽 | true | 都带规则 |

**标签**（说明里有规则或有信仰偏好的留，纯同义反复的关）：

| 标签 | tip | 理由 |
|---|---|---|
| 近战、远程 | false | 作者点名 |
| 赐福、附魔、弹药、材料、零件、工具、试剂、消耗品、装备、血肉、宝石、食物、皮革、帝国、蛮族、遗物、战利品 | false | 说明 = 名字换个说法（「弹药。」「材料。」「吃的。」） |
| 骨制品、金属、自然 | true | 说明里写了哪位神看重它（献祭信息） |
| 武器、信仰、信物、盾、防具、防具插件、珍宝、特殊道具、封印、符号 | true | 带规则（各自出手 / 休眠 / 激活 / 不参战 / 不再出现……） |
| 火焰、毒、流血 | true | 指向伤害类型的规则 |

例子里的长弓改完后侧窗从 13 个降到 4 个：信仰、武器、信物、标记。

### 2.4 休眠不用词条：信仰那几行灰 / 亮就够了（作者定）

悬浮窗里信仰相关的行 ——「信力 Lv.1：伤害 +4」「信力 Lv.2：增伤 +15%」「信物：当前信仰」—— 现在已经按状态上色（096：生效的白、没生效的灰）。作者定：**只靠这个区分**，不再出「休眠」词条，也删掉那一行「信仰道具：别的信仰激活时休眠（保留通用效果）—— 现在已激活（Lv.0）」。
规则：这件道具的信仰是激活的 → 信仰相关行亮色；别的信仰激活着（休眠）或还没激活 → 全部灰色；信仰行后面的「—— 现在…」状态尾巴去掉，状态就是颜色。`TERMS` 里「休眠」整条删除（文字搬进 `docs/` 的机制说明，不再是玩家词条）。`FaithTooltip` 末尾那句「别的信仰的道具休眠：只留通用效果…」保留，它在信仰的悬浮窗里，不在道具上。

### 2.5 顺手的一条

主文字里重复出现的词只收一次（现在 `terms_in` 已经按首次出现去重），不动。
