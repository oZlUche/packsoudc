# 244 金块 / 金条：把现金换成能进保险箱的东西；「不参战」两处补正

作者 2026-10-24 08:04（分支阅读线，转架构设计）：「引入类似【金条】【金块】等贵重物品，且有概率在商店刷出，主要用途是让玩家可以将现金转换成道具通过保险箱带回」。同一条里的「不参战」「战败保钱」已随合作者分支整体合入（243，PR #318），这里只补「不参战」两处小问题。

## 〇 一句话

加两件新道具 **金块（一格）** 与 **金条（一乘二）**，只有一个用处：**值钱**。商店按固定概率上架、按面值加一成手续费卖，玩家买下放进保险箱，战败也带得回基地，基地回收页**按面值全额**收回。它们不算总分、不参战、不进配方。

## 一 为什么要它

- 现在钱的三条路：撤离 1:1 带回；战败全丢（行囊科技保两到五成，243）。保险箱是战败的唯一保险，但钱进不了保险箱。
- 金块就是「能进保险箱的钱」：买它 = 给这笔钱买保险，手续费一成；保险箱只有三乘三，装多少是取舍。
- 它不能变成赚钱的路：买价 ≥ 回收价，任何折扣 buff 都不作用在它身上（§2.3）。

## 二 设计

### 2.1 道具

| | 金块 `gold_nugget` | 金条 `gold_bar` |
|---|---|---|
| 形状 | `["1"]` 一格 | `["11"]` 一乘二 |
| 稀有度 | 1 优良 | 2 稀有 |
| 面值 `value` | 60 | 150 |
| 重量 | 3 | 7 |
| 标签 | `bullion` | `bullion` |
| 说明（中） | 一块沉手的生金，谁都认它的分量 | 打上印记的金条，带回去一分不少 |
| 说明（英） | A heavy lump of raw gold; its weight speaks for itself | A stamped bar of gold, worth every coin back home |

数全是占位，进 status.md 的占位清单。**不**带 `material` / 自然 / 工艺 / 魔法 / `metal` / `treasure`（`treasure` 被商店排除，材料三标签会被信仰和配方认）；新标签 `bullion`「金银」：值钱、不参战、基地按面值回收。没有 `combat`，没有耐久（侵蚀损坏不碰它：148 的损坏只对有 `wear` 的件）。

### 2.2 商店上架

`EconomyRules` 加两项：`bullion_slot_chance` 0.35（每次刷货，有这么大概率把**一个**货架换成金银件；一次最多一个）、`bullion_items` `["gold_nugget", "gold_bar"]`（等权抽）。不走稀有度权重池，所以 `shop_rarity_weights` 不用动；`candidates()` 把带 `bullion` 的排除掉，免得又从权重池里抽一次。深度越深金条占比越高：`bullion_bar_share_by_depth` `[0.3, 0.7]`（最外三成是金条、最内七成），线性插值。

### 2.3 价钱：买贵一成、回收按面值、不吃任何倍率

- 商店售价 = 面值 × `bullion_premium` 1.1，**不乘** `shop_price_mult`、不乘 buff 的 `price_mult`（`ShopSession.price_of` 对 `bullion` 单独一条）。否则「打折 buff 买金、基地全价回收」就是印钞机。
- 局内商店回购（拖进卖框）：照常 `shop_sell_ratio`（五成）——局内不是回收处。
- 基地回收页：`bullion` 按**面值全额**（`MetaRules.sell_ratio` 对它不生效；`MetaState` 的出售一键按档卖也按面值算）。
- 结算：**不算总分**。`RunResult.settle` 累加 `value` / `safe_value` 时跳过 `bullion`（224 的「总分」是搜刮成绩，花钱买的不该算分）；钱照常回仓库。

### 2.4 别的地方

- 不进配方、不进敌人掉落池（敌人组装的通用标签表没有它）、不进搜索掉落（`drop_rules` 的池按标签，`bullion` 不在任何池里）。只有商店出。
- 百科：两条，归「珍宝」页后面。
- 美术：两张 png（金块 / 金条），交美术设计线；落地前用占位图（152 件的现有占位路径）。
- 名字进 `Names`，中英各一；说明里没有阿拉伯数字。

## 三 「不参战」两处补正（243 落地后发现）

| # | 现状 | 定 |
|---|---|---|
| 1 | 标了不参战的件仍被邻居当作「受益」的提供者（`Compiler._lit_neighbors` 不看 `is_benched`），和它旁边的件照样点亮 | **不参战 = 不在场**：`_lit_neighbors` 跳过 `is_benched()` 的件，既不给邻接也不受（它本来就不进 fighters）。休眠（`dormant`）的件照旧，不在本报告动——087 写的是休眠丢邻接，现在的实现没丢，这是另一个问题，列在 §五 |
| 2 | `benched` 标记随存档，带回基地后仍在，下一局摆上就还是不参战 | **回基地清掉**：`MetaState._adopt()` 里 `inst.set_benched(false)`（和 207 的成长清零放一起）。局内照旧保留（存档读回还是不参战，这是对的） |

## 四 测试

- 金块：商店 `candidates()` 不含 `bullion`；`bullion_slot_chance` 1.0 时每次刷货恰有一个金银件、0 时没有；售价 = 面值 × 1.1 且不随 `price_mult` 变；基地回收 = 面值；结算 `value` 不含它；保险箱里的战败回仓库（已有 092 路径）。
- 不参战：两件相邻、一件标不参战 → 另一件的受益规则数为零；`absorb` 后 `is_benched()` 为假。
- 内容：`tools/check_content.gd`、`bash tools/snapshot_content.sh`（新内容进快照）。
