# 057 · M6-3 打磨：撤离确认、仓库带进下一局；M6 完结

> 阶段 6 · M6 ｜ 架构文档 8.2、8.3、12 节（v1.54）｜ 前一步：[056 M6-2 搜刮界面](056-loot-reveal-and-search-screen.md)

M6 的第三步，也是最后一步：把循环真正闭合 —— 上一局背出来的东西能带进下一局，带进去的死了就没了；撤离前问一句。

## 几条决定

**带进去的从仓库拿走，而且立刻存。** 不存的话，带着仓库里的传说品进去、死了、关掉游戏再开，东西还在仓库 —— 搜打撤的全部张力就没了。
`begin` 在开局成功之后才拿（生成不出图不该吃掉东西），拿完马上 `MetaSave.write`。一局里是新实例（3.1：存档只写 id），
撤离了走 `MetaState.absorb` 回来，重新编号。

**确认是提示，不是挽留。** 3.4 说得清楚：暂存区里的道具 = 不存在，离开前提一句可能遗落，仅此而已。确认面板列三件事：付费撤离点收多少、棋盘上什么会背出去、
暂存区里什么带不出去；付不起时「确定撤离」灰掉，其余情况一按就走。免费的、暂存区空的也问一句 —— 撤离结束一局，值得一次确认。

**不做的。** 卖东西给商店、局外货币怎么花、商店能不能回头、遭遇后能不能接着搜 —— 都在 status.md「留给作者定的」里，这里没有替作者拍板。

## 验证

```
bash tools/test.sh
通过  6616 项断言，39 个套件，耗时 71 秒
```

- 仓库带进一局：先撤离一局攒仓库；带一件开局 → 仓库少一件、那个 uid 不在了、meta 立刻存了（读回来也少一件）、这一局里多了一件那个道具；
  不存在的 uid 忽略；战败带出去的没回来；撤离棋盘上的全回仓库。
- 导演：不在撤离点上按撤离没反应；隔着导演一路走到最近的免费撤离点（每一步把叠上来的屏按它们自己的按钮看完）；按撤离先问一句、再想想面板关了人还在、
  确定撤离 → 结算（账上遗落的件数 = 暂存区里的）→ 局外（仓库里就是背出去的）。
- 截图（`DEMO_SCREEN=confirm` / `setup`）：撤离点上的确认面板；开局屏中间一列仓库、勾了一件，预览里多一个包、写着「从仓库带 1 件」。

## M6 回顾

三步（055、056、057）之后，正式游戏（`ui/game/game.tscn`，主场景）从主菜单一条线玩到仓库：开局挑章、挑装备、从仓库带 → 地图上挑出生点、走 →
战斗回放 / 战利品一件一件亮出来拖走 / 搜索点逐次装 / 商店 / 事件 / 休息 → 撤离确认 → 结算 → 仓库与战绩 → 再来一局。
状态机是纯逻辑的 `GameFlow`，测试驱动它走完整条流程一屏都不画；导演另有帧测试证明它真的换屏；每一屏的动作都是公开方法，鼠标只是调它们。
