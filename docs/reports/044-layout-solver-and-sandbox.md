## 角度是解出来的

数据层只有「第几环、环上第几个、和谁相连」。求解器的输入是**形态无关的**：每个点一个层（0 = 圆心）、
一个圈上的位置（0～1）、加上跨层的边。同心环图把 ring/order 翻成它，手绘图把 row/col 翻成它，
求解器只写一次 —— 这正是 5.9 说的「两个生成器只产出次序，同一个求解器画它们」。

**第一版是 5.9 写的逐层贪心**（由外向内，有外层邻居的钉住、其余插值），在随机生成的图上画歪了：
每个点向内连一两条，「一点接着两个外层点」是常态，均值一层层叠下去，整层的点被顺着推到一边，
沙盒里左半张图是空的。

改成**松弛**：最外层按位置钉死；里面每个有径向边的点反复取径向邻居角度的圆周均值（四百轮，六环的图
两百轮就不动了，34 毫秒）；每轮之后按圈上的次序整理一遍 —— 同层的点不许越过彼此、不许挤到一起，
挤到一起的两个各让一半（只往一个方向推，整层又会被推到一边）。一条链就整条垂直；
一个点接着两个外层点就落在它们中间。
两条告警：一个内层点接着多个角度不同的外层点（这种图没法让每条径向边都垂直），
和一层按次序不单调 —— 告警并照画，不拒绝。随机生成的图上前者是常态（一张图十几处），
沙盒只报个数，不逐条列。

**两种图的目标不一样。** 手绘图的 `|` 就该竖直：`anchor` = 0，每条简单的链解得精确。
随机生成的图不一样 —— 每个点向内连一两条 ±1 槽位的斜边是它的本意（5.4「不交叉」那一节作者定的），
把所有径向边硬拉直等于把整层的点往一处挤；解到底（`anchor` = 0）十二个种子里有三个比按槽位画还歪。
所以随机图每个点留三成半的力往名义位置拉（`anchor` = 0.35），只把径向边往竖直方向带一带：
十二个种子平均总偏差降到名义的七成，从不更歪。扫过 0 / 0.2 / 0.35 / 0.5 / 1.0，0.2～0.5 差不多，取 0.35。

两个踩过的坑：整理次序时第一版以第一个点为基准把整层展开到一条线上，一个点只落后基准一点点就被折到
一圈之外、当成差了六个弧度去推，整个内圈一轮轮被推着转 —— 改成带符号的圆周差；
没连到最外层的分量（几个内环点互相连着、不接外环）没有东西钉住，会被整理推着满圈游走 —— 给它一点回到名义位置的拉力。
均值一步到位会和整理互相打架来回抖，加了一半的阻尼。

没有随机，解两次逐位相同。按 `MapGraph.version` 缓存：鼠标每动一下都要问位置，不能每次都解。

测试守着：`chapter01_v0.1.txt` 里简单的 `|` 链都竖直、总偏差比按列画的小；随机图十二个种子
从不比按槽位画更歪、平均至少好一成五；画不成全垂直的图有告警。

## 地图沙盒

启动选择器第五个入口。从 `data/chapters/chapter_01.tres` 的 `MapSource` 拿图：

1. **挑出生点。** 右栏每条路线一张卡：出生点、风格、尽头（打 BOSS 还是撤离点）、风险与收益；
   悬停卡或悬停图上的出生点，那条路线加粗。这是这一章第一个真正的决策，沙盒里就该长得像个决策。
2. 点相邻的点走一步：HUD 的行动点变，用过的点变灰，走回头路照样花点。
   悬停相邻的点先说「去哪、花几点、是不是穿行」。
3. HUD：行动点 / 距最近撤离点 / 距最近休息区 / 距核心 / 体力 —— 全是 `MapNavigator` 的只读查询。
4. `R` 换种子，重开这一局，`F` 缩到放下，`1` 原比例。

它只接线：图来自 `ChapterDef`，走路是 `MapTravel`，画是 `MapView`。撤离动作是 M6 的事，
到了撤离点日志里说一句。
