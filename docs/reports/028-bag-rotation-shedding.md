# 028 · 包也能转：内容物按本地坐标跟着转，跨包的脱落

> 阶段 3 · 背包交互补完 ｜ 架构文档 v1.22（3.2、3.3）

## 一、规则

包可以旋转，连同里面的东西一起抓着转。

- **整件在包里的东西跟着转。** 竖着的步枪跟着变横，左上角的方块转到右上角，
  每一件都还在包里，一件不掉。
- **跨包的东西脱落。** 一件横跨两个包的东西不属于这个包，带不走；包一走它又少了半边依托。
  包原样放回它就回原处，放到别处或换了朝向，它进暂存区。

![转过的包：内容物跟着转，跨包的手枪标橙](images/028-bag-rotation.png)

兴奋剂、匕首、电池随包转了 90°，都还在轮廓里。竖着横跨上下两个包的手枪
压暗描橙 —— 放手它就脱落。

## 二、第一版错在哪

第一版让内容物**不**跟着转，留在原处，出了新轮廓就脱落。截图一看就不对：
一件明明整件在包里的兴奋剂，转一下包就掉出来了。那不是脱落，是**旋转出错** ——
用户一眼指出来，并给了正解：区分本地坐标与全局坐标。

内容物记的是**本地坐标**：相对包原点、折回包 rot 0 坐标系的位置与朝向。
包换朝向时，内容物按同一个变换跟着走。

```
to_local(bag, item)                    全局 → 本地：减去包原点，再用包的逆变换折回 rot 0
to_global(bag, local, item, origin, rot)  本地 → 全局：用包在新朝向下的正变换，加上新原点
```

逆变换 `ItemShape.untransform_point` 是 `transform_point` 的精确反演 ——
后者做「旋转、再减去规范化平移」，前者「加回平移、再反向旋转」，一步不差。
测试里先转再转回去，每件东西回到原来的格子、原来的朝向。

改成本地坐标之后，脱落只剩**跨包**这一种，语义正好对上「依附不上才脱落」。

## 三、于是允许跨包了

第一版的脱落规则用户描述时就说的是「原本跨包的道具」，而那时系统根本不允许跨包 ——
我按字面把它理解成了「转出轮廓的」。这次一并放开：一件东西可以横跨两个包，
只要每一格都有包覆盖。

早先禁止跨包的理由是「归属必须无歧义」：包的效果要知道给谁，拿起包要知道带走谁。
现在这样回答：

- **`bag_of` 只认整件落在里面的。** 跨包的谁的都不是，两边加成都拿不到。
  跨包因此是**用加成换空间**的取舍，不是双份加成的漏洞。
- **拿起包只带走整件在里面的。** 跨包的一并摘下，记着全局位置：
  原样放回就回去，放到别处就脱落。

准入标签跟着收紧：碰到的**每一个**包都得接受这件东西。只收药水的药水带，
哪怕只被一把步枪压住一格也不该收。

归属仍然无歧义，只是多了一种「谁的都不是」。

## 四、一条路径，两个入口

```
bag_fit_report(payload, origin, rot)       → {ok, fallen}   不改状态
attach_bag_shedding(payload, origin, rot)  → 照报告执行
rotate_bag(uid, steps)                     = detach_bag → attach_bag_shedding(同原点, 新朝向)
```

原地转与拖拽中按 R 走**同一段代码**。`attach_bag` 保留为一件不能少的严格版，
只给 `_restore` 的「原样放回」用 —— 那条路上朝向就是原来的朝向，跨包的也能回原处。

`detach_bag` 的载荷里内容物改记 `locals`（本地坐标），跨包的另记 `straddlers`
（实例 + 原全局位置）。取消拖拽时严格版把两者都放回去。

## 五、没地方去就不让转

脱落的东西需要暂存区接着。没有、或满了：预览直接判红，放手不成立，
包连同内容物、跨包的一起退回原处。

## 八、遗留

- 跨包的东西拿不到任何包的加成，这是我定的。另一种是「碰到的每个包都给一份」——
  那会让跨包变成白拿双份，所以没选。要改只动 `_apply_bag_effects` 一处。
- 残影上跨包的那件只有颜色没有文字。等有人抱怨再加「将脱落」的标签。
