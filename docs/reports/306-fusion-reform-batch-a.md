## 二、改了什么

| 方案条目 | 做法 |
|---|---|
| 锁定检查（304 第 8 节 ②） | `Fusion.spendable`：玩家锁定、扎根、随身之物都不能被合掉。拼接不出锤、点锤不合；拖合时手上那件或被压那件锁着也不合 |
| 统一结算 | 拼接与拖合走同一笔 `_settle`：记一次合成、学到这张配方、认识成品；回执带配方 id |
| 配方发现记录（§6.1） | 新 `Lore`：合成成功过的配方、认识的道具两个集合。只在合成成功时记配方；取消、预览、拿到成品、铁匠打造都不记 |
| 道具认识（§6.1） | 摆进自己背包、或自己造出来（落在地上也算）就认识；铁匠铺打造、砧锤出的也认识。和图鉴计数分开，图鉴不虚增 |
| 存档与崩溃一致性（§6.3） | 按架构设计的建议，不做交易日志：一局学到的记在这一局的存档里（和物品变动同一份文件，一次写盘），局终并进局外（死了也记）。并集只加不减，重复并不重复计，两次写盘之间断了不需要恢复 |
| 旧档（§6.1） | 局外老档没有「认识」：按图鉴点亮的和仓库 / 待置入棋盘里真有的补上；配方**不反推** |
| 悬浮窗可见性（§6.2） | 「可拼为」「可升为」只列知道的配方；成品那边新加「由 甲 与 乙 合成」（同样只列知道的）。配方词、道具词子窗都从这几行开，跟着一起受限 |
| 拖合提示 | 不认识成品：「合成 → ？？？」，配方说明也不写 |
| 点锤先确认（§6.2） | 点小锤开钉住的确认窗：成品（不认识就是问号，不写名字、稀有度、属性）、消耗哪两件、会丢掉的附魔 / 品质 / 成长；「合成」才合，合的那一下再查一遍两件还贴着、没锁；「取消」什么都不动 |
| 砧（UpgradeCompare） | 没锤过、也不认识出件：便条上那张升级的名字写问号（要什么材料照写）、出件槽不画图、右窗只写问号 |
| 寂灭献祭漏扫（304 第 8 条） | 条件与执行都改查本局全部容器 + 局外（新钩子 `unique_owned` → `UniqueItems.owned`）。只补检查，不补冰 / 毒之核来源 |

## 三、作者会注意到的变化

- **「可拼为」会先变空。** 方案规定旧档不反推配方，所以作者自己档里原来列出的 14 条拼接，要各自重新合成一次才会回来。这是方案明文的规则，不是退化。
- **「可升为」同理**：砧上锤过（或认识出件）才列。D 批会关掉砧，届时这一行整体退场。
- 确认窗和未知成品现在用文字问号占位，统一的未知图标与确认窗样张另请「UI替换美术」出样张，作者挑定后再换。
