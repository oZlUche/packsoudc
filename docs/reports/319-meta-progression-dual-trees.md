# 319 局外成长改革：双科技树与单局阶梯奖励

- 方案：[docs/plans/2026-11-14-meta-progression-dual-trees.md](../plans/2026-11-14-meta-progression-dual-trees.md)（作者 2026-11-14「执行改进」）
- 基线：main `5e4a867`（v6.19）
- 本报告按方案第 9 节分批记：A 审计 + B 双树闭环（v6.20）在本页第一到第六节；C 批（v6.22）在第七节；D 批落地后接着往下写。

## 目标

把局外成长拆成两棵互不相干的树：**数值成长**照旧花钱和材料，**机制成长**只花新点数「见识」；见识按每局最终总分的阶梯发，撤离失败也发。幸运科技换成精英 / BOSS 额外保底（C 批），讨价只管买价（C 批），局内商店可付费刷新一次（C 批）。

### 1.2 效果调用链

- 配置：`docs/techs.xlsx`（节点表新加「树」「上移」两列，等级表新加「见识」一列）→ `tools/techs_xlsx_to_json.gd` → `data/authoring/techs/*.json` + `run_buffs/tech_*.json` → `tools/import_content.gd` → `data/techs/*.tres`。
- 定义：`TechDef.tree`（`stat` / `mechanism`）、`TechDef.lift`、`TechTier.insight`。
- 购买：`TechService.ready / upgrade`，机制树扣 `MetaState.insight`；数值树照旧扣钱、交材料。
- 生效：`TechEffect.derive`（不变）。局外 buff 在开局那一刻进 `RunState.meta_buffs`，一局里冻结；`TechEffect.applies_next_run()` 告诉面板写不写「下一次出征起生效」。

### 1.3 计分来源审计

原来的「战利」= 撤离时棋盘上全部道具的价值 + 保险箱价值（战败只有保险箱）。逐项看能不能刷：

| 来源 | 问题 | 处理 |
|---|---|---|
| 带进图的道具 | 带一件贵的进图、马上撤出，整件价值算战利 | **扣本金**：开局时身上（棋盘、地上）每件记 `basis` = 当时价值；结算按「现在值的 − 本金」算（`ItemValue.net_in`），带进带出 0 分 |
| 店里买的 | 买进来带出去，价值算战利（钱换分） | 店里摆上的货都记本金；买走带出 0 分 |
| 托付 / 保险箱 | 同一件在棋盘和保险箱之间搬 | 一件只在一个容器里，按实例算，不会重复；本金跟着实例走 |
| 合成 | 用带进来的两件合一件更贵的，整件算战利 | 成品接着两件本金之和（只有捡来的两件合的没本金）；铸牌、魔晶石碎成碎片同理 |
| 买卖循环 | 卖出得钱、买回 | 钱不算分；买回来的东西带本金 |
| 合成次数 / 搜索 / 走过的点 | 每次 5 / 5 / 2 分 | 合成要消耗两件、不可逆；搜索按同一个点只算一次；走过的点按不同点数。出生点 2 分 × 难度系数，离第一档 1000 分很远，不另处理 |
| 图鉴新点亮 | 每件 25 分 | 本来就是存档级去重（第一次带出才点亮） |
| 难度系数 | 放大一切 | 放大的是上面这些已经扣过本金的项，不另处理 |

账单（结算第一页）的「带出」行、军功碑、`best_value` 仍按全价（那是展示）；只有总分里的「战利」那一项改成本局新得。计分规则记版本：`score.json` 的 `version` 从 1 到 2，历史行写 `score_v`，旧记录不重算。

### 1.4 旧档映射（存档 v4 → v5）

按方案第 7 节默认策略，旧成本写死在 `MetaMigrations.V4_COSTS`（不从新表推算）：

| 原状态 | 处理 |
|---|---|
| 数值树节点 | 等级、已交材料都不动 |
| 机制树节点（除讨价 / 幸运） | 等级保留、不补交见识；**没交完的材料退回**、清上交记录 |
| 讨价 1 级 | 记 1 级（新的固定 9 折） |
| 讨价 2 级 | 记 1 级，退第二级的 1000 币 + 1 银锭 |
| 幸运任意级 | 删掉；每一级按旧成本退：400 / 800 / 1300 币，第 3 级另退 2 硬木板 + 2 铆钉盒 |
| 历史总分 | 不换见识 |

退的钱直接进 `funds`；退的材料由 `MetaState.from_dict` 装完仓库后放进去（按页序找空位、不行临时加页、再不行折钱，同 173 的救援）。迁移前原文件留一份 `<存档>.v4.bak`；迁移做了什么记进 `migration_log`。迁移只在读 v4 文件那一刻做，存回去就是 v5，再读不会重复退。

样例（`tests/fixtures/meta_v4.json`）：钱 100、讨价 2 级、幸运 3 级、法杖工艺交了 2 碎晶、仓库交了 1 钢锭 → 读回来钱 3600（100 + 2500 + 1000），仓库多 2 硬木板、2 铆钉盒、1 银锭、2 碎晶，讨价 1 级，没有幸运，仓库扩建那 1 钢锭的上交记录还在。

正式档与切片档本来就是两份文件（`user://slice/slots`），各迁各的。

## 二、B 批实现（v6.20）

| 范围 | 改了什么 |
|---|---|
| 配置 | `docs/techs.xlsx` 节点表加「树」「上移」，等级表加「见识」；表的校验：树只能是数值 / 机制，前置不许跨树，机制树每级见识 ≥ 1 且钱、材料留空，数值树见识留空 |

| 不重复发 | `MetaState.settled_runs` 记最近 64 局的 `run_id`；同一局再进 `absorb` 返回 `duplicate`，什么也不动。局外存档写成了才删这一局的档；读到一局已经结算过的档（写完局外、没来得及删）直接删掉不继续 |
| 切片 | 切片档不发见识、结算屏不摆见识小纸，科技页照旧不开 |
| 科技页 | 树区上面两枚页签：数值成长 / 机制成长（后者写见识余额，悬停说怎么得）；树区只画当前那棵；选到另一棵树的节点自动换页签；机制节点的账目行写见识、下面一行小字「见识：每局结算达到积分档位获得，撤离失败也可获得」；局外 buff、保险箱、腰带类的写「下一次出征起生效」 |
| 树的摆法 | 机制树有五个根，按前置排会宽过羊皮内框（792）。加了「上移」（`TechDef.lift`）：行囊摆在侦察上面、法杖工艺摆在秘银冶炼上面，同列中间隔着节点的连线绕右边的列缝走。两棵树都在 792 × 556 以内 |
| 结算屏 | 账单左边一张小纸：见识 +n、三档各打勾、离下一档还差几分（满档写已完成所有档位）、见识余额；账单全显了才露 |

## 三、关键决策

- **本金按实例记**，不按道具 id：同一种道具捡一件、带一件，只扣带进来那件。
- **阶梯门槛、成本都在配置里**：阈值在 `score.json`，见识成本在 `techs.xlsx`，没写进代码。都是首轮测试值，没做平衡结论。
- **方案的前置拓扑全按原样**，没有为排版改前置；排版靠「上移」解决。
- 「追踪一个科技目标」（方案第 8 节）这一批没做，放到 D 批随统计一起补（它要显示材料的已知来源，跟审计工具共用一份数据）。
