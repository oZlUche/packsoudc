# 方案：地图屏的读数拆成可随意摆放的组件（倒计时、行动点、体力、货币……）

日期：2026-10-10　状态：架构 · 提议（待作者确认后交「架构方案执行」）

作者原话（2026-10-10）：

> 记住界面设计还需要继续调整，比如步数倒计时、体力剩余值的布局和位置。先将这些元素设计成组件可以随意布设位置

---

## 0. 结论（一段话）

地图屏顶上那一串读数现在是**一个标签里拼出来的一整行字**（`_hud.text = "行动点 %d　距最近撤离点 … 体力 %d/%d　货币 %d　地上 %d 件"`），倒计时是另一个大字标签，信仰又是一个；位置全写死在 `_build` 里，想把体力挪到左下角就得改代码。方案：每种读数做成一个**独立组件**（`HudWidget`：自己订阅一局的信号、自己刷新、自己有大小两档），地图屏上放一层 `HudHost`，按一份**布局文件**（`data/authoring/ui_layouts/map.json`：组件 id → 锚点 + 偏移 + 档位 + 显隐）把组件摆上去；没有布局文件就按今天的样子摆，所以落地那一刻画面不变。「随意布设」靠调试抽屉里的**「摆读数」模式**：开着时组件能拖、吸附八像素网格、右键隐藏，「保存布局」写回那份 JSON、「重置」回默认 —— 作者在游戏里拖好就是最终布局，不用进 Godot 编辑器。以后换皮（121 的按屏换皮）只换组件内部的画法，位置不动；美术线程也拿同一份组件清单出样稿。

## 2. 方案

### 2.1 组件

`ui/hud/hud_widget.gd`：`HudWidget extends PanelContainer`。

- `id: StringName`（布局文件里引用）、`setup(run: RunState, screen: GameScreen)`（接信号）、`refresh()`、`tier: Tier { LARGE, SMALL }`（大档 = 倒计时那种一行大字；小档 = 14 号）。
- 底与字走主题变体 `PanelHud` / `LabelHud` / `LabelHudLarge`；倒计时的「颜色随剩余变」与「边框色随剩余变」这两处 121 特例搬进倒计时组件内部（仍是特例，数量不增）。
- 每个组件自己 `tooltip` 或悬浮窗（信仰组件把现在的 `FaithTooltip` 带走）。
- 首批组件（`HudWidgets.KINDS: id → script`，新增一种 = 一个脚本 + 登记一行）：

| id | 内容 | 现在在哪 |
|---|---|---|
| `countdown` | 倒计时 剩 / 总，颜色随剩余 | 大字标签 |
| `action_points` | 行动点 | HUD 一行字 |
| `distances` | 距撤离 / 休息 / 核心几步（三个小字一组，也可拆三件：待定 1） | HUD 一行字 |
| `vitality` | 体力 当前 / 上限（可选画成格点，一格一点体力） | HUD 一行字 |
| `wallet` | 货币 | HUD 一行字 |
| `ground_count` | 地上几件 | HUD 一行字 |
| `encumbrance` | 负重档（轻装不显示） | HUD 一行字尾巴 |
| `faith` | 信仰 + 信力 + 阶（悬浮窗） | 信仰标签 |
| `buffs` | 这一局的 buff 一句 | 信仰标签 |
| `erosion` | 侵蚀一句 | 信仰标签 |
| `belt` | 147 的腰带（落地后登记） | — |

### 2.2 布局与宿主

- `HudLayout`（资源）：`[{ "id": "vitality", "anchor": "top_left", "offset": [16, 12], "tier": "small", "visible": true }, …]`。锚点九宫（`top_left / top / top_right / left / center / right / bottom_left / bottom / bottom_right`），偏移相对锚点；同一锚点多件按列表顺序横排（`anchor_flow: "row" | "column"`，默认横排），所以「顶上一排」仍写得出来。
- `ui/hud/hud_host.gd`：铺满屏幕、`mouse_filter = IGNORE` 的一层，读布局、从 `KINDS` 造组件、按锚点摆；每个组件摆好后 `screen.reserve_ground(rect)`（128），改大小或挪位置时重新报。窗口尺寸变了重排。
- 布局文件在 `data/authoring/ui_layouts/<screen>.json`，走内容管线（新种类 `ui_layouts`，没有 `.tres` 也行，导入器只校验 id 与锚点合法）。**没有文件 = 代码里的默认布局**，默认布局就是今天的样子（倒计时顶中、读数一排在它下面、信仰那串跟在后面）。
- 地图屏 `_refresh_hud` 变成 `_hud_host.refresh()`；三个旧标签与两块底框删掉。

### 2.3 「摆读数」模式

- 地图屏加 139 的调试抽屉（右缘箭头），里面一个开关「摆读数」+「保存布局」+「重置」。
- 开着时：每个组件显示虚线框与 id，按住拖（复用 `FloatingWindow` 的拖法），松手吸附八像素网格，并换算回「最近的锚点 + 偏移」（这样窗口换大小位置仍合理）；右键切显隐；滚轮切大小档。
- 「保存布局」：开发版写回 `res://data/authoring/ui_layouts/map.json`（作者直接提交），导出版写 `user://ui_layouts/map.json`（优先读）。「重置」删 user 那份、回默认。
- 不进玩家设置（待定 3）。

### 2.4 别的屏

同一套宿主可以放到事件屏 / 战前屏 / 休息屏，各自一份布局（`event.json` 只放 `vitality` + `countdown` + `wallet` 之类）。第一步只做地图屏；其他屏等作者看了效果再说（待定 2）。

### 2.5 和美术的关系

组件清单就是美术线程出「读数」样稿的清单：每个 id 一张大档一张小档。换皮时只改组件的 `_draw` / 主题变体，布局文件不动。

## 3. 实施清单（给执行线程）

1. `ui/hud/hud_widget.gd`、十个组件脚本、`hud_widgets.gd`（登记表）、主题变体三种（`UiTheme.build`）。
2. `HudLayout` 资源 + 导入（`ContentPaths` 新种类 `ui_layouts`，只校验）+ 默认布局（代码常量）。
3. `hud_host.gd`：摆放、重排、`reserve_ground`、刷新。
4. 地图屏接入：删旧标签与底框，`_refresh_hud` 改转发；调试抽屉 + 摆读数模式 + 保存 / 重置。
5. 测试（`tests/ui/`）：无布局文件时组件位置与今天一致（截图或矩形断言）；布局文件改偏移后位置跟着变；每个组件对假的一局刷新出正确文字（体力 3/5、货币 120……）；隐藏的组件不报 `reserve_ground`；保存 → 读回往返一致；窗口缩放后锚点保持；121 棘轮不超（搬走的两处特例只是换地方）。
6. `docs/architecture.md` 10.x「界面」加一小节「HUD 组件与布局文件」；README 落地记录。

## 补充（2026-10-10，作者）：腰带槽、日志、背包按钮也是组件

作者原话：

> 同理，额外槽、事件日志（这个应该只在调试模式下才出现，当然现在默认调试模式开启）以及背包按钮都是组件

### 补 1. 组件不只是读数：按钮、容器、日志都算

`HudWidget` 的定义放宽为「地图屏上任何一块可以单独摆的东西」，首批再加：

| id | 内容 | 现在在哪 | 备注 |
|---|---|---|---|
| `belt` | 147 的腰带槽（1 × N 格的 `InventoryView`，注册进 `DragLayer`） | — | 147 落地前先登记 id，布局里可以预留位置；147 落地时直接做成这个组件，不再往 `InventoryPanel` 里塞 |
| `bag_button` | 「背包（B）」按钮（`toggle_bag`） | 右栏顶部按钮行 | 快捷键 B 仍由屏幕处理，组件只是那个按钮 |
| `extract_button` | 「撤离」按钮（可用性随所在点刷新） | 右栏顶部按钮行 | |
| `menu_button` | 「存档并回主菜单」 | 右栏 | |
| `routes` | 路线列表（`_routes_box`） | 右栏 | |
| `log` | 事件日志（`_log` 那块 `RichTextLabel`，`_note` 往里写） | 右栏底部 | **只在调试模式下显示**（见补 2）；关着时 `_note` 照写、不显示，开了就能看到之前的 |

右栏本身因此消失：里面的东西全成了组件，默认布局把它们按今天的位置摆在右缘（`anchor: right`，`anchor_flow: column`），画面不变。

### 补 2. 调试模式开关

现在代码里**没有**「调试模式」这个开关（`GameSettings` 里只有 `unlock_all` 等零散项）。加 `GameSettings.debug_mode: bool`，**默认开**（作者定：现在默认调试模式开启），设置页一个勾选，调试抽屉头部也显示当前状态。布局项多一个 `debug_only: bool`；`HudHost` 在 `debug_mode` 关着时跳过这些组件（不造、不报 `reserve_ground`）。首批只有 `log` 是 `debug_only`；以后调试读数（种子、节点 id）也挂这个旗。发布版把默认改成关，一处改。

### 补 3. 清单与测试增补

- 实施清单第 1 条加六个组件；第 2 条布局项加 `debug_only`；新增第 7 条：`GameSettings.debug_mode` + 设置页勾选 + 调试抽屉状态。
- 测试加：`debug_mode` 关着时 `log` 不在树上、`_note` 不报错、开回来后能看到之前写的；`bag_button` 点击等价于按 B；腰带 id 在布局里但 147 未落地时跳过不报错。
- 147 的实施清单第 5 条（`InventoryPanel` 腰带行）改为「做成 150 的 `belt` 组件」；哪个先落地由执行线程按顺序处理（150 先落地则 147 直接用组件；147 先落地则 150 把它搬进组件）。

### 补 4. 体力组件画成红心（作者定，2026-10-10）

> 体力槽可以直接设计成 N 颗红心，失去体力就掉一颗（变为黑色）

待定 4 由此定案（不再是「先文字」）：`vitality` 组件画 `maximum` 颗心，前 `current` 颗红、其余黑（`UiPalette.HP` / 熄灭色，走 `_draw`，不新增 `add_theme_`）；上限变了（科技、章节加成、149 的百分比）颗数跟着变；体力变化时掉的那一颗从红变黑（可以先不做动画）。大档一行大心，小档一行小心；上限超过一行能放的（比如十一颗）自动折成两行。悬浮窗仍写「体力 当前 / 上限」。美术线程出样稿时按「红心 / 黑心」两个状态出。
