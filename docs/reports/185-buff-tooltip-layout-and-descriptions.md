## 0. 结论

1. **「留了太多空」的主因不是排版，是字被染成了墨色**。战斗屏整块压在浅色大理石板（`OverlayFrame`，tone light）里，石板给自己挂了「墨字」小主题；效果悬浮窗 `HoverTip` 是 `BattleView` 的子节点，它那块深色皮革窗没有自己的主题，于是**继承了墨字**：标题「标记」、「减益」、「每层带【破绽】3 层（格挡 −3）」全是深字写在深皮革上，只有 103 用十六进制写死的例外色（`#e0b45c`「不可叠层」「持续 8.0 秒」）露了出来 —— 和截图完全一致。道具悬浮窗没中招，因为它的正文整段包了 `[color=@tip_fg]`。
2. 次因：悬浮窗宽度写死 360（170 定稿是为武器那一行），一两行短字也撑满一格；修成**按内容收窄**（下限 220、上限 360）。
3. 文案：现在的说明全由字段生成（`Glossary.describe_buff`），只有「每层带什么」，没有「它是什么」，也没有「现在一共多少」。171 的 `blurb` 是**句子里的称呼**（「获得血怒」里的那个词），不是解说，所以十六个基础状态**一条解说都没有**。本篇给 `BuffDef` 加 `desc`（解说句），十四个 JSON 状态 + 两个系统状态（衰竭、鏖战）各写一句（§3）。
4. 新版式四段：**名字行**（名字 + ×层数 + 增益 / 减益小字）→ **解说句** → **效果**（可叠层写「每层」与「当前 N 层」两行，不可叠层只写一行）→ **规则行**（计时、减半、不可解除……），只写**不是默认**的事实（§2.2）。
5. 变量全部上色（§2.3）：数值一色（新样式 `val`，暖金）、伤害类型字沿用 175 的伤害色、状态关键词沿用元素关键词色并可钉开子窗、属性 / 轴名用正文色不另染。

## 1. 现状与诊断

### 1.1 字看不见（主因）

| 证据 | 位置 |
|---|---|
| 战斗屏把 `BattleView` 放进 `_centered_panel()` → `OverlayFrame`（一整块大理石板） | `ui/game/battle_screen.gd:15-28`、`ui/game/game_screen.gd:272-280` |
| 石板按自己的深浅挂字色：`UiTheme.apply_tone(area, PANEL_OVERLAY)`；大理石 tone light → 挂上 `text_theme(light)`，里面 `RichTextLabel.default_color = INK` | `ui/game/game_screen.gd:199`、`ui/ui_theme.gd:540-556` |
| `HoverTip` 直接 `add_child` 在 `BattleView` 下 | `ui/battle/battle_view.gd:687` |
| `TipWindow._init` 只调 `UiTheme.panel(self, -1, PANEL_TOOLTIP)`；皮革是深底，`set_tone(dark)` 对深底**不挂主题**（`text_theme(dark)` 返回 null），于是 `theme` 为空、一路继承到石板的墨字 | `ui/inventory/hover_tip.gd:57-58`、`ui/ui_theme.gd:584-588` |
| buff 悬浮窗的正文没包颜色：`"[b]%s[/b]\n%s"`，靠 `default_color` | `ui/battle/battle_view.gd:160-164` |
| 道具悬浮窗整段 `[color=@tip_fg]`，所以正常 | `ui/inventory/item_tooltip.gd:234` |
| 名牌早就撞过同一个坑，自己挂了 `bright_text_theme()` 解决 | `ui/widgets/nameplate.gd:29` |

截图里能看见的恰好只有 `_exception()` 染的两段（`core/text/glossary.gd:258-262`），是这个诊断的直接印证。沙盒、回放浏览器里的同一个 `BattleView` 不在石板里，所以那边看着是对的 —— 这也是为什么一直没人发现。

### 1.2 宽度写死（次因）

`HoverTip.MAX_WIDTH = 360`（`hover_tip.gd:16`）直接作为 `rich_block(width)` 的 `custom_minimum_size.x`。富文本只会按内容长高，不会按内容收窄；「不可叠层　持续 8.0 秒」一行十几个字也占满 360，右边一大片空。

### 1.3 文案只有「每层带什么」

`Glossary.describe_buff()`（`glossary.gd:205-255`）逐字段拼：第一行「减益　不可叠层　持续 8.0 秒」，之后每层的轴 / 属性 / 规则、上身 / 到期、计时、减半、按类型易伤、元素印、截治疗、恢复叠层。问题：

- 没有一句**人话**说它是什么。中毒那条读出来是「减益　不限层　永续 / [每 1.0 秒] 对自己造成 1 点毒素伤害（每层） / 毒元素的印：……」。
- 没有**当前总量**：面板知道现在几层（`CombatantPanel.stacks()`），悬浮窗不用。
- 逻辑写死在引擎里的四个状态读起来最薄：**寒冷 / 麻痹**只有「武器出手时，这一次的冷却每层 +10%；之后层数减半」一行；**剧毒**只有「受到的毒素伤害每层 +25%」；**菌血**是三行机制拼起来。
- 默认事实也占行：「增益　不限层　永续」对坚韧这类说了三个「没什么特别」。

### 1.4 变量不上色

现在只有两类字带色：103 的例外色（不可叠层 / 会过期）和 175 的「X伤害」。数值（+3%、8 层、1 点、8.0 秒）、层数、时长都是正文色。

## 2. 方案

### 2.1 版式（四段，宽 220–360 按内容收窄，内边距沿用 14）

```
┌──────────────────────────────────┐
│ 中毒 ×5                     减益  │  ← 名字 19 号粗体、状态色、描边（170 同款）；×层数 19 号粗体正文色；增益/减益 13 号 tip_meta 右对齐
│ 毒在身上，每秒按层数掉血。          │  ← 解说句 14 号斜体 tip_desc（170 道具描述同款）
│ ─────────────────────────────── │  ← 170 的分隔线
│ 每层　　每秒受 1 点毒素伤害         │  ← 15 号正文；数值 val 色；「毒素伤害」毒伤害色
│ 当前 5 层　每秒受 5 点毒素伤害      │  ← 同上；「5 层」val 色
│ ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈ │  ← 170 的虚线
│ 毒元素的印：再挨别的元素会引发反应    │  ← 规则行 13 号 tip_meta；只写不是默认的事实
└──────────────────────────────────┘
```

- **名字行**：`Names.of(def)`，颜色 `Glossary.status_style(def)`（元素状态用元素关键词色，其余 `term`）；系统状态（衰竭、鏖战）用 `CombatantPanel.SYSTEM_COLOR`。可叠层的写 `×N`（N = `panel.stacks()[id]`）；不可叠层不写。右端小字「增益」/「减益」/「系统」。
- **解说句**：新字段 `BuffDef.desc`（§3）。一句，不带数字（数字都在效果段里，改数值不用改句子；`TextLint.STRICT` 照常拦阿拉伯数字）。
- **效果段**：
  - 可叠层（`is_stackable()`）：两行，「每层」+「当前 N 层」。N 从面板来；图鉴、道具子窗没有层数就只写「每层」。
  - 不可叠层：一行「效果」。
  - 「当前」= 每层 × N，按字段类型折算（§2.2 表）。注意它只是**这个状态自己**的合计；同一条轴若还有别的来源，总数看轴格（`axis:*`）的悬浮窗，那边本来就写「现在 N 层 → …」。
- **规则行**：只在**不是默认**时出现（默认 = 永续、可叠层、无计时、无减半、可解除）：「不可叠层　持续 8 秒」「每次结算后层数减半」「每层各计 1 秒，再叠上来就延长」「系统效果，不可解除」「其中 N 层不可解除」（175 补充四保底）。103 的例外色**退役**：不默认的事实现在靠「出现 / 不出现」区分，不再靠染色。

轴格（`axis:*`）和「格挡 N」格套同一版式：名字行「强攻 ×3」、解说句（表里一句：「造成的伤害按层加成，正为强攻、负为虚弱，相抵」）、效果「每层 +3% / 当前 3 层 +9%」、规则行「其中 N 层来自系统规则，不可解除」。`StatAxes.describe()` 的三行并进去，不再单独一套格式。

### 2.2 「每层」与「当前」怎么从字段折算

| 字段 | 每层一行 | 当前 N 层 | 例 |
|---|---|---|---|
| `axes`（`BuffAxis`） | `StatAxes.effect_text(axis, stacks)`，前面带轴名 | `effect_text(axis, stacks × N)`（连乘轴 `STAMINA_COST` 由它自己算幂，不手乘） | 血怒（不可叠）：「造成的伤害 +3%、攻速 +3%」 |
| `mods`（`StatModifier`） | `Glossary.mod_text(m)` | 量 × N 再走 `mod_text` | 坚韧 ×2：每层 护甲上限 +15 / 当前 2 层 +30 |
| `rules` 里按层的 `deal_damage`（`per_stack`） | 「每秒受 1 点X伤害」（`rule_text` 现成，把「对自己造成」改口为「受」） | 量 × N | 中毒 ×5：每秒受 5 点毒素伤害 |
| `per_stack_percent` + `decay_halve_on = weapon_fired` | 「下一次出手的冷却 +10%，出手后层数减半」 | +10% × N | 寒冷 ×3：当前 3 层 下一次出手的冷却 +30% |
| `per_stack_percent` + `stamina_paid` | 「下一次付耐力多付 10%，付过后层数减半」 | × N | 麻痹 |
| `damage_taken_by_type` | 「受到的毒素伤害 +25%」 | × N | 剧毒 ×2：+50% |
| `seconds_per_stack` | 「每层各计 1 秒；再叠上来就延长」 | 「约还持续 N 秒」 | 菌血 ×4、燃血 |
| `heal_cut` / `heal_echo` | 不按层：「回血只回一半；回了几点就叠几层中毒」 | 不写当前行（和层数无关） | 菌血、燃血 |
| `element` | 规则行「X元素的印：再挨别的元素会引发反应」 | — | 流血、寒冷、麻痹、中毒、灼伤 |
| `on_apply` / `on_expire` | 「上身时：…」「到期时：…」 | — | （目前没有状态用到） |
| 衰竭（系统，`OvertimeRules.decay_buff`） | 「生命上限 −N」 | × 层 | 衰竭 ×3 |
| 鏖战（系统，轴格的系统层） | 「双方受到的最终伤害 +20%」 | × 次 | 鏖战 ×2：+40% |

`Glossary` 拆成几个小函数（§4），`describe_buff(def, stacks := 0)` 保留做总装：`stacks ≤ 0` 时不出「当前」行（图鉴、道具子窗、编辑器）。

### 2.3 颜色规则（都走 `text_colors.json`，深浅各一版）

| 什么 | 样式 | 备注 |
|---|---|---|
| 数值：+3%、5 点、8 秒、×5、「5 层」里的 5 | **新样式 `val`**：dark `#f3c969` / light `#6b4e00` | 暖金，和铜框同族；作者说的「变量」就是它们 |
| 「X伤害」 | 175 的伤害色（`Glossary.DAMAGE_STYLES`，`mark_rich` 已经在做） | 整段「毒素伤害」一色 |
| 状态关键词（菌血句里的「中毒」） | 175 的元素关键词色 + 下划线 | 钉住后可开子窗（170 机制现成，`terms` 从 `Glossary.buffs_in_*` 收） |
| 名字 | `status_style(def)`；系统状态 `SYSTEM_COLOR` | 描边（`UiTheme.outline`） |
| 属性 / 轴名（造成的伤害、攻速、格挡、护甲上限） | 正文 `tip_fg` | 不另染，免得一行五种色 |
| 解说句 | `tip_desc` 斜体 | 道具描述同款 |
| 规则行、增益 / 减益小字 | `tip_meta` | |
| 103 例外色 `#e0b45c` | 退役 | 见 §2.1 规则行 |

数值怎么染：生成函数在拼数字时统一经 `Glossary.val(text)` → `[color=@val]…[/color]`。不改 `StatAxes.effect_text` 的签名；它返回的「造成的伤害 +3%」里的数字由一个小正则在 `Glossary` 一层补色（数字、正负号、% 和「点 / 秒 / 层」前的那个数）。

## 4. 改动清单（给执行）

**数据与定义**
- `core/battle/buff_def.gd`：加 `@export_multiline var desc: String = ""` 与 `descs: Dictionary`（别的语言，`display_names` 同款）；`desc_text(lang)`。`blurb` 不动（它还是 171 的句内称呼）。

- `core/authoring/content_importer.gd`：非系统状态 `desc` 为空 → `report.warn("desc", …)`（和 171 的 blurb 警告并排），新状态不会再漏。

- `ui/buff_editor/buff_editor.gd`：加解说句输入框；`axes_text()` 现在取 `describe_buff().split("\n")[1]`（第二行），版式一改就取错 —— 改成直接调 §4 的 `buff_per_stack_lines(def)`。

**界面**
