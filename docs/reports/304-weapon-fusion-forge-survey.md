## 一 主要发现（一页）

1. **数量**：武器 120 把（白 7 / 绿 20 / 蓝 34 / 紫 24 / 金 19 / 红 16，红里 8 把是 `_lesser` 劣化版）。配方 124 张：相邻拼接 14、拖上去合 9（只有 1 张产武器）、**升级 82**（局内砧与局外铁匠铺共用同一张表）、铁匠打造 17、冶炼 2。产物是武器的 111 张。没有失效引用（输入 / 输出 id 全部存在）。
2. **关系分类**：102 把武器至少有一条配方关系，18 把没有（8 把红武本体 + 8 把劣化版 + 胫骨大棒 + 狩猎赐福长弓）。只参与拼接 7 把，拼接与升级都有 14 把，只参与升级 73 把；14 把是铁匠打造成品。
3. **升级是主干**：82 张升级占武器配方的 74%，覆盖绿→蓝→紫→金四段；每张都是「上一把 + 一类材料（或一族魔晶石）」。18 把金档里 17 把元素纹 + 帝国佩剑带 `forged_only`，**只能升出来**，不进任何随机池。
4. **局内砧与局外铁匠铺是同一套配方的两个入口**：砧免费（每个休息点一次）、**不看铁匠铺级数和科技**；铁匠铺收 60 / 120 / 200 金、要 1 / 2 / 3 级。所以现有 82 条升级**已经全部是双渠道**。
5. **合成知识不存在**：全项目没有按配方 id 记的发现记录。图鉴只有 `MetaState.codex`（道具 id → 件数）。拼接成功不点亮图鉴，砧和铁匠铺会点亮。悬浮窗「可拼为 / 可升为」、配方子窗、升级前后两窗都**不看图鉴**，未知成品的名字、图、稀有度、属性全部可见。
6. **成品不继承实例状态**：拼接、砧、铁匠铺都用 `ItemInstance.create` 新建成品。附魔、生长、法杖进出局次数、不参战标记全丢；只有砧与铁匠铺写品质（max(原件, 材料超门槛档数)，上限 2），拼接成品品质恒为 0。
7. **红武**：唯一性按 item_id、每次现扫全部容器（`UniqueItems.owned_ids`），没有缓存、没有「解除」步骤。8 把本体里**没有一把正常可得**：寂灭整条链写完了但冰 / 毒之核没有来源（配置在·未接通）；破晓只有信物起点；其余 6 把仅设计或已作废。劣化版已实现、可掉落、可卖。
8. **复现了一处唯一性漏洞（条件层）**：寂灭已在本局地上时，神坛献祭条件仍然成立（`verify.log` 第四节），可献出第二把；当前被「缺两颗核」挡住，玩家走不到。
9. **锁定件会被拼掉**：拼接和拖合不查玩家锁定（砧与铁匠铺查）。

## 三 全量武器与相关道具（摘要）

完整表见 [weapons.csv](research/evidence/2026-11-11-weapon-fusion/weapons.csv)。字段说明与口径：

- **身份**：`item_id`、中英名、类别标签（`dagger / one_hand / dual / polearm / two_hand / ranged / staff`）、`rarity` 原值与颜色（`ui/inventory/item_painter.gd:7-14`：0 白 1 绿 2 蓝 3 紫 4 金 5 红；**279 报告把 4 叫「橙」，代码与界面是金**）、标签、材质、`unique / lesser / forged_only / requires_unlock`。
- **使用成本**：占格数与形状（rot 0）、重量、`value`（定义值；实际售价由 `ItemValue` 与经济规则推导，本表不重算）。
- **战斗定义**：`damage_base` 是定义里的 `base_stats.damage`；`cooldown_s` 是每条规则的冷却秒数（`CycleCadence` 法杖记步长）；`costs` 是每条规则的资源消耗。**这是定义值，不是运行值**：运行时品质按 `BattleCompiler.quality_stats` 给伤害 / 格挡 / 护甲 ×(1 + 0.1×品质)、暴击 +5 点，`quality_rules` 给施加层数 / 轴层数 / 写死点数每档 +1，耐力价不动（`core/battle/compiler.gd:207-253`）；标准轴、套装、邻接等单位级修正不在本表。
- **每击效果**：`per_hit_extra = true` 的 86 把，其每次出手规则里除了伤害还有别的效果（施加状态、轴、追加伤害）——**这些武器不能只用伤害 / 冷却估战力**。
- **资产**：120 把全部有 `assets/items/<id>.png`；**120 把的 `description` 全空**（作者规则：道具不写描述）；名字有中英两份。
- **渠道**：`channels_by_rule` 是**按代码规则能进哪个候选池**，不是实测掉率（§五）；`named_refs` 是作者数据里按 id 点名的位置（敌人招牌装备、NPC 等），点名不等于可达。

相关非武器道具见 [related_items.csv](research/evidence/2026-11-11-weapon-fusion/related_items.csv)：配方点名的组件只有 4 种——木棍（7 张）、磨刀石（5 张）、鞣革（4 张）、燧石（1 张）；其余都是**材质谓词**（12 个，[material_predicates.csv](research/evidence/2026-11-11-weapon-fusion/material_predicates.csv)），例如 `metal≥绿` 有 15 个合格候选，`metal≥金` 只有 1 个，三族魔晶石 `≥紫` 各 2 个。判断「能不能顶」用的是 `SmithRecipeDef.material_fits`：`material` 标签 + `ItemDef.material` 相等 + 稀有度够，魔晶石看 `crystal` 标签与 `crystal_family`——**不看名字**。

### 5.1 随机池的总闸

搜索、掉落、局内商店、集市、敌人装备、信仰送物都从 `ItemDatabase.ids()` 拿候选（`core/inventory/item_database.gd:86-97`）：封存、随身、赐福、铸牌、签名件不进；`forged_only`、`unique`、`lesser`、券、成就未解锁的也不进。各渠道再叠自己的条件：

| 渠道 | 额外条件（作者数据） | 金档 | 红档 |
|---|---|---|---|
| 搜索 | 排除 `treasure`；稀有度权重 50 / 30 / 15 / 4 / 1（`node_rules/standard.json`，只有 5 档） | 可（权重 1） | 不可（无权重，且 unique 已被拦） |
| 局内商店 | 排除 `treasure / supply`；权重 40 / 30 / 20 / 8 / 2 / 0.5（`economy_rules/standard.json`） | 可 | 被总闸拦 |
| 集市固定兵器摊 | 每级上限 白 / 绿 / 蓝（`base_rules/market.json`） | 不可 | 不可 |
| 集市散货摊 | 权重 50 / 30 / 14 / 5 / 1 | 可 | 不可 |
| 敌人携带 | 武器档上限 0 / 1 / 2 / 3（三个 enemy_pools 都一样）、排除 `extreme`、低档不背真实伤害武器 | **不可**（上限紫） | 不可 |
| BOSS 金色保底 | `drop_rules.boss_rarity = 4`，本档有 `treasure` 件时只抽 treasure（rarity 4 有 `pale_shard`） | 实际抽不到武器 | — |

| 一次性任务红武重拿 | 寂灭可重做整条链（现走不到）；破晓信物不可 | §4.5 |
| 不同具名红武共存 | 可以 | `tests/inventory/test_unique_281.gd:52-72` |
| 旧档重复实例 | 不去重；红武 281（v5.20）才加入，更早存档不可能有 | `run_migrations.gd`、`meta_migrations.gd`、`SaveReconcile` 无相关步骤 |

**用户规则对照**：「同名红武一个存档只能一件，遗失 / 销毁 / 出售后才可再得」——同名一件：已按 id 实现（有上述漏洞）；遗失后再得：机制上自动成立（现扫），但破晓信物被永久旗标挡住；**出售**：现状是红武根本不能卖，与「出售后可再得」的表述冲突，需要作者定。「地上 / 托付 / 回购里还能取回的算不算已遗失」：现状一律算「仍拥有」（局内地上、托付都在扫描范围），局结束时地上的会消失、自然释放。

## 六 合成发现、图鉴与 UI 现状

逐条证据见 [discovery_ui.md](research/evidence/2026-11-11-weapon-fusion/discovery_ui.md) §3～§6。

2. **配方知识**：不存在任何按 recipe_id 的记录（局内、存档、全局都没有）。
3. **铁匠配方许可**：只看铁匠铺级数（`facility_level smithy`）与 `tech / tech_level`；和图鉴不共用字段；配方没有 `requires_unlock`。

## 十 决策问题

**事实**

1. **现在有多少武器、多少真正可用的配方、覆盖哪些家族？** 武器 120 把（不含 312 件赐福异体）。产武器的配方 111 张，其中真正可用（输入可得、入口可达）111 张：拼接 14、升级 82、铁匠打造 14、拖合 1。覆盖 18 个家族，五大近战类、弓弩、法杖都有。没有任何关系的 18 把里，16 把是红武本体与劣化版。
2. **取消铸造升级，什么会立刻失去用途或来源？** 来源断：18 把 `forged_only` 金档。用途断：12 个材料谓词（骨 / 金属 / 木 / 石各档，三族魔晶石≥紫）。另外 73 把只参与升级的武器会失去「升上去」这层用途，但本身仍可从随机池拿到。任务线：没有任何任务依赖升级（寂灭、破晓都和升级无关）。
3. **哪些武器已具备双渠道条件？** 82 张升级配方本来就是「局内砧 + 局外铁匠铺」两个入口；`longbow`、`shortbow`、`bloodletter` 另有铁匠打造或拼接的第二条路。**局内限定**目前只有 14 张拼接（铁匠铺不能拼）。

**建议**（与事实分开，只供后续方案参考）

4. **适合保留为少量特色合成的组合**：14 张拼接都是「两件具体白档 → 一件有身份的绿档」（匕首 + 匕首 = 双刀、木棍 + 匕首 = 短矛、手斧 + 磨刀石 = 战斧），组合本身好记、有画面感。升级链里双前驱的 15 组（骨 + 金属两条路会合到同一把）只是数值阶梯，材料只决定走哪条路。元素纹金档是「紫档 + 三颗同族魔晶石」，身份来自元素，可以考虑作为局内限定的少量高阶合成候选。
5. **发现规则最少要改的模块**：存档里加配方发现记录（`MetaState` + `meta_save`）；写入点 `CraftingModule`、`GameFlow.anvil_strike`、`Smithy.forge`；遮挡点 `ItemTooltip.fusions_line / upgrades_line`、配方子窗、`UpgradeCompare`、铜徽提示。**唯一规则**最少要改：`JimiePath.sacrifice_ready`（漏洞），以及作者定「能不能卖」后的 `item_actions`、`meta_state.sell_item`、`shop_session` 三处；破晓信物的旗标时机在 `npc_chatter.gd`。

**必须由作者决定**

- 保留哪些拼接、哪些升级改为拼接、哪些武器直接获取；元素纹金档以后从哪里来。
- 红武能不能出售（现状不能；用户规则写「出售后可再得」）；地上 / 托付里的红武算不算已遗失。
- 配方知识与图鉴的跨局范围、成品已知与配方已发现是否分开、旧档如何继承。
- 局内砧不看铁匠铺级数是不是有意（决定金档能否第一局就锤出）。
- 破晓信物丢失后能否重拿；冰 / 毒之核的来源是否补（决定寂灭能不能走通）。
- 锁定件能否被拼掉。

**可按现有规则直接实施**（不需要新决定）：`sacrifice_ready` 的唯一性漏洞（作者已定「同名一件」）；拼接后点亮图鉴与砧一致（属于既有的「拿到就点亮」口径，需作者确认一句即可）；补测试覆盖 §八列出的缺口。
