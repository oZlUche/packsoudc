# 289 耐力那张签的悬浮窗列出消耗与回复的来源（084 补充）

> 作者 2026-11-07 15:04（游戏反馈小修线程，经协调转来）：「增加一个设计，在耐力说明的悬浮窗里列出耐力消耗的来源」。直接指派：待定按推荐派执行。

## 〇 一句话

状态条（`StatsStrip`）耐力那张签的悬浮窗，现在只有评级和两个总数；下面加两段：**消耗来源**（每件会出手的道具一行：名字 + 每秒平均消耗，大到小排）、**回复来源**（基线一行 + 每件带「每秒回耐力」的道具一行）。数字和总数同一套算法（`StaminaEstimate.of`），只是拆开写；不加解释句。

## 一、现状（读码）

- `StaminaEstimate.of(spec)`（`core/battle/stamina_estimate.gd`）：遍历 `spec.active_items()` 的每条有 `cadence` 的规则，`estimated_hz × _stamina_of(rule)` 累加成每秒消耗；回复 = `CombatantRuntime.from_spec` 的 `regen_stamina`（基线 + 道具并起来，口粮在这里才算进去）；比值分 低 / 中 / 高 / 极高。装着魔晶石的法杖（`free_when_loaded`）跳过；触发型规则不算。
- `describe(spec)` 套 `stat.stamina_tip`：「耐力消耗：%s / 每秒平均消耗 %.1f　每秒回复 %.1f　耐力上限 %.0f」—— 只有总数，看不出谁在花。
- 签在哪：`ui/widgets/stats_strip.gd` 135–140 把 `describe` 的字当 `tip`，背包窗、战前屏、容器屏、开局屏（`inventory_panel`）、战斗侧板都用同一张签，所以改一处全有。
- 道具自己的悬浮窗已经写「耗耐力 N」（`tip.costs_stamina`），但没有频率，玩家心算不出每秒多少。

## 二、做法

### 2.1 拆账：`StaminaEstimate.breakdown(spec)`（core，纯函数）

返回 `{"costs": [{uid, def_id, per_sec}], "regen": [{label, value}], "cost", "regen_total", "ratio", "rating"}`：

- `costs`：按**道具**合并（一件多条规则加在一起），`per_sec` = Σ `hz × _stamina_of`；0 的不列（装着魔晶石的法杖、开战先出手不耗耐力的那几下、没有消耗的规则）；按 `per_sec` 大到小排，一样大按棋盘顺序。
- `regen`：第一行 **基线**（角色 + 局外加成并起来的那份：`from_spec` 的 `regen_stamina` 减去各道具的贡献）；之后每件 `stats` 里 `regen_stamina > 0` 的道具一行（口粮、野战口粮…），按值大到小。超重（`超重` 词条：耐力回复 −25%）已经折在基线里，不另列（待定 2）。
- `of()` 改成调 `breakdown` 取总数，保证两边一个数。

### 2.2 悬浮窗（`describe`）

```
耐力消耗：高
每秒平均消耗 3.2　每秒回复 2.0　耐力上限 60
消耗来源
长剑　1.6 / 秒
短弓　1.2 / 秒
匕首　0.4 / 秒
回复来源
基线　1.0 / 秒
口粮　+1.0 / 秒
```

- 两段标题小字 `@dim`；行文只有名字和数字，不写公式、不写「每下 × 频率」（道具悬浮窗里已有「耗耐力 N」，奥卡姆）。
- 没有消耗来源 → 消耗段只一行「没有消耗」；回复段至少有基线那一行。
- 行数封顶 8 行消耗 + 4 行回复，超出合成一行「其余 %d 件　%.1f / 秒」（待定 3）。
- 道具名 = `ItemDef.display_name`（同名多件就重复出现几行，不合并同名；品质不写）。
- 用 `[url=item:<uid>]`？不要：这张悬浮窗是数字账，不开子窗。

### 2.3 战斗侧板

- 战斗中那张签（`combatant_panel`）同一份字；战斗里耐力实时变化但估算仍是战前编译结果，和现在一样，不加「实时」账。

## 三、改动清单（执行）

1. `StaminaEstimate.breakdown(spec)`；`of()` 走它；`describe()` 加两段。
2. `UiText` 新键：「消耗来源」「回复来源」「基线」「没有消耗」「%s　%.1f / 秒」「%s　+%.1f / 秒」「其余 %d 件　%.1f / 秒」；`stat.stamina_tip` 不动（头两行照旧）。
3. 测试：拆账之和 = 总数（消耗、回复各自）；装着魔晶石的法杖不列；一件多条规则合一行；排序；口粮出现在回复段、基线 = 总回复 − 口粮；没有消耗时写「没有消耗」；封顶合并行。
