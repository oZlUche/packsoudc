## 1. 现状

- `MapView._draw()`（`ui/map/map_view.gd:526`）先在**屏幕坐标**把这一章的底图 `assets/maps/<skin>.png`（1920 × 1200）按 `MapSkin.cover_region` 铺满整个视图、裁边；然后 `draw_set_transform(pan, 0, zoom)` 在**画布坐标**画环、边、节点、棋子。滚轮缩放、中键拖动只动后者，底图纹丝不动 —— 于是放大看局部时路网在动、山河不动，像在玻璃上滑一张透明片。
- 画布大小由布局定（同心环 `2 × (环数 × 110 + 边距)`，四环约 1000 px 见方、六环约 1500），**不随视口**；底图上美术留的「中间淡一档的椭圆」只是在屏幕上大致罩住路网，和画布没有固定对应。
- 装饰层 `<skin>_deco.png`（180 §4）同一种铺法，也在屏幕坐标。入局转场（180 §4.2）把第三页预览的圈和局内的环对齐：预览里底图也是按整页 cover 铺的，所以纸「不跳」。
- 缩放范围 `ZOOM_MIN 0.3`、`ZOOM_MAX 2.5`，开局缩放按点距自动（`start_zoom`，至多 1.5），F 看全图，1 回原比例。

## 2. 目标

底图是**画布的一部分**：放大，山河树石和路一起变大；拖动，一起走；路永远踩在同一块地形上。这也让「地图中间要有内容（丘陵、小径、树丛、河、石、废墟）」这条早先的要求有了意义 —— 内容和路有固定的相对位置，放大才看得清它们。

## 3. 三个做法

### 甲 · 底图钉在画布上（推荐）

底图在画布坐标里画：先算一次「图 → 画布」的缩放与偏移，之后和路网走同一个 `draw_set_transform`。

- **怎么对齐**：每张底图的 json 加 `safe_area: [x, y, w, h]`（美术留的淡色椭圆的外接矩形，图像素）。进图时取 `s = max(画布宽 / w, 画布高 / h)`，底图整张放大 s 倍、把 `safe_area` 的中心对到画布中心 —— 路网一定落在淡色区里，图的其余部分向四周延出画布外。四环图 s ≈ 1.1，六环图 s ≈ 1.7（图会被放大，见「清晰度」）。
- **画布外是什么**：底图延出去之后再往外，是「桌面」——一张平铺的木桌 / 布面纹理（或先用一块纯色 `UiPalette.bg()`），地图纸像摊在桌上。看全图（F）时能看到纸的四边与桌面；放大时桌面不出现。纸边可以让美术加一圈卷边 / 阴影（九宫格 `map_paper_edge`），不加也能用。
- **缩放范围**：`ZOOM_MIN` 改成「纸刚好装进安全区」（不再更小），`ZOOM_MAX` 不动（2.5）。
- **清晰度**：现在屏幕上底图约是 1:1；钉到画布后，六环图在 zoom 1 已经放大 1.7 倍，zoom 2.5 时 4 倍，会糊。两条路：① 美术按 3840 × 2400 重出四张（`art/maps/gen.py` 是程序生成的，重出成本低），仓库里放 @2x、`MapSkin` 按 2 倍逻辑尺寸读（`player_pawn` 已有 @2x 先例）；② 先不换图，把 `ZOOM_MAX` 临时压到 1.5。推荐 ①。
- **开局与转场**：`start_zoom` / `frame_spawns` / `focus` 全在画布坐标，不用改。入局转场里纸的「洞」是屏幕空间的遮罩，不用改；但第三页预览 `MapPreview` 里的底图也要换成同一套「图 → 圈」的对应（预览的圈距 ÷ 110 就是那一刻的 zoom），否则落地一瞬间底图会跳一下。
- **拖动边界**：加一条软限制 —— 纸的任何一边不能拖进安全区中心线以内（不许把纸整个拖没了只剩桌面）。
- **地图编辑器**：同一个 `MapView`，自动跟着；编辑器里 `show_backdrop` 的环线照旧。
- **字色深浅**：仍按 json 的 `tone`，不变。
- **代价**：`MapSkin` 多一个 `canvas_transform(canvas_rect)`，`MapView._draw` 底图两行搬进变换之后，`MapPreview` 同步，json 四个 `safe_area`，美术重出 @2x + 一张桌面纹理。改动都在画法层，不碰图的生成和玩法。

### 乙 · 半随动（视差）

底图跟着动，但只动一部分（比如缩放取 `zoom^0.5`、平移取一半）：有「底图在更远处」的纵深感，大图不会糊得那么快。

- 好处：不用重出图，缩放范围不用动。
- 坏处：路和地形没有固定对应（放大时路会「滑过」山河），正是作者不要的「两者独立」的温和版；预览转场的对齐也更难算。**不推荐**，列出只为对照。

### 丙 · 底图就是画布（手绘地图 + 手摆节点）

反过来：以图为准，画布 = 图的像素尺寸，节点位置按图上的地形手摆（或者生成后吸附到图上预留的锚点），路沿着图里画好的小径走。这是「真正的手绘关卡地图」，最好看，但和现在「按种子生成、同心环布局」的管线冲突：每张图要配一份节点锚点表，规模（环数）不同要配不同的图或裁切。

- 适合将来做「固定章节地图」（序章）时用；自由模式的随机图仍走甲。
- 可以把甲当作丙的第一步：甲先把图钉到画布上，丙只是再把「布局算位置」换成「图上读位置」。

## 4. 推荐

**甲**，连带两件美术活：四张底图重出 3840 × 2400（同时在 json 里标 `safe_area`），加一张平铺的桌面纹理（深色、低对比；也可先用纯色顶上）。丙留作序章固定地图的方向。
