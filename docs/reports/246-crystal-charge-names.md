# 246 魔晶石按剩余次数起名：破碎 → 完美十级，一个形容词

作者 2026-10-24 09:19（架构设计线）：「魔晶石的命名规则应当按照使用次数来，从次数低到高（0开始）分别为：破碎的/熄灭的/黯淡的/闪烁的/微光的/显眼的/明亮的/光耀的/夺目的/完美的，不过我也在考虑是否让每档对应的次数多一点，破碎的依旧为0，熄灭的为1~3，黯淡的4~6以此类推，至于其他语言由你翻译，重点是只要一个形容词」；09:19「注意魔晶石的使用次数和本身品质不挂钩」。

## 〇 一句话

机制已经有（148 的耐久前缀：`WearProfile.prefixes` 按剩余次数取词，208 的按次数换图），只是现在只有三档、满四次。改成**作者的十级词表**，满次数跟着词表定；五种魔晶石**同一张耐久表**，稀有度、供给强度各自算，次数一律相同。两套档宽给作者选（§二），默认按推荐落地。

## 一 词表（只带一个形容词，直接拼在名字前）

| 级 | 中 | 英 |
|---|---|---|
| 0（破碎，归零） | 破碎的 | Shattered |
| 1 | 熄灭的 | Extinguished |
| 2 | 黯淡的 | Dim |
| 3 | 闪烁的 | Flickering |
| 4 | 微光的 | Glimmering |
| 5 | 显眼的 | Vivid |
| 6 | 明亮的 | Bright |
| 7 | 光耀的 | Radiant |
| 8 | 夺目的 | Dazzling |
| 9（满） | 完美的 | Flawless |

例：「完美的火焰魔晶石」/ Flawless Fire Crystal；用了三场后「明亮的火焰魔晶石」/ Bright Fire Crystal。归零照 208：换成碎晶，「破碎的」只在没有 `broken_into` 的耐久件上出现。英文前缀自带空格（现有约定）。

## 二 每档几次（作者定，默认甲）

| | 甲 一档一次（推荐） | 乙 一档三次（作者在考虑的） |
|---|---|---|
| 满次数 | 9 | 27 |
| 名字多久变一次 | 每场 | 三场 |
| 一块新晶石能撑 | 一局半（一局约六场） | 三到四局 |
| 感受 | 每场打完都看得见它在暗下去，耐久是取舍 | 一局里几乎不变，耐久形同没有；跨局才见衰减 |

推荐甲：魔晶石刚改成一百五十面值的贵重品，耐久是它和「永久件」的区别，一局里看不见变化就白做了。要乙的话只是 `max_charges` 27 + `charge_band` 3，一行数据的事。

## 三 改法

- `WearProfile` 加 `charge_band: int = 1`：前缀下标 = 0（归零）或 `(剩余 − 1) ÷ charge_band + 1`，上限词表长度。甲时等于现在的算法。
- 五种魔晶石（火焰 / 冰霜 / 闪电 / 清明 / 琥珀）的 `wear`：`max_charges` 9、`prefixes` 九个（熄灭 → 完美）、`prefixes_by_lang.en` 九个、`broken_prefix` 破碎的、`broken_into` 照旧碎晶。**同一张表**，和稀有度无关（作者 09:19）；写成一份共用的耐久定义被五件引用，免得改五处——内容管线有没有「引用一份 wear」的形式由执行线看，没有就五份一样的 json，`check_content` 顶着。
- 图：208 的 `@c<剩余>` 变体现在每件四张（c0～c3）。不要补到十张：`ItemPainter.variant_of` 改成按**图的张数**折算（`WearProfile.art_levels`，默认 = 现有变体数 4）：变体号 = 四舍五入(剩余 ÷ 满 × (张数 − 1))。满 9 → c3，6～7 → c2，3～4 → c1，1～2 → c0 的暗图；归零换碎晶。以后美术要补更多亮度就加张数。
- 文本：前缀进字集检查（168）——「熄」「黯」「耀」「夺」要确认在子集里，不在就补子集（这次顺手做，别再出「澄」那样的替换）。
- 百科 / 悬浮窗：名字走 `Names.of_item`，自动带前缀，不用改。

## 四 不做

- 不按品质给不同次数（作者明说不挂钩）。
- 不改供给强度、面值、稀有度（244 刚定）。
- 不改扣次规则（每场点亮过的 −1，148）。

## 五 测试

`prefix_for` 对 0 / 1 / 5 / 9 的中英；`charge_band` 3 时 1～3 同词、4 换词；五件 `max_charges` 相同；变体号折算 9→c3、1→c0；字集覆盖新字。

## 六 补充一（作者 09:20）：魔晶石分三品；果果之心 = 永不消耗的中品魔晶石

作者原话：「1. 增加三种品质的魔晶石，不仅有威力和叠层的差距，也要有特殊效果，具体想不出来可以占位。2. 让果果之心这种顶级的宝石也设定为魔晶石，威力和中等品质相同，但是永不消耗」

### 6.1 三品（三种元素各三件，九件；清明 / 琥珀仍是单一的中品通用供给）

品质进**名词**，不占形容词的位置（作者 09:19「只要一个形容词」）：

| 品 | 名（火 / 冰 / 雷） | 英 | 稀有度 | 面值 | 供给（法杖伤害） | 叠层（每击） | 特效（占位） |
|---|---|---|---|---|---|---|---|
| 下品 | 火焰晶石 / 冰霜晶石 / 闪电晶石 | Lesser Fire / Frost / Lightning Crystal | 1 优良 | 70 | +6 | 一层 | 无 |
| 中品（现有，id 不变） | 火焰魔晶石 / 冰霜魔晶石 / 闪电魔晶石 | Fire / Frost / Lightning Crystal | 2 稀有 | 150 | +9 | 一层 | 无（基准） |
| 上品 | 火焰魔晶核 / 冰霜魔晶核 / 闪电魔晶核 | Greater Fire / Frost / Lightning Crystal | 3 史诗 | 320 | +13 | 两层 | **开场先施**：开战时给对手两层本元素状态（`on_battle_start` 一条 feed_rule）；元素名各起一个词：余焰 / 凝霜 / 先声 |

- id：`fire_crystal_low` / `fire_crystal`（中）/ `fire_crystal_high`，冰雷同。
- 三品的 `wear` **完全相同**（满九次、同一张词表，作者 09:19「使用次数和本身品质不挂钩」）。
- 特效是占位：下品留空，等作者想到再填；上品那条是「有特效」的最小实现，用现有效果类型就能做。
- 分布：不加新池，靠现有稀有度上限自然分层——外环档位只放得下优良（下品），内环才出史诗（上品）；商店按稀有度权重照抽。
- 一行描述模板共用，`{amount}` / `{max_charges}` 占位符照旧；上品多一句特效。

### 6.2 果果之心

- 加标签 `magic` / `crystal` / `valuable`，保留 `gem` / `treasure`；稀有度 5、面值十万不动。按 2026-10-03 规则它现在是【魔法】。
- `adjacency`：`feed_mods` +9（= 中品）、无元素转换、无叠层、`feed_filter` 法杖——和清明魔晶石一样的通用供给。
- **没有 `wear`**：永不消耗，名字永远没有前缀，不换图。
- 描述加一句：「放进法杖，永不耗尽。」

### 6.3 美术

六张新基础图（下品三件：同元素更暗、更粗的原石；上品三件：切面、带芒）。按次数的亮度变体先不画——§三 的按张数折算在没有变体图时直接用基础图。果果之心沿用现图。
