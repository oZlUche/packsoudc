# 046 · 三个问题的解释与设想：路线为什么「没有空间」、搜索路线在中途撤离点结束、高危区只从非搜索路线岔出

> 阶段 4 · M3 ｜ 状态：**设想，未采纳** ｜ 起因：作者对报告 045 的追问

## 一、路线为什么「没有空间」—— 不是点不够，是高危区抢走了下一步

### 作者的疑问

7 环图 3 条路线、平均不到 11 步，路线一共占 33 个点；配额 58～66 个点，几乎两倍 —— 怎么会「没有落点」？是不是节点生成顺序错了？

### 量出来的答案

给生成器套一层，在每一次「路线走到第 N 环没有落点」发生的当场记下现场（60 个种子一档）：

| | 6 环 | 7 环 |
|---|---|---|
| 一张图的点数 / 路线占的点数 | 47.8 / 25.9 | 61.9 / 30.8 |
| 没有落点的现场：几何上就没有向内的邻居 | 0 | 0 |
| 没有落点的现场：**向内的邻居都被高危区占了** | **38（100%）** | **71（100%）** |
| 发生在第几环 | 第 3 环 24、第 2 环 14 | 第 4 环 33、第 3 环 22、第 2 环 16 |
| 横着挪被谁截住 | 别的路线 / 换乘弧 59、高危区 17 | 别的路线 / 换乘弧 110、高危区 32 |
| 占走落点的那片区从哪来 | 别处 35、**这条路线自己的头上刚岔出来的 25** | 别处 52、**自己头上 57** |

所以：

1. **顺序没错，点也够。** 没有一次是「几何上够不着」；成图之后没有向内边的点每张图只有 2.6 个。
2. **缺的不是节点数，是那一步能走的那两三个点。** 一条路线每一步只能落到下一环里**正对着 ± 1 个槽位**的点上
   （`route_drift = 1`、`edge_max_slot_offset = 1`），内环一个槽位很宽，正对着的往往只有 1～2 个点。
   六成填充的图上「点很多」，但对某一个头来说，可选的落点从来只有一两个。
3. **占走那一两个点的是高危区。** 节拍是：所有路线在第 r 环落子 → 每片在长的高危区各长一个点 → 过了半程的路线头上按概率岔出新的高危区。
   高危区长的时候只避开**已经是路线的点**（受保护），不避开**路线下一步要落的点**；
   岔出新区时更直接 —— `first` 是从岔出点的「空间邻居」里挑的，而岔出点向内的邻居**正是这条路线下一步的落点**。
   一半的失败就是这条路线自己刚岔出的区吃掉了自己的下一步。
4. 落点没了本来可以横着挪，但挪的时候撞上的是别的路线（合流之前互不相撞）、换乘弧、或另一片高危区。
   内环槽位少（6～12 个）、三条路线、加上高危区，第 2～4 环就是挤的。

这就是路线与高危区「实时抢地方」设计的代价（报告 036）。它让高危区真的长在路线旁边，但也让它有一半概率堵在自己的路线前面。

### 设想：高危区长的时候避开路线的下一步

不改节拍，只改「哪些点算空」：

- 每条还在走的路线，算出它的头向内一环够得着的落点（`_inward_candidates`），把这些点标成**预留**。
- `_zone_free` 除了受保护的点，也不给预留的点 —— 除非这条路线的落点不止一个，那可以占走多余的、只留一个。
- 岔出新区挑 `first` 时同样避开。

代价：`_zone_free` 多一个字典查询；高危区能长的地方少了一点（每条路线每环少一两个点），
`zone_missing` 可能略升 —— 但它现在只占重试的一小部分（6 环 3 / 60）。收益：把重试的主因（build 失败的 28/37、57/63）拿掉。
放宽 `route_drift` 也能缓解，但那是改路线的形状，不是改冲突。

## 二、搜索路线在中途撤离点结束，不走到核心前一环（大改动，先估成本）

### 现在

偏搜索路线 `ends_at = "extract"`：和别的路线一样一环一环走到**核心前一环**（作者数法的第 0 环）停下，
末端那个点独自定为撤离点。它和中途撤离点是两套东西：中途撤离点在撤离环间、两条路线共用；
收尾撤离点在第 0 环、只属于这条路线（点本身不专属，别的边照连，但它不在撤离环间，校验里是个例外）。

### 设想

搜索路线走到**撤离环间**就结束，末端就是那里的一个中途撤离点 —— 和相邻路线共用的那个。
一张图上只剩一种撤离点，全在撤离环间；「核心前一环例外」这条校验可以删掉；
偏搜索的玩法变成「走半程、搜一路、从中间撤」，而不是「走到核心门口再撤」。

### 要改什么

| 处 | 改动 | 量 |
|---|---|---|
| `RingMapGenerator._lay_skeleton` | 去撤离点的路线停在撤离环间（偶数环取外侧那环还是内侧那环，或随机）而不是第 1 环；`_route_ends` 跟着 | 小 |
| `RingTypeAssigner._fix_route_ends` / `_place_extracts` | 合并：搜索路线的末端必须是撤离点，且优先与相邻路线共用（末端本身就是合流点 / 换乘点时直接用它；不是的话在末端与相邻路线之间的换乘弧上挑，或把末端定为撤离点再保证间距）。间距规则要能容下「每条搜索路线一个末端」 | 中 |
| 校验 `extract_band` | 删掉「第 1 环例外」；变成「撤离点只在撤离环间」 | 小 |
| `RouteStyle` | `ends_at` 的含义从「核心 / 核心前一环」变成「核心 / 撤离环间」；文档 5.4.2 | 小 |
| 换乘安排 `_schedule_pivots` | 换乘环是均分的（6 环 1 次 → 第 3 环，正好在环间）；搜索路线停在环间之后，它和邻居的换乘只能安排在环间或更外 —— 要把换乘环夹到 ≥ 环间 | 小 |
| 路线校准 `_calibrate_routes` | 搜索路线只有一半长，风险收益总和天然只有别人的一半；`risk_band` 现在是 0.15～0.6，大概仍落得进，但 mix、min_share 的分母只剩 3～4 个点，「八成是搜索点」在 3 个点上就是 3 个全是 | 数值 |
| 喘气处 `_place_route_havens` | 搜索路线只有 3～4 个可放的点，1/3 与 2/3 就是第 1 和第 2 个点；小型图（4 环）搜索路线只剩 1～2 步，放不下 | 数值 / 小 |
| 高危区 | 岔出的时机是路线过半程；搜索路线在半程就停了 → 它身上几乎不会再岔出高危区 —— 第三条自然成立 | 0 |
| 测试 | 路线尽头在第 1 环那几条、末端是撤离点那几条、撤离环间例外那条，加「搜索路线末端 = 共用撤离点」 | 中 |

**主要成本不在代码，在数值：** 6 环图搜索路线从 8 步变成 4～5 步，4 环图变成 2～3 步。
「偏搜索」这条路线会短到没什么内容可搜 —— 除非给它更大的 `route_length_factor`（横着走补长），
或者让它在撤离环间**横着走完一整段弧**再在撤离点结束（环间加了 3 个槽位，正好有地方走）。
这样路线长度不变、只是形状从「直插核心」变成「走到中间横着搜」—— 我倾向这个方案，它把「搜索路线」画出来就和别的路线不一样。

要不要做，取决于两点：偏搜索路线该不该有走到核心门口的选项（现在换乘点还在，想打 BOSS 换乘就行，改了之后一样）；
以及搜索路线的内容量（横着走那一段能不能补上）。代码量中等，一天之内；数值要跑几轮看。

## 三、高危区只从非搜索路线岔出

### 现在

`_spawn_zone` 在所有还在走的路线里挑岔出点（每条路线至多 `zones_per_route` 片）；哪条路线都可能。

### 设想

`RouteStyle` 加一个字段 `spawns_zones: bool`（默认 true，搜索风格 false）；`_spawn_zone` 跳过 false 的路线。
把「谁能岔出高危区」放进数据，而不是在生成器里认 `ends_at == "extract"`。

### 代价与影响

- 代码：几行。
- 小型图 2 条路线（combat、search）→ 只有 combat 能岔，`zones_per_route = 1` → 至多 1 片，小型要求正好 1 片，刚好。
  但只有一个候选头，「周围空间充足」那一条不满足时就岔不出来 —— `zone_missing` 会升。
- 中型 3 条路线（combat、search、mixed）→ 2 条能岔，至多 2 片；模板允许 1～3 片，第 3 片永远长不出来（记进 `zones_skipped`，不算失败）；
  4 个出生点时风格轮到 combat、search、mixed、combat → 3 条能岔。
- 第一条的问题（高危区堵自己的路）在 combat / mixed 路线上照旧，这一条不解决它。
- 如果第二条做了，搜索路线在半程就停，本来就岔不出高危区 —— 这一条就成了「把已经成立的事写进数据」，仍然值得写，
  不然将来某个风格的路线走得深了又会岔。

## 建议的顺序

1. 第一条的「预留下一步」先做：小改动，直接砍掉重试的主因，和另外两条互不冲突。
2. 第三条随手做：几行，数据里多一个开关。
3. 第二条等作者定方向（直插核心 vs 走到中间横着搜）再动，数值要跑。
