# 方案：敌人棋盘只写死「相邻组合」，其余道具按整理的办法随机摆（165）

> 作者原话（2026-10-13，架构设计）：「关于敌人的配置道具，我认为除了特定的组合（相邻有关）外，其余的道具位置不需要写死，用类似"整理"的逻辑将它们随机置入，相邻增益道具除外，因为它们需要紧挨着彼此」
> 性质：架构 · 实施。待定按推荐。关联 084（敌人也背包）、087（招牌 / 身份标签）、108（附加效果）、109（整理）、143（异形）、159 / 162、小修「摆不下自动找位」。

## 1. 现状

- **随机图的敌人**（`EnemyPlacer.build_content`）：位置本来就不是写死的 —— 挑好道具后按「包先摆、招牌 → 流派 → 通用、大件先」逐件 `try_add`（第一个放得下的格子，`find_first_fit`），结果的 `at / rot` 记进节点内容；之后战前、战斗、尸体容器、掉落都按这份内容重建（`EnemyKit.board_of`）。**完全不看相邻**：箭挨不挨着弓是碰运气，神射手的长弓 + 箭常常一上一下错开。
- **预设图的敌人**（序章一 ～ 三，`data/maps/tutorial*.json`）：每件的 `at` 手写在 JSON 里 —— 药师的短剑就是这么出的事（143 改形状、挪位置，旧档里的旧位置放不下被悄悄跳过）。现在六个手摆的敌人里没有一对真正的相邻组合（三把匕首、一把锤、符 + 匕首、解毒包 + 短剑），手写的位置没有一处是必要的。
- 相邻关系在道具定义里（`AdjacencyProfile`：`grant_cells / grant_filter`，受益 `receive_cells / receive_filter`），十二件有：箭 / 锯齿箭 / 毒箭（给上方的远程武器）、弹匣、三种魔晶石、法杖、护甲板、软甲（给上方的装备加护甲）、毒手套、蛮神护符。敌人定义（`EnemyDef`）只有招牌（`signature / signature_by_strength`），没有「组合」的概念。
- 「整理」（`GridTidy`，109）是仓库的：全部取下 → 同类 → 大件先 → `find_first_fit` 放回左上。确定性，不随机。

## 2. 改法

### 2.1 内容格式：位置可省，组合另写

节点内容 `items` 里每件的 `at / rot` 改成**可选**：写了就是手摆（只给真要钉死的用），没写就由 2.2 摆。新增可选字段 `groups`：

```json
"items": [{"id": "bag_leather"}, {"id": "longbow"}, {"id": "arrows"}, {"id": "salve"}],
"groups": [[{"id": "longbow", "at": [0, 0]}, {"id": "arrows", "at": [0, 2]}]]
```

- 一个组 = 几件 + 组内相对位置（第一件为锚点，`at` 是相对锚点的格），整组当一块刚体找位置：组里每件都在包里、互不重叠、相对位置分毫不差。组内的 `rot` 也可写（默认 0）。
- 不在任何组里的件是「散件」。预设图的六个敌人全部改成散件（删掉 `at`），`board` 保留。
- 读入后 **摆一次、记下来**：`EnemyPlacer.arrange(content, items, rng)` 把每件的 `at / rot` 写回内容（组内的按组的落点展开）。这一步在内容**诞生**时做 —— 随机图在 `fill / place_one` 的 `build_content` 末尾、预设图在 `MapPreset.load_graph` 之后对每个带敌人的点做一次（随机数用节点的 `content_seed`，同一张图同一个点永远一样）。之后的管线（存档、`board_of`、战前、战斗、尸体、掉落）**一个字不改**，因为它们拿到的内容仍然带 `at`。
- 旧档 / 旧内容（已有 `at`）原样用；放不下的件按小修那条「自动找位 + 警告」兜底。

### 2.2 摆法：包 → 组 → 散件随机

`EnemyPlacer.arrange(content, items, rng)`：

1. **包**：照旧，先摆（`try_add`，有包时棋盘 `requires_bag`）。
2. **组**：按组占格从大到小。对每个组枚举所有锚点位置（与整组 0 / 90 / 180 / 270 四个朝向，待定 2），筛出整组都放得进、都在包里、不压别的件的位置，**随机挑一个**。一个也没有 → 这个组拆成散件继续（回报里记 `ungrouped`，和现在 `short` 一样能看见）。
3. **散件**：按占格从大到小（大件先，和整理一样 —— 小件去填缝），每件枚举所有放得下的 `(origin, rot)`，**随机挑一个**。放不下 → 跳过（现有「差件」逻辑，补件照旧）。
4. **重试**：随机摆比贴左上更容易把包切碎；散件有放不下的就整个重来（最多 `ARRANGE_TRIES = 4` 次，每次随机数接着用），仍不行最后一次用「整理」那种 `find_first_fit` 贴左上的确定性摆法保底 —— 件数不会比现在少。

### 2.3 随机图的敌人：组合自动成形

随机敌人没人手写 `groups`，组合从道具定义里**推**出来（`EnemyPlacer.auto_groups(picks, items)`，在 `choose_items` 之后、`arrange` 之前）：

- 挑出的道具里有带 `grant_cells` 的（箭、护甲板、魔晶石……），就在同一批里找一件符合 `grant_filter` 的受益者（箭 → 任一 `ranged`；软甲 → 任一 `gear`），配成一组：相对位置 = 受益者的某一格正好落在施益者的 `grant_cells` 之一上（多格道具取第一个成立的摆法；几种都成立随机挑）。一个受益者可以收好几件施益者（长弓上面一把箭、右边一袋弹匣各占各的格），一件施益者只配一个受益者。
- `receive_cells` 的件（自己要邻居）同理反过来配。
- 没配上对象的施益者（抽到了箭却没有弓）当散件 —— 现有的保底武器 / 身份标签逻辑不变，这里只管摆，不管挑。要「抽到箭就一定有弓」是另一件事（待定 3）。
- `EnemyDef` 加可选 `combos: Array[Array[StringName]]`（身份固定的组合，如神射手 `[["longbow", "arrows"]]`）：这些件都在时一定成组且不被拆；没写就全靠自动推。

### 2.4 预设图数据

- `tutorial2.json / tutorial3.json` 六个敌人删掉所有 `at`（`board` 留着）。序章二的教学点要的是「对手是谁、带什么」，不是具体格子；四场克制关系靠的是道具与数值，不靠位置（`test_tutorial2` 的克制用例按真模拟验，不依赖位置）。
- 以后预设图加组合就写 `groups`；教程若要「让玩家看见箭挨着弓」，组本身就保证了。

### 2.5 测试

- `test_enemy_placer`：组整体落在包里且相对位置不变；散件随机但同一 `content_seed` 两次一样（可复现）、换种子位置不同；放不下重试、保底摆法件数 ≥ 现在；自动配对：长弓 + 箭成组、箭的 `grant_cells` 正压在弓的格上（编译后弓吃到加成 —— 用 `BattleCompiler.compile_board` 验）；抽到箭没有弓时箭是散件。
- `test_tutorial2 / test_prologue`：删掉 `at` 之后每个教学敌人仍全部摆上、`spec_of` 的生命 / DPS 不变（位置不影响无相邻的数值）。
- `test_enemy_pool` 的「过一趟 JSON 重建件数不变」不动（内容带 `at` 之后行为同今）。
