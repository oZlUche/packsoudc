### 2.1 观看时间线（§8.1）

| 新增 / 改动 | 做什么 |
|---|---|
| `core/run/calibration/viewing_session.gd`（`ViewingSession`） | 只记账，不认识界面。两条时间线分开：模拟时长（战斗本身）和实际观看时长（开始到结果揭晓的墙上时间，扣掉暂停、教程停住、窗口失焦，三样分开记）。还记倍速切换、拖时间轴、跳过时回放走到的模拟时刻、揭晓（只记第一次）、离开、揭晓后又待了多久、提示弹出到收起的停留时间（停留不等于读了）。没看到揭晓就走时实际观看时长是 null，不按模拟时长推算 |
| `ui/game/battle_screen.gd` | 诊断开着（`--diag-capture` 或 `PACKSDC_DIAG=1`，和诊断包同一个开关）才开一份：开屏、停 / 放、教程停住 / 放开、失焦 / 回焦、倍速、跳过、拖动、揭晓、教程与反应说明的弹出和收起；按「继续」或屏被换走时补上战后状态、盖来源，落到 `user://diagnostics/viewing/<时间>_<战斗标识>.viewing.json`，只留最近 200 份 |
| `ui/battle/battle_view.gd` | 加两个信号 `skipped`、`seeked(t)` 和 `playback_time()`，别的不动 |
| `core/run/node_events.gd`、`game_flow.gd` | 战斗标识 `battle_id_of(种子)`（局标识 : 种子，和诊断包同一个）；`state_brief()`：体力、钱、包里件数、步数；开打前记一份，跟着回放屏的载荷走 |
| `core/battle/battle_diagnostics.gd` | `write_viewing()`、`VIEWING`、`viewing_dir`（测试改目录用）；`list` / `prune` 按扩展名 |

### 2.2 战斗体验报告（§8.2）

```
godot --headless --path . --script res://tools/battle_experience_report.gd -- <包.diag.tres> [--viewing=<.viewing.json>] [--viewing-dir=…] [--seeds=40] [--no-factors] [--out=<报告.md>] [--json=<报告.json>]
```

读诊断包重跑；观看记录没给就按包里的战斗标识去目录里找。五节（`core/run/calibration/battle_experience.gd`，`BattleExperience`）：

| 节 | 内容 |
|---|---|
| 一 原因可见性 | 双方伤害主要来源（按道具 id，前三，带份额）；双方身上上过的状态；耐力见底的时刻；落败一方挨的伤害里装得下一半的最短时间窗，以及这个窗在屏上按当时倍速放了多久、有没有被跳过。明写「伤害多的不一定是取胜关键」，不给唯一原因 |
| 二 准备有效性 | 我方每件（最多 8 件）拿掉以后，同一批种子配对重打的胜率 / 余血 / 时长差，配对自助法区间（`core/run/calibration/battle_factor.gd`，`BattleFactor`）。差值叫这一场条件下的边际变化，几行不能相加。编译后拿掉做不到严格单因素（连结、相邻、套装加成编译时已算进别的件），每行列出连带变化；从棋盘重新编译的两份配装用 `BattleFactor.collateral()` 比，空 = 只改了声明的那几种 |
| 三 过程节奏 | 双方出手次数和出过手的件数、第一次打出伤害的时刻、双方血线（等距 11 个点）、实际观看时长、跳过、倍速 |
| 四 后果差异 | 单场战果（胜负、余血）和整局变化（战前 → 离开回放屏的体力、钱、件数、步数）分开写；屏上显示了哪些字段这一版不记，写「不知道」 |
| 五 未知项 | 没比对过 / 重跑对不上、没有观看记录、没看到揭晓、缺战前或战后状态、战后状态取在掉落还没捡的时候、屏上显示不记、没做配对、耐力停火原因量不到，逐条列出，不默认为正常 |

退出码：0 写出了；1 用法或读写错误；3 包读不出来。

### 2.3 人工验证场景（§8.3）

```
godot --headless --path . --script res://tools/make_feel_scenarios.gd -- [输出目录=user://diagnostics/feel] [--no-replays]
```

`core/run/calibration/feel_scenarios.gd`（`FeelScenarios`）：每个场景是「我方一张棋盘 × 池里一个真敌人 × 一个种子」，从候选里按顺序找第一个满足条件的，找不到写「没找到」，不放宽条件。换装后那一场固定敌人和种子，只把短剑换一件；战后得失那一场是正式开一局（`free_mode`，标准开局装备）打图上第一个有敌人的战斗点，得失为零的种子跳过。

输出：每场一份 `<代号>.diag.tres`、`scenarios.json`（说明和预期事实，来源 `synthetic`）、`questions.md`。不加 `--no-replays` 时每场再写一份回放存档进 `user://battle_logs`，章节名 `feel:S1`…，从启动选择器的「战斗回放」里看。代号 S1～S9 不带场景名，成对的两组（同一配装换对手、同一对手换一件）在顺序里错开。

本批生成的一份在 [balance/feel/2026-11-10/](balance/feel/2026-11-10/)：9 个包、`scenarios.json`、`questions.md`、`diagnostics/S1～S9.md`（§2.2 的报告，40 个种子）。仓库里这份是用 `--no-replays` 生成的；本地要看回放，在本地跑一次上面的命令（不带 `--no-replays`），结果一样。

40 个种子的配对对照（`diagnostics/S*.md` 第二节）里值得记的几条，都是这一场条件下的事实：

- **S2 被针对**：带着淬毒匕首 40 场赢 3 场，拿掉以后赢 24 场（差 −52 个百分点，区间 −70～−35）。对免疫毒与流血的机关，淬毒匕首不只是没用，带着反而输得多。
- **S8 换装后**：同一个敌人，短剑换成战斧，40 对配对胜率 +78 个百分点（+65～+90）；两份棋盘除了换的那两种以外没有别的变化（`collateral` 为空）。
- **S7 耐力见底**：四件都在时 40 场全输，我方 9.9 秒耐力见底；拿掉长剑以后赢 4 场（差 −10，区间 −20～−2）。
- **S9 战后得失**：标准开局装备打这一个 pit_viper（档 0），40 个种子只赢 1 场。

推测（没有单独验证）：S7 拿掉长剑反而好，可能是少一件出手的武器、剩下的耐力更够用。引擎没有「耐力不够、这一下没出手」的事件，报告只能给耐力见底的时刻，证实这一条要先补那个事件。S2 我方耐力没见底，「拿掉反而好」的原因不在耐力，这一批没有拆；编译后拿掉不重算相邻加成，要用重新编译的棋盘对照才分得清。S9 那场敌人是图上节点顺序里第一个战斗点，不一定是开局相邻的点，不能据此说开局太难。
