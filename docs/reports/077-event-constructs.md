# 077 · 8-3 事件构件：条件看一局的状态，后果能挪人、等时间、改点、拿东西；休息 / 商店点的默认事件

> 第 8 阶段 8-3 ｜ 架构文档 6.5 事件层、5.6、12（v1.74）｜ 前一步：[076 第 8 阶段规划与 8-1 传送点](076-phase8-plan-and-portals.md)

作者问「假如我想将传送功能做进事件，当前模式支持吗？」，答的是：差两小块（没有挪人的后果构件；旅程只认有边的传送），都在 8-3 的范围里。
作者说继续 8-3。这一步照 076 的切法交付：**条件与后果的构件按内容需要加**（步数 / 段位 / 侵蚀深度 / 有某道具 / 点是什么；传送 / 改节点类型 /
照常发生 / 原地耗时 / 失去道具），**商店与休息点的默认事件**，以及导入器对撞车组合的校验。加构件的规矩没变：一个子类、注册表一行，导入器 / 导出器 / 编辑器不认识具体类型。

## 一、条件（`EventCondition`，只读）

| 类型名 | 字段 | 说什么 |
|---|---|---|
| `steps_within` | `min_steps`、`max_steps`（-1 不封顶） | 到现在为止花的行动点在区间里 |
| `bracket_within` | `min_bracket`、`max_bracket` | 段位（074，只看步数）在区间里。**这一局没有猎手机制 = 没有段位，永远不满足** |
| `erosion_depth_within` | `min_depth`、`max_depth` | 这个点被侵蚀了几层（075：没被侵蚀 -1、刚被侵蚀 0）。min 0 = 只要被侵蚀；没有侵蚀 = 永远不满足 |
| `has_item` | `item`（空 = 任何道具）、`count`、`where`（棋盘 / 暂存区 / 两处） | 身上有某道具 |
| `node_type_is` | `types` | 这个点现在算的类型（随机点按揭开的算）在名单里 —— 同一个事件挂在几种点上时按点分支 |

条件看的东西都进了 `EventContext`：地图、步数、棋盘与暂存区、段位与侵蚀深度两个回调（持有方接；没接就是 -1）。

## 二、后果（`EventOutcome`）

| 类型名 | 字段 | 做什么 |
|---|---|---|
| `teleport` | `target`（最近 / 最远 / 随机 / 指定）、`node_types`（空 = 任何）、`min_steps`、`max_steps`、`unvisited_only`、`action_cost` | 挑一个目的地、立旗。指定 = 节点内容里 `teleport_target` 写的 id（生成器 / 编辑器往里写）。挑不到就不传、什么也不发生 |
| `change_node_type` | `node_type` | 这个点从此算另一种类型：写进内容的 `resolved_type`（和随机点揭开是同一个记号），同一个选项里后面的「照常发生」「开战」按新类型走；发 `type_changed`，地图重画 |
| `proceed` | — | 这个点照它的类型照常发生（休息回体力、商店开店、搜索开搜、战斗开打、撤离报到）—— 数值都还在 `NodeRules` |
| `pass_time` | `actions` | 原地耗掉几个行动点：计数走、侵蚀推进、脚下的点照结算、猎手得一个回合 |
| `lose_item` | `pick`（随机 / 最值钱 / 最不值钱 / 指定 id）、`item`、`count`、`where`、`include_bags` | 失去身上的道具（献祭、被偷、交钥匙）。挑法与侵蚀的「损坏一件」相同 |

## 三、传送怎么走的

**后果只挑目的地，挪人在 `NodeEvents.choose` 的最后。** 这个点的事都完了（照常发生、开战打完）才挪：造一个 `MoveIntent.teleport(这个点, 目的地, 后果说的代价)`，
交给持有方的 `relocate`（`RunState.relocate`：关会话、离开发生过事的点清暂存区、`travel.apply`、地图 buff 计时、猎手回合 —— 和走一步一样的壳，只是意图不同）；
没有持有方（裸测试）就直接给旅程。落地那个点头一回踩上就触发它的事（可能又排上一个事件屏），和走过去一样。打输了、开着会话就不挪。

**旅程放宽了一条校验。** `MapTravel._check` 原来对一切意图都要求「两点之间有那条边」；现在只对 `step` 要求，`teleport` 信任解析方（传送点边、事件的后果），
只查目的地存在、不是原地。顺序、计数、侵蚀、事件一处没改 —— 这就是 5.6 早留的那条缝。

**原地耗时是旅程的新入口。** `MapTravel.wait(actions, reason)`：计数 → 侵蚀推进 → 脚下的点结算，不挪人，发 `waited`。顺序和 `apply` 一样、出于同一个理由：
等到侵蚀推进的那一步，脚下的点得立刻结算。它在判战败之前跑（耗时可能把体力耗光）。

## 四、导入器多了几条校验

- 传送：代价不能是负的、步数区间不能反、节点类型名单里的名字得认得。
- 改类型：类型得认得、**不能改成结构性的类型**（出生 / 撤离 / 岔路 / 核心由拓扑定）。
- 失去指定道具 / 需要指定道具：道具得存在。耗时得是正数。类型名单不能空（永远不满足）。
- **同一个选项里传送和留在这里的事撞车**：传送 + 搜索 / 开店 / 接下一个事件 → 人走了会话就断了，报错；传送 + 给道具 → 离开发生过事的点暂存区会清空、给的东西立刻没了，报错。
  这条是规则一致的结果：暂存区在离开发生过事的点时清（060），传送也是离开。作者要「传送还带着东西」得改那条规则，不是在传送上开口子。

## 五、内容

| 文件 | 挂在 | 用了什么 |
|---|---|---|
| `rest_default.json` | 休息点 | 歇一会儿（`proceed`）/ 扎营（`pass_time` 2 + `proceed` + 体力 +1）/ 继续赶路（不歇、点用过） |
| `shop_default.json` | 商店点 | 进去看看（`open_shop`）/ 不进 |
| `event_rift.json` | 事件点 | 跳进去（随机传到 2～5 步外，花 1 点）/ 顺着风走到底（需要步数 ≥ 4：传到最远处，花 2 点、体力 -1）/ 绕开 |
| `event_altar.json` | 事件点 | 献上棋盘上最值钱的一件（需要棋盘上有东西：体力 +2）/ 用撬棍撬开（需要 crowbar：失去它、随机给一件）/ 砸了它（变成战斗点、开战）/ 离开 |

`node_rules/standard.json` 的 `events_by_type` 挂上了 `rest` 与 `shop`。**休息点从此也先过事件屏**：「歇一会儿」是照常发生，回多少还是 `rest_restore`。
数字都在 JSON 里（扎营耗几点、回几点、裂隙传多远），一个没写死。

## 六、界面

结果页多认四样：失去了什么、耗了几个行动点、这里变成了什么点、被传送到了哪。地图屏记一句「原地耗了几点」「点 x 变成了什么」并重画；传送本身走 8-1 的「⇢ 传送」那句。
事件编辑器不用改：条件 / 后果的下拉来自注册表，枚举字段（传送目标、挑法、范围）表单自己认。

## 八、没做的、留着的

- 结果页写的是「被传送到了点 N」—— 点还没有名字（第 8 阶段的内容）。
- `teleport` 的「指定」目标只认节点内容里的 id，还没有生成器 / 编辑器往里写它的入口；要用先手填。
- `proceed` 对 `event` 类型走的是老路的加权结果（`NodeRules.event_pick`），这条老路留着给没定义的章节。
- 商店 / 休息屏仍没有背包按钮（15 节第 7 项的尾巴）。
