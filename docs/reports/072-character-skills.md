# 072 · 角色技能接口：技能是一局规则的效果构件，猎手系统读上下文

> 069 第八节的第 3 步 ｜ 架构文档 8.1、8.5（v1.69）｜ 前一步：[071 猎手核心](071-hunters-core.md)

作者定的（069 第六节）：不同类型的角色可能拥有侦察、逃跑的技能，留一个接口。

## 产出

| 文件 | 职责 |
|---|---|
| `core/run/effects/scout_range.gd`、`stealth.gd`、`flee_bonus.gd` | 三个 `RunEffect` 构件：侦察（隐形猎手在几步内可见，取大）、潜行（猎手感知距离的倍率，相乘）、逃跑（成功率加成，相加）；登记在 `RUN_EFFECTS` |
| `core/run/character_def.gd` | `skills: Array[Effect]`（被动技能）、`run_effects()` / `loot_effects()` / `skills_summary()`；导入器：只能是掉落或一局规则的效果 |
| `core/run/run_state.gd` | `character`（定义，开局给、读档持有方找回）；`buff_context()` 与 `_loot_context()` 把角色技能编进去 |
| `core/run/game_flow.gd` | `_adopt` 找回角色定义（之前只找基线） |
| `ui/game/setup_screen.gd` | 角色说明里多一行「技能：……」 |
| `data/authoring/characters/scout.json` | 第二个占位角色「侦察兵」：侦察 2、潜行 ×0.75、逃跑 +20%，生命 50，一个皮革包一个小包 |
| `tests/test_character_skills.gd` | 2 组 |

## 几条决定

**技能不是新东西，是 062 那条路的第三个来源。** 局外 buff、进阶难度、角色技能都是「往 `RunContext` 加数」的效果构件，`RunState.buff_context()` 一起算，
各系统在对应的点读自己那一项。于是同一个构件三处都能用：临时的侦察效果就是一个带时限的地图 buff，某档难度也可以给全员潜行。

**猎手系统在 071 已经读了这三个字段。** 隐形的猎手进了侦察距离就画出来；感知距离 = 定义 × 潜行倍率；逃跑选项写着加成后的几率，掷的也是加成后的。
本步只是把往里加数的构件和角色的那一栏补上，猎手系统一行没改。

**叠加规则写在构件里。** 侦察取大（两个侦察不是叠成 4 步）、潜行相乘、逃跑相加封顶 1。这是构件自己的 `modify`，不在系统里。

**主动技能等有了第一个真的技能再说**（069 第六节）：走事件层，开打前的事件屏多一个选项，条件是「有这个技能」，后果是构件。

## 验证

```
bash tools/test.sh
通过  7429 项断言，49 个套件
```

- 上下文默认不侦察、感知 ×1、逃跑 +0；带三个技能的角色往返逐字节相同、三个数各在；两份同样的技能叠加规则对；战斗效果 / 认不得的类型都报错；
  作者数据里有一个带技能的角色，按它开局上下文里就是那几个数，没技能的角色是默认。
- 猎手读它：感知距离 = 定义 × 潜行倍率；隐形猎手在侦察距离内看得见、外看不见；逃跑选项写着加成后的几率，0.9 + 加成 ≥ 1 时必逃掉、它歇定义里的步数；
  存档读回来（持有方按 id 找回角色）技能还在上下文里。

## 没做的

- 主动技能（事件层的选项）。
- 侦察兵的数是占位；开局屏还没有「这一趟的预估 DPS」。
