# 045 · M4 规划与 M4-1 敌人池

> 阶段 5 · M4 ｜ 架构文档 5.10、6.0、10（v1.44）｜ 前一步：[报告 044](044-layout-solver-and-sandbox.md)

作者的提议原话：

> 为了保证敌人类型丰富：高伤低频型、低伤高频型、混伤型、流血型等等，同时有不同强度档位（受道具数量影响），
> 敌人池需要持有一个配置表，配置表记录了敌人名称、强度、流派（可以存在多个，类似 tag），然后根据地图类型
> （未来会出现不同风格地图）、地图难度、地图规模配置不同敌人，并根据配置生成道具（默认规则是一些通用道具 + 流派道具组合）。

这份报告两件事：先把 M4 分几步说清楚，再把第一步（敌人池）做完。

## 一、M4 分四步

M4 是「节点里有什么」。M3 把 `MapNode.content` 这个槽位留好了，规矩也定了（5.10：内容在生成地图时就定好，
敌人就是一个背包），M4 往里填。

| 步 | 做什么 | 架构文档 | 算过的标准 |
|---|---|---|---|
| **M4-1 敌人池** ✅ | 敌人配置表、档位表、按节点挑人、按「通用 + 流派」组装棋盘、走内容管线、沙盒里悬停可看 | 5.10、6.0 | 每个战斗点生成时就有敌人，件数在档位范围内，同种子同结果，预览与编译一致 |
| **M4-2 掉落与尸体容器** ✅（[046](046-drop-rule.md)） | `DropRule`（章节按 id 引用）：每件各掷、越稀有越难掉、难度 / 幸运 / 局外 / 地图修正、珍宝；`LootContext` 的效果真正接上 | 6.1、6.4 | 尸体容器就是 `GridInventory`；套装与道具的战利品效果改变掉落 |
| **M4-3 随机点与搜索点** ✅（[047](047-random-search-node-events.md)） | `random` 的概率表（在 A/S/R/V/Q 里挑）；搜索点的遭遇曲线（搜几次、每次遭遇概率、遭遇谁 —— 敌人池按 `search` 类型出人） | 5.4、6.2、6.3 | 概率表是数据；搜索点的敌人**看不见**，只有踩上去搜才知道 |
| **M4-4 节点事件接线** ✅（[047](047-random-search-node-events.md)） | 踩到战斗点 → 拿玩家棋盘与节点敌人打一场 `BattleSim` → 结果回到体力（7.1）；商店 / 休息 / 事件各接一个钩子 | 5.6、7.1 | `MapTravel.on_node_event` 有真正的接收方；战败按 7.1 扣 |

M4-4 与 M5（run 状态）、M6（场景流）挨得很近：这里只接「节点类型 → 发生什么」的逻辑，界面与转场不做。
每一步一份报告。作者提的这一条，全在 M4-1 里。

## 三、关键决策

### 流派是标签，「混伤型」不是一种流派

作者说流派「可以存在多个，类似 tag」。照做：`EnemyDef.schools: Array[StringName]`，道具按 `ItemDef.tags`
里带没带这个名字归到流派里。于是**新增一种流派 = 给几件道具打标签 + 写一个带这个标签的敌人**，代码不动。
「混伤型」就是同时带两个流派的敌人（蛮兵：`burst` + `bleed`；守卫：`rapid` + `burst`），不必单独发明一个流派。

第一版三个流派：`burst`（高伤低频：狙击枪 / 撬棍 / 霰弹枪）、`rapid`（低伤高频：手枪 / 步枪 / 冲锋枪 / 匕首）、
`bleed`（流血：匕首 / 剁刀）。导入器要求**每个流派至少有一件道具带这个标签**，不然「按流派挑」挑出来的是空架子。

### 强度 = 档位 = 道具数量，敌人定义里只写「本色」

作者说强度档位「受道具数量影响」。档位表（`EnemyPool.tiers`）每一行：这一档背几件、棋盘多大、基线乘多少、
稀有度上限。**敌人定义不写背几件**，只写本色档位 `strength`，用来在池里按「想要的档位」挑人（容差内取，
没有就取最近的）。实际用哪一档组装，记在节点内容的 `strength` 里 —— 同一个拾荒者在外环是档位 0 背两件，
在高危区里是档位 2 背五件。

### 哪个点该多强：全是加法

`StrengthRule`：`by_depth`（最外 → 最内，按 tier 在全图里的位置插值，**形态无关**：手绘图也只看 tier）
+ `danger × danger_bonus`（5.5：危险叠在 tier 之上）+ `type_bonus[类型]`（精英、核心）+ `difficulty × difficulty_bonus`
+ `by_scale[规模]`。每一项各管一件事，调哪个都看得出来；结果夹进档位表的范围。

作者要的三个输入都在：**地图类型**落在条目的 `kinds`（环的种类 `RingSpec.kind`，生成器已写进节点 `layout.kind`：
废墟里出拾荒者，深处出守卫）；**地图难度**是 `ChapterDef.difficulty`；**地图规模**是 `by_scale`。

### 组装：招牌 → 流派 → 通用，大件先摆，放不下换一件

默认规则就是作者说的「通用道具 + 流派道具」：招牌道具先占位（屠夫总带着刀），件数 × `school_share` 件从流派池抽
（至少 `min_school` 件），剩下从通用池抽（带 `common_tags` 且**不带**本敌人流派标签的道具）。
摆的时候按占格从大到小，放不下的换一件从小到大补 —— 只有棋盘真的满了才会差件数，`fill` 的回报里列出是哪个点、差几件。
第一版就靠这条抓出了 6×4 的棋盘放不下「狙击枪 + 霰弹枪 + 撬棍 + 重甲 + 核心」，档位表的棋盘于是调大、低档加了稀有度上限
（外环小兵不背传说品 —— 这本来就该是设计）。

### 章节按 id 引用池，不内联

几章共用一个池、只改难度是常态。`ChapterDef.enemy_pool: StringName`，导入器在批量导入时（上下文里有池）查它存不存在。
导入顺序：items → enemies（招牌道具、流派标签对着道具查）→ enemy_pools（条目对着敌人查）→ chapters。

### 「对着别的东西查」的校验只在批量导入时生效

单独导一个敌人（编辑器、测试）时上下文是空的，流派有没有道具无从判断，这几条就跳过；其余（档位为负、打错字段名、
份额越界、档位重复、条目限定在池不放敌人的节点类型里）照旧。

### 生成器不认识敌人

`EnemyPlacer.fill` 是生成之后的第二遍，随机数只用节点自己的 `content_seed`：同一张图同一个点永远是同一个敌人，
预设图 `reroll_content_seeds` 关掉时连内容都原样照搬。生成器、校验、编辑器一行没改。

### 预览 = 编译

`EnemyKit.spec_of` 把内容重建成棋盘，走玩家同一个 `BattleCompiler`。沙盒悬停看到的生命、DPS、件数就是真打时的数。
`board_of` 重建出来的棋盘直接是 6.1 的尸体容器 —— M4-2 从这里接。

### 顺手：作者数据重写成导出器的格式

`tools/normalize_content.gd`。仓库里的作者数据应该就是导出器的格式（测试拿它和再导出的文本逐字节比）。
跑一遍发现六件老道具的 `base_stats` 写的是 `5.0`，按「整数值的浮点两头写成整数」的约定（报告 043）该是 `5` —— 一并重写了。

## 四、验证

```
bash tools/test.sh
通过  5393 项断言，32 个套件（其中敌人池一套 1936 项，单独跑 1.6 秒）
```

整套跑了 236 秒 —— 不是新套件慢，是这台机器上同时开着两个 Godot 编辑器在抢 CPU（此前 45 秒）。
`tools/test.sh` 的超时从 240 秒放到 480 秒，免得下次在同样的环境下被误判成挂死。

- 往返：敌人、池各导出 → JSON 文本 → 导入 → 再导出逐字节相同；`Vector2i`、字典里的整数与浮点都没变。
- 校验：流派没道具、招牌道具不存在或是个包、打错字段名、档位重复、没有档位规则、条目限定在不放敌人的类型、章节指向不存在的池 → 全错；
  上下文为空时单独导一个敌人 → 过。
- 仓库文件：六个敌人与一个池导得进、文本就是导出器格式、资产与作者数据一致；第一章引用得到池；每个流派至少两件会打的道具，
  在每一档的稀有度上限下都还有得抽。
- 档位：最外 = `by_depth.x`、最内 = `by_depth.y`，精英 / 高危 / 难度 / 规模各加自己那一份，再高也夹进档位表；深度按 tier 归一化。
- 挑人：节点类型、环种类、危险等级三种过滤；容差内取，容差内没有取最近；权重 9:1 抽一千次落在 800～980。
- 放置：第一章五个种子，每个战斗点都有敌人、非战斗点没有；记的档位等于规则算出来的；条目的过滤对得上；件数在档位范围内且没有差件；
  流派道具不少于 `min_school`；招牌在；稀有度不超这一档；按记的位置重建出同样多件；编译得出有血、有流派道具就有 DPS；摘要里有名字；
  同种子再放一遍逐字相同；难度 +1 档位不降且至少抬高一个点。
- 纯函数：同一份内容编译两次生命与 DPS 相同；基线 = 覆盖 × 倍率；过一趟 JSON 重建不变。

## 五、没做的

- 敌人预览是沙盒底下一行字，不是浮窗、不画棋盘。画棋盘要复用背包沙盒的棋盘控件，等 M4-4 接战斗时一起做。
- 数值全是占位：六种敌人的血、档位表的件数与倍率、池的权重。作者定数时改 JSON。
- 搜索点的遭遇（M4-3）没接：池的 `combat_types` 只有 battle / elite / core。加 `search` 进去、再给 `MapView` 的「给不给看」加一条，就是 M4-3 的一半。
- 敌人自己的规则（不靠道具的技能、BOSS 阶段）没有：敌人就是一个背包，5.10 就是这么定的。真要的话在 `EnemyDef` 上加 `rules: Array[AbilityRule]`，编译时并进 `set_rules` 那条路。
