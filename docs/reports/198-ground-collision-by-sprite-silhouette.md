# 198 方案：地上的掉落物按贴图轮廓算碰撞，不按格子

> 2026-10-19 08:11，架构设计。作者：「关于道具，我还有一个设想，就是掉落在地上时，道具的体积碰撞要去计算道具本身的贴图而不是格子」。
> 格子是背包里的真相（占格、拼接、负重都按它），地上是物理的真相：一把剑躺在地上占的是剑的形，不是 1 × 4 的方块。本篇定「轮廓」这个概念、它从哪来、碰撞解算怎么改，并分两期：道具图还没有，**先用格子的外形把机制做出来**；图一到，轮廓的来源自动换成图的透明通道，别的不动。§4 待定按推荐即执行。

## 1. 现状（已核实）

- 地上 = `ui/inventory/ground_layer.gd`（128 一整片地、134 落地动画、162 补充二 竖直下落、180 §2.2 相遇弹开）。每件记一个归一化落点 `ItemStash.spots`（包围盒左上角），**只是样子，不进规则**（`docs/architecture.md` 3.4）。
- 现在的「体积」比格子还粗：弹开（`_bump_pair`）、撞墙 / 面板（`_bump_walls`）、找支撑（`floor_under`）、推开面板（`push_out`）、「有没有重叠」（`overlapping_pairs`）全部用 `item_rect` = **转过朝向的格子集合的轴对齐包围盒**（`span_px`）。L 形的缺角照样挡住邻居；两件东西永远像两块砖；落地朝向只有四个（`ItemShape.rest_rotation` 取重心最低的那个）。点选（`uid_at_local`）倒是按格子算的。
- **道具图还不存在**：`ItemPainter.art_available()` 恒为 false（187），地上和棋盘都画稀有度色块 + 名字。187 已约定图包落地时把 `art_available()` 接到图包的存在判断上，别的跟着翻 —— 本篇沿用同一个开关。
- 解算是画面层自己写的小步积分（1/120 s，最多 1 s），不是 Godot 物理；测试 `tests/inventory/test_ground_bump_180.gd`、`test_ground_landing.gd` 直接调 `advance_bumps` / `advance_landing`，无头可跑。本篇不换成 `RigidBody2D`（见 §2.5）。

## 2. 设计

### 2.1 一个词：轮廓

每个 `ItemDef` × 朝向（0–3）有一个**轮廓**：像素坐标（格 60 px），原点 = 该朝向的格子包围盒左上角，内容是**一组凸多边形**（最多 6 块）。它只在画面层存在，不进存档、不进规则。

| 来源 | 什么时候 | 怎么得到 |
| --- | --- | --- |
| **图的透明通道**（作者要的） | `ItemPainter.art_available()` 为真且这件有图 | `Image` → `BitMap.create_from_image_alpha(img, 0.5)` → `grow_mask(2)`（细长部位最少 4 px 厚，刀刃不会从缝里滑过去）→ `opaque_to_polygons(rect, 2.0)` → 取面积最大的那块外轮廓 → `Geometry2D.decompose_polygon_in_convex` → 多于 6 块就退成 `Geometry2D.convex_hull` 一块。朝向 1–3 把顶点转 90° × n 再归一到左上角 |
| **格子的外形**（现在） | 没图 | 占格集合的外轮廓多边形（沿格边走一圈，128 的画法已经在算这条边）→ 同样凸分解 / 退凸包 |

- 新文件 `ui/inventory/item_silhouette.gd`（`ItemSilhouette`，静态缓存 `of(def, rot) → {parts: Array[PackedVector2Array], mask: BitMap 或 null, bounds: Rect2}`），第一次用到时算一次，之后查表；换语言、换皮肤不影响它。
- 图的尺寸约定（给美术，187 那批落地时一起定）：**画布 = 这件在朝向 0 的格子包围盒 × 60 px**，透明通道可以贴到画布边，但不能超出画布 —— 超出的部分轮廓里没有（棋盘里它也只占这些格）。朝向 1–3 不另画，程序转。
- 轮廓只用于地上；棋盘、拖拽残影、合成、负重照旧按格子。

### 2.2 碰撞解算：模型不变，形状换掉

180 §2.2 的半弹性碰撞模型（e = 0.5 / 0.15、质量按重量、分开速度、小步积分、1 s 收尾）全部保留，只把「两块矩形重叠多少」换成「两组凸多边形的最小分离」：

| 现在（包围盒） | 改成（轮廓） |
| --- | --- |
| `_overlap(a: Rect2, b: Rect2)` 各轴重叠 | **分离轴（SAT）**：对两件的每一对凸块，拿两块所有边的法线当轴，投影区间重叠最小的轴 = 分离方向 n，重叠量 = 深度；所有块对里取深度最大的那一对。包围盒不相交的直接跳过（粗筛） |
| `_bump_pair` 沿重叠较小的轴分开 | 沿 SAT 给的 n 分开（任意方向，不限横竖），冲量公式不变 |
| `_bump_walls` 屏边 / 地面 / 面板 = 矩形 | 屏边、地面：轮廓最低 / 最左 / 最右**顶点**碰边；面板：面板矩形也是凸多边形，同一套 SAT |
| `floor_under` 用包围盒的上沿当支撑 | **竖直投射**：这件轮廓的每个顶点向下、对方轮廓每条上边的竖直距离，取最小正值 = 还能掉多远；对方 = 下面每件（按 x 区间粗筛）、面板上沿、屏幕底 |
| `overlapping_pairs` 包围盒相交 | SAT 深度 > `BUMP_EPS` |
| `push_out` 推离面板 | 同 SAT，四个方向试位不变 |
| `uid_at_local` 按格子 | 有图：`mask.get_bit(局部像素)`（透明的角点不着）；没图：格子（不变） |
| `spot_for_drop`（放手落点） | 不变（落点仍是包围盒左上角，归一化存档格式不变） |

- 落地朝向（`rest_rotation`）**仍是四选一**，但「重心最低」改成按轮廓算：重心 = 轮廓多边形的面积重心，支撑面 = 轮廓最低一段边的 x 区间；重心在支撑区间外的朝向不算稳，四个都不稳就取重心最低的。自由角度（一把剑斜躺着）留到图到了再议（§4 待定 2）。
- 落地动画（162 补充二）里绕重心转、缩放不变，只把转轴换成轮廓重心。
- 收尾兜底不变：1 s 还相交的退回 `ItemStash.next_free_spot`（它仍按包围盒扫空处 —— 兜底用粗的没问题）。

### 2.3 画

- 有图：地上按包围盒 `draw_texture_rect`（和棋盘同一张图、同一尺寸，187 那批会写），描边 / 高亮（`highlights`，合成提示）改成**沿轮廓外多边形描 2 px**（`draw_polyline`，多边形来自 §2.1 的外轮廓，不是凸分解后的块），落地中的透明度照旧乘在 modulate 上。
- 没图：照旧 `ItemPainter.draw_item` 画色块。

### 2.4 性能

地上一般 < 30 件，每件 ≤ 6 块、每块 ≤ 8 条边：一对最多 36 块对 × 16 根轴，先用包围盒粗筛掉绝大多数；1/120 s 一步、最多 1 s = 120 步，最坏几十万次投影，GDScript 也在毫秒级。轮廓只算一次。`BitMap` 每件一张（60 × 60 × 格数位），可忽略。

### 2.5 为什么不换成 Godot 物理

`RigidBody2D` + `CollisionPolygon2D` 能白得这一切，但：地上的东西要在 `_draw` 里和棋盘同一套画法、同一个像素尺寸；落点要可存可读、落稳后一帧都不能再动；测试无头直接推时间；面板开关要能「再掉一次」。180 已经为这些写了自己的小解算，加上 SAT 是 150 行量级的改动，比接物理服务器、再把结果同步回落点省事得多，也不会出现物理引擎抖一下的问题。

## 6. 阶段一落地（2026-10-19，架构方案执行）

已落地：`ui/inventory/item_silhouette.gd`（`ItemSilhouette`）+ `GroundLayer` 全部碰撞改轮廓 + `tests/inventory/test_ground_silhouette.gd`（43 项）。180、162、128 原有的地上测试一项没改、全过 —— 矩形件和以前完全一样（另用 300 对随机矩形逐一对过 SAT 与 180 的旧算法：轴、深度、方向都相同）。截图 /mnt/project-files/screenshots/198/ground.png。

和方案不一样的地方：

1. **没图时的凸块不走 `decompose_polygon_in_convex`，用合并后的整格矩形**（一行行的连续格，上下同起同止的接成一块）。Godot 的凸分解是三角剖分再合并，会沿对角线切（L 切成两块带斜边、T 切成四块）；块与块之间的假斜边也会被 SAT 当成分离轴，方块碰到 L 会被斜着推开。整格矩形精确、没有假边、块数通常更少。外轮廓照样沿格边走一圈（描边、支撑面用它）。有图时仍按方案走凸分解；内部斜边那个问题阶段二同样存在，图到了看效果再定要不要换分解方法。
2. **阶段二的路径写好了但走不到**：`from_image`（透明通道 → 位图 → 膨胀 2 → 外轮廓 → 凸分解 / 凸包）、位图点选（`ItemSilhouette.hit`，`uid_at_local` 在有位图时用它）、`_draw` 沿外轮廓描 2 像素都在；`ItemSilhouette._art_image` 现在返回 null，取哪张图留给 187 那批接图包时填。`from_image` 用程序生成的带透明角 png 测过。
3. **屏边**：撞墙、地面按轮廓最外的顶点；但写回落点（`to_spot`）与画的时候（`_fit`）仍把**包围盒**夹在屏内，`spot_below` 横向也按包围盒夹。没图时两者完全一样；有图且画布边上有透明时，收尾可能挪几像素 —— 阶段二再看。
4. `floor_under` 改了签名：`floor_under(parts, pos, self_uid) → {dy: 还能掉多远, panel, item}`（原来是横向区间 + 起始 y → `{y}`）。竖直投射对已经压着的块对不算支撑，横向重叠不到 0.5 像素的（并排贴着）也不算。
5. **落稳朝向的变化**：只对「重心最低但重心悬空」的形状有影响，例如 Z 形 `100/111/001` 以前会用一个角格立着，现在落成 `011/010/110`（两格着地）。L、T、长条、方块的结果不变。核心层的 `ItemShape.rest_rotation` 留着（测试在用），地上改调 `ItemSilhouette.rest_rotation`。
6. 看到的一点（不在本期范围）：「稳不稳」只看这件自己的底边，**落在别人窄窄的顶上**不检查会不会翻（截图里 T 横杠朝下落在 L 竖着的那一格上，重心在外面也停住了）。要处理得引入「支撑在别人身上时按接触段判稳、不稳就往一边滑 / 翻」，和待定 2（自由角度）是一回事，建议一起议。


## 7. 补充一：自由角度躺倒（2026-10-19，作者在卡片上选「自由角度」）

> 待定 2 定了：地上的东西可以斜着躺。201 落地后作者看过地面（/mnt/project-files/screenshots/201/ground.png），在卡片上选了自由角度而不是四向。§6 第 6 条（落在别人窄顶上不会翻）和这件事是同一件事，一起做。

### 7.1 想要的样子

- 掉在平地上的东西还是和现在一样横平竖直地躺着（长条躺平、方块不转）。
- 掉在**堆上**的东西按真实的样子停：一半搭在盾上的剑斜靠下去，一头落在圆木上的弓歪着停住，T 横杠落在 L 竖着的那一格上会**翻下来**而不是悬着。
- 斜着的东西捡起来还是四向之一（拖拽残影、棋盘都只认四向）。
- 地上任何时候仍不重叠；落稳后一帧都不再动；存档记得住斜度；无头测试直接推时间。

### 7.2 状态：四向 + 斜度

每件在地上多一个 **斜度 `tilt`**（弧度，绕轮廓重心转，顺时针为正），范围 **(−45°, 45°]**。

- `ItemInstance.rotation`（四向）照旧，捡起来就是它；`tilt` 只在地上有意义，捡起即丢。
- **归一化**：落稳时若 `|tilt| > 45°`，`rotation += round(tilt / 90°)`（mod 4），`tilt -= round(tilt / 90°) × 90°`。201 的贴图变换和 `cells_rotated` 是同一套顺时针变换，所以这步重算 `rotation` 画面上一个像素都不跳，只是「捡起来是哪一向」跟着视觉走（竖着的剑倒成横的，捡起来就是横的）。
- 位置仍是 `spots`（不斜时包围盒左上角的归一化坐标）；画与碰撞都是「先按 `rotation` 摆，再绕重心转 `tilt`」。`_draw` 里 201 已经有 `base` 变换，把 `Transform2D(tilt, pivot = pos + centroid)` 乘进去即可；落地动画的转缩照旧叠在上面。
- **存档**：`ItemStash.spots` 的每项 `[x, y]` 变成 `[x, y, tilt_deg]`（第三项可省，省 = 0；写时保留一位小数）；`ItemStash.tilts: Dictionary`，`set_tilt / tilt_of`；`read_spot` 多读第三项。旧档没有第三项照常读；新档给旧版本读时第三项被忽略，不坏。173 快照不涉及（不是内容）。

### 7.3 解算：180 的弹开解算长出转动和重力

180 §2.2 的解算只有平动、没有重力，所以东西只会被推开、不会翻。自由角度要翻、要靠、要滑到停，就得补上三样：**转动自由度、重力、摩擦**。整个仍然是 `GroundLayer` 自己的小解算，不接 Godot 物理（§2.5 的理由一条不少）。

| 项 | 现在（180 + 198） | 改成 |
| --- | --- | --- |
| 物体状态 | `pos, vel, m, parts, box` | 加 `ang`（= tilt）、`w`（角速度）、`I`（转动惯量，`m × (宽² + 高²) / 12`，宽高取轮廓包围盒）、`asleep` |
| 碰撞形状 | 这一向的凸块 | 凸块绕重心转 `ang`（每步重算，≤ 6 块 × ≤ 8 顶点，便宜；`ItemSilhouette.tilted(sil, ang) → {parts, outline, bounds}`） |
| 一对相交 | SAT 给 `n, depth`，沿 n 的冲量只改速度 | SAT 不变，再取**接触点**（§7.4），冲量按接触点算：`j = −(1 + e) v_rel·n / (1/m_a + 1/m_b + (r_a × n)² / I_a + (r_b × n)² / I_b)`，同时改 `vel` 和 `w`；接着一个沿切线的**摩擦冲量**，封顶 `μ × j`（物件之间 μ = 0.6，地面 / 面板 / 屏边 μ = 0.8） |
| 撞墙 / 地面 / 面板 | 按包围盒顶点或 SAT，只改速度 | 同上：墙是无限质量的物体，接触点 = 碰到墙的顶点；e_wall = 0.15 不变 |
| 重力 | 无 | 每步 `vel.y += g × h`，`g = LAND_G × 屏高`（和落地动画同一个数），睡着的不加 |
| 位置修正 | `BUMP_FIX`、`want = depth / BUMP_SEP_SEC` | 不变（角度不做位置修正，靠冲量） |
| 静止判定 | `|vel| < BUMP_REST` 两步 | `|vel| < BUMP_REST` 且 `|w| < BUMP_W_REST`（0.2 rad/s）且有接触，连续 0.1 s → **睡着**（不再积分重力，被撞到再醒）；全部睡着 = 结束 |
| 时限 | 1 s | **1.5 s**（翻一下再滑停比弹开慢）；到时冻在当前姿态；还相交的照旧退回 `next_free_spot` |
| 触发时机 | 落稳、松手、推开、读档有重叠 | 一样，另外 **落稳后一律进解算**（有重力才知道稳不稳）；平地上的东西一步就睡着，和现在一样不动 |

接触的瞬间速度和 180 的参数（e = 0.5、`BUMP_AFTER`、贴住）照旧。

### 7.4 接触点：平的面要两个点，不然会摇

一个点的接触压不稳一条平底边（会左右摇着停不下来）。按 SAT 的方向 n，取 **被压入的那一侧沿 n 最深的顶点**：两件各自取沿 n 最深、且离最深处不到 1 px 的顶点（最多两个，取沿切线最两头的），合起来就是这对的接触点（1～2 个），冲量按点依次算（split impulse）。长条躺平时两个角各一个点，稳；斜靠时剑上一个点在盾沿、一个点在地上，正好是两件接触各一个点。

### 7.5 落、翻、靠的全流程

1. 落地动画照旧（162 补充二 + 198：转到四向里重心最低的，落到第一个支撑上）。
2. 触地、弹一下结束 → 进 §7.3 解算，`tilt` 从 0 起。平地上的：重心在支撑上，一步睡着，和现在一样。
3. 堆上的：重心悬空 → 重力扭矩让它绕接触点翻，翻到碰上第二个支撑（别的东西 / 地面）就有了两个接触，摩擦让它停住 = **斜靠**；碰不上就一直翻到躺平 = **歪倒**。被它压着、撞着的邻居一起进解算，连锁。
4. 结束：归一化（§7.2），写回 `spots` + `tilts`，`_rest_on` / `_support` 按最后的接触重算（朝上的接触法线那一侧是谁）。`_refall_if_hanging` 用斜着的凸块算 `drop_gap`。
5. 下面的东西没了：托着的照旧再掉一次（从斜着的姿态起落，落地动画的起手角 = 当前 `tilt`，落完再解算）。

- 拖拽层从地上拿起：读 `inst.rotation`（已归一化），`tilt` 丢掉；放回地上从 `tilt = 0` 起落。

## 8. 补充一落地（2026-10-19，架构方案执行）

按 §7 做完，待定 1–4 全按推荐：摩擦物件 0.6、地面 / 面板 / 屏边 0.8；归一化阈值 45°；没图的件也斜；时限 1.5 s。

**落了什么**

- `ItemStash.tilts` / `tilt_of` / `set_tilt`，捡起（`remove`）即丢。存档 `spot_entry`：斜着的写 `[x, y, 斜度（度，一位小数）]`；`read_tilt` 读第三项，没有就是 0。按点暂存（`NodeStorageModule.tilts`）走开、回来、存档都带着。
- `ItemSilhouette.tilted(sil, ang)` 和 `turn`：轮廓绕重心转。`contact(pa, pb, touch)` 给出分离轴的方向、深度和 1～2 个接触点，按 §7.4 把两边最深的那条边或那个角沿切线取交。
- `GroundLayer` 的解算段整段重写。
  - 每件物体多了 `ang`、`w`、`I`、`asleep`。
  - 每小步依次做：
    1. 重力；
    2. 找接触（物件两两、屏边、地面、面板）；
    3. 冲量迭代 8 轮，法向带反弹，切向带摩擦；
    4. 分开重叠；
    5. 撞击后的 180 衰减和贴住；
    6. 前进一步；
    7. 夹回屏内、推出面板；
    8. 静够了就睡着。
  - 落稳、松手、推开、读档有重叠时照旧进解算；落稳的再多看一步站不站得住（`is_stable`）。
  - 收尾时调 `normalize_pose`（§7.2），再写回落点和斜度，然后按最后的接触重算托着谁（`supports_of`）。悬着的照旧再掉一次。
- 跟着改的地方：
  - `item_rect` 仍是不斜时的包围盒。新增 `item_bounds`（斜着的包围盒）和 `tilt_of`。`floor_under` 对别的件按斜着的轮廓投射。
  - `uid_at_local` / `_cell_under` 先把点反转回去。
  - `_draw` 绕重心转（落地动画的转缩照旧叠上去）。
  - 落地动画的起手角 = 当前斜度。
  - `settle` 推开面板时带着斜度。
- 拖拽层：拿起时读 `inst.rotation`，斜度丢掉；放到别处从不斜起落；**取消拖拽原样放回时还斜着**。

**和 §7 不一样的地方**

1. **分开重叠只挪位置、不留速度**（split impulse）。180 原来是给一个「重叠 ÷ 0.1 s」的速度，再每 1/60 秒乘 0.85 衰减。现在有了重力和摩擦，`BUMP_DAMP` 删掉了。如果分开的速度留着，半空里压在一起的会炸开、飞老远。现在压在一起的推开就停；迎面撞上的照旧按 e = 0.5 弹，并带 `BUMP_AFTER` 和贴住。
2. **睡着多一个条件：重心要在接触点围成的横向区间上方。** 只看速度的话，一个角着地、刚开始往下倒的东西头 0.1 s 角速度还很小，会在倒的途中睡着。斜靠在方块沿和地面之间的长条两处都算接触，区间罩住重心，照样睡着。
3. **到时（1.5 s）还在倒的不冻在半倒的样子。** 这种件重心不在支撑上方，比如 T 侧躺后还在慢慢滚。先再给它一段 1.5 s 让解算自己把它翻下去；还在倒的，从当前姿态再落一次：落地动画从当前斜度转回四向里最稳的那个，落完再看站不站得住。别的件到时照旧冻在当前姿态。
4. **斜着的件，落点记的是斜着的包围盒左上角**（不斜的照旧是包围盒左上角）。斜 45° 的长条不斜时的包围盒会比斜着的伸出去十几像素。贴着左边 / 上边时，那个角是负的，被落点的 0～1 夹取一挪就压到邻居。`item_rect` 把落点换算回不斜时的左上角，存档、按点暂存都不受影响。
5. **「落稳后一律进解算」做成了先判站不站得住**：站得住的不进解算，和「一步睡着」结果一样，省一次解算；180「落在别人顶上不用弹」的测试原样过。站不住的才醒着进去，邻居睡着，被撞到才醒。
6. **两个接触点的法向冲量一起解**（2 × 2 块解法，两点太近退回逐点）。逐点解时，平底边压在地上会凭空攒出一点转动，180 的「横向分开、竖直不动」就过不去。另外，浮点误差攒出来的 < 0.00001 弧度当 0；收尾时斜度 < 0.5° 的摆正（不压着别人才摆），再贴回支撑。
7. 撞击线 = max(`BUMP_REST`, 2 g h)。躺着时每步被重力压进去的速度在高分辨率下会超过 20 像素 / 秒，不能算撞，否则每步都会「贴住」清零。
8. 托着的关系可能绕成圈（两件斜靠着互相托）。`_drop_resting_on` 加了防护，不会来回掉个没完。
9. **1.5 s 是每件醒着的总时长，被邻居碰醒不重新计时。** 用真道具图把 20 件一起扔下去时，一堆东西会互相碰醒个没完（一件刚冻住，旁边还在挪的又把它碰醒），整堆一直在抖。现在只有新的事（刚落稳、刚被摆过来）才从头计时；醒够 1.5 s 冻住的不再被碰醒，当推不动的。另设一整轮的兜底 6 s（从最后一次有新落稳的算起）。
10. **质量 = 重量开平方。** 重量差几十倍（板甲压着小刀）时，夹在中间的轻件会被挤炸；开方后重的仍挪得少，但不会炸。另外速度、角速度都封顶，夹在两件之间解不开时冲量不会越攒越大。
11. **卡着的也能睡。** 重心不在接触点区间上方、但静了 0.5 s 的（斜卡在两件之间、靠在侧面上）也睡着，真在倒的 0.5 s 早就快起来了。
12. **收尾时少落几次。**
    - 自己静下来、还挨着别的东西的（卡在两件之间）不算悬着，不再落。
    - 收尾时再落的件不连带它上面的件；上面的各自看还悬不悬着，低的先落。原来一件翻下去，压在它上面的十几件会跟着重落一遍。
    - 同一件在收尾时又落了两次，再落稳就不再按「站不住」解算。这是落了翻、翻了落的兜底。
    - 收尾时还压着 4 像素以内的，先沿分开方向就地推开，再不行才退回网格空处。原来冻在半路的轻微重叠都会被瞬移到空处。
13. **不斜的件夹进屏里也按轮廓。** 原来按包围盒夹：道具图底下有一两行透明的，贴地的轮廓会被顶离地面 2 像素，收尾判成悬着，落下去、又被顶起来，来回落个没完。现在透明的那一圈可以出屏。摆正（斜度 < 0.5°）后往下贴回支撑最多挪 4 像素。
14. 没加 warm start（上一小步的冲量接着用）。试过，真道具图的堆停稳反而更慢（8 组平均 11.9 s 对 7.4 s），轻件夹在重件之间还会被挤炸。
