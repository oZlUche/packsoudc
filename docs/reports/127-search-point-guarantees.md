# 127 方案：搜索点保底 —— 常规点每次至少两件（稀有度不保）、进阶点按「逐件保底稀有度」出；每级进阶难度改两种点的保底

> 架构 · 提议（2026-10-05）。作者补充（同日）：「高危搜索点默认采用比当前地图更高一阶的保底」。作者：「常规搜索点和进阶搜索点的掉落概率需要修改，常规应该保底两件但稀有度无保底；每级进阶会对两者进行修改（增加保底数量或者保底稀有度，注意保底稀有度可以以单个道具计算，比如保底三个，保底稀有度一蓝两绿，而非要么全绿要么全蓝）」。

## 一、现状（已核实）

- 搜索抽取在 `SearchSession.draw_items`：每次搜 `items_per_search = [1, 2]` 件，每件独立按 `rarity_weights × 深度 × 危险` 抽，**没有件数保底、没有稀有度保底**；一次搜只出一件白的是常态。
- 节点类型只有一种 `search`；节点带 `danger`（5.5 危险等级，高危区里的点 > 0）。**还没有「进阶搜索点」**这种东西。
- 进阶难度（`DifficultyDef.level`，现在只有「进阶 1 占位」）通过 `mechanics`（侵蚀、猎手）和 `effects` 改一局，**没有一个字段碰搜索**。
- 节点内容已能逐点覆盖搜索（`search_max / search_min / search_curve / search_finds`），序章就是这么写死的。

## 二、两种搜索点

| | 常规搜索点 | 进阶搜索点 |
|---|---|---|
| 是哪些 | 高危区外的 `search` | **高危区里的 `search`**（`danger ≥ 1`）；预设图 / 编辑器可用内容键 `search_tier: "advanced"` 直接指定，`"normal"` 反过来压回常规 |
| 地图上 | 照旧 | 同一个图标加一个角标；节点浮窗第一行写「进阶搜索点」 |
| 保底 | 本难度那一行的表（普通难度：`[0, 0]`，两件、稀有度不保） | **作者定（2026-10-05）：默认用比当前地图高一阶难度的那一行**（普通难度下的高危点 = 进阶 1 的表） |

不加节点类型：类型牵动生成器配额、路线风格、风险 / 回报表（5.4），而「高危区里的搜索点更好」已经是生成器赋予的含义（`danger`），顺着它走零改动。

## 三、保底怎么写、怎么抽

### 3.1 数据：一张「难度 → 逐件稀有度下限」的阶梯表

`SearchRules` 加一个字段（节点规则 JSON 里写），**下标 = 进阶难度等级**（0 = 普通）：

```
"search_floors": [
  [0, 0],        # 普通：每次搜保底 2 件，稀有度不保
  [1, 0],        # 进阶 1：第一件 ≥ 绿
  [1, 1, 0],     # 进阶 2：三件，两绿
  [2, 1, 1]      # 进阶 3：一蓝两绿
]
```

**每一行表长 = 保底件数，每一项 = 那一件的稀有度下限**，所以「保底三件、一蓝两绿」就是 `[2, 1, 1]`，不存在「要么全绿要么全蓝」。

- 常规搜索点用第 `level` 行；**进阶（高危区）搜索点用第 `level + 1` 行**（作者定）。
- 超出表长：取最后一行，再把第一项抬一阶（最高 5）—— 表没写到的高进阶也有合理的默认，不用每加一级难度都补表。

### 3.2 抽法（`draw_items` 改）

1. 这次搜的件数 `n = max(floor.size(), randi(items_per_search))`。
2. 前 `floor.size()` 件是保底位：第 i 件只在 **稀有度 ≥ floor[i]** 的候选里按原权重抽；那一档以上一件都没有（内容少、或 `rarity_cap` 压着）就逐级往下放宽，直到有。
3. 其余 `n − floor.size()` 件照旧全池抽。
4. `rarity_cap`（事件给的）仍然是硬上限：`floor[i]` 先夹到 `≤ cap`。
5. 顺序打乱后返回（别让玩家从揭示顺序猜哪件是保底）。

深度与危险的权重偏移照旧，所以保底只定地板，不定天花板。

### 3.3 进阶难度怎么改保底

默认全在 §3.1 那张阶梯表里：难度每升一级，常规点和高危点各往下挪一行，「每级进阶改两者」自然成立，不进代码。

某一档难度要和阶梯不一样时，`DifficultyDef.search_floors: {"normal": [...], "advanced": [...]}`（绝对值）盖掉对应那一种；没写的沿用阶梯。节点内容 `search_floor: [...]` 可逐点覆盖（序章要写死就写它）。优先级：节点内容 > 难度覆盖 > 阶梯表。

### 3.4 说明文字

节点浮窗（章节开着时）在「进阶搜索点」下面加一行「每次至少 {search_floor_count} 件，其中 {search_floor_text}」—— `search_floor_text` 由表生成（「一件绿及以上、两件任意」），走 112 的占位符规矩，不写死数字。
