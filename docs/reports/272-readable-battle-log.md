# 272 可阅读的战斗回放（战记）

作者 2026-11-04 14:55：「给战斗添加一个可以阅读的回放，要清楚列出每次伤害、效果以及治疗，每次出手都用一种和上下行不同的颜色文字。格式参照『[角色]使用[伤害道具]造成了[N][属性]伤害，（被抵挡了[M]伤害，最终伤害为[N-M]）』」。

## 〇 一句话

回放屏下方加一栏「战记」：回放每放到一条事件就写一行人话，按出手分组、相邻两次出手用两种墨色交替；拖时间轴时重写到那一刻。文字由一个无界面的 `BattleNarrator` 从回放事件生成，正式游戏、开发工具的回放浏览器、`.txt` 日志三处共用。

## 一、现状（读码）

| 项 | 现状 | 出处 |
|---|---|---|
| 回放事件 | `BattleResult.log` 只存 `VIEW_EVENTS`：开战 / 出手 `item_fired` / 伤害 `damage` / 资源 `resource_changed`（生命、耐力、法力、护甲，带 reason 治疗 / 消耗 / 回复 / 护甲吸收）/ 状态叠层 `status_stacked` / 倒下 / 反应 / 鏖战 / 衰竭 / 轴变动 | `core/battle/battle_event.gd` |
| 伤害载荷 | `{type, raw 原值, absorbed 护甲挡下, block 格挡挡下, amount 最终扣血, crit, direct, source_side, uid 打出的道具, cancelled}`；amount 为负 = 被反转成治疗 | `damage_resolver.gd:_notify` |
| 出手载荷 | `{uid, ready_at, step/steps/next（法杖轮读第几颗）}`；天生规则（uid 0）不发出手事件 | `rule_engine.gd:_fired_payload` |
| 文字播报 | `BattleView._ticker` 已有逐条播报（伤害一行带类型色、叠层、倒下、反应、鏖战、衰竭、轴），但 157 补充一起**正式游戏不建**，只在开发工具回放浏览器里有；行文是「我方 火焰 12」式的短句，没有分组、没有「被抵挡」 | `ui/battle/battle_view.gd:650–691` |
| 收尾战报 | 一行总结（秒数、双方造成 / 承受）藏着不显示（229） | `BattleView.report_of` |
| 名字 | 回放里双方叫「我」/ 敌人名，道具名表 `set_item_names(side, {uid: 名})` | `battle_screen.gd:98–103` |
| 字色 | `data/authoring/ui/text_colors.json`：fire / frost / thunder / poison / bleed / heal / crit 等都有深浅两套 | — |
| 人读日志 | `user://battle_logs/*.txt` 是内部日志排版（程序味，给作者查数） | `BattleTrace.format_lines` |

## 二、方案

### 2.1 行文（`BattleNarrator`，纯函数：事件 + 名字表 → 行）

每行 = `[时间] 正文`，时间淡墨 `12.3s`。[角色] = 我方用角色名（名牌上那个）、敌方用敌人名；[道具] = 道具名（法杖轮读写成「魔法杖·火焰晶石」）。

| 事件 | 行文（中文；英文同款键） |
|---|---|
| 伤害，未被挡 | 「{角色}使用{道具}造成了 {N} {属性}伤害」 |
| 伤害，被挡 | 「{角色}使用{道具}造成了 {N} {属性}伤害（被抵挡了 {M} 伤害，最终伤害为 {N−M}）」，M = 护甲挡下 + 格挡挡下；两者都有时括号里拆成「护甲 a、格挡 b」 |
| 暴击 | 前面加「暴击！」，数字用暴击色 |
| 被化解（cancelled）/ 反转成治疗 | 「…的一下被化解了」/「…反而治疗了 {N}」 |
| 持续伤害（没有出手事件，uid 0） | 「{角色}因【{状态}】受到 {N} {属性}伤害」；状态名取自同刻的来源（没有就写「持续效果」） |
| 治疗（resource hp，reason heal） | 「{角色}使用{道具}恢复了 {N} 生命」；没道具时「{角色}恢复了 {N} 生命」 |
| 护甲 / 耐力 / 法力变动 | 不单写行（护甲挡下已进括号；耐力消耗与回复每秒都有，只会刷屏，待定 1） |
| 施加状态 | 「{角色}使用{道具}给{对方}施加了 {K} 层【{状态}】（共 {S} 层）」；自己身上的（增益）写「{角色}获得了…」 |
| 状态消失 | 「{角色}身上的【{状态}】消失了」 |
| 反应 | 「{角色}身上引发了【{反应}】」（反应色，沿用现有） |
| 倒下 / 不死 | 「{角色}倒下了」/「{角色}凭【不死】撑住了」 |
| 开战 / 鏖战 / 衰竭 / 轴 | 沿用现有句子 |
| 收尾 | 最后一行写现有的 `report_of` 总结（秒数、双方造成 / 承受、胜负） |

### 2.2 分组与颜色（作者要求）

- **一次出手 = 一组**：从一条 `item_fired` 起，到下一条 `item_fired` 之前、同一方同一 uid 引出的伤害 / 治疗 / 施加都归这一组（同一刻、`source_side` + `uid` 相同）。没有出手事件的行（持续伤害、消失、倒下）各自成组。
- **相邻组交替两种墨色**：`text_colors.json` 新增 `log_a` / `log_b`（深浅各两套，建议 a = 正文墨、b = 偏褐的第二墨），整组正文用同一种；组内的数字与属性词仍用属性色（火 / 冰 / 雷 / 毒 / 流血 / 治疗 / 暴击），这样一眼能分出手、也能分属性。
- 同一组多行时，第二行起缩进两格，少重复「{角色}使用{道具}」：第二行写「又给{对方}施加了…」。

### 2.3 放哪、怎么跟回放走

- **战记栏**：战斗屏的铜面板里，棋盘下方、控制条上方插一栏 1100 × 200 的滚动文字（`RichTextLabel`，13 号 = 现有播报字号），深底（铜面板上，tone dark）。回放每放一条事件就追加一行并滚到底；暂停 / 拖动时间轴 → 清空后重写到游标那一刻（`seek` 已经走 `play` 再 `_drain_until`，顺路）；跳过到底 → 全文。
- **收合**：控制条上加一颗「战记」键（和播放 / 倍速 / 跳过同排），按下 = 收起栏，棋盘下移回原位；记进设置 `battle_log_open`（默认开）。
- **看完后**：栏留着，玩家按【继续】前可以上下翻；不另做战后页。
- **开发工具**：回放浏览器的播报改用同一个 `BattleNarrator`，删掉旧的逐条拼字；`.txt` 内部日志不动（它是查数用的）。
- 行数上限 400，超了丢最早的（一场通常几十到一两百行）。

## 三、改动清单（执行）

1. `core/battle/battle_narrator.gd`（新，静态）：`lines(result: BattleResult, names: Array, item_names: Array[Dictionary]) -> Array[Dictionary]`，每条 `{time, group, side, text(bbcode)}`；分组规则见 2.2；`line_at(i)` 给回放逐条取。文案键进 `UiText`（zh / en）：`log.hit` / `log.hit_blocked` / `log.heal` / `log.apply` / `log.dot` / `log.fade` / `log.down` …，属性名走 `DamageTypes.name_of`，状态名走 `BuffDef.display_names`。
2. `BattleView`：`_ticker` 改为正式栏（`show_ticker` 去掉，改 `log_open`），`_apply` 里改为取 narrator 的行追加；`seek` / `skip_to_end` 重写；保留 `_log_line` 给鏖战等现成句子但一律经 narrator。
3. `BattleScreen`：栏位（棋盘下方 1100 × 200）、「战记」键（占位用现有符石键样式，定稿由 UI替换美术 出）、`GameSettings.battle_log_open`。
4. `text_colors.json`：`log_a` / `log_b`。
5. 回放浏览器改用 narrator；`report_of` 作为末行。
6. 名字：我方传角色名（`flow.meta.last_character` 对应的名字，没有就「我」），敌方敌人名。
7. 测试：固定一段手搓事件 → 行文（被挡括号、暴击、治疗、施加、持续伤害、分组交替）；en 版本不含中文；拖动后行数 = 到那一刻的行数。
8. 美术：UI替换美术 出「战记」键样（同排其余三键同款）给作者。

## 四、待定（没回音按推荐）

1. 耐力消耗 / 回复、法力变动要不要写行 —— **推荐不写**（每秒都有，刷屏；护甲挡下已进括号）。
2. 栏默认开还是收 —— **推荐开**（作者要的就是能读）。
3. 第二行缩进省略主语 —— **推荐省**（一次出手打中又施加时少一半重复字）。
4. 持续伤害的状态名：事件里没带来源，按同刻 / 同方最近叠的状态推断 —— **推荐推断**，推断不出写「持续效果」；要准就给 `damage` 载荷加 `source_buff`（一行）。
