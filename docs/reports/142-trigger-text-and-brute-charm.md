- 日期：2026-10-08
- 来源：作者在「架构方案执行」里提的两条：「由状态触发的效果，在道具里文案不够准确和详细，需要作出区别，而且文案最好是直接根据效果字段类型生成，而不用手动编辑」；「把力量的符号和蛮神护符合并」。

## 一、规则文案

### 1.1 现在怎么生成

道具悬浮窗、战前被动表和信力加成的规则行，都由 `Glossary.rule_text(rule)` 生成：`[扳机名] 每 N 秒　效果1，效果2`。

- 扳机名查的是一张**按类型写死的表**（`TRIGGER_NAMES`），比如施加时、层数够时、受伤前。扳机自己的字段（哪个状态、谁身上、谁施加、几层、消不消耗、伤害方向和类型）一个都不读。
- 规则的**条件 / 消耗**（`costs`：若对手有流血、几率、消耗层数……）完全不写。
- 效果那半句已经是各效果的 `describe()` 按字段生成，但有两处漏了字段：
  - `remove_status` 直接写 buff 的 id（「移除 bleed 全部 层」）；
  - `deal_damage` 不写固定值、按层数和按比例那几个字段。

结果是现在这六件流血 / 中毒道具：

| 道具 | 规则（字段） | 现在显示 | 问题 |
|---|---|---|---|
| 猎血者的符号 | 对手身上被**你**施加流血 → 自己获得血勇 | [施加时] 获得血勇 | 不知道是施加什么、施加给谁 |
| 嗜血护腕 | 同上 → 获得嗜血 | [施加时] 获得嗜血 | 同上 |
| 溃烂之刃 | ① 每 1.4 秒出手 ② 你给对手施加流血 → 施加中毒 | [自发] 每 1.4 秒　造成 物理 伤害，施加流血 / [施加时] 施加中毒 | 第二条看不出和流血有关 |
| 放血刀 | 对手流血 ≥ 6 层 → 每层 3 点物理伤害，再清掉对手全部流血 | [层数够时] 造成 物理 伤害，移除 bleed 全部 层 | 谁的层、几层、伤害多少都没写；出现内部 id |
| 创口盐 | **你造成**物理伤害前，**若对手有流血** → 这一下 +20% | [受伤前] 伤害 +20% | 方向写反了（是造成伤害，不是受伤）；条件没写 |
| 蝰蛇毒腺 | 你给对手施加中毒 → 中毒转为剧毒 | [施加时] 中毒转为剧毒 | 不知道谁身上的中毒 |

### 1.2 改成：每个扳机、每个条件自己按字段说一句

和效果的 `describe()` 一样，**扳机**和**条件 / 消耗**也各自带一个 `describe()`，句子只由字段拼出来，作者不写任何文案。数字一律来自字段（沿用「数字读字段」的规矩）。

一条规则拼成：

```
[扳机那句] 条件那句，效果1，效果2
```

- 扳机那句放在方括号里，和现在一样。
- 有冷却的「自发」不再写「自发」两个字，方括号里直接写「每 N 秒」（武器那条仍会被悬浮窗换成实算的冷却）。
- 条件 / 消耗紧跟其后，用「若……」「消耗……」开头；没有就省掉。
- 武器的耐力消耗悬浮窗已经单独写了「耗耐力 N」，规则行里不重复。

**扳机的句子（按字段）：**

| 扳机 | 字段 → 句子 |
|---|---|
| 状态被施加 | `on_self` × `by_self`：你给对手施加{状态}时 / 你给自己施加{状态}时 / 你被施加{状态}时 / 对手被施加{状态}时（`by_self=false` 表示不管谁施加） |
| 状态掉光 | `on_self`：你的{状态}掉光时 / 对手的{状态}掉光时 |
| 层数达到 | 你的 / 对手的{状态}达到 N 层时；`consume` 时补一句「（消耗这 N 层）」 |
| 受伤前 / 受伤时 | `direction`：受到 / 造成；`damage_type` 留空时写「攻击」，否则写类型名；前 / 时；`min_amount` > 0 补「（单次至少 N）」；`crit_only` 写「暴击」 |
| 资源低于 / 高于 | 你的 / 对手的{生命}低于 N% 时（`absolute` 写点数；`full` 写「满时」） |
| 轴达到 | 你的 / 对手的{轴名}达到 N 时 |
| 出手时 | 按 `same_side`、`source`、`source_tags` 写成「你的{标签}出手时 / 对手出手时 / 这件出手时」 |
| 开战 / 加时 | 开战时 / 加时开始时（没有字段，不变） |

**条件 / 消耗的句子（按字段）：**

| 条件 / 消耗 | 句子 |
|---|---|
| 状态条件 | 若对手有{状态}；`stacks` > 1 时写「若对手{状态}至少 N 层」；`negate` 写「若对手没有{状态}」；`on_self` 换成「你」 |
| 扣层 | 消耗你的 N 层{状态} |
| 几率 | N% 几率 |
| 资源条件 | 若你的{生命}不低于 / 不高于 N% |
| 资源消耗 | 消耗 N {资源}（耐力在武器上省掉，见上） |
| 轴条件 / 轴消耗 | 若你的{轴名}至少 N / 消耗 N {轴名} |
| 充能 | 每第 N 次才生效 |
| 次数 | 每场最多 N 次 |

**效果里补上的两处：**

- `remove_status` 用状态名，写目标：「清掉对手全部流血」「移除你 N 层{状态}」。
- `deal_damage` 写出固定值、按层数和按比例：「对手每层流血造成 3 点物理伤害」「造成 N% 最大生命的物理伤害」。只读属性表的那种（武器的普通攻击）照旧只写「造成物理伤害」，伤害数值看 DPS 那行。

### 1.3 改完后的这六件

| 道具 | 改完显示 |
|---|---|
| 猎血者的符号 | [你给对手施加流血时] 获得血勇 |
| 嗜血护腕 | [你给对手施加流血时] 获得嗜血 |
| 溃烂之刃 | [冷却 1.4 秒] 造成物理伤害，施加流血 / [你给对手施加流血时] 施加中毒 |
| 放血刀 | [冷却 1.1 秒] 造成物理伤害，施加流血 / [对手的流血达到 6 层时] 对手每层流血造成 3 点物理伤害，清掉对手全部流血 |
| 创口盐 | [造成物理伤害前] 若对手有流血，伤害 +20% |
| 蝰蛇毒腺 | [你给对手施加中毒时] 中毒转为剧毒 |

其余所有道具、buff 自带的规则、信力加成、附加规则走的是同一个 `rule_text`，一起变准，不用改任何内容文件。

### 1.4 怎么做

- `Trigger` 和 `Cost` 基类各加一个 `describe() -> String`（默认空），每个子类按上面两张表实现。
- `Glossary.rule_text` 改成「扳机 describe ＋ 条件 describe ＋ 效果 describe」，删掉 `TRIGGER_NAMES` 写死的表；扳机没写 describe 时退回类型名（和效果一样，不会空着）。
- 状态名统一由一个 `Glossary.status_name(id)` 查（buff 定义的显示名，查不到才用 id），`remove_status`、状态扳机、状态条件都用它。
- 测试：六件道具的规则行逐字断言；每种扳机 / 条件各一条字段 → 句子的断言；全部道具的规则行里不再出现英文 id。

## 二、力量的符号并进蛮神的护符

### 2.1 现在

| | 蛮神的护符 `charm_brute` | 力量的符号 `strength_sigil` |
|---|---|---|
| 作用 | 信物：放进包就信蛮神；序章三教程用它，事件「蛮神的召唤」给它 | 也是蛮神信物，**带效果**：信力加成「开战获得血怒（10 秒，+10%）」、四个增益槽（相邻武器 +15%） |
| 稀有度 / 价值 | 3 / 200 | 2 / 按稀有度 |
| 标签 | 珍宝、信仰、蛮神、骨、信物 | 信仰、蛮神、零件、符号、信物 |
| 其他神 | 日神 / 地母 / 狩神 / 自然 / 技艺各只有一枚护符，都没有效果 | —— |

两件都是蛮神的信物，所以在包里是重复的；而其他神都只有一枚护符。

### 2.2 改成（推荐）

- **留下蛮神的护符**（`charm_brute`，名字、形状、稀有度 3、价值 200、标签都不变），把力量的符号的**信力加成**和**增益槽**原样搬过来。
- **删掉力量的符号**。改名表（`IdAliases.ITEMS`）加一条 `strength_sigil → charm_brute`：老存档、仓库、图鉴里的力量的符号读档时自动变成蛮神的护符。
- 引用跟着改：
  - 帮助页「蛮神」里两件并成一件；
  - 测试里用力量的符号的那些换成蛮神的护符；
  - 战斗编译的蛮神金样（`brute.json`）重新生成：护符现在多了增益槽和开战血怒。
- 序章三教程、事件、章节里本来就只用护符，文案不用改。教程里拿到的护符从此带开战血怒和相邻武器 +15%，序章三的那两场战斗会稍微好打一点。

### 2.3 合并带来的变化，供拍板

- **获取途径变少**：护符带「珍宝」标签，商店和搜索不出它；力量的符号以前可以从商店、搜索、事件奖励里拿到（它带零件 / 符号标签）。合并后蛮神的这套效果只能从信仰事件（「蛮神的召唤」）和教程里拿到，和其他神的护符一样。
- **蛮神的护符成了唯一带效果的护符**，其他神的护符仍是纯信物。以后要不要给每位神的护符都配一套信力加成，是另一个话题，这次不动。
- 序章三的战斗略变简单（见上）。

### 2.4 另一种合法（不推荐）

留下力量的符号的 id、改名叫「蛮神的护符」。这样商店和搜索还能出它，但教程、事件、帮助页、金样里所有 `charm_brute` 都要改成另一个 id，改动面大，而且这件就和其他神的护符不是一类东西了。
