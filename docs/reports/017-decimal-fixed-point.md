# 017 · 定点标度改为十进制

对应架构文档 **v1.2**：4.3 数值约定、4.7 模拟循环。

## 问题

被问到「为什么要保留 65536」。答案是：**没有好理由，那是反射动作。**

`65536 = 2^16` 是 C／嵌入式定点数的老惯例，图的是乘除 `ONE` 能编译成移位指令。
但在 GDScript 里：

- **这个好处根本不存在** —— 整数除法不会因为除数是 2 的幂而变快，何况这里远不是瓶颈
- **代价实打实** —— 设计师写的每一个十进制数都被舍入

报告 016 里已经被咬过一次：`0.1` 在 2^16 下是 `6554/65536`，三次累加不等于 `0.3`，
测试断言失败。当时把它当成「定点数的固有性质」绕过去了，**其实是标度选错了**。

## 审计

```
代码中对 65536 的引用：1 处常量 + 3 处注释
位运算/掩码依赖 2 的幂：0 处
```

没有任何地方真正利用了 2 的幂这个性质。改一个常量即可。

## 为什么是一万，不是一百万

`mul(a, b)` 要算 `a * b`，两者都是「值 × ONE」，所以约束是
**两个原值之积 < 2^63 / ONE²**：

| 标度 | 十进制精确性 | `mul` 安全余量（两值之积） |
|---|---|---|
| `65536` (2^16) | ❌ `0.1` / `0.2` / `0.3` 全不精确 | `2.1e12` |
| `1_000_000` | ✅ 六位小数 | `9.2e6` ← 百万血 × 10 倍就溢出 |
| **`10_000`** | ✅ 四位小数 | **`9.2e10`** |

四位小数对冷却是 0.1 毫秒、对百分比是 0.01%，远够用；而余量比一百万高五个数量级。

正常量级（伤害上万 × 倍率上百 = `1e6`）离溢出线还有四个数量级。

## 收益

把报告 016 里那条「不要断言 0.1 × 3 == 0.3」的警告**删掉了** —— 现在它成立。

测试相应改回 0.1 秒周期，并注明：

> 十进制标度下 0.1 是精确的。换成 2^16 标度这几条会差 1/65536 秒而失败 ——
> 这正是不用 2 的幂的理由。

这条断言从此成为标度选择的回归保护：谁要是把 `ONE` 改回 2 的幂，它会立刻红。

## 一个反复出现的失败模式

这是同一个模式的第四次：把邻近领域的默认做法当成不言自明的前提。

| 照搬自 | 结果 |
|---|---|
| Diablo／塔科夫的装备栏 | 参照作没有，且它取消了「空间是唯一约束」 |
| ARPG 的 `socket` | 该作里 socket 另有所指（宝石孔），命名误导 |
| C／嵌入式的 2^16 定点 | 好处在 GDScript 里为零，舍入代价照付 |
| 引擎的固定步长帧循环 | 模拟不需要帧；我还为此写过补丁去修这个前提造出的 bug |

共同点：这些做法在各自来源领域里都是对的，所以不会触发怀疑。
**它们出错的方式不是「明显不合理」，而是「换来的好处在这里不存在，代价却照付」。**

由此定下的检查：做技术选型时说清楚**换来了什么、代价是什么**，再确认好处在本项目的实际
环境里确实成立。理由是「这是标准做法」时，那恰恰说明还没想过它。
