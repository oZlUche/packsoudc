# 144 方案：道具编辑器总览加「有效果 / 无效果」两个页签，再加一个搜索栏

- 日期：2026-10-09
- 提出：作者（架构设计线程）
- 性质：架构 · 提议（本线程只写方案，不实现、不跑测试）
- 作者原话：「在道具编辑器的总览里面，制作两个选项卡，专门用于区分有效果的道具（药物、食物、装备、信物）和没效果的道具（材料、珍宝）。另外增加搜索栏用于快速搜索列表里的道具」

## 一、现状（`ui/editor/content_editor.gd`）

总览 = 左边一列竖排的分类页签（`_tab_host`：「全部 n」+ 每个标签一页 + 「无标签」，从数据里的标签长出来，`Filter { ALL, TAG, UNTAGGED }`）+ 右边 `ItemList`（`_shown` 是筛选后的 id 顺序，行号对它）。
没有按「有没有效果」分的视角，也没有搜索；110 件道具要找一件得先猜它的标签。

## 二、改成

### 2.1 「有效果 / 无效果」是列表上方的一排，和标签页签是两级

```
[ 全部 110 ] [ 有效果 65 ] [ 无效果 45 ]        ← 新：分组行（横排三个切换钮）
┌──────────┐ ┌──────────────────────────┐
│ 全部  65 │ │ 🔍 [搜索 id / 名字 / 标签 ] │  ← 新：搜索栏
│ 武器  14 │ │ 匕首                       │
│ 药剂   9 │ │ 制式短剑                   │
│ …        │ │ …                          │
└──────────┘ └──────────────────────────┘
```

- 分组行放在左列页签之上、横跨整个总览；三选一，默认「全部」。
- 左列的标签页签**在当前分组内**长出来：切到「无效果」时只列无效果道具带的标签（材料、建材、珍宝、战利品、宝石……），「武器」「药剂」这类页签自然消失；计数也按分组算。
- 筛选 = 分组 AND 标签页签 AND 搜索，三者都作用在 `_matches_filter`，`_shown` 还是唯一的真相。

### 2.2 「有效果」怎么判（代码里一个静态函数，不是标签）

`ItemDef.has_effect()`（放 `core/inventory/item_def.gd`，编辑器与将来百科都能用）：

| 算有效果 | 依据 |
|---|---|
| 战斗定义 | `combat != null` 且 `base_stats` / `rules` / `mods` 任一非空（武器、甲、盾、药、食物、魔晶石的属性） |
| 邻接定义 | `adjacency != null`（内甲、插件、弹药、手套这类只靠增益格起作用的） |
| 跨域效果 / 包体加成 | `effects` 或 `bag_mods` 非空（现在没有内容，留着口子） |
| 包 | `is_bag`（皮革包、小背包、长条包、药水带 —— 装备） |
| 信物 / 特殊道具 | 标签 `faith_anchor`（六个护符、赐福长弓、赐福盾、力量的符号）或 `keepsake`（望远镜、都行） |

其余 = 无效果：材料、建材、矿石、锭、珍宝、战利品、试剂、宝石。

按现有 110 件（不含封存）过了一遍：**有效果 65、无效果 45**。边界件核过：贴身内甲 / 防弹装甲 / 毒匠手套 / 三种箭 / 弹匣走邻接 → 有效果；魔晶石带 `combat.base_stats` → 有效果；破碎的魔晶石同；果果之心、灰白色的金属碎片、异化黑曜石（珍宝，只有价值）→ 无效果；毒药瓶 / 蝰蛇毒腺 / 创口盐（试剂）：毒药瓶与蝰蛇毒腺带 `combat`，创口盐带 `combat` → 有效果，这是数据说的，不是分类错。

判定是从数据读的，作者给材料加了 `combat` 它就自动跳到有效果那页 —— 和现在「标签页签从数据长出来」同一个原则。

### 2.3 搜索栏

- `LineEdit`，在 `ItemList` 正上方，占位文字「搜索 id / 名字 / 标签」，右端一个清空按钮（×），Esc 也清空。
- 匹配：不分大小写的子串，对 `id`、`display_name`、`display_names` 里每种语言、每个标签的 id 与中文名（`TagRegistry` 的显示名）任一命中即显示。
- 每敲一字 `_repaint_list()`（110 件，不需要防抖）。
- 搜索只筛列表，不改分组与标签页签；但页签上的计数按「分组 + 搜索」算，作者一眼看到「武器 3」就是搜到的三把。
- `_select_in_list(id)`（新建 / 存盘后定位）：目标不在当前筛选里时，现在是把标签页签退回「全部」；改成**连分组和搜索一起清掉**再定位，不然新建的一件在「无效果」页签下永远看不见。
- 列表为空时 `ItemList` 里一行灰字「没有匹配的道具」。

### 2.4 不做的

- 不加新标签、不改任何道具 JSON；「有效果」不是标签，是从定义算出来的。
- 其他三个编辑器（事件 / buff / 套装）不加搜索 —— 它们的列表都在三十条以内；若要加，等 141 的基类再统一做。

## 三、改动清单

| 文件 | 改什么 |
|---|---|
| `core/inventory/item_def.gd` | `has_effect() -> bool`（第 2.2 节） |
| `ui/editor/content_editor.gd` | `enum Group { ALL, EFFECT, PLAIN }` + `_group`；分组行三个切换钮；`_search: LineEdit`；`_matches_filter` 三段 AND；`_all_tags()` / `_count_of()` 按分组 + 搜索算；`_select_in_list` 清三级筛选；空列表灰字 |
| `tests/authoring/test_content_editor.gd`（现有编辑器测试所在文件） | 第四节 |
| `docs/architecture.md` 编辑器一节 | 一句：总览两级筛选 + 搜索 |

## 四、测试

- `has_effect()`：制式短剑 / 伤药 / 口粮 / 皮革包 / 贴身内甲 / 箭矢 / 日神的护符 / 望远镜 → 真；铜矿石 / 钢锭 / 果果之心 / 鹿角 / 麻绳卷 → 假；全集计数 65 / 45（数据改了跟着改断言）。
- 切「无效果」→ `_shown` 全是 `has_effect()` 为假的；左列没有「武器」页签；「全部」的计数 = 45。
- 搜索「剑」→ `_shown` = 制式短剑、长剑、秘银附魔长剑（按当前排序）；搜索「metal」命中所有金属标签的；搜索「zzz」→ 空列表 + 灰字；清空后恢复。
- 在「无效果」+ 搜索「铜」下新建一件带 `combat` 的道具 → 分组、搜索都清掉，列表定位到它。
- 分组 + 标签 + 搜索叠加：「有效果」+「武器」+「刀」→ 匕首、涂毒匕首、放血刀、剁刀、弯刀（按数据）。

## 五、待定（都按推荐）

1. **分组行横排在上，还是并进左列页签顶部三行。** 推荐：**横排在上**，两级关系一眼看清。
2. **页签计数要不要随搜索变。** 推荐：**随**。
3. **搜索要不要同时匹配说明文字 `description`。** 推荐：**不**，说明长、命中太散。
