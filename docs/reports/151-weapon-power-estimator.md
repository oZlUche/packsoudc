# 方案：编辑器里的「当前战斗力」—— 武器威力估算器、推荐稀有度与推荐价值

日期：2026-10-10　状态：架构 · 提议（待作者确认后交「架构方案执行」）　承接：143（格数等比）、145（规则弹窗）、146（构件库）

作者原话（2026-10-10，头脑风暴后定案）：

> 当使用编辑器新建一个道具时，如果该道具为武器，先让玩家在画布（大小最多到 8*8）上规划该道具的形状，然后生成一个默认战斗力，后续玩家设计攻击力和速度时会计算当前战斗力，添加效果会增减当前威力（假如是负面效果就会减，而扳机 / 消耗 / 触发条件对变化值做乘法不改变符号），负重也会降低战斗力，最终生成一个推荐稀有度和推荐价值。

头脑风暴里一并定下的前提：稀有度买的是**预算**不是面板；估算器的输出是**提示与推荐**，不是硬约束（流派件单看偏弱是故意的）；真相由木桩跑分校准；联动价值不进单件估算，另算「组合值」。

---

## 0. 结论（一段话）

新加一个纯函数 `PowerEstimate`（`core/authoring/power_estimate.gd`，只看 `ItemDef`，不碰运行时）：**战斗力 P = (基础 + Σ效果增减) × 负重折扣**。基础 = 直接伤害 DPS（现成的 `estimated_dps`，含暴击期望）；每条规则的每个效果先按「效果估值表」得一个**带符号**的数（打对手、给自己增益为正；伤自己、给自己减益、给对手增益为负），再乘扳机率 × 消耗折扣 × 条件折扣 × 上限折扣（全在零到一之间，**只缩不翻号**）；负重按重量打一个折扣。新建武器时画完形状就有**默认战斗力** = 每格基准 × 格数，并预填一套能打的攻击力与冷却；之后每改一个字段右栏实时重算，列出每一项的贡献，最后给出**推荐稀有度**（战斗力 ÷ 格数预算落在哪一档）与**推荐价值**（按推荐档的每格价 × 格数），一键「采用」写进字段。所有系数放在一张表 `data/authoring/balance/power_weights.json` 里，作者改表不改码；跑分工具多一张「估算 vs 实测」对照表用来校表。

## 2. 公式

### 2.1 总式

```
P = (B + Σ_规则 Σ_效果 V_效果 × T_扳机 × C_消耗 × K_条件 × L_上限) × W_负重
```

- 一切系数来自 `power_weights.json`；本文的数全是**占位**，由作者改表。
- 估算视野 **H**（一场打多久，占位三十秒）：持续类效果按 H 内能跑多久算，永续按 H。
- 每一项都保留在结果里（`PowerEstimate.Breakdown`：基础、每条规则的 V / T / C / K / L 与乘积、负重折扣、总分），右栏要逐项列。

### 2.2 基础 B 与默认战斗力

- `B` = 直接伤害 DPS（`estimated_dps` 的结果，只数 `deal_damage` 对对手的那部分）。
- **默认战斗力** `P0 = 每格基准 × 格数`（每格基准占位二点零 DPS）。新建武器画完形状，预填 `damage = round(P0 × 默认冷却)`、默认冷却两秒、`stamina_cost` 按格数（占位），于是一出生 P ≈ P0；作者改攻击力 / 冷却，P 跟着走。
- 快慢是武器自己的事：伤害 × 频率 = B，战锤慢重、短剑快轻，预算一样。

### 2.3 效果估值 V（带符号）

| 效果 | V（对对手为正，对自己反号：伤自己、减益自己、增益对手为负） |
|---|---|
| `deal_damage` | 现成 `estimated_damage`（含暴击期望；`percent_of` 按假定对手生命算） |
| `apply_status` | 层数 × 该 buff 的「每层价值」：buff 自己规则的 DPS（流血一层每秒一点）× 期望持续 + mods 的价值（见下）；期望持续 = 永续取 H，有时长取 min(时长, H)；`per_stack` 按假定来源层数 |
| buff / `shift_axis` 的属性修饰 | 属性权重表：伤害 +x% = x% × B；防护 / 格挡一层 = 假定受击频率 × 一点 × 持续；生命上限一点 = 一点 × 生命权重；加速 +x% = x% × B；耐力回复一点 = 耐力权重 |
| `change_resource` | 回血 / 护盾：量 × 治疗权重（占位零点五，一点治疗抵半点伤害）；扣对手资源同 deal_damage；扣自己为负 |
| `modify_damage` / `low_hp_empower` | 百分比 × B（低血强化再乘「低血时间占比」占位零点三） |
| `convert_damage_type` | 零（元素抗性落地后改为按目标抗性表） |
| `remove_status` | 清自己的减益 = 该减益的剩余价值为正；清对手的增益同理；清光全部按假定两层 |
| `reflect_damage` | 百分比 × 假定对手 DPS |
| `fire_enchant` | 现成 `estimated_damage` |
| `convert_status` | 目标 buff 价值 − 来源 buff 价值（可正可负） |
| 没登记的效果 | 零，并在右栏标「未估」—— 新效果加一行估值是登记表的事，不是估算器的 |

### 2.4 扳机率 T（每秒次数或时间占比，乘上节奏）

| 扳机 | T |
|---|---|
| `on_schedule` | 节奏频率（`estimated_hz`，含冷却与加速） |
| `on_item_fired` 听自己 | 本件直接攻击的频率 |
| `on_item_fired` 听别人 / LINKED | 假定邻居频率（占位每秒零点五） |
| `on_damage` / `on_before_damage` | 假定受击频率（占位每秒一次）；`crit_only` 再乘假定暴击率 |
| `on_battle_start` | 1 / H（一场一次） |
| `on_resource_below p%` | 时间占比（占位 = p / 100）× 节奏频率 |
| `on_stacks_at_least` / `on_axis_at_least` | 时间占比占位零点五 × 节奏频率 |
| `on_status_applied` | 若本件自己施加那个 buff，取施加率；否则占位每秒零点三 |
| `on_status_removed` | 占位每秒零点二 |
| `on_overtime` | 零（在 H 之外） |

带冷却的非自发规则：T = min(T, 1 / 冷却)。

### 2.5 消耗折扣 C、条件折扣 K、上限折扣 L（零到一）

| 消耗 / 条件 | 折扣 |
|---|---|
| `resource_cost` 耐力 | 可持续比例 = min(1, 耐力回复 ÷ (每次消耗 × T))，回复取基线四 |
| `uses_cost` N 次 | min(1, N ÷ (T × H)) |
| `charge_cost` 每 n 次 | 1 / n |
| `chance_condition` p% | p / 100 |
| `axis_cost` / `status_stack_cost` 吃层 | 占位零点五（吃掉的层本身有价值） |
| `status_condition` / `resource_condition` / `axis_condition` | 占位零点六；`negate` 取一减 |
| 上限 L | 可叠且有上限的 buff：min(1, 上限 ÷ (T × H))；不可叠层：min(1, 1 ÷ (T × 持续))；别的为一 |

**符号规矩**（作者定）：T、C、K、L 只做乘法、全在零到一之间，V 的符号由效果本身决定；所以负面效果永远是减项，条件再苛刻也只是减得少。

### 2.6 负重折扣 W

`W = max(下限, 1 − 重量 ÷ 负重基准)`，负重基准取马库斯的四十八（149），下限占位零点六。重量来自 `ItemWeight.of`（标签档 × 格数），所以重金属大件自然吃亏。

### 2.7 推荐稀有度与推荐价值

- 预算比 `r = P ÷ (每格基准 × 格数)`。
- 档位阈值（占位）：r < 1.15 普通；< 1.5 优良；< 2.0 稀有；< 2.8 史诗；其余传说。神话不推荐（留给手定）。
- 推荐价值 = `BASE_PER_CELL[推荐档] × 格数 × (0.8 + 0.4 × 档内位置)`，四舍五入到五的倍数；档内位置 = r 在该档区间里的相对位置。
- 右栏「采用」按钮把两个数写进 `rarity` / `value`；不按就不动。导入器只在**实际稀有度与推荐差两档以上**时给警告（不拦）。

### 2.8 不做的

- 联动 / 组合值不进这个数（头脑风暴已定）；参考套组跑分另做（见 §4）。
- 不把 P 反推成「最终公式」改数值；数值仍由作者定。

## 3. 编辑器

- 右栏那一行「占 N 格　预估 DPS」换成一块「战斗力」面板：总分大字；下面逐行：基础（直接伤害）、每条规则一行（规则句 + 贡献 ±，悬浮显示 V × T × C × K × L 各是多少）、负重折扣、未估的效果标灰；底部「推荐稀有度 ○○　推荐价值 ○○　[采用]」。
- 表单任何改动（`changed`）重算；145 的规则弹窗里改效果也会经 `changed` 传上来。
- 新建道具时若带 `weapon` 标签（或在新建对话里选「武器」）：先聚焦形状画板，画完（第一次改形状）预填 §2.2 的默认值并弹出战斗力面板。
- 非武器（护甲 / 盾 / 信物）：面板也算（防护、护盾、buff 按同一张表），但第一步只对武器给推荐稀有度；非武器的阈值等有数据再定（待定 2）。
- 样式走主题变体；121 棘轮已顶满，不新增 `add_theme_`。

## 4. 校表：估算 vs 实测

- `tools/bench_battle.gd` 加一种模式：每件武器单独放在「平均玩家」木桩上，对三档敌人各打若干场，输出一张表：id、格数、稀有度、估算 P、实测 DPS、比值。
- 另一张表：参考套组（按流派标签，130 的流血 / 中毒套）的整套实测，减去去掉某件后的实测 = 该件的组合贡献。两张表并排就是「单件值 / 组合值」。
- 比值偏得多的那一类效果 → 改 `power_weights.json` 里对应的系数；不改公式结构。

## 落地记录（2026-10-10，五项待定全按推荐）

- **估算器**：`core/authoring/power_estimate.gd`。`estimate(def, weights, buffs)` 返回 `Breakdown`，里面有基础 B、出手频率、逐条规则（扳机率、消耗、条件、上限、各效果的值和是否未估）、负重折扣、P、格数、默认战斗力、预算比、推荐稀有度（非武器为 −1）和推荐价值。`default_weapon(cells)` 给新建武器反算预填值：冷却两秒、伤害 = 默认战斗力 × 冷却、耐力 = 每格 2 × 格数。
- **偏差 1：`PowerWeights` 和 `PowerContext` 放在 `core/battle`，不在 `core/authoring`**。各效果、扳机、消耗、buff 的估值方法都在战斗层，要用到这两个类；放在 authoring 会让战斗层反过来依赖制作层（依赖方向测试会拦）。`PowerEstimate` 和跑分 `PowerBench` 仍在 `core/authoring`。
- **偏差 2：估值方法统一收一个上下文对象**。方案里写的是 `estimated_value(stats, weights)`、`estimated_rate(host_hz, weights)` 这类签名，实际都改成收 `PowerContext`：里面带系数、属性、自己的 DPS 与频率、站在哪一边（主人 / 对手）、层数、受击还是出手、buff 表、自己上 buff 的频率、嵌套深度。buff 的值要换到「挂着它的那一边」再算（流血挂在对手身上就是对手每秒掉血，对主人为正），一个上下文对象换边最省事。
- **偏差 3：基础 B 不打消耗折扣**。B 只是「按冷却打对手」那一下的每秒伤害，含暴击期望；耐力跟不上的情况由默认武器本身的耐力消耗体现，单看一件武器时不折。
- **新系数 `persist_share`（0.3）**：持续类效果（不可叠的 buff、长时间的 debuff）在三十秒视野里只算三成「一直挂着」的值，否则长时 buff 会把预算比顶到传说。档位阈值调成 `[0.9, 1.35, 1.9, 2.8]`。
- **现有武器**：二十一件里十六件推荐和实际差不超过一档。差两档的五件列在测试的 `KNOWN_OFF` 里，等作者决定改数还是改 `power_weights.json`：
  - 匕首（1 格，普通，推荐史诗）、冲锋枪（2 格，优秀，推荐史诗）：小件伤害密，每格预算比高。
  - 毒匕首（1 格，稀有，推荐传说）：一格上叠毒，预算比 13.7。
  - 剁刀（3 格，优秀，推荐史诗）：便宜的件上了流血。
  - 狙击枪（4 格，史诗，推荐优秀）：单看偏弱，靠暴击 / 组合。
- **对照表**（`godot --headless --script res://tools/bench_battle.gd -- power`）：
  - 单件实测 ÷ 估算在 1.07 ～ 2.0 之间。偏高的都是带 DoT 的（毒匕首 2.0、溃烂之刃 1.95、弯刀 1.89）：木桩打三十秒以上，DoT 叠满的时间比估算视野里假设的长。直伤武器在 1.07 ～ 1.35。
  - 三档敌人的实测一样：木桩不死、不会打断出手，敌人强弱只影响主人掉血，不影响输出。
  - 流派组合贡献多数为负：同一套里的武器共用一个耐力池，凑在一起会抢耐力。这张表现在主要用来看「哪件在套里真有用」（溃烂之刃在流血套里 +44），不是校系数用的。
- **编辑器**：`ui/editor/power_panel.gd` 替换原来那一行 DPS。面板列出 B、每条规则一行（正绿负红、未估标灰）、负重折扣、P、推荐稀有度与价值，「采用」写回。工具条加「新建武器」：带武器标签，画完形状后第一次收集时按格数预填战斗档。面板没有新增任何主题覆写（`add_theme_` 仍是 134）。
- **导入器**：武器有战斗规则、且稀有度和推荐差两档以上时给 `rarity` 提醒，不拦。
- **测试**：`tests/authoring/test_power_estimate_151.gd`，覆盖公式单调性与符号、五成几率减半不翻号、负重与下限、未估记零、流血双向、耐力折扣、推荐档与价值、默认武器出生约等于默认战斗力、系数表缺项 / 多写 / 错类型、现有武器差档、跑分表能生成、导入提醒，以及编辑器面板、「新建武器」和「采用」。

## 补充（2026-10-10，作者）：非武器的护盾、减伤也算价值

作者原话：

> 非武器提供的护盾或者减伤也要作为价值的一部分计算进去

- 公式多一项 D：P = (B + D + Σ V×T×C×K×L) × W。D = 道具自带（基础属性）的护盾上限 × `shield_per_point` + 防护 × `armor_per_point`，两个系数在 `power_weights.json` 里（0.5、3.2）。
- 待定 2 改口：**护具**（带 `armor` 或 `shield` 标签）和武器一样给推荐稀有度与推荐价值，「采用」可按；别的非武器（药、符、材料）照样把 D 算进分数，但仍只看分数。导入器的「差两档」提醒仍只管武器。
- 系数按现有护具定：皮甲（30 护盾，6 格）、圆盾（5 防护，5 格）推荐都是优良，和实际一致；圣盾推荐史诗，也一致。塔盾（重 32）推荐普通、板甲（重 40）推荐普通而实际是稀有 —— 负重折扣对重甲压得狠，等格挡方案（防护只归盾牌、只取最高）落地后一起再调。
- 编辑器的战斗力面板多一行「自带护盾 / 减伤」。
