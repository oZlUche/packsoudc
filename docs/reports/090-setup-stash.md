# 090 · 开局屏的暂存区（带回来的没置入的：出发就没了，回主菜单原样放回）

> demo 打磨 ｜ 架构文档 8、8.2、15 节第 4 项、16（v1.95）｜ 前一步：[089 三个存档位与图鉴缩略图](089-save-slots-and-codex-grid.md)

## 一、作者定的

在开局界面添加一个**暂存区**：包（棋盘）里有东西时，进开局界面那一刻它们被移到暂存区；**进入游戏则失去暂存区里的所有东西**；退回菜单 / 仓库则东西被移回背包（**视为没发生过移动**）。

这里的「包里的东西」= 上一局撤离带回来、还没在基地置入仓库的那块棋盘（`MetaState.board`）。原来的规矩（058 第 7 条 / 061）是没清空就 `can_begin()` 拒绝开新局；现在这道门**撤了**，由开局屏的暂存区接手。

## 二、开局屏（`ui/game/setup_screen.gd`）

- 三栏：左棋盘（初始包）｜ **中暂存区**（`ItemStash`，容器 id `STASH_ID = 110`，只有带回来的东西时才显示）｜ 右仓库。同一层拖拽。
- 进屏 `_build_stash()`：带回来的棋盘上每一件挪进暂存区，`_pending[uid] = {origin, rot}` 记原位。带回来的棋盘随之空了（`has_pending_board()` 为假），但 meta 还没存 —— 中途退出游戏，磁盘上的存档仍是搬动前的样子。
- **落点规则** `_allow_drop`：仓库的东西**进不了**暂存区（进去就等于出发时丢掉）；暂存区的东西能放回暂存区、能进仓库（= 置入）、能上棋盘（要这一章 `allow_carry_in`）；其余照旧。
- 公开动作：`carry_in(uid)` 现在从仓库或暂存区带上；新增 `store(uid)` 把暂存区的一件收进仓库；`carried()` 照旧数棋盘上的非包（含从暂存区带上的，角色的件数 / 稀有度上限一起管）。
- **换角色**：棋盘上带着的都下来 —— 仓库来的回仓库，暂存区来的回暂存区（`_return_carried`）。
- **出发** `depart()`：`GameFlow.begin` 成功后清空暂存区与 `_pending`。带回来的棋盘由 `begin` 清（见下）。生成不出图留在这一屏，什么都不丢。
- **回主菜单** `cancel()` → `_restore_pending()`：带回来的（不管还在暂存区还是已经拖上棋盘）按记下的原位放回 `MetaState.board`（原位放不下就找位置，再不行进仓库）；仓库来的回仓库；**玩家已经拖进仓库的留在仓库**（那是他自己的置入，不算「移动」）。`to_main_menu` 顺手存 meta。
- 暂存区栏的说明文字写明这四条去处。

## 三、流程（`core/run/game_flow.gd`）

- `can_begin()` 现在总是空串（带回来的没清不再拦）；新增 `pending_hint()` 给基地屏一句提示：「上一局带回来的背包还有 N 件没置入：可以现在置入或不要了；不管的话，开局屏里它们会放进暂存区，出发就没了」。
- `begin()`：`RunState.start` 成功后，带回来的棋盘还在就 `discard_board()` 并存 meta —— 「进了游戏就没了」对不经开局屏的路（`begin_direct`、教程）同样成立；`start_next_chapter` 本来就先一键置入，不受影响。
- 基地屏（`meta_screen._refresh`）与仓库面板（`warehouse_panel`）的提示改成上面那句，「再来一局」不再因为没清空而灰掉。

## 四、测试

- `tests/test_character_setup.gd` 新增 `frame_setup_stash`：仓库有一件、带回来的棋盘三件 → 进开局屏三件进暂存区、棋盘空、仓库没动、栏显示件数；落点规则四条；带上一件 / 收进一件 / 留一件；换角色带上的回暂存区；再带上一件暂存区的和一件仓库的 → 回主菜单：带回来的两件按原位回棋盘、收进仓库的留在仓库、仓库来的回仓库、存盘里棋盘在；再进开局屏两件进暂存区，带上一件出发 → 一局里有它、带回来的棋盘清了、暂存区空、仓库没动、存盘里也清了。
- `tests/test_meta_grid.gd` `run_flow_gate`、`tests/test_game_flow.gd`：原「没清空开不了新局」改为「也能开」。
- 全套 **63 个套件、11256 项断言**通过。

## 五、留给作者

- 「回主菜单视为没发生过移动」我按**自动那一步**理解：玩家自己拖进仓库的留在仓库。要是想连这一步也回退（回主菜单时把置入的也放回棋盘），`_restore_pending` 里按 `_pending` 把仓库里的也捞回来即可，一处改。
- 基地屏的「一键置入 / 剩下的不要了」还在：想立刻清的照旧在那儿清；不管它直接开新局也行了。

## 六、附：悬浮窗侧窗压主窗（作者截图）

主窗贴着屏幕左边时，词条侧窗压在了主窗上。根子在 `HoverTip._place`：主窗和侧窗各自「出屏就翻、翻过头就夹到 0」，两个都夹到 0 就叠在一起；而且「屏」取的是提示层自己的尺寸 —— 背包浮窗那种比屏窄的宿主里，一开始就判定右边放不下。

改法（`ui/inventory/hover_tip.gd`）：主窗 + 词条列当**一组**摆 —— 先试鼠标右边（主窗贴鼠标、侧窗在它右边），放不下再试左边（主窗贴鼠标、侧窗在更左），两边都放不下就整组夹进屏里、侧窗在右；不再各自夹边，所以永远不叠。「屏」按真正的视口算（`get_viewport_rect()` 换到本控件坐标）。`tests/test_text_and_tooltips.gd` `frame_hover_tip` 补了两组断言：宿主只有 200 宽、鼠标在左边 → 侧窗在主窗右边、不叠、不出屏；鼠标靠屏幕右边 → 也不叠、侧窗在某一侧。全套 63 个套件、11263 项断言通过。
