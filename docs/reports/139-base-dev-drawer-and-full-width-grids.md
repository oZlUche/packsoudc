# 139 方案：基地屏右侧的开发栏改成箭头抽屉；仓库与图鉴的格子占满整行

- 日期：2026-10-07
- 提出：作者（架构设计线程），附截图（基地「仓库」页：左边 10 × 14 的仓库格子，右边一整列开发开关 / 局外解锁 / 科技等级 / 最近几局）
- 性质：架构 · 提议（本线程只写方案，不实现、不跑测试）
- 作者原话：「右边的调试台改成额外的伸缩界面（点一下箭头打开再点一下关闭的哪种），仓库和图鉴的格子占满整行」

## 一、现状（`ui/game/meta_screen.gd`）

- 「仓库」页是一行 `HBoxContainer`：左 `WarehousePanel`（仓库格子 + 带回来的背包），右一列 `VBoxContainer` 占满剩余宽度（`SIZE_EXPAND_FILL`），里面从上到下：
  开发：局外 buff 开关（非导出包）、局外解锁开关、科技等级数字框（非导出包，119）、**最近几局**（所有包都有）。
- 仓库格子 `InventoryView` 的格子是全局常量 **`InventoryView.CELL = 60`**，10 列 = 600 像素，`SIZE_SHRINK_BEGIN` 靠左；右列拿走了其余一千来像素。
- 「图鉴」页的缩略图网格 `GridContainer.columns = CODEX_COLS（8）`，缩略图 `CodexTile.SIZE = 96 × 112`，一行 8 个约 830 像素，右边空着。
- 「出售」「科技」页各自也有一块仓库视图（`_sell_view`、`tech_panel` 折叠的仓库），都是同一个 60 像素常量。

## 二、改成

### 2.1 开发栏 → 右侧抽屉

- 右列整个（开发开关、局外解锁、科技等级、最近几局）搬进一个 **`DevDrawer`**（`ui/game/dev_drawer.gd`，一个 `PanelContainer`），默认**收起**。
- 屏幕右缘一个竖长的箭头按钮「◂」（收起时）/「▸」（展开时），固定在头部那一行的最右边（和「基地」标题、页签同一行），**点一下开、再点一下关**。
- 展开时抽屉从右边**盖在页面上**（`Control` 放在 `margin` 之上、锚到右缘，宽 420，高占满），不把下面的格子挤变形；收起时 `visible = false`。抽屉自己能竖向滚（里面已经很长）。
- 抽屉在五个页签都能开（它是屏幕级的，不属于「仓库」页）。
- 导出包里：开发开关与科技等级本来就不建，抽屉里只剩「局外解锁」和「最近几局」—— 照旧放抽屉里（待定 1）。
- 开关状态只记在本屏（换页签不变、离开基地屏再进来默认收起），不进设置。
- `tech_panel` 里「仓库 ▸ 展开 / ▾」那种文字按钮的写法沿用，不另造控件。

### 2.2 仓库格子占满整行

格子大小是全局常量，拖拽层（`drag_layer.gd`）、地上那层、滚动框、冷却覆盖层二十多处按它算像素。要让基地屏的仓库横向撑满又不动别的屏，做法是**每个视图自己的格子大小**：

- `InventoryView` 加 `var cell_px: float = CELL`（默认不变），`cell_at_local` / `cell_origin_px` / `custom_minimum_size` / `_draw` 里的 `CELL` 改读 `cell_px`。
- `DragLayer` 凡是**对着某个视图**算的地方（`target_origin`、吸附落点、投影 / 残影画在视图上的那几处）改读 `view.cell_px`；拖拽中跟着光标的残影和抓取偏移仍按起点视图的 `cell_px`（同一屏里两块视图一样大，看不出差别）。`ScrollBox.wrap` 的最小尺寸也按视图的 `cell_px`。
- `GroundLayer`、`CooldownOverlay`、`InventorySandbox`、开局屏读数照旧读常量（它们不在基地屏上，格子仍是 60）。
- 基地屏：`WarehousePanel` 在 `resized` 时算 `cell_px = clamp(floor((可用宽 − 14) / 仓库列数), 60, 96)`，仓库格子和「带回来的背包」的棋盘用同一个数；右侧没有了开发栏，可用宽就是整行。10 列在 1920 宽下约 96 像素一格（封顶），仓库从 600 像素宽变成约 960；再宽就居中（待定 2）。
- 「出售」页的仓库视图同样撑满；「科技」页折叠的仓库跟科技树并排，保持 60。

### 2.3 图鉴占满整行

`columns` 不再是常量：`scroll.resized` 时 `columns = max(1, floor((宽 + 8) / (CodexTile.SIZE.x + 8)))`，特殊道具那一格网格同理。缩略图大小不变。

## 四、测试

- 基地屏打开：抽屉不可见；按箭头 → 可见、按钮变「▸」；再按 → 收起。`tech_spins_of()` 之类给测试的口子在抽屉展开前后都能拿到（节点在树里，只是不可见）。
- 仓库页在 1600 宽下 `cell_px` ≥ 90、视图宽 ≈ 列数 × `cell_px`；拖一件到仓库某格，落点和光标所在格一致（按 `cell_px` 算）；双击置入照旧。
- 图鉴页：1600 宽 → 列数 ≥ 14；窗口缩到 900 宽 → 列数变少、不横向滚。
- 其余屏（地图背包、战前准备、开局）`cell_px == CELL`，现有拖拽测试全绿。

## 五、待定（都按推荐）

1. **「最近几局」留在抽屉还是放回仓库页底部。** 推荐：**抽屉**，作者把整列叫「调试台」。
2. **格子封顶 96 还是不封顶一直撑满。** 推荐：**封顶 96**，再大道具名字和格子比例失衡；超出部分居中。
3. **抽屉盖在页面上还是把页面挤窄。** 推荐：**盖上**，开关抽屉时格子不重排。

## 追加（2026-10-09，作者）：仓库格子封顶改小

作者：「仓库单个格子面积太大，稍微改小（不用恢复原状），大概在原来的 1.5 倍到现在的 2/3 之间」。
原来一格 60，1.5 倍 = 90；现在封顶 96，2/3 = 64。取中间：**`WarehousePanel.CELL_MAX` 96 → 80**（原来的 1.33 倍、现在的 5/6）。
只改这一个常量与它的注释（`ui/game/warehouse_panel.gd:6, 15`）；下限 60、按宽度算、超出居中都不动；1920 宽下仓库约 800 像素宽。测试里若有对 96 的断言跟着改成 80。小修即可。
