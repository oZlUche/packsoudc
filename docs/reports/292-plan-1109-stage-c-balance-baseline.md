## 一、先看结论

1. **扫表的档 2、档 3 不代表真实地图**（最要紧）：`bench_matrix` 用一个没有区域（`kind`）、危险度 0 的空战斗点抽敌人，池子里写了区域或 `min_danger` 的敌人全被排除。`standard_ruins` 档 3 于是只剩 brute 一种（500 / 500 场）；`clockwork` 档 2、档 3 只剩两个强度 1 的敌人。下面所有档 2～3 的格子都要按这个读。
2. **brute 在档 3 很难打**：同段同档（★）的胜率段 0～2 在 55%～96%，段 3（全是 brute）0%～34%，五路平均 15%。档 3 的配装一次多了三样：蓝色武器、真实伤害武器、格挡 ×1.75。
3. **仗打得太短**：★ 格平均 2～10 秒，实测时长中位 2.2 秒；估算表假定一场 12 秒（`fight_sec`）、30 秒（`horizon_sec`）。耐力类加成在这么短的仗里几乎不起作用：兵刃变体 drill / sun 的胜率差 0～3 个百分点。
4. **机关沙漏看起来比自由模式容易，但这是第 1 条的假象**：两张图同时解锁（都只要 `prologue3_done`），机关沙漏 ★ 格段 3 有 37%～95%；可它的档 3 实际抽到的是强度 1 的 steam_turret 和 tinker_apprentice。

## 七、引擎：连锁触发截断（已修）

**现象**：几张表跑出来几千条「单帧连锁派发超过 256 条，已截断」（旧输入 867、当前输入 3626、机关 2512、猎手 8674、武器实测 7638）。`standard_ruins` 当前输入里有 1305 场至少截断一次，多数是 brute，也有 berserker、butcher、pit_viper、marksman、tracker、assassin。

**原因**：`bonesteel_broadsword`、`ironwood_steel_sword` 这类阔剑带一条「其他道具出手时 → 攒下一下」（`on_item_fired` + `prime_next_hit`）。规则放出效果就算这件出手、会再发一条出手事件；两把同时在场，A 的出手触发 B，B 的出手又触发 A，一直到 256 条截断。截断会**清掉整条队列**，同一刻别的事件也一起丢了。108 修过「听自己出手」的单件自环，两件以上的环没拦。

**修法**（`RuleEngine._settle`）：一次出手带起来的这一串连带出手里，每件**最多出手一次**；已经出过手的件再被这一串触发，效果照放，只是不再发出手事件。出手事件带上这一串的根（`chain`，最先那一下的 seq），`BattleContext.cascade` 记这一串里谁出过手，一轮排空后清空。每次出手的事件数从「可能无限」变成「最多在场件数」。

**影响**：按最终代码重跑了两池扫表、hunter_1 和武器实测：胜率、时长、余血、实测 DPS **逐格逐件一致**，截断警告全部归零。武器实测从 271 秒降到 67 秒（组合表里十几件互相听，原来每次出手都打转到上限）。

**测试**：`test_effect_system`「连带触发与派发保护」：两件互相听 → 1、2 各出手一次、效果各放一次、不截断；七件都听「其他道具出手」→ 共 7 次出手、不截断、记录清空；派发上限设成 1 仍然兜底。
