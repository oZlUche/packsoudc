# 194 · 铸牌（铸炉）三条：入口并列进休息点选项、三槽逐槽实时显示、映射表重复度清单（给作者过目）

> 架构设计线，2026-10-18 晚。作者原话：「触发界面应该和其他选项并列，而不是休息后独有的」「应该实时显示每个字段的效果，而不是三个放进去后再显示」「当前重复性太高，整理一个列表出来让我过目」「铸牌的界面需要替换（留到待办，和整个休息点的 UI 重新设计放在一起）」。§1 / §2 直接派执行；§3 是清单，作者过目后再定改哪几行（本线程照改表、执行只跑导入）；§4 记进待办。

## 1. 入口：铸炉成为休息点事件的一个选项，不再藏在「歇完之后」
**现状**：铸炉按钮在休息屏（`rest_screen.gd`）里——只有选了「歇一会儿 / 扎营」、回完体力那一屏才看得见；神坛早就是事件选项（`open_altar`），铸炉却不是，所以「不歇就铸不了」。

**改法**（照神坛那一套）：
- 新后果 `OpenForge`（`core/run/events/outcomes/open_forge.gd`）：`ctx.open_forge = true`；`NodeEvents` 事件结算处（`node_events.gd:399–407` 处理 `proceed` / `open_altar` 的那段）加 `elif ctx.open_forge: forge_opened.emit(node)`；`GameFlow` 订 `forge_opened` → `_push({"screen": Screen.FORGE, "node": node})`（和 `rested` → REST 同款，`game_flow.gd:1286`）。
- 新条件 `ForgeUnused`（`core/run/events/conditions/forge_unused.gd`）：`not NodeEvents.forge_used(ctx.node)`，`describe()` =「这座铸炉已经用过了」。
- `rest_default.json` 加一条选项，排在神坛后面、「继续赶路」前面：
  ```json
  {"label": "铸炉（三件道具熔成一枚铸牌）", "hide_when_locked": true,
   "requires": [{"type": "forge_unused"}], "outcomes": [{"type": "open_forge"}]}
  ```
  选项文字按 185 只写名字与效果，不解释机制（三槽那段话留在铸炉屏里）。
- 铸炉**不算用掉休息那一份**（和「继续赶路」一样，`settle_rest` 只看 rest / altar 两份）；铸过了选项自动藏起（`hide_when_locked`）。
- `rest_screen.gd` 删掉「铸炉」一栏和按钮，只剩回体力那句 + 继续；`GameFlow.open_forge()` 留着给测试 / 调试台。
- 两个新构件登记进 `RunRegistry`（EVENT_OUTCOMES / EVENT_CONDITIONS）与编辑器下拉；`docs/text-placeholders.md` 的构件表补一行。
- 测试 `tests/run/test_forge_194.gd`：休息点事件的选项里有「铸炉」且在神坛后；选它进 FORGE 屏、休息那一份仍未用；铸过后再进点选项消失；休息屏不再有铸炉按钮。

## 2. 三槽逐槽实时显示
**现状**：`forge_screen._refresh()` 只在三槽都满时算 `Forge.forge()` 写一句「将铸出……」，否则写「还差：【…】」。调一件要先凑齐三件才看得到变化。

**改法**：每个槽下面挂一块三行小字（`rich_block`，13 号），放进一件立刻写**这一件在这个槽里贡献的字段**，拿走就清：
- 新查询 `Forge.slot_summary(slot: StringName, def: ItemDef) -> Array[String]`（纯函数，测试直接调），按三张表的行组句：
  - 时机槽：「什么时候：{trigger.describe()}」「方向：造成 / 受到 / —」「多久一次：{cadence 描述}」。方向只对「受伤时」「受伤前」两种扳机有意义，别的扳机写「—（这种时机不分方向）」；皮革（开战时）固定一次，写「一次（开战时不看稀有度）」。
  - 效果槽：「做什么：{effect 的短句}（前缀「嗜血的」）」「给谁：对手 / 自己 / 只能给自己」「阶：基础 / 升阶（{upgraded 短句}）/ 升阶并附带（{bonus 短句}）」——没有 `upgraded` 的行在升阶那一档写「升阶：没有变化」，让作者在界面上就看见 §3 说的空档。
  - 数值槽：「档：×{size}（稀有度 N）」「材质 ×{mult} · 用途 ×{mult}」「合计 ×{乘起来}」。
  - 短句复用 `AdjacencyText` 的效果 / 扳机片段（171 的句子生成），不另写一套文案。
- 三槽都满时原来的「将铸出：…」照旧；**两槽满时**也给一句灰字「按空槽的默认行：将铸出 …」（空槽用 `default` 行补齐算一次 `Forge.forge()`，需要 `forge()` 接受 null 走 default——加个 `preview := true` 参数）。
- `InventoryView` 槽的 `changed` 已经连着 `_refresh`，不用新信号；三块小字由 `_refresh` 一起刷。
- 视觉：小字用 `@tip_meta` 色、数值 `@val`，深浅跟铸炉屏现在的底（这块界面本身在待办 §4 里会重做，这里不做美术）。
- 测试：放进一件金属武器到时机槽，`slot_summary` 三行含「出手时」「造成」「6 秒」；效果槽放骨制品含「流血」「嗜血的」；数值槽放稀有度 2 的金属含「×2」「×1.25」；两槽满时预览句非空且含「默认」。

### 3.5 重复点
1. **一半道具是「default」**：50 件没有材质标签（食物、材料、零件、药剂、珍宝……多数是 122 的来源类标签 工艺 / 自然 / 魔法 而不是材质类），放进任何槽都读 default 行——时机 = 出手时、效果 = 伤害 2「附魔的」、数值 ×1。再加 77 件用途 default，**随手三件铸出来大多是「附魔的：出手时 伤害 2」**，这是「重复性太高」的主因。
2. **时机的方向槽几乎无效**：方向只对骨（受伤时）、宝石（受伤前）两行有意义；对出手时 / 开战时 / 按节拍 / 施加状态 / 资源低于 40%，用途槽放武器还是盾毫无区别。盾与防具又是同一行。
3. **效果的稀有度只有三档且升阶大多空**：0 与 1 同、2 与 3 同；「升阶换成」只有血肉一行写了（中毒 → 剧毒），其余七行放稀有度 0 和稀有度 3 的效果件完全一样（差别全在数值槽）。
4. **附带效果互相抄**：骨的附带 = 伤害 2 ≈ 金属的基础；金属的附带 = 流血 = 骨的基础；皮革 / 木 / 石三行的附带是对方的基础（护甲 +2 / 生命 +2 / 护甲 +2）；default 的基础 = 伤害 2 = 宝石去掉元素。八行里真正不同的「基础」只有 6 种，「附带」只有 4 种。
5. **数值表三行是空行**：骨 ×1、盾 ×1、防具 ×1 和 default 一样；材质 × 用途 8 种组合只产生 ×1 / ×1.2 / ×1.25 / ×1.5 四个倍率。稀有度五档是这张表唯一真正起作用的列。
6. **用途在效果表对「只给自己」的三行无效**：皮革 / 木 / 石 `self_only`，放武器还是盾都给自己。
7. **木制、血肉两行没人能用**：没有道具带这两个材质标签（血肉之物的道具都归 `trophy` / `food`，木制的归 `material` / `nature`），这两行现在只是文档。
8. **稀有度 4 的件只有 1 件**：「升阶并附带」与「每次触发」「×4」三档几乎到不了。

有效空间粗算：时机 7 种扳机 × 4 档节奏（皮革固定）≈ 20 种；效果 6 种基础 + 1 种升阶 + 4 种附带 ≈ 12 种有区别的结果；数值 4 倍率 × 5 档 = 20 档。看着是 8 × 4 × 5 三张表，玩家手上常见的三件料真正能铸出的不同铸牌不到二十种。

### 3.6 可以改的方向（供作者圈选，不是定案）
- 甲 **给来源类标签也配行**：工艺 / 自然 / 魔法 三行进三张表（例如 自然 → 时机「施加状态时」、效果「回春」；魔法 → 时机「按节拍」、效果「按元素」；工艺 → 数值 ×1.5），50 件 default 立刻分成四类。
- 乙 **方向槽改成对所有扳机都有意义的字段**：用途决定「对手 / 自己」已经在效果表里了，时机表的用途改成决定**节奏修正**（武器 −1 秒、盾 / 防具 +1 层数之类）或者干脆去掉这一列，少一个无效槽。
- 丙 **每行都写满三档**：升阶换成（流血 → 大量流血、火焰 → 爆燃……）与附带各自不同，且附带不再抄别行的基础。
- 丁 **盾 / 防具分开**：盾 → 格挡 / 弹开，防具 → 护甲；数值表给盾 ×0.8 防具 ×1.2 之类，让两行不同。
- 戊 **删掉没人能落的木制 / 血肉行**，或者给几件道具补上这两个标签（骨头汤 / 肉干 → 血肉？木柴 / 木盾 → 木制）。
- 己 **稀有度 1 与 0、3 与 2 分开**（效果阶改成 0 / 1 / 2 / 3 / 4 五档，或至少 0–1 / 2 / 3 / 4 四档）。
