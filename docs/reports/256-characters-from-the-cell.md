# 256 角色重梳：从「一格」出发 —— 四个问题、三人重排、新角色的顺序与机制

作者（2026-10-26 13:59）：「我并不认为给每个角色设计短板是必须的，因此初始的三个角色没必要有短板。短板是用于改变游玩决策的设定，不要盲目的添加。重新梳理现有的角色和角色方案，从一个核心玩法要素开始，然后拓展并落实机制」。

本篇只写方案，不实装。三人的短板已另派 255 补充三撤掉（`flaw` 改选填）。

## 〇、先定规矩（据作者原话改 136 / 254）

1. **短板不是必备项。** 136「外加一条明确的短板」作废。短板只给「改了它玩家就换一种打法」的角色；只是数值减一点的，写进基线就好，不另立一行。
2. **角色从一个核心要素长出来。** 每个角色先回答「对这个要素，他的态度是什么」，再配面板与被动；被动里**至少一条直接作用在核心要素上**，另一条是辅助。
3. 其余不变：角色 = 初始面板 + 技能（136），科技全局（149），主动藏着（166），包是玩家财产不是角色的（225 / 255），随身之物 / 缺格可用（255）。

## 一、核心要素选哪个：**一格**

核心循环（架构文档 §0）：进图 → 遭遇 → 搜刮 → **受背包格子限制做取舍** → 深入或撤离。战斗、搜刮、撤离三件事最后都落到同一处：**棋盘上的一格放什么**。打得赢不赢是格子里东西的邻接，拿不拿是格子够不够，撤不撤是格子里的东西值多少。所以选「一格」当要素，而不是选战斗或撤离：那两样都是格子的后果。

每一局玩家对「一格」反复回答四个问题，角色就按这四个问题分：

| 问题 | 玩家在想什么 | 现成的系统 |
|---|---|---|
| **甲 有多少格、什么形** | 棋盘大小、缺格、包怎么铺 | `board_size` / `board_mask` / 包架 / 负重 129 |
| **乙 放什么** | 值不值得带、重不重、要不要留空 | 带入预算 225、负重三级、稀有度、信物休眠 |
| **丙 放在哪** | 邻接、成套、装载、随身之物 | `AdjacencyProfile` 的增益 / 受益 / 装载格、`fixed_items` |
| **丁 带出多少** | 撤离点、卖价、战败保什么 | 撤离点、出售 0.3 / 0.5（251）、`keep_on_death`、保险箱 |

**一个角色认领一个问题**，用一条被动把这个问题的答案扭一下，玩家选了他就得换一种摆法。四个问题四个角色是一组；现有三人占甲、乙、丙，丁空着 —— 第四个角色从丁来。

## 二、现有三人重排

数字沿用现值（136 调过），只动被动。每人「核心被动」是新构件，「辅助被动」从现有两条里留一条，另一条退掉（退掉的放在待定，作者说留就留成第三条）。

## 四、机制落实（三个新构件 + 两个现成的）

### 4.1 「棋盘被动」构件 `BoardEffect`（新，三人共用）

现有 `RunEffect` 只读 `RunContext`，看不见棋盘；`AbilityRule` 只看自己这件。三人的核心被动都要**数棋盘**，所以加一类构件：编译玩家时（`BattleCompiler.compile(board, …)`）把角色的 `BoardEffect` 跑一遍，拿到 `GridInventory`，产出 `StatModifier`（挂到单位或指定道具）或 `RunContext` 的数（逃跑、感知）。

```json
{"type": "board_fill", "per_cells": 10, "mods": [{"stat": "armor", "flat": 3}]}                       // 布鲁图斯 满载：开战护甲，按占格数
{"type": "board_empty", "per_cells": 4, "flee_percent": 5, "stealth_percent": 5}                     // 安德烈乌斯 轻身：进 RunContext.flee_bonus / stealth，棋盘变了就重算
{"type": "row_allies", "tag": "weapon", "mods": [{"stat": "haste", "mult_category": 3, "mult_percent": 8}]}   // 马库斯 军阵：按横排相邻同标签数，挂到每件
```

- `board_fill` / `board_empty` 数的是 `GridInventory` 里**被包覆盖的格**：占住 = `cell_at` 有普通物品；空 = 覆盖但没物品。随身之物算占住；缺格不算。
- `row_allies`：对每件命中 `tag` 的物品，取它占的每一行，看左右紧邻（`absolute_cells` 的 x ± 1、同 y）是否有另一件命中 `tag` 的物品；战友数 = 不同物品的个数；`mods` 乘战友数挂到这一件。悬浮窗写「军阵 ×N」（走 132 受益规则那一路的显示）。
- `board_empty` 不在战斗里，在 `RunState.refresh_encumbrance` 同一处（棋盘变了就重算）写进 `RunContext`；猎手与逃跑已经读那两个数。
- 注册进 `RunRegistry` 新表 `BOARD_EFFECTS`，`RunSkill.passive` 允许混放（`RunSkill.board_effects()` 筛出来）。编辑器自然能编；字段文案进 `field_text`。

### 4.2 行商用现成的

`sell_ratio_mult`（254 §四已列、要加：`MarketRules` 的局内 0.3 × 它）、`shop_price_mult`（现成）、`keep_on_death`（现成）、`battle_reward_mult`（现成，写 0.5 就是短板）。

### 4.3 面板与选角色卡

- 选角色卡（255）：三人没有短板行；行商有一行，用裂纹纹样。
- 技能图标：满载 / 轻身 / 军阵 / 行商 / 押金 五枚新图（美术）；退掉的三枚图留在目录不用。

### 4.4 数值的说法

数字全走 `{占位}`（text-numbers-from-fields）；推荐值只是起点，242 的平衡台架跑过再调：满载在 9 × 6 铺满 ≈ 54 格 → +15 护甲，相当于一件中甲；轻身全空 42 格 → +50% 逃跑，捡到一半就剩 +25%；军阵三把剑一排 → 中间那把 +16%、两边 +8%。

## 五、顺序

1. **255 补充三**（已派）：撤三人短板，`flaw` 选填。
2. **256 第一批**：`BoardEffect` 三种 + 三人被动重排 + 五枚图标占位 → 执行；图标 → 美术设计。
3. **256 第二批**：行商（第四人）—— 面板、四条、头像（美术）、`sell_ratio_mult`。
4. 之后按 §三 的顺序：军团魔法师（用 255 的缺格 / 法印）→ 盾卫 / 弃信者 / 奴隶孩童 / 猎人 → 堕化版。

## 六、待定（默认按推荐）

1. 退掉的三条被动（野地里长大 / 溜得掉 / 军功）：推荐**退**，让每人两条都和核心有关；作者要留就各留成第三条。
2. 核心要素选「一格」而不是「撤离」或「战斗」：推荐**一格**（§一）。选撤离的话四个问题会变成「走多深 / 什么时候走 / 走哪条 / 带什么走」，角色就按行程分 —— 也能做，但现有系统里行程的构件最少。
3. 行商是否第一批就做：推荐**第二批**，先让三人的新被动在台架上跑一轮。
4. 军阵只认横排：推荐**只横**（竖排会让 1 × 3 的长武器天然成阵，没有取舍）。

## 七、测试

1. 满载：9 × 6 铺 30 格 → 开战护甲 +9；地上的不算；随身之物算。
2. 轻身：7 × 6 盖 42 格放 2 件（占 6 格）→ 36 空 → 逃跑 +45%；拖一件上去立刻重算。
3. 军阵：三把剑横排 → 中间 +16%、两侧 +8%；竖排 0；中间隔一格 0；悬浮窗写「军阵 ×2」。
4. 三人开局无任何短板 buff；行商有且只有「战利品 ×0.5」；行商局内卖价 0.5、商店 0.85、战败剩一半钱。
5. 选角色卡：三人无短板行；行商有；五枚技能图标各有占位。
