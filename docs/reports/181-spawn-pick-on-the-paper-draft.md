# 181 讨论稿：开局挑出生点的引导 —— 在铺开的纸上先挑，再拉近到所选入口

> 架构设计线程，2026-10-17。头脑风暴，不派发；作者选定后再按所选写定稿。
> 起因（作者 15:17）：「开局需要一个更显眼的引导方式，现在这种缩小地图强行显示三个点的方法和新的开局冲突」。

## 1 现状与冲突

- 挑出生点（`RunState.Phase.PICK_SPAWN`，096 / 121）：进图时 `frame_spawns()` 先把缩放压到所有出生点都装得下，再把那一团按相对位置摆在屏上；全图蒙灰 0.8，只露出生点（绿圈、脉动、顶部一行「挑一个出生点」）；右侧「路线」盒列三张卡（出生点 N · 风格 → 核心 / 撤离点，风险 / 收益），悬停加粗对应路线。
- 180 批三的入局转场：纸从预览半径化开、镜头从预览圈距**拉近**到平时视角、节点按离出生环的远近一环环长出、装饰层浮现；最后一环长全之后灰罩才盖上。
- 冲突有三处：（a）镜头先拉近再被 `frame_spawns` 拉远，一进一出；（b）刚浮现的装饰画立刻被灰罩压掉，转场白做；（c）大图（12 环）为装下三个点要缩到 0.29，节点半径只剩 5 像素，出生点反而不显眼。根子是：**挑点需要全图视角，转场的终点是局部视角**，两个要求绑在同一个瞬间。

## 2 思路

### 甲（推荐）：在铺开的纸上先挑，挑完再拉近

把「挑出生点」放到转场**中间**，用转场天然的全图时刻来挑：

1. 出发 → 纸化开、虚线圈显出（180 转场的前半段，镜头**不动**，仍是预览那个全图视角，所有出生点天然都在屏内）。
2. 纸上只「画出」三样东西：三个入口标记（屏幕空间定长，不随缩放缩小）。其余节点、边、装饰一概不画 —— 这张图还没画完，只有入口已经标好。这就是引导：满纸空白只有三处印记，比灰罩明显得多。
3. 悬停一个入口：它的路线以墨线一圈圈画到终点（核心 = 打 BOSS / 撤离点），旁边立一张小纸签写风格、风险、收益（现在路线卡的内容搬上纸，右侧路线盒可留可删）。
4. 点选 → 转场后半段开始：镜头**拉近到所选入口**（不是拉近到图心），节点从所选入口所在的环一环环长出（`node_front` 的排序本来就按「离出生环几环」算）、装饰层浮现、HUD 最后出来。
5. 读档回到 PICK_SPAWN 阶段：直接摆在第 2 步的状态（全图、只有入口标记），不播前半段。

好处：没有灰罩、没有一进一出、出生点在最显眼的时刻独占画面，「拉近」有了对象（拉近到你选的门）。改动都在 `MapScreen` 的转场时间线与 `MapView` 的「只画入口」分支，核心层不动。

要点：入口标记用屏幕空间定长绘制（和现在灰罩里的圈一样），美术给一张入口印记（旗 / 蜡印 / 门楣，三个入口可同图换色）与纸签底；大图上三点相距远也看得清。

### 乙：在第三页就挑

第三页预览画的已经是真图，把三个入口印在晕染区里，悬停看路线、点选即定；摘要加一行出生点；出发直接是 ON_MAP，转场一口气拉近到所选入口。

比甲省一个「转场中途等输入」的状态，但晕染区小（小型图直径约 440），入口与路线挤在一起；第三页已经承载地图 / 规模 / 难度，再加一个要看风险收益的决定会重。适合作者觉得「挑点本来就是开局配置的一部分」时选。

### 丙：不挑，固定或随机入口

`ChapterDef.auto_spawn` 已有（序章在用）。最省，转场完全不受影响；代价是丢掉 121 设计的路线风险 / 收益选择。只在作者想砍掉这个决定时考虑。

### 丁：保留现状结构，只换罩子的画法

灰罩改成「未画完的草图」：除出生环外全图淡墨，镜头仍在最后拉远装下三点。只治（b），不治（a）（c），不推荐。
