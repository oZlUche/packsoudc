## 第一批 · 元素印与反应表

### 1.1 印

五个元素：火、冰、雷、毒、血。**毒与血的印就是现有状态层**（中毒 / 流血，130），不另记账；火、冰、雷各加一个轻状态当印：【灼】【寒】【麻】（`BuffDef`，可叠，几秒衰减，本身只做标记，不伤不减）。伤害类型定义里加一个字段 `mark`（`fire → scorch`、`ice → chill`、`lightning → numb`），管线第 5 步命中后按类型盖印；`apply_status` 施加中毒 / 流血本身就是盖印。物理没有印。

**元素来源不止法杖**（作者）：任何带元素伤害类型的武器；108 的附加（火箭、毒箭：挨着远程武器就让每一箭带印）；投掷弹（腰带技能 160 或 `on_battle_start` 一次性规则）；附魔（第三批的铸牌，效果为元素时每次出手盖印）；晶石（第二批）。规则层一行不加，印是伤害类型与状态的副产品。

### 1.2 反应表（定稿名）

目标身上有甲印、这一下带乙印 → 反应，**两印都消耗**。效果走现有规则内容，不加效果类型（菌血例外，见待定 1）。数值全是占位，由执行线程按 103 的数值约定填并过一轮金样。

| 组合 | 名 | 效果 |
|---|---|---|
| 火 + 毒 | 爆燃 | 吃掉中毒层，按层数一次火伤，再盖灼烧 |
| 火 + 冰 | 淬裂 | 对方护甲清零 + 固定伤 |
| 火 + 雷 | 过载 | 自己下一次出手伤害翻倍 |
| 火 + 血 | **燃血** | 对方几秒内治疗无效 + 固定伤 |
| 冰 + 雷 | 超导 | 对方几秒内受伤倍率上升（破绽层） |
| 冰 + 毒 | **凝毒** | 对方身上的中毒**无法被清除**（`remove_status` / 解毒剂对中毒失效）且层数不衰减，直到寒印消失 |
| 冰 + 血 | 冻疮 | 对方几秒内出手间隔拉长 |
| 雷 + 毒 | 电解 | 中毒升阶为剧毒（130 的转化件） |
| 雷 + 血 | 激荡 | 自己下一次攻击必定暴击 |
| 毒 + 血 | **菌血** | 几秒内，**对方每次恢复生命时**：恢复量减半，减掉的那一半变成中毒伤害（待定 1） |

同元素再碰 = 加深一层。数据 `data/authoring/reactions/<甲>_<乙>.json`：`{elements: [a, b], name(s), description(s), consume: "both", effects: [规则内容…], duration}`；`ReactionResolver` 挂在 `DamageResolver` 第 5 步之后，以攻击方为来源发一条临时规则。130 的「溃烂之刃」那条桥收进菌血，道具改成「出手时盖血印」。

### 1.3 可见性（验收项）

回放里反应弹字（名字 + 170 的描边字色）；悬浮窗武器句后加一行「可引发：爆燃、燃血……」（按棋盘上其他武器的元素算）；百科新页「反应」，触发过的才点亮；对阵屏（157）在敌人武器上标元素图标。

### 1.4 第一批测试

印：火伤盖灼、施加中毒即毒印、物理不盖；衰减到期消失。十对反应各一例：触发、两印消耗、效果落地；同元素加深不反应；凝毒期间解毒剂无效、层不衰减、寒印到期恢复；菌血期间治疗减半并转毒伤；燃血期间治疗为零。反应不再触发反应（本次结算内不盖新印）。金样重录并写明原因。

## 第二批 · 法杖：无晶石读基础，有晶石顺时针轮读，单次 CD + 总 CD

### 2.1 规则（作者定）

- **没有晶石**：法杖就是木棍 —— 按自己的 `base_stats` 与规则出手（现状 1.2 秒一下、物理）。
- **有晶石**：每一轮**按顺时针顺序**逐颗读取装载槽里的晶石（171 的归属表：一颗只给后放的那把），每颗一下：伤害 = 法杖属性（+ 这颗晶石的 `feed_mods`），类型 = 这颗晶石的元素，盖印；耗这颗晶石的供给次数（148 照旧按场计）。
- **两种冷却**：颗与颗之间是**单次 CD**（`step_cooldown`），一轮读完到下一轮开始是**总 CD**（`cooldown`）。两种都吃加速（`HASTE`，现有 `CooldownCadence._duration` 的除法）。**只装一颗时没有单次 CD，只有总 CD**（一轮 = 一下，总 CD 直接覆盖）。

### 2.2 实现

- 新节奏 `CycleCadence {step_seconds, cycle_seconds, use_haste}`：状态里记 `index`、`steps`；`next_time` 在 index < steps−1 时用单次、否则用总；`steps` 由编译器按归属表写进 `CompiledItem.loaded: Array[uid]`（**顺时针**：以法杖中心为原点，按装载格的方位角从 12 点起顺时针排；同角按 `placed_seq`）。空表 → steps = 1、不读晶石、走基础属性。快照语义不变（出手那刻算死下一时刻，103）。
- 法杖的 `deal_damage` 前加一个效果 `fire_loaded`（新，法杖专用）：取 `loaded[index]` 那颗，把它的 `feed_mods` 并进这一下、把 `feed_rules` 的 `convert_damage_type` 作用在这一包上、扣供给。晶石 json 不改形状：`feed_mods / feed_rules / feed_filter` 原样，只是执行从「常驻挂在法杖上」改成「轮到它那一下才用」。
- `magic_staff.json`：`base_stats` 加 `step_cooldown: 0.6`，`cooldown: 1.2` 保留为总 CD；规则节奏换成 `@cycle`。
- 回放：法杖的冷却扇形走的是**当前这一段**（单次或总）；法杖格上小字标「第 N 颗」（Roman numeral 风格与 167 一致）。
- 悬浮窗（171 的装载词条改写）：「装载 N 颗，顺时针：火 Y → 冰 Y → 雷 Y；颗间 X 秒，一轮后歇 Z 秒」；一颗时「装载一颗：火 Y，每 Z 秒」；空时「没放晶石：物理 Y，每 Z 秒」。
- 估算器（`stamina_estimate` / 预估 DPS）按 steps、两种 CD 算频率。

### 2.3 第二批测试

空杖 = 基础属性；一颗 = 只有总 CD；三颗 = 顺时针顺序、颗间单次 CD、一轮后总 CD；加速同时缩短两种 CD；供给次数按场扣；一颗晶石压两把杖只给后放的那把（171 不变）；战斗中晶石碎了（0 次）→ 从序列里摘掉，steps 变短，一颗都没了回木棍；金样重录。

## 第三批 · 铸炉节点、铸牌、附魔字段与前缀命名

### 3.1 铸炉（新节点类型 `forge`）

地图节点类型加 `forge`（154 宝箱节点的做法：`node_rules` 加类型、`NodeEvents` 加分支、新屏 `ui/game/forge_screen.gd`，图标与皮肤交美术）。节点规则：每局几座、落在哪几环、用一次关一次（待定 2）。

铸炉屏：一整块石板（157），上半三个凹槽**【时机】【效果】【数值】**，下半一个出牌槽与「铸」按钮；左侧是玩家的棋盘 / 暂存区 / 地上（拖进凹槽）。三槽都填了才能铸；铸完三件消失，出牌槽出现一枚铸牌，拖回棋盘或暂存区。预览：三槽填着时出牌槽就显示将要铸出的那句话。

### 3.2 槽位 → 字段：读【材质】【用途】【稀有度】

任意道具都能进任意槽（作者定）。每个槽从道具的三项读出一个字段，三槽合成一条规则。查表 `data/authoring/forge/<slot>.json`（内容编辑器加一页「铸炉」），表里是**三张映射**：材质类标签（171 的 `material` 类：金属 / 骨 / 皮革 / 木 / 石 / 布 / 魔法晶石……）、用途类标签（`purpose`：武器 / 盾 / 防具 / 饰品 / 材料 / 药剂……）、稀有度（0–4）。首批表（占位，作者与执行线程过内容）：

| 槽 | 材质 → | 用途 → | 稀有度 → |
|---|---|---|---|
| 时机 | 金属 = 出手时；骨 = 受伤时；皮革 = 战斗开始；石 = 按节拍；木 = 施加状态时；布 = 资源低于；晶石 = 受伤前 | 武器 = 自己出手 / 受伤方向为「造成」；盾 / 防具 = 方向为「受到」；药剂 = 资源类条件 | 频率：0 冷却长 → 4 每次都触发 |
| 效果 | 骨 = 施加流血；毒剂 = 施加中毒；晶石 = 盖对应元素印；皮革 = 加护甲；药草 = 回血；金属 = 固定伤害；布 = 加速层；石 = 格挡层 | 武器 = 给敌人；盾 / 防具 = 给自己；饰品 = 给相邻武器 | 效果阶：0–1 基础，2–3 升阶（流血 → 大量流血），4 加一个附带效果 |
| 数值 | 金属 = 固定值；晶石 = 百分比；其余 = 层数 | 武器 = 伤害量纲；防具 = 护甲量纲；药剂 = 资源量纲 | 大小：0 … 4 五档 |

查不到的材质 / 用途落到表里的 `default` 行。三个字段拼成 `AbilityRule`（时机 → `Trigger`，频率 → `Cadence`，效果 + 对象 + 数值 → `CombatEffect`），**和 146 构件库一样是数据**，不写代码分支。

### 3.3 铸牌

- 一个道具定义 `forge_token`：1×1、重量 1、`value` = 三件投入价值之和的一半（待定 3）、标签 `token / internal`。**不进图鉴、不进掉落、不进商店**（`ItemDatabase.ids()` 排除，`MetaState.absorb` 不记 codex），但 `keeps()` 放行：能带出、能存仓库、能再带进下一局。
- 实例数据在 `ItemInstance.state["enchant"]`：`{trigger, cadence, effect, target, magnitude, prefix, from: [三件 id]}`。悬浮窗（170）：名字「铸牌 · 〈前缀〉」，正文一句话（171 的句子生成）：「【附魔】出手时 为敌人 施加流血 二层」。
- **用法**：从棋盘上拖到任意武器上放手 → 铸牌消失，武器获得附魔；武器已有附魔则**覆盖**（后来者覆盖前者，作者定）。交互复用 114 的「压上去是合成」那条路（`DragLayer.craft_drop` 的绿色预览），加一条 `enchant_drop`：手上是铸牌、底下恰好一件武器 → 预览写「附魔：〈前缀〉的〈武器名〉」，放手调 `InventoryService.enchant(token_uid, weapon_uid)`（原子：摘铸牌、写 state、发 changed）。拖到非武器上照常顶替。

### 3.4 附魔字段与前缀命名（作者定：所有附魔都视为铸牌附魔）

- `ItemDef.enchant: EnchantDef`（新资源，字段与铸牌的 `state.enchant` 同构）：内容作者给一件道具**预置附魔**用；`ItemInstance.state["enchant"]` 覆盖它。编译器只认一个入口：`_attach(weapon, EnchantDef.to_rule(), origin = "enchant:<prefix>")`（108 的入口），同一把武器只挂一条。
- **命名**：`ItemNaming.display_name(inst)` = 耐久前缀（148 的 `wear.prefixes`）+ **附魔前缀** + 定义名。前缀由效果字段给（表里每个效果一个形容词：流血 → 「嗜血的」，火印 → 「燃烧的」，护甲 → 「坚壁的」……），悬浮窗、棋盘名牌、战斗日志、结算都用这一个函数。**以后不再为「火焰长剑」「淬毒短刀」造新定义**：长剑 + 燃烧的附魔。`mithril_sword` 的附魔迁到 `enchant` 字段（金样不变则不重录）；日神附魔是整局的赐福（`ScopedMod`，093），不是道具附魔，不迁（待定 4）。
- 掉落：第一期掉落不随机附魔（待定 5），只有铸炉与预置。敌人棋盘（165）的内容里可以给武器写 `enchant`，对阵屏显示前缀。
- 存档：`state.enchant` 随实例存；173 的对账层加一条：附魔里引用的构件 / 效果查不到 → 去掉附魔、报告一行。

### 3.5 第三批测试

铸炉：三槽任意道具都能进、少一槽不能铸、铸完三件消失、出牌一枚；映射表 default 行；预览句 = 铸出后的句子。铸牌：不进 `ids()`、不进 codex、能撤离入库、重量 1。附魔：拖到武器上 → 武器 `state.enchant` 写入、铸牌消失；再拖一枚 → 覆盖；拖到非武器 → 顶替；编译只挂一条规则、以宿主身份跑（108 校验照用：只许的时机扩成表里允许的那几种，不许 costs）。命名：耐久前缀 + 附魔前缀 + 定义名，三处（悬浮窗 / 名牌 / 日志）一致。存档：附魔往返；查不到的构件 → 对账报告。

## 附录：作者原话（2026-10-15 07:52）

> 关于元素反应 1. 封口改名为【燃血】 2. 凝毒的效果会使毒素无法被清除 3. 溃烂可以改为【菌血】，对手每次恢复生命时
> 元素的施加不止依赖魔杖，一些特殊道具（火箭、毒箭、投掷弹）或者武器（XX附魔）也能附加，拓宽思路
> 关于魔杖，我现在想到的是没有魔晶石时读取基础属性（木棍）。有魔晶石时，读取魔杖属性，然后魔晶石将其转换属性发动攻击，多个魔晶石时挨个读取（按照顺时针顺序），存在不同单次CD（魔晶石之间）和总CD（全部读取完后），两种CD都受加速影响。备注：特殊情况如只装载了一个魔晶石，那么不存在单次CD，只有总CD，也就是同时进入时总CD覆盖单次CD。
> 放弃导管系统，词链改为一个特殊节点，玩家可以将三个道具熔铸成铸牌，可以附魔给道具（效果永存，后来者覆盖前者）。如此一来所有的附魔道具都视为被铸牌附魔，给道具增加附魔字段。不再是制造多个类似的道具，而是让它们可以被自由组合的铸牌命名前缀。
> 关于铸牌系统：1. 存在三个材料部位，【时机】【效果】【数值】，任意道具都可以放入其中一个位置，并读取它的【材质】【用途】【稀有度】产生不同的字段效果 2. 铸牌产生后是一个1x1的道具，可以拖动到任意武器上使用，重量为1 3. 铸牌不是常规道具，不存在于图鉴之中，但可以被带出存放

## 落地记录

### 第一批（v3.03）· 元素印与反应表

## 补充一（2026-10-15 09:46，作者）· 菌血改叠层；反应按层数结算

> 作者原话：「『恢复量减半，减掉的一半变成中毒伤害』这不正好等于没有回血吗，好像没什么意义？改成叠加等量的中毒层数（中毒默认 1 层 1 点伤害，N 秒跳一次，不衰减）。元素反应的详细机制，参考以下我写的伪代码」—— 伪代码见文末附录二。第一批已落地（v3.03），这一节是对落地结果的修正，派执行。

### 补 1.1 菌血

- 待定 1 的 A 作废。菌血期间，**对方每次恢复生命时，按恢复量叠加等量的中毒层**（回了 7 点就加 7 层），恢复本身照常发生。燃血仍是「治疗无效」，两者分得开。
- 实现：`BuffDef.heal_cut / heal_cut_to` 里菌血那一路改成新字段 `heal_echo: {buff: "poison", per_point: 1}` —— `CombatantRuntime.heal` 结算完后按实际恢复量 × per_point 施加该状态。燃血继续用 `heal_cut`。
- **中毒的默认数值随之改**（作者定）：1 层 1 点，每 N 秒跳一次，不衰减（可叠层永续，085 的规矩本来就是不衰减）。现在是每层 2 点、每秒跳；改成每层 1 点，跳的间隔 N 见待定 补 1。剧毒按同比例看一遍（现在每层 5）。流血（每层 1、每秒）不动。

### 补 1.2 反应的结算算法（作者伪代码的落法）

伪代码的意思，逐条对到实现：

1. **印都有层数**。中毒 / 流血 / 剧毒的层就是层；灼 / 寒 / 麻从「不可叠、4 秒刷新」改成**可叠层**（`stackable`，按 085 永续不衰减，待定 补 2 给个上限）。来源给几层：施加状态给几层就是几层；带元素的一下伤害默认盖 1 层（`DamageTypeDef.mark_stacks`，道具可改）。
2. **给目标加新印时**：在目标身上找**元素不同、层数 > 0** 的印里**层数最多的那个**（并列按火、冰、雷、毒、血的顺序）；一个都没有 → 新印照常叠上去，没有反应。
3. **有的话反应**：`N = min(已有印的层数, 新来的层数)`（作者 10:02 更正，原写 max；见补充三）；已有印扣 N 层（N 不会超过它，所以不会扣成负）；新来的印扣 N 层后**若还有余量，照常叠到目标身上并记录**（作者 10:02：「如果新加的元素层数没有被扣光，则记录并保留」）；反应效果以 N 为量。
4. 反应效果里的量：`ReactionContext.stacks = N`，`deal_damage.per_stack` 乘它（爆燃 = N × 每层火伤），`apply_status` 的层数默认 = N（见下）。
5. 反应不连锁（落地规矩不变）：反应效果施加的状态不再触发第 2 步。

**和落地结果的差别**：落地是「两印全吃、几种印同在按固定顺序取第一个、量按各反应自定」，再给凝毒（`consume: none`）和电解（留中毒）开了例外。按更正后的伪代码，`N = min`：两印**各扣 N**，等量相消，多出来的那边留着（已有印剩的留在原位，新印剩的叠上去）；只有新来的 ≥ 已有的时候已有印才被扣光。真正的改动是 ① 取层数最多的而不是固定顺序第一个，② 量 = N，③ 两边都只扣 N 而不是全吃，④ 没有例外 —— 凝毒和电解不再需要「留着中毒」的特判，中毒多出的部分本来就留着。所以这两对改成**产物式**：吃掉 N 层中毒，产出 N 层新状态：

| 反应 | 产物 |
|---|---|
| 凝毒（冰 + 毒） | N 层【凝毒】：和中毒一样每跳伤害、**不可清除**、不衰减；寒印没了也不解锁（它自己就是锁住的毒），只能等它跳完或被别的反应吃掉 |
| 电解（雷 + 毒） | N 层【剧毒】（现有） |
| 菌血（毒 + 血） | N 层【菌血】状态（时长见落地数值），期间 `heal_echo` |
| 爆燃（火 + 毒） | N × 每层火伤 + 灼烧 |
| 其余六对 | 固定效果，N 只决定持续时间档或层数（燃血 / 超导 / 冻疮的层数 = N，有上限） |

这样 `consume` 字段删掉，反应定义里只剩 `effects`，`BuffDef.locks / locks_while` 不再需要（凝毒自带不可清除：`BuffDef.uncleansable`）。

### 补 1.3 测试

## 补充三（2026-10-15 10:02，作者）· 更正：N 取较小值，新印余量保留

> 作者原话：「关于我给出的代码进行一个纠错，maxStackReacted 应该是 min 函数而非 max，理解意思」「也就是说如果新加的元素层数没有被扣光，则记录并保留」。

### 补 3.1 算法定稿（替代补 1.2 第 3 条）

目标身上已有甲印 a 层，这一下来乙印 b 层，甲是异色印里层数最多的：

1. `N = min(a, b)`。
2. 甲印扣 N 层：剩 `a − N`（新来的多就扣光）。
3. 乙印扣 N 层：剩 `b − N`，**不为 0 就照常叠到目标身上**（和没反应时一样叠层、刷时长）；为 0 就什么都不留。
4. 反应效果以 N 为量；**余下的乙印不再触发第二次反应**（一次加印只结算一次，和伪代码一致，也守「反应不连锁」）。

三种情形：已有 5 新来 1 → N = 1，甲剩 4，乙不留；已有 1 新来 5 → N = 1，甲扣光，乙叠 4 层；已有 3 新来 3 → N = 3，两边都清。

`ReactionResolver` 的改动：`record.stacks -= N` 之后再 `apply_mark(incoming, b − N)`；没有异色印时的分支（直接叠）不变。

### 补 3.2 对 N 控表（补 2.2）的影响

- 带元素的一下伤害默认盖 1 层（待定 补 3 推荐 A），所以**连击里的每次反应 N 几乎都是 1**；已有印攒了多少层不再放大这一下，只决定能连反应几次（攒 5 层寒，连来 5 下火，各炸一次 N = 1）。

### 补 4.3 要加的几个通用件（都是数据字段 / 效果类型，不是特判）

1. **`BuffDef.decay_per_sec: int`**（0 = 不衰减）：每秒自动扣这么多层，扣到 0 移除；和 `on_schedule` 同一个时间轮。燃血 / 菌血用它表达「层数 = 剩余秒数、再反应就延长」。**`decay_halve_on: StringName`**（空 / `tick` / `weapon_fired` / `stamina_paid`）：在那个时机把层数减半——流血 `tick`（每次跳伤后）、寒冷 `weapon_fired`、麻痹 `stamina_paid`。两种衰减都**不低于 `guard`**。
2. **`BuffInstance.guard: int`**（保底层数，默认 0）：`RemoveStatus.take`、反应消耗（`record.stacks -= N`）、两种衰减都夹到 `max(guard, …)`；`stacks < guard` 时补到 `guard`（冻疮的「重置为冻疮层数」）。反应选印、算 N 时**照常数 stacks**（含保底的）——这就是「纳入计算但不真正减少」。新效果 **`guard_status {target, buff, stacks}`**：目标身上有那个 buff 就 `guard += n`（上限 = 当前层数？不设——guard 可以高于当前层数，这时层数补到 guard，等于「凝毒 N 层」直接给了 N 层锁死的毒；待定 补 4.5）。悬浮窗：「其中 N 层不可解除」。
3. **`BuffDef.damage_taken_by_type: Dictionary`**（`{类型: 每层百分比}`）：伤害管线第 4 步、「受到伤害」轴之后，按守方身上这类 buff 的层数 × 百分比再乘一次（剧毒）。只在管线里读一次，不加轴。
4. **`BuffDef.hooks`** 的两个新时机落在现有钩子上：寒冷 → `CooldownCadence._duration` 里读 `ctx.owner` 的 `chill` 层数（`RuleContext.source_tags` 含 `weapon` 才乘）；麻痹 → `ResourceCost.pay` 里 `resource_key == stamina` 时乘。两处都在乘完后调 `decay_halve`。乘数 M_寒、M_麻 写在 `chill.json / numb.json` 的新字段 **`per_stack_percent`** 上。
5. 三种 N 写法的导入器（补 2.2）加 `"n/2"`；`shift_axis` 加 `overflow_to`。
6. 真实伤害：`DamageTypeDef.pure`（补 4.1）。
