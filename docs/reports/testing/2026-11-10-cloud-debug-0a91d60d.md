## 游戏问题

### G01 · P2 · 离开休息点时悬浮窗访问空 Viewport

**复现：** 自由模式进入休息点，把鼠标停在帐篷等场景部件上显示说明，再点击右侧 `MOVE ON` 离开。

**实际：** 游戏能继续，但调试日志出现 `ERROR: Parameter "get_viewport()" is null.`。调用链：`CampPiece.mouse_exited` → `rest_camp_screen.gd:243` → `HoverTip.release()` → `hover_tip.gd:904` 的 `get_global_mouse_position()`。

**预期：** 场景切走时安全关闭/释放说明，不再向已经离树的提示节点取鼠标位置。

**定位与建议：** 检查鼠标退出回调与提示节点的拆除顺序；`release()` 在离树后直接清理，不访问 Viewport。不要仅屏蔽错误日志。手工实测出现 1 次；全量及独立 `author_087` 回归也复现同一入口的离树访问。

证据：[实际游戏日志](evidence/2026-11-10-debug/game-debug.log)、[独立复现日志](evidence/2026-11-10-debug/repro-author087.log)。

### G02 · P2 · “走过的点”实际统计的是内容已消耗节点

**复现路线：** 自由模式，小图、普通难度，种子 `236064`，布鲁图斯/Bulwark。从北侧出生点依次到：搜索点（离开）→ 商店（查看后离开）→ 收费撤离点（暂不撤离）→ 休息点（不休息，离开）→ 无名神坛事件（离开）→ 免费撤离点。

**实际：** 6 步到过 7 个不同节点，结算及存档历史却写 `Nodes visited = 5`、`steps = 6`、`score = 423`。收费撤离点和未使用的休息点没有计入。

**定位：** `core/run/run_result.gd:73` 遍历 `MapNode.is_visited()`；而 `core/map/map_node.gd:10` 明确规定该状态表示“内容是否已消耗”，并非“是否到达”。结果页标签为 `ledger.visited`（走过的点 / Nodes visited）。

**建议：** 将“到达过”与“内容已消耗”分别记录。若产品实际想奖励消耗节点，则应更改结果页名称及说明；若按现有“走过的点”含义，当前路线应显示 7，探索分相应增加 4，总分为 427。需同时统一战绩和计分口径。

证据：[自由模式结算](evidence/2026-11-10-debug/free-mode-result.png)、[实测存档历史](evidence/2026-11-10-debug/saves/slots/2/meta.json)。

### G03 · P3 · 英文大字号入库标题超出木牌

## 测试工具问题

### Q01 · P2 · 非 SCRIPT ERROR 的意外错误没有使回归失败

`tools/test.sh` 会扫描 `SCRIPT ERROR`，但未区分并拦住其他意外 `ERROR:`。本次 EXIT=0 的日志中包含：

- 两处格式化错误：`tests/run/test_author_087.gd:62`、`tests/ui/test_adjacency_sentence_171.gd:87`。带 `%s` 的格式串同时有未转义的 `15%`，应写成 `15%%` 或改用不会二次解释百分号的拼接。
- `HoverTip.release()` 的空 Viewport，以及 `InventoryView._gui_input()` 对离树节点调用 `get_tree()`。
- `tests/run/test_author_087.gd:332` 直接调用控件 `_draw()`，导致多条“Drawing is only allowed…”错误；断言通过不能证明这些绘制执行成功。
- `tests/ui/test_pawn_184.gd:116` 对负尺寸 Rect2 调用 `has_point()`。

独立运行 `author_087`，仍显示 **2,196 项断言通过 / 1 套件 / 21,391 ms / 退出 0**，同时再次出现格式化、空 Viewport 和非法绘制错误。

**建议：** 修正测试自身的格式串、节点入树与绘制时机；对已明确预期的错误建立精确匹配，其余引擎 ERROR 令检查失败。不能简单把所有 `ERROR:` 一刀切判失败：地图生成失败、损坏 JSON、未知 hook 等负向用例本来就会主动产生错误。

证据：[全量日志](evidence/2026-11-10-debug/full-tests.log)、[独立复现](evidence/2026-11-10-debug/repro-author087.log)。

### Q02 · P3 · 退出清理的泄漏告警需要单独治理

全量测试退出报告 1,371,626 个 ObjectDB 实例、3,875 个资源仍在使用，并有 CanvasItem/字体/纹理 RID 告警。内容检查退出也有资源和 PagedAllocator 告警。建议拆分定位测试清理、静态缓存和循环引用。

这些数字来自一次集中回归退出，**不能据此断言玩家每局都会泄漏相同数量**；本轮没有做多小时内存增长测试。

## 体验改进建议

1. **教程提示增加“点击任意处继续”、进度和跳过入口。** 现有遮罩有说明与箭头，但没有持续可见的操作提示；新玩家容易把高亮区当成必须点击的目标。
2. **为没有配图的事件调整左页。** 序章和多处随机事件左半本书长期空白，右页在英文大字号下需要滚动。可补插图，或在缺图时给正文更多空间。
3. **长篇交代增加“下方还有内容”的提示。** 英文大字号首次自由模式交代需要滚动，`Got it` 始终可直接点击，重要倒计时/撤离规则容易没读到。保留玩家跳读自由，不必强制滚到底。
4. **在启动文档和脚本中统一引擎版本。** 云端默认 4.6.3 不适配本版本；`tools/run_game.sh` 默认仍指作者 Windows 路径，而 `tools/test.sh` 已会找 PATH。建议提供版本检查和一致的跨平台启动入口。
5. **颜色微调。** 内容检查报告深面板上 `styles.hp`、`styles.danger` 对比度 4.40，距该检查的目标 4.50 差 0.10；这是工具测量结果，建议小幅提高对比度。
