# v5.85 云端游戏体验与评估

日期：2026-11-11。体验版本：`b2f62f0dfcb1665ad34ba94bdfc6abefac15bb9c`（PR #581 合并后的 main）。本次只提交报告、证据与索引，不修改游戏规则。

交付时主分支已前进到 v5.87（`fe6f04ba`），本报告合入最新主分支；v5.86–v5.87 的新增功能不在这次体验验证范围内。以下问题以所测提交为准，后续复测需核对是否已被修正。

## 评估结论

“整理背包 → 侦察与选择路线 → 自动战斗 → 带出物品”的循环已经成立。纸张、书本、实体道具和交易天平形成了统一的表达，配装产生的战斗差异也能被实际感知。当前更值得投入的是**确保教学能成功，以及让玩家准确理解结果的原因**。

本次最明确的问题是：序章实际发放了祝福异体匕首，教学配方却只接受普通匕首。玩家可以通过备用选项完成序章，但没有完成所教的合成。其次，护甲与格挡的语言，以及反应教学的指向时机，会干扰对现有战斗系统的理解。建议先修复这些问题，再扩大教学内容与数值复杂度。

这是一名熟悉项目的自动化代理进行的专家走查，不是盲测或真人用户研究；不据此推断留存、商业潜力或总体难度，不给缺少依据的综合分数。

## 环境、方法与范围

- 全程在云端 Linux 桌面运行原生 DEBUG 游戏，通过可见界面点击、拖放、查看提示和战斗回放；没有修改存档、注入装备或跳过战斗来制造体验结果。
- Godot 官方 4.7.1，Compatibility 渲染，Mesa llvmpipe；独立全新用户目录，中文、中字号，默认动画。为云端操作限制 30 FPS，音频使用 Dummy。工具等待时间和此环境帧率不作为产品性能结论，未评价音效与音乐。
- 完成新玩家序章与一局普通难度小型自由地图，均走到撤离、结算、入库。额外查看第二章开场，不代表完成第二章。
- 体验后仅为核对根因读取源码、运行配方探针及相关定向测试。功能事实与设计判断分开记录。

## 值得保留的体验

### 背包的空间约束确实参与决策

序章装备短剑后，面板 DPS 从 0 增到 7.4；加入皮甲，负重从 10 增到 16。后续弯刀、盾牌无法自动放入已有空间，留在地上。我选择继续，而不是把所有东西无条件带走。这让“捡到”与“能携带并使用”成为两个决定。全部拾取与一键入库减少重复整理，也保留了手动调整的余地。

需要注意：拖拽中的一次落地、一次取消挤出后的自动回填，不能直接归为游戏摆放错误。本次包含工具定位和玩家操作因素，没有得到独立复现的空间判定缺陷。

### 已有信息足以支撑一部分战前判断

自由模式强攻预设显示 28/48 负重，DPS 24.1，耗耐力约 14.6/秒、恢复 4/秒，并标注“极高”。敌人节点可悬浮预览装备与生命，战前又能检查双方棋盘。应优先帮助玩家读懂这些现有信息，不必立即增设复杂面板。

实际战斗记录如下，各场装备、敌人及增益不同，不能当作受控平衡对比：

| 战斗 | 观察 |
|---|---|
| 序章拾荒者 | 3.0 秒结束；我方 85/85 生命、61/65 耐力。回放可拖回具体时间看减伤日志 |
| 序章持刀敌人 | 我方使用异体匕首、毒药瓶等，13.8 秒结束；26/85 生命、102/105 耐力。低输出带来更长暴露时间 |
| 序章守卫 | 加入新战利品后 8.0 秒结束；63/85 生命、78/105 耐力；触发首次菌血教学 |
| 自由局魔法学徒 | 使用偷袭，敌人生命由 48 降至 34；2.0 秒结束；我方 19/45 生命、34/55 耐力，承受 26 点伤害 |
| 自由局焰狼精英 | 未用偷袭，敌人 83 生命；4.0 秒结束；我方 35/45 生命、17/55 耐力；日志承受 35 点伤害，治疗也参与过程 |

短战斗有明确爆发感，回放又为追查细节提供了入口。但本次没有打到耐力耗尽，不能验证强攻在长战斗中的教学或平衡。

### 路线收益能转化为可感知的取舍

自由局祭坛给出蛮神护符，悬浮能查到武器增伤 15% 与开战血怒；商店购买蜂蜜罐花费 12 币，货币 25 → 13；精英获胜后达到 51 币；最终选择支付 50 币撤离，带出 1 币。地图、事件、交易和撤离因此进入同一个资源循环。

商店交易实际完成：双击选商品 → 点击己方钱袋补差价 → 点击成交。天平从“还差 12”变成“够了”，成交后出现商品名并清空挂账，反馈清楚。全图模式也能看见节点种类与限时撤离提示，利于规划。

## 问题与改进优先级

### E01 · P1 功能问题：异体掉落使序章合成目标不可完成

**实测：**第一战取得 `knife_brute`（蛮神赐福的匕首）；第二次搜索取得毒药瓶。按教学把毒药拖向匕首不会合成，发生物品挤出。守卫教学仍提示“先把毒药瓶拖到匕首上面合成涂毒匕首”，主选项不可用，却提供“手里没有匕首，就这么上”。背包里实际有异体匕首。最后通过备用选项打完守卫，结算合成 0。

**根因证据：**[RecipeDef.matches](../../../core/inventory/recipe_def.gd) 精确匹配输入 ID；普通 `knife + poison_vial` 查得到配方，`knife_brute + poison_vial` 在直接拖拽与相邻拼接两种查询下都为 false。教学事件也只检查普通匕首与涂毒匕首。见[探针输出](evidence/2026-11-11-game-experience/recipe-probe.log)、[探针脚本](evidence/2026-11-11-game-experience/probe_recipe.gd)和[现场截图](images/2026-11-11-eval-09-crafting-gate.jpg)。

**复现：**使用本报告版本和[合成前存档](evidence/2026-11-11-game-experience/tutorial-before-craft.json)，在隔离测试槽中恢复为 `run.json`，继续第二次搜索取得毒药瓶；确认棋盘已有 `knife_brute`，按教学尝试合成，再进入守卫事件。该文件保留种子及第一战后的棋盘；应在相同版本、隔离用户目录复核，不覆盖正常存档。

**建议：**教学固定提供能完成该课的原料，或另行设计明确的异体转换与产物继承规则。不要简单把所有异体静默当成普通材料消耗。备用选项应承认“当前材料无法合成”，而不是断言没有匕首。

**验收：**覆盖普通掉落与祝福替换的教学种子；所有路径能完成指定合成，或明确跳过并补教；持异体时不再显示“没有匕首”。本报告只确认失败实例与匹配规则，没有统计发生概率。

### E02 · P2 信息问题：护甲、格挡与教学叙述没有对齐

首战我方装备皮甲、没有盾牌，回放把敌人的 5 点物理攻击描述为“被抵挡了 5 伤害，最终伤害为 0”。源码确实把护甲吸收与格挡相加；只有两者同时存在时才分别叙述，单独护甲也落到通用“抵挡”文本。见[日志截图](images/2026-11-11-eval-06-defense-log.jpg)及 `core/battle/battle_narrator.gd` 的 `stopped` 分支。

另一方面，[守卫教学](../../../data/authoring/events/tut_elite.json)写“披着甲……每下都要被削掉一截”，实际该守卫携带的是格挡 5 的圆盾。v5.84 已把护甲改为有限吸收池，继续用这句话教盾牌会混淆两种防御。

**建议与验收：**单独护甲也明确写“护甲吸收”；守卫按真实装备解释格挡。分别用仅护甲、仅格挡、两者同时存在、毒/流血四类场景核对描述与实际扣除。词条已有两者定义，优先让场景语言引用正确含义。首次还应明确“每场生命”与地图红心体力的区别：本次胜利后进入下一战恢复生命，不是生命恢复 Bug。

### E03 · P2 教学呈现：反应说明出现时，目标区尚未显示对应反应

序章守卫约第 5 秒触发菌血教学。界面稳定后，说明在讲毒与流血，高亮区域却只看见蓝色盾牌数字 5；关闭教学后才看到毒、流血状态。见[截图](images/2026-11-11-eval-10-reaction-coach.jpg)。代码把教学目标设为敌方整个状态行，并非某个确定的反应图标。

**建议：**等待状态 UI 更新后暂停，指向实际相关状态；首句先说“毒 + 流血触发菌血”，计算细节保留在后续说明。需要在相同战斗回放中再核对刷新顺序；本次不能断言底层反应计算错误。

### E04 · P2 体验改进：第一轮可操作时间被多段说明切碎

初始地图 4 段教学，首次战前 3 段、战斗播放 4 段，打开背包又有多段说明；搜索也反复在书页和背包间切换。叙事风格统一，但在玩家还没完成一个自主决策前，已经需要读和记很多内容。

**建议：**把一项教学收束为“做一个动作 → 看一个结果 → 再解释原因”。第一课只完成一次放武器和一场战斗；后续遇到真实容量、合成或状态问题再逐步展开。长风味文字仍可查阅。增加清晰的继续操作提示与页数进度，让玩家知道还需读多少。此项是专家判断，不是真人流失数据。

### E05 · P3 体验改进：商店的初次操作需要更明确提示

本次先尝试单击和拖放，后来双击商品才进入挂账；悬浮的“放上秤”没有直接说明双击，首次面对“还差 12”也需要发现钱袋可点击。最终购买正常，不能列为交易功能故障。

**建议与验收：**首次商店用一句短提示说明“双击挑选；点钱袋补差；成交确认”，并对可点击钱袋给出悬浮提示。邀请没玩过项目的人完成一次购买，观察能否自行找到这三步。

## 下一步投入建议

1. 先修 E01：保证序章材料、配方和教学条件一致；随后修 E02 的术语与伤害归因。这两项影响玩家能否学会规则。
2. 修 E03 的显示时机，再压缩 E04 的前置讲解；商店补一句操作提示即可，不必重做交易系统。
3. 用 4–6 名未接触项目的玩家做小规模观察，检验他们能否完成合成、解释护甲与格挡、区分生命与体力、完成一次交易并自行选撤离路线。记录求助次数、错误预测与复述，不把本次代理操作耗时当作基准。

现有 [303 报告](../303-events-materials-difficulty.md)与 [306 合成改革报告](../306-fusion-reform-batch-a.md)已包含大量系统工作。本次没有实际触发 v5.85 的相邻拼接确认窗，不对它的持续显示和未知配方体验作通过结论；也不以“再加系统”代替当前教学修正。
