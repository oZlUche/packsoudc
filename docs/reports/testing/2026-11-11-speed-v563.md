# 速度评估：v5.51 对 v5.63（2026-11-11）

> 执行：游戏测试（新）｜ 流程：`/mnt/project-files/testing/speed-evaluation-procedure.md`（代码审阅精简 定）｜ 依据：作者 2026-11-11 12:57「能让测试线程运行并测试速度吗？……让它生成一份报告」
> 原始 csv 与日志：共享文件夹 `testing/2026-11-11-speed/`。本报告只贴汇总。

## 一、一句话结论

1. **玩家等多久**：一次挡住主线程超过 1 秒的有五处：启动装内容、新的游戏、自由模式选「大」地图档、大地图出发、结算看完。真机上（v5.65）启动装内容 1.8～1.9 秒，新的游戏 1.2～1.3 秒，结算看完 1.1～1.2 秒，其余都在 340 毫秒以内。
2. **画面顺不顺**：真机平均每帧 6.6～11.6 毫秒，战斗屏约 7 毫秒、最大 20 毫秒，是顺的。云端（软件渲染）里最重的是选人 / 配装备三页（每帧约 175 毫秒，基地只有 20 毫秒），其次是回放浏览和战斗屏（约 130～146 毫秒）。两个版本没有差别。
3. **算得快不快**：一场战斗模拟约 3.1～3.3 毫秒，两个版本没有差别。
4. **越玩越慢吗**：不会。连跑三局，每局回到主菜单时静态内存 234.5 → 234.9 MB，对象 11248 → 11255，孤儿节点始终 0。
5. **开发侧快不快**：冷导入约 2 分 20 秒，热导入约 7 秒，静态警告收集 32 秒（两版都是 0 条），全量测试约 12 分钟（v5.51 733 秒、v5.63 715 秒，没有差别）。测试用例里最慢的是 `run_all_builds_fit`（36 秒）和内容编辑器冒烟（34 秒）。
6. **瘦身前后变没变**：没有一项变慢到玩家能感觉到。结算看完、第一次进基地、从别的屏返回基地、开局到选人页都变快了，各快 150～480 毫秒；后勤、铁匠铺、市场页签快了约 50～80 毫秒。变慢的只有测试脚本往仓库里塞 200 件物品这一步（玩家碰不到这么多件一起放），以及 v5.63 的静态内存多 2.6 MB。

## 三、方法

- **版本目录**：旧版本用 `git worktree add --detach /tmp/claude-0/wt551 fa0cd407`，新版本用 `git worktree add --detach /tmp/claude-0/wt563n 1819021c`，两个目录各跑一次 `--import`，各用自己目录里的 `tools/` 脚本。
- **运行规矩**：同时只开一个 Godot。每轮开始前清掉 `slots/`、`settings.json`、`settings.json.prev`、`meta.json*`、`run*.json*`、`diagnostics/`、`calibration/`、`battle_logs/`、`ui_layouts/`。
- **轮次与判断**：每项旧、新交替跑三轮。表里给中位数，括号里是最小～最大。「差」是新减旧。两版的差不大于两版里较大的那个轮间波动时，判「没有差别」。

| 步骤 | 命令 |
|---|---|
| 导入 | 先 `rm -rf <目录>/.godot`，再 `godot --headless --path <目录> --import`，记墙上时间（冷）；紧接着再跑一遍（热）。只跑一轮 |
| 探针 | `xvfb-run -a -s "-screen 0 1600x1000x24" godot --path <目录> --rendering-driver opengl3 --script res://tools/perf_probe.gd -- <csv> 1`；v5.63 另跑末尾参数 `3` 和 `1 bench` 各一次 |
