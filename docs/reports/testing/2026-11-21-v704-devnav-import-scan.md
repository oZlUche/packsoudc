## 一、全量测试

## 二、启动走查

脚本 `probe704.gd` 不进游戏场景，只在每帧记录开发期导航（DevNav）的几项状态：扫描任务、扫出几件没导入的素材、后台导入进程，以及 `.godot/devnav_import_head` 里记的提交号（下称「戳」）。每种情况都是从命令行重新启动一次。

| 情况 | 结果 |
|---|---|
| 1. 第一次启动，还没有戳 | 要扫。扫描在工作线程里跑，用了约 3 秒，主线程在这期间照常走了 462 帧。没有缺的素材，扫完把当前提交号写进戳。 |
| 2. 再启动一次，提交号没变 | 不扫，第 2 帧就结束，戳文件没被重写（修改时间前后一样）。 |
| 3. 提交号变了（把戳改成旧号来模拟） | 重扫，0.27 秒扫完，戳更新成当前提交号。 |
| 4. 有一张新图没导入（新目录里放一张 png，戳也是旧号） | 扫出 1 件，后台起了导入进程，右上角显示「新素材导入中……下次启动生效」。导完后这行字撤掉，`.import` 文件也生成了。因为这次扫到了缺的素材，戳没有更新。 |
| 5. 导完再启动 | 因为戳还是旧号，又扫了一遍，这次一件不缺，戳更新。 |
| 6. 正常启动游戏（启动场景跑 600 帧） | 没有报错，戳没被重写。 |

测试用的那张图和它所在的目录已经删掉。

## 三、观察（不算问题）

是否要扫只看 Git 提交号。如果本地新加了图片但还没提交，提交号不变，启动时就不会扫，也就不会自动导入，要等下次提交号变了才会导入。作者平时是拉取别人的提交，提交号会跟着变，不受影响。只有在本地直接放图、不提交就运行时才会遇到。
