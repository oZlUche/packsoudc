# v6.14 垂直切片体验、Bug 与玩家反馈核对

日期：2026-11-13。实测提交：`c1b1de036786724f7ca1418655dd0f21104f76c2`，v6.14。入口：`-- --profile=slice`。本次交付只有报告、截图、日志和测试档案，不修改游戏逻辑。

交付前主分支已前进至 v6.15（`5548f2a3`，移除休息点的砧与升级配方）。报告会合入最新主分支，以上新改动没有在本轮重新体验；问题与截图以所测提交为准。

## 结论

切片可以用正常获得的装备击败终点守卫、免费撤离、入库，再进入下一局。搜索、交易、合成、战斗与带出已经形成完整循环；两段短引导和明确的商店操作提示比之前的序章更易读。

但现阶段不宜仅以“清单审计通过”和已有 S3 路线通过判断试玩完成度：**本次出现一次阻断 DEBUG 会话的背包悬浮回调脚本错误；强攻预设能带入清单外长剑；首次合成机会缺少主动教学。** 此外，双向分支允许从休息点绕过盾卫取得其后物资，需要确认是否符合路线设计。

用户提出的四点中，前三点均有具体界面事实支持；第四点的“角色只有一个”属实，但“没有角色特点介绍”需要修正：现有页面已介绍安德烈乌斯的数值、求饶、偷袭，只是没有多角色比较和首次选择引导。增加角色是产品扩展建议，不是现有选择器故障。

## 用户四项反馈逐条核对

| 反馈 | 核对结果 | 建议与优先级 |
|---|---|---|
| 1. 出战界面没有仓库，后续无法使用自己的道具 | **对当前切片准确。** 通关入库后，基地仓库能看到带出物品；第二次出征的“配道具”页仍没有仓库。`slice_ruins` 明确 `allow_carry_in: false`，界面据此隐藏仓库；这是当前切片规则，并非物品没有保存，也不能推广成正式版全部章节都缺仓库 | **P2，先讲清规则，再决定是否改变循环。** 若继续固定开局，应在整备页解释“本试玩每局固定补给，仓库装备不带入”，并说明收集的用途。若希望体验连续搜打撤成长，则另行设计有限携入及预算，重做平衡验证；不要把打开开关当作纯 UI 修复 |
| 2. 预设缺少教程，玩家不知道可选强攻/坚守 | **准确。** 默认“不带预设”，旁边两块小挂牌可点击；首次进入没有引导。我实际切换两套，棋盘会换装。现有悬浮主要列物品，不解释这是互斥的整套开局方案 | **P2。** 首次指出预设区域，用短句说明“任选一套，点击可预览”；展示“强攻：爆发高、耗耐力高”“坚守：盾甲减伤”等现有特点。选择后让装备变化承担反馈，不需要长篇教程。不过应先修 B02 的切片范围问题 |
| 3. 首次发现容器+背包有可合成物品时，应出现教程 | **准确，且是本次最值得优先补齐的教学。** 第一战掉落匕首时，与初始匕首已经能合双刀；第一次搜索的磨刀石也能与背包匕首合成。两次均没有自动出现合成教学。我因已知机制主动拖放才发现确认窗。小锤是在拿起物品之后才出现，无法告诉不知道拖放的人先做什么 | **P1 教学。** 等物品已揭示、场景稳定，检测已揭示战利品/搜索容器、当前背包与地面中的真实可用组合，首次给一页短引导并高亮搭档：“拿起一件 → 拖到搭档 → 确认”。不要提前泄露未知产物，不自动消耗原料。触发应记在独立切片档案，避免每个容器重复弹出 |
| 4. 增加初始角色，首次介绍不同角色特点 | **部分准确。** 切片章节的 `characters` 仅有 `andreus`，首次和再次出征都只有他可选；目前角色卡已经写明技能与基础数值。不存在可以切换却未被告知的其他角色 | **P3 扩展、P2 说明。** 当前先把已有角色概括为“可用物资抵消败仗损失、有限次数偷袭”的打法，并说明试玩角色范围。若目标是让试玩展现角色差异，再加入一个定位明显的角色，比较耐力、负重、体力和能力，并重新测试整条路线；不要无条件开放正式版角色池 |

证据：[基地仓库](images/2026-11-13-slice-16-warehouse.jpg)、[再次整备无仓库](images/2026-11-13-slice-18-no-warehouse.jpg)、[强攻](images/2026-11-13-slice-19-assault-selected.jpg)、[坚守](images/2026-11-13-slice-20-bulwark-selected.jpg)、[单角色页面](images/2026-11-13-slice-17-character-only-one.jpg)。

还存在一句上下文冲突：`setup.no_preset_tip` 通用提示写“只带包架上的包，其余从仓库拖”，当前切片却隐藏仓库。建议按章节条件改文案，而不是让玩家猜是否漏了入口。

## Bug 与交互缺陷

### B01 · P1：背包/地面悬浮回调报错并中断 DEBUG 会话

**已观察的故障事实：**第一局在商店之后打开 B 背包、合成阔剑与绷带卷；一次较长材料拖放挤出纱布与皮甲到地面。随后关闭背包，打开/关闭右侧调试抽屉，再按 B、移动鼠标准备收回地面皮甲。发生：

```text
ERROR: Condition "slot >= slot_max" is true. Returning: nullptr
  inventory_panel.gd:360 → hover_tip.gd:1220
SCRIPT ERROR: Invalid call. Nonexistent function 'is_open' in base 'Vector2'.
  BagWindow.<anonymous lambda> (inventory_panel.gd:354)
Debugger Break
```

游戏窗口关闭，原 DEBUG 进程退出；后续必须重新启动。日志见[首会话原始记录](evidence/2026-11-13-slice/game-first-session.log)。退出码为 0 也不能视为成功：日志包含明确的脚本错误与调试中断。不能把之后清理阶段输出解释为独立的数百个玩法问题。

**恢复与重测：**原自动档恢复至商店交易后，阔剑与绷带卷需重做。重启后完整局最终成功；[重启记录](evidence/2026-11-13-slice/game-restart.log)又记录三条 `slot >= slot_max` 对象查询错误，同样涉及悬浮输入链，但没有第二次同名 `SCRIPT ERROR`。第二局的较短“取消合成→关背包→悬浮→重开”操作未稳定复现退出。故**脚本故障已确认，最小稳定复现条件尚未确定**，不声称每次都崩溃。

**排查方向：**[InventoryPanel._quiet_tip](../../../ui/game/inventory_panel.gd)将闭包装入 `HoverTip.hover_quiet`，闭包访问 `fuse_note` 并调用前一个回调 `prev`；首次打开合成窗也会给跨面板的 `ground.tip` 安装这一层。代码中没有对应的回调恢复逻辑；应优先核对旧面板销毁、GroundLayer 复用和嵌套回调的生命周期。这是有依据的定位方向，尚非已验证根因或修复。

**复核材料：**[中断前最近自动档](evidence/2026-11-13-slice/before-restart.json)，同版本隔离测试槽可作为起点，文件应复制为该槽 `run.json`。需重新通过 UI 执行上述合成、地面挤出、关开面板与悬浮；存档不会包含内存中的旧闭包，不能仅加载文件就期待报错。

**验收：**相同局档反复开合背包、合成/取消、挤出、切换场景、悬浮及回收地面物品，均没有悬浮链对象错误；另测正常发布运行方式，不能把只在 DEBUG 会话观察到的退出直接推广为所有导出包必崩。

### B02 · P2：切片允许预设引入清单外道具，审计未覆盖这个入口

**复现：**切片新游戏或再次出征 → 配道具 → 强攻 → 出发 → B。长剑实际进入局内，见[截图](images/2026-11-13-slice-21-assault-in-run.jpg)与[第二局现场档](evidence/2026-11-13-slice/second-run.json)。

`data/manifests/slice_ruins.json` 的 19 件允许道具中没有 `longsword`；`GameFlow.presets()` 对不允许仓库携入的章节仍提供免费预设，强攻直接发长剑。`RunState.start()` 还会叠加章节初始三件物品，因此不是单纯的预览图错误。

本次 `slice_audit --seeds=20` 返回 0 条问题，但 `SliceAudit.walk()` 直接以空 kit、无整备 layout 开局，没有遍历可选预设。这解释了为何它检查不到这条入口。它不代表审计工具其他项目均失效。

**建议：**先确定切片是否允许这些预设。若允许，应同步内容清单、来源、开局配装与对打表；若仍保持固定补给，应过滤或换成切片专用预设。给审计补上每个可见预设及携入组合的入口检查。本次默认配置与强攻初始 DPS 为 5.3 对 29.4，不能继续只用默认配置解释首次合成门槛。

### U01 · P2：长材料多重重叠使配方操作方向不对称

**实测：**亚麻布卷为竖置长物品，纱布在其左侧包顶。按配方文案把布卷拖到纱布上，布卷形状同时覆盖皮甲，系统挤出“纱布、皮甲”，没有合成确认。反向把单格纱布拖到布卷上，立刻得到正确确认窗并可合成。

证据：[多重重叠后](images/2026-11-13-slice-09-multi-overlap.jpg)、[反向成功](images/2026-11-13-slice-10-reverse-fusion.jpg)。`DragLayer._fuse_target_grid()` 明确要求 `displaced_by()` 恰好一件；只要覆盖第二件，就退回一般摆放/挤出逻辑。因而这是可解释的交互约束，不是“配方不存在”或“取消把原料吞掉”。

**建议：**有明确可合搭档时考虑按光标所在搭档判定，或在多重覆盖时拒绝并反馈“还压到其他物品，请换一侧/反向拖”，避免看似在执行配方却拆散装备。先验证不会引起误合包、自动消耗或破坏既有摆放意图。验收需比较长→短、短→长、旋转与多重覆盖。

### U02 · P2：整备预览没有展示章节出发后才发放的装备

首次“不带预设”的整备页只有两个包，出发后自动获得匕首、纱布、口粮；选强攻时整备页预览一套装备，实际开局又多一把匕首及纱布、口粮。`RunState.start()` 在整备 layout 之外追加 `chapter.starting_items`。

这不阻止开局，但玩家无法在该页看清最终配置和来源；也会强化“要去哪里拿自己的道具”的困惑。建议在整备中预览章节补给或列明出发时发放，标明预设与固定补给的关系。不要只增加一页教程来解释不完整预览。

## 需要作者判断的设计改进

### D01 · P2：分支风险收益门槛可绕行

实际走 `3→4 商店→5 补衣人→8 休息→7 搜索二`，不打节点 6 盾卫，即能搜索获得毒药瓶与圆盾，再 `7→8→10→11 守卫`。本次终点胜利用到了这些装备。截图见[搜索二物资](images/2026-11-13-slice-12-bypass-reward.jpg)。

双向图本身可以是允许绕路的设计，不直接判为移动 Bug；但 [313 报告](../313-vertical-slice-s1.md)按“盾卫之后的搜索二”解释奖励和配置成长，当前地图并没有把这一风险作为取得奖励的前置条件。若希望两条路线互补，允许花额外时间绕行，也应按这条路线重评收益；若希望盾卫守住奖励，可用击败条件或单向/门控关系，不必全面禁止回头。

### D02 · P3：补衣人有一项在切片内永远做不到的交易

熟皮革选项一直灰着，切片清单中没有其来源；此前 313 已记录，本次再次确认，属于已知内容适配问题。不要把所有灰选项一起判错：亚麻布卷有来源，我已用来合成而不能出售，是正常取舍。建议对切片隐藏无来源分支，或提供切片专用事件，不影响正式版的材料来源。

### 地图与反馈的正面观察

- 地图 2 步、战前 2 步讲解都有进度，文字比原序章集中；商店首访提示明确写了实际三步操作。
- 全图 F 能完整显示 13 点与分支；默认视野中最右终点一度在屏外。可在首次路线选择时提示全图/缩放，先利用现有能力。
- 皮甲可自动旋转装入包位；无法放入的圆盾留在地面，调整匕首位置后，从地图双击圆盾成功装入。搜索容器弹层打开时，背景地面拖拽尝试没有收取成功，不据此判定空间算法错误。
- 旧版护甲归因已有改善；本次看到了“护甲吸收”和“格挡抵消”。没有重新观察到旧版道具卡压住合成确认窗。
- 终点战盾牌阻挡敌方低伤攻击，毒穿过对手格挡；配置效果清楚。但只有三场胜利，不能断言整体平衡、重玩性或角色强弱已经合格。
