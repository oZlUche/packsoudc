# 253 地上掉落三件事：角落组件不当墙、别吸在背包窗上沿、半空不卡住

作者 2026-10-25 14:44（架构设计线）：「关于道具的掉落和碰撞反馈：1. 道具的碰撞要无视左下角和右下角的UI组件，直接掉落在前面 2. 道具拿出棋盘外时有时候会吸附在背包界面的边缘，尤其是上缘，要检查原因 3. 道具拿出时有时候会卡住不动」

只写方案，不改代码。三件事的根都在 `GroundLayer`（128 / 162 / 180 / 198 / 249）与 `DragLayer`。

## 〇 原因

| # | 作者看到的 | 原因（代码处） |
|---|---|---|
| 1 | 东西掉到左下 / 右下角，被 UI 组件顶开、或落在组件顶上 | `HudHost` 把**每一个** HUD 组件都登记成占地面板（`hud_host.gd` 98 行 `ground.reserve(w)`）：左下的 `routes` / `legend`、右下的 `belt`（160 腰带）都成了墙 + 支撑 + 推开区（128 / 162 / 198）。地上那一层本来就画在所有屏之上（`GameDirector` 的 `GROUND_Z`），所以「掉在前面」不用改画法，只要**别登记**它们 |
| 2 | 拿出棋盘外的东西吸在背包窗边上，尤其上沿 | 两处叠加：**(a)** 162 补 1 作者当时选了 A「面板上沿当桌面」：`floor_under` / `supports_of` / `_wall_contacts` / `_clamp_body` 都把登记面板当支撑和墙，背包窗（`InventoryPanel` 自己 `reserve(self)`）的上沿就是一道架子，松手点在窗上方的件全落在上沿上、还能在上面滑着停住；**(b)** 拖拽的吸附范围：光标出了棋盘、但整块有一半以上还压在棋盘里就算落回棋盘（`DragLayer._view_under_footprint`），`target_origin` 再把落点夹进边界 —— 抓着长条下端往上拖，光标已出上沿、残影却钉在第一行，看着就是「吸在上缘」 |
| 3 | 拿出的东西半路卡住不动 | 三条，按可能性排：**(a)** 解算里醒着满 `BUMP_MAX_SEC` 1.5 s 就冻住（`_bump_step` 末尾 `asleep = true`），不管它是不是还在半空；249 甩出去的件飞加弹很容易超过 1.5 s（再给一段 `more` 也只到 3 s），冻在半空等整批都睡着或满 `BUMP_RUN_MAX_SEC` 6 s 的 `_finish_bumps` 才再掉一次 —— 这就是「卡住不动、过几秒又掉下来」；**(b)** `_after_impact`：撞墙 / 面板一下速度先夹到 0.25 屏高 / s 再乘 0.3，50 ms 内连撞两下直接归零（`BUMP_STICK_SEC`）—— 甩出去撞到背包窗 / 屏边就像粘住了，再从零开始掉；**(c)** 松手点压在面板里时，`spot_for_drop` 推开算出的落点被 `_begin_fall` 的 `spot_below` 覆盖，`settle()` 只在面板打开 / 改尺寸时跑，落稳后压着面板的不再推开 |

## 一 改法（推荐，都在画面层，核心层与存档不动）

### 1.1 HUD 组件不占地

- `HudHost` 不再对组件 `reserve`，只留顶端栏 `hud_bar`（红心 / 金币读数不该被东西盖住；东西也到不了那儿，除非甩上去）。左下 `routes` / `legend`、右下 `belt` 从此不是墙、不是支撑、不推开 —— 东西落到角落就落在它们前面（画在上层）。
- 腰带是能点的（160）：东西压在腰带上时，点那一块先被地上的件接走（地层只在件的轮廓上接鼠标）。按作者的意思照办，§三 待定 1 记一句。

### 1.2 面板不当桌面，只「不压着」

- 162 补 1 从 A 改回 B 的精神：登记面板**不再是支撑与墙**——`floor_under` / `supports_of` / `_wall_contacts` / `_clamp_body` / `_new_body` 的 `skip` 都不看 `_reserved`；`_support` 字典与「面板关了再掉一次」（`unreserve` 的再落）一并删掉。
- 面板仍然是「不压着」区：落稳时（`advance_landing` 落稳的那一批、`_finish_bumps` 收尾的那一批）对压着面板的件跑 `push_out`，推到最近空处后再按 180 弹开一次；`settle()` 照旧在面板打开时跑。`_begin_fall` 的落点 x 用 `spot_for_drop` 推开后的 x（现在被 `spot_below` 丢掉了）。
- 效果：松手在背包窗上方，件从松手点竖直掉**过**窗面（地层在上，看得见它飞过去），落到屏底；若落点在窗底下，往左右推到窗边外。上沿不再有架子。

### 1.3 吸附回棋盘加一道距离

- `_view_under_footprint` 保留「整块一半以上在棋盘里」，再加一条：**光标离棋盘可见矩形不超过半格**（`cell_px × 0.5`）。超过半格就是地上，不管整块压多少。
- `target_origin` 的夹边照旧（只在上面那条成立时才用得到）。

### 1.4 半空不冻、撞墙不粘

- `_bump_step`：「醒够 1.5 s 就睡」只对**这一步有接触**的件（`hit != 0` 或 `propped`）生效；悬在半空的（没接触、速度不为零）不计时、不睡，重力照落。`BUMP_RUN_MAX_SEC` 6 s 的硬停只在所有件都有接触时才算到（防止一堆件互相弹个没完），半空的件到了 6 s 改成「就地竖直再掉」（`_begin_fall`），不是冻住。
- `_after_impact`：`thrown` 还为真的件（249：第一次撞地 / 墙 / 面板前）撞**竖直墙 / 屏边**时不走 0.25 屏高的夹与 ×0.3，只按 e_wall 0.15 反弹、μ 0.8 摩擦（`_solve` 里已算）；`BUMP_STICK_SEC` 归零只对法线朝上的接触（落在地 / 件 / 顶上）生效，侧面撞不归零。第一次落地后照旧。
- 松手点压在面板里（1.2 已不是墙）：`_new_body` 不再需要 `skip`。

### 1.5 常数

`BUMP_MAX_SEC` 1.5 / `BUMP_RUN_MAX_SEC` 6.0 / `BUMP_WALL_VCAP` 0.5 不动；新加 `SNAP_BACK_CELLS` 0.5（1.3）。

## 二 测试

- HUD：开一局，角落组件在场，`reserved_rects()` 只含顶端栏；一件落到右下角落在腰带矩形里不被推开、不被当支撑。
- 面板：背包窗打开，松手点在窗正上方 → 件落到屏底（不是窗上沿）；窗底下的落点被推到窗侧；窗关掉没有件再掉一次（`_support` 已删）。
- 吸附：抓 1×3 长条下端，光标出上沿 0.4 格仍落回棋盘；出 0.6 格落地。
- 不冻：甩一件飞 2.5 s（无接触），`advance_bumps` 推到 2.5 s 时它仍醒着、位置在变；撞屏边后速度不低于 e_wall × 迎面速度的量级；两件互弹满 6 s 照旧收尾。
- 既有 162 / 180 / 198 / 249 测试里「落在面板上沿」「面板关了再掉」的断言改成新规矩。

## 三 待定（按推荐走）

1. 腰带（右下）被东西盖住就点不到那块：推荐**照作者的办，不加特殊处理**；真有人抱怨再给腰带一个「地上东西自动让开一行」的规矩。
2. 顶端栏要不要也不占地：推荐**仍占**（读数不该被盖；甩上去的件从栏底弹回）。
3. 开局屏 / 沙盒那种不铺满屏的地层（`fills_screen = false`）同样生效：推荐**一致**，一套规矩。
4. 件飞过背包窗面时画在窗上面（地层在上）：推荐**接受**，飞过只有零点几秒；要藏就得给窗一个更高的 z，牵动 230 / 239 的拖拽层，不值。

## 四 不改

- 128 的「不压着面板」仍在（只是从「落稳前当墙」改成「落稳后推开」）；180 / 198 的弹开、翻倒、斜躺、249 的甩出都不动；核心层落点仍只是样子。
