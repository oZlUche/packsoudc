规矩：

- **数值和火漆签同一来源**：拖一下包就重编译（`InventoryPanel` 已经每拖一下 `compile_player()` 一次），属性表挂在同一个刷新上，永远和真打出来的一致。
- 每行停上去开悬浮窗（`HoverTip`）：说这一项是什么、哪些道具在影响它（基线 + 各件的贡献，`CombatantSpec.items` 里有）。耗气那行的悬浮窗直接复用火漆签耐力那张的 tip。
- 百分比行写「±N%」，零写「±0%」不留空；数字用等宽；中文标签走 `UiText`（中英都写）。
- 深浅：整窗沿用石板窗（深底浅字）；属性表若美术做成蜡板 / 羊皮纸则那一块是浅底墨字，按 169 的 tone 字段来。
- 教练目标：加一个 `stats_panel`（218 补充一的 `control_rect`），序章一的背包教练暂不加步（220 刚压到四步）。

## 六、补充一：右栏到底给玩家看什么（作者 2026-10-21 14:36）

作者：副行不要；格挡、护甲这类只在局内（战斗里）才出现的效果，摆在这里有没有意义，好好想一遍该展示什么。第二稿：https://claude.ai/artifact/Jp9ExGkwUSN2NGbu7wS9sK

### 6.1 想过的候选，和取舍

| 候选 | 判断 |
|---|---|
| 名字 + 肖像 | 要。副行删 |
| 体力（红心） | **不放**：顶栏一直有，背包窗叠在地图上时也看得见 |
| 生命上限 / 耐力上限 / 回气 | **要**。这是角色的「身体」，不靠包也存在；而且不是常数 —— `effective_baseline()` 会乘上局外加成（科技 / 局外 buff）、负重档的减成、生长轴，玩家现在没有任何地方能看到乘完之后的数。写成「70 ▲7」，停上去看是谁给的 |
| 角色被动（野地里长大 / 坚韧 …） | **要**。开局屏之后就再也看不到了，而它们决定这个人怎么玩（休息多回一点、低血自动护甲、军功多拿钱、熟门熟路省步数）。隐藏的主动技能（166 补充一）不列 |
| 格挡 / 护甲 / 急速 / 暴击 / 伤害 ± | **不当固定行**。它们全靠包里的东西，大多数时候是零，一列零行是死的；每件的数值道具悬浮窗已经写了，合起来的结果战前准备屏和回放里会看到。要看「这包合起来给了什么」，另有一种做法（乙案，下） |
| 估算输出 / 耐力档 / 负重 | 火漆签已经在，不重复 |
| 信仰、侵蚀、步数、钱 | 顶栏都有，不重复 |
| 本局第几场、收获价值 | 结算屏的事，不放 |

### 6.2 两种定稿

- **甲 角色卡**（推荐）：名牌（肖像 + 名字）→ 身体三行（生命上限 / 耐力上限 / 回气，带 ▲▼ 与来源悬浮窗）→ 被动两条（名字 + 一句现成的 summary）。全是「这个人是谁」，开包时随时可看，没有零行。栏高约 400，窗高不变。
- **乙 角色卡 + 「这包给的」**：甲之下再加一块动态行，只列非零的包内合计：格挡（最高的那面盾）、护甲、急速、暴击、造成 / 受到伤害 ±；什么都没有就整块不画。给爱算数的玩家一眼看合计，又不出现零行。

推荐先做甲；乙随时能加，不改结构。
