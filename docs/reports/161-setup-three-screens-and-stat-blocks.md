# 方案：开局拆成三屏（选角色 → 配道具 → 选地图与难度），选角屏用方块与爱心读属性差异，包不算重（161）

> 作者原话（2026-10-12，架构设计）：
> 「包不要算重量，或者重量很低，另外在出战界面选择角色时显示角色的初始耐力上限和体力，体力以爱心图标的方式显示，耐力用黄色卡通方块显示（每个方块代表10点耐力），生命上限也用红色方块条显示，每个块代表10点生命上限，以这种方式让角色的属性差异更加显眼。」
> 「之后加入选更多界面，开局流程变为：选择角色【显示初始属性差异和棋盘以及背包】，配置道具（这一步再出现仓库），选择地图和难度。也就是总共分为三个界面，且每个界面右下角都有对应继续和返回的显眼按钮」
> 性质：架构 · 实施。待定按推荐。关联 067（开局屏）、090（地上）、096（预设装备）、129（负重）、157（石板框）。

## 1. 现状

- 开局只有一屏（`ui/game/setup_screen.gd`，712 行）：左列「模式 / 角色 / 预设装备 / 难度 / 规模 / 种子 / 回主菜单」一串单选按钮，中间棋盘（初始包摆好）+ 地上，右边整块仓库，拖拽层盖在中右。角色之间的差别只在左列的一行说明文字（`description` 里「生命 {max_hp}、体力 {vitality_max}」）。
- 开局屏只对**自由模式**有意义：三个序章都 `skip_setup`（084，`begin_direct`），不经这一屏。所以「先选角色再选地图」和现在「先选章节再筛角色」的顺序之争不存在 —— 能进这一屏的章节都允许全部角色；真要有限制角色的章节出现时，第三屏把不能走的章节灰掉并写一句原因。
- 角色数据（`CharacterDef`）：`base_stats.max_hp / max_stamina / regen_stamina`、`vitality_max`、`board_size`、`starting_bags`、`weight_capacity`。三个角色现在是：布鲁图斯 生命 70 / 耐力 55 / 体力 7 / 9 × 6 / 两个皮革包；安德烈 45 / 55 / 默认 5 / 7 × 6 / 两个皮革包；马库斯 55 / 65 / 默认 5 / 默认 8 × 6 / 皮革包 + 小包。没写的走默认（`CombatantBaseline.DEFAULT_STATS`：生命 25、耐力 50；`vitality_max` 默认 5）。
- 负重（129）：`ItemWeight.total(board)` 把棋盘上每件**含包本身**加起来；包写死了重量（皮革包 3、长条包 2、小包 2）。布鲁图斯两个皮革包 = 6 / 56，开局就占一成。

## 2. 改法

### 2.1 三屏向导：同一个 `SetupScreen`，三页轮换，状态不丢

`SetupScreen` 保留现有的公开方法与状态（`choose_character / choose_preset / carry_in / store / depart / cancel …`，测试照调），把 `open()` 里的一大块布局拆成三页，一次只挂一页（`_show_page(i)`：卸掉上一页的控件，重建这一页；选项与棋盘上的东西都在屏的字段里，换页不丢）。页面共用 157 的石板框：标题条写「开局 · 一 / 二 / 三」+ 这一页的名字。

| 页 | 标题 | 内容 | 右下角 |
|---|---|---|---|
| 一 | 选角色 | 左：角色列表（单选，名字 + 一句话）。中：**角色卡**（2.2）—— 名牌（157 的 `Nameplate`，有肖像钩子）、三排读数（生命上限 / 耐力上限 / 体力）、技能行（现有 `skill_lines()`）。右：这个角色的**棋盘预览**（`board_size`，初始包按 `starting_bags` 摆好，只看不拖）+ 下面一行「背包：皮革包 × 2」 | 继续（去第二页）／ 返回（回主菜单 = `cancel`） |
| 二 | 配道具 | 现在的中 + 右：棋盘（可拖）、地上（090）、仓库（仓库**只在这一页出现**）、预设装备一栏（096，挪到棋盘上方一行横排）、负重行（129 的 `encumbrance_text()`，在棋盘下） | 继续（去第三页）／ 返回（回第一页，带上的东西留在棋盘上；换角色才按现有逻辑放回仓库） |
| 三 | 选地图与难度 | 左：模式（章节）列表；中：这一章的说明（`_desc`）+ 规模（085，随机图才有）+ 难度列表 + 种子行；右：一块**出发摘要**（角色名、带了几件、负重级、难度名） | **出发**（= `depart`，主档、大号）／ 返回（回第二页） |

- 右下角按钮：两颗并排锚在页面右下，`继续 / 出发` 用 `UiPalette.Tier.PRIMARY` 的大号（157 顶栏两倍档 28 号字那一档），`返回` 用 `MINOR` 但同样大小 —— 作者要「显眼」，两颗都大，主次靠档位颜色分。快捷键：Enter = 继续 / 出发，Esc = 返回（第一页 Esc = 回主菜单，和现在一致）。
- 第一页选了角色才能「继续」（没角色定义时按钮灰、红字照旧）；第三页选了章节才能「出发」。
- 「回主菜单」只在第一页；第二、三页的返回是回上一页。090 的「回主菜单原样放回带回来的东西」逻辑不变（只在 `cancel` 时发生）。

### 2.2 角色卡的三排读数：`StatBlocks` 组件

新建 `ui/widgets/stat_blocks.gd`（`Control`，自己 `_draw`）：

- `setup(kind, value, unit := 10)`：`kind` ∈ `hp`（红方块，`UiPalette.HP`）/ `stamina`（黄方块，`UiPalette.STAMINA`）/ `vitality`（爱心）。
- 方块：每块代表 `unit` 点（作者定 10），边长 22、间距 4、圆角 4、底一圈深线；**最后一块按余数画成部分填充**（55 耐力 = 五块满 + 半块），所以 45 和 55 一眼能分出来。一排最多 10 块，超过换行（现在最高 70 = 7 块，不换）。
- 爱心：复用 `VitalityWidget` 的画法（抽成 `UiPalette.draw_heart(canvas, pos, size, color, filled)` 静态函数，HUD 与这里共用），一颗一点体力，`vitality_max` 颗全满。
- 每排左边一个小标签（「生命」「耐力」「体力」，`LABEL_HUD` 变体），右边不写数字 —— 方块就是读数；鼠标停上去的提示写具体值（「生命上限 70」）。
- 数值来源：`character.baseline().base_stats` 的 `max_hp / max_stamina`（没写的就是默认值，照样画）、`character.vitality_max`。**不含**科技 / 局外 buff 的加成（那是开局那一刻 `RunState.start` 才算的；这里是「角色自己的底子」，卡上一行小字说明）。
- `耐力回复`（`regen_stamina`）三人也不同（3 / 4 / 5），作者没点名；卡上在耐力那排后面用小字写「每秒回 N」（待定 1）。

### 2.3 包不算重

- 数据：`bag_leather / bag_long / bag_small` 的 `weight` 改为 `0`；`ItemWeight.of()` 对 `weight == 0` 会回落到公式 —— 所以公式里加一条：`def.is_bag` → 0（不看格数）。以后新包不写重量也是 0。
- 129 的架构文档「含包本身」改成「不含包」；`encumbrance_text()` 不变。
- 不改负重上限（56 / 40 / 48）：作者说的是包不算，不是上限变。

### 2.4 负重分级：最高一级挪到两倍之后，门槛先测后定

> 作者原话（2026-10-12）：「最高级的负重惩罚应该在200%以后才出现，现在太容易达成了，对此你可以开一个测试用的线程来看看每局平均负重（在武器不大于三且配有至少两件防御性道具，并带有不少于一定数量的珍贵材料或道具时）」。

- 现状（`data/authoring/encumbrance_rules/standard.json`，只有自由模式用）：吃力 > 1.0 倍、超重 > 1.25 倍、寸步难行 > 1.5 倍（走路翻倍）。按现有道具算：武器平均 8.8 重、防具 18、盾 22、材料 3 —— 布鲁图斯（上限 56）带三件武器 + 两件防御件 + 五份材料约 80 重 ≈ 1.45 倍，再捡一件就寸步难行；安德烈（40）更早。
- 改法：三档门槛改成 **1.0 / 1.5 / 2.0**（寸步难行只在两倍之后），中间档的减成不动。门槛是数据，`EncumbranceRules.level_of` 不改。
- **先量再定**：请协调开一个测算线程（不是本线程、不是执行线程）：用 `core/run/calibration` 的写法跑若干局自由模式（三个角色各若干种子），按作者的画像装包 —— 武器 ≤ 3、防御件（防具 / 盾）≥ 2、珍贵材料或珍宝 ≥ N（N 取 3 和 6 两档），记每局撤离时的负重 / 上限倍数，给出平均与分布；再按结果定三档门槛（上面的 1.0 / 1.5 / 2.0 是没量之前的默认）。测算写进 `docs/reports` 一份短报告。

### 2.5 测试

- `test_setup_screen`：三页轮换（`page()` 读数、`next() / back()`）；第一页换角色后第二页的棋盘尺寸与初始包跟着变；第二页带上的东西在第三页「出发摘要」里件数对；`depart` 的结果和现在一样（layout、preset、difficulty、seed）；`cancel` 只在第一页；Esc / Enter 映射。
- `test_stat_blocks`：70 生命 = 7 块满；55 耐力 = 5 块 + 半块；`vitality` 7 颗心；`unit` 可改。
- `test_item_weight`：包重为 0；布鲁图斯空棋盘负重 0。
- `test_encumbrance`：1.9 倍是超重、2.1 倍才寸步难行（门槛按测算结果改时测试跟着改）。
- UI 棘轮（`tests/ui/test_theme.gd` `RATCHET`）：新控件只用主题变体与自绘，不加 `add_theme_` 覆盖。

## 补充一（2026-10-12）：负重三档门槛按测算定为 1.2 / 1.6 / 2.2（不含包）

测算报告：`/mnt/project-files/architecture/encumbrance-load-survey.md`（测算线程，PR #117；469 局自由模式，三个角色 × 两种规模 × 两种拿法，机器人塞满棋盘 = 负重上沿）。要点：

- 现行（含包，1.0 / 1.25 / 1.5）：撤离时 **91%** 的局在最高档，画像局 96% —— 满包本身就是上限的 1.9 倍，门槛与取舍无关。
- 包不算重（2.3 节）是最有效的一刀：满包倍数整体降约 0.3。
- 画像局（武器 ≤ 3、防御件 ≥ 2、珍贵 ≥ 3）不含包：平均 **1.74**、中位 1.73、P90 2.12；珍贵 ≥ 6 几乎一样（卡人的条件是「防御件 ≥ 2」，盾重）。
- 门槛对比（不含包，最高档占比 全体 / 画像）：1.0 / 1.5 / 2.0 → 10% / 19%；**1.2 / 1.6 / 2.2 → 4% / 7%**；1.25 / 1.75 / 2.25 → 3% / 7%。
- 分角色：安德烈乌斯上限 40，画像局不含包平均 1.99、P90 2.38 —— 三人满包绝对重量相近（65 / 74 / 88），上限最低的他最容易到顶。

**定数**（待定 5 的 A 改成这一组）：`standard.json` 三档 `over` = **1.2 / 1.6 / 2.2**，减成不动。理由：作者要「最高档在两倍以后」，2.2 留了余量（画像局 7% 到顶，都是塞满盾与金属的局）；一档提到 1.2 让「装得克制就不罚」有一点空间（轻装从 4% 升到 10%）。安德烈乌斯仍约两成画像局到顶 —— 按「擅长逃跑的人背不动」的定位接受，不单独调上限（作者要调再说）。测算没算科技「扛重」（+6 / +12 / +20），点满之后倍数还会明显下降。

测试：`test_encumbrance` 的断言改成 1.5 倍是吃力、1.9 倍是超重、2.3 倍才寸步难行。改动范围不变（`data/authoring/encumbrance_rules/standard.json` + 重新导入）。
