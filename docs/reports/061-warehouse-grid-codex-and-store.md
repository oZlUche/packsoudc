## 几条决定

**账在进结算屏之前记。** 原来是结算屏按「继续」才 absorb；现在结算屏要画带回来的棋盘和仓库，所以一局一结束（战败或撤离）就算账、absorb、存 meta、删存档，
结算屏拿到的已经是记完账的局外。「继续」只是换屏；再按一次不会记两遍（`_settled` 守着）。

**带回来的棋盘是一块不要求包的格子。** 大小和一局里的棋盘一样，非包道具按原来的位置放回去，包不带（只计图鉴）—— 这就是作者说的「所有包统一替换成最大的默认背景包」：
不要求包的格子，处处可用。位置照旧的好处是玩家在结算屏看到的和撤离前一样，拖起来不用重新认。

**一键置入按栏位顺序、放不下就停。** 作者的原话是「中途停止并提示」：停在放不下的那一件，报它的名字和还剩几件；玩家可以挪仓库再按一次，或者不要了。
不做「跳过这件放下一件」—— 那会让人以为放完了。

**什么能存进局外只问一处。** `MetaState.keeps(def)` 现在是「不是包」。作者说过包只是当前的媒介、将来可能删掉，所以存档格式、界面都不依赖「一定有包」，删的时候删这一个分支。

**仓库大小以存档为准。** 规则给的是新仓库的大小；成长过的仓库不该被规则缩回去。局外存档版本升到 2，v1 是开发期的，作废。

**图鉴计数幂等。** 每件各计一次（包也算），`lit` 只在计数从 0 变 1 时加，第二次带出同一种不算点亮 —— 和作者第三轮说的一致。

## 验证

```
bash tools/test.sh
通过  6734 项断言，41 个套件，耗时 87 秒
```

- 局外规则走管线：往返、仓库至少 1×1、作者文件是不动点、资产在、`GameFlow.load_meta_rules` 取得到、`MetaState` 按规则开仓库、没规则用默认。
- 撤离棋盘带回：带回的件数 = 非包件数、和原来一样大、不要求包、包没带回、每件都在原位置；仓库没自动进；图鉴每件各计一次、点亮数 = 种类数、包也点亮；
  2×2 的仓库一键置入放不下就停（放进几件、卡在谁、剩几件）；第二局同样的东西不算点亮、计数翻倍、没清完的并进来一件不丢；大仓库全放进去、棋盘清空、uid 两两不同；不要了就清。
- 存档 v2 往返（仓库、带回来的棋盘、图鉴），v1 → null。
- 流程：一局一结束账就记了、meta 已存；没清空 `can_begin` 有原因、`begin` 拒绝；局外屏一键置入后能开新局、存了。
- 现有套件改成新语义：结算与局外、走到撤离点撤离（带回 → 置入 → 仓库）、仓库带进一局（先置入再带）、导演帧测试在结算屏一键置入。
- 截图（`DEMO_SCREEN=result` / `meta`）：结算屏左边带回来的棋盘、右边仓库格子、一键置入；局外屏多了图鉴一页。
