# 128 方案：不画暂存区 —— 格子外的整块屏幕就是「地上」，拖出背包放哪就在哪，每个节点各自一片地

> 架构 · 提议（2026-10-05）。作者：「并不真正作出一个暂存区，而是将整个界面（格子外）的空间做成容纳道具的区域，换言之也就是将道具从背包拖出就是一个存放行为，同时每个节点独立的界面就是一个独立的容器」。

## 一、现状（已核实）

- 语义上作者要的**已经成立一大半**：084 定了「棋盘外的空间全都是暂存区」（`DragLayer.drop_outside_to_stash`，放手时底下没有容器视图就进暂存区）；087 / 101 定了「暂存区按点独立」（`NodeStorageModule`：离开一个点，暂存区里的东西留在那个点，回来再出现；撤离不带走；地图上标得出哪些点存着东西）。
- 差的是**表现**：暂存区是一个列表（`ItemStash`，3.4：没有坐标、没有占格），画成右下角一个框（`StashView`，一行一件），所以玩家看到的是「拖进一个面板」，不是「放在地上」。
- 3.4 当年把它做成列表的理由是**不要发明「暂存区也要整理」的玩法**。这条理由本篇保留：地上的位置**只是记个样子**，不占格、不碰撞、不参与任何规则。

## 二、设计

### 2.1 一个词：「地上」

暂存区改叫**地上**（术语、提示、百科、事件文案里的 `{zone:暂存区}` 全换成 `{zone:地上}`，`IdAliases` 不需要 —— 这是文字不是 id）。规则一字不变：不参战、不参与邻接 / 套装、留在这个点、撤离不带走、不限件数。

### 2.2 数据：每件记一个落点

`ItemStash` 加 `spots: Dictionary`（uid → `Vector2`，**归一化到 0～1 的屏幕坐标**），`insert(inst, at, spot)` 多一个可选参数；没有落点的（读旧档、程序塞进来的脱落物、「全部拾取」放不下的）由 `next_free_spot()` 给：从屏幕左下角起按网格找一个和已有落点不重叠的位置。`to_dict / from_dict` 带上；`NodeStorageModule` 存的是 `ItemInstance` 列表，落点跟着 stash 的字典一起存（`nodes[node_id] = {items, spots}`）。不升存档版本：没有 `spots` 就全部重新铺。

归一化是为了换分辨率、换窗口大小时东西还在屏幕里；画的时候乘回视口尺寸再夹进可用区。

### 2.3 画：`GroundLayer`，整个节点只有一层

作者补充（同日）：「在一个节点中打开背包、战利品、战前、搜索的背景界面都是共同的，虽然布局不同」。所以地不是每个屏各画一份，而是**一个节点一层**：

`ui/inventory/ground_layer.gd`：一层铺满视口的 `Control`，由 `GameDirector` 持有**一份**，放在背景之上、整个叠层栈（地图屏、背包面板、容器屏、战前准备、商店 / 休息 / 神坛 / 事件）之下。切换、叠加、最小化哪一屏它都不动，画的永远是当前点的 stash；换了节点（`arrived`）才换内容。各屏只是摆在地上的不同布局：它们向 `GroundLayer` 登记自己占住的矩形（`reserve(rect)`，关闭时撤销），地上的东西被面板盖住时往最近的空处推开（§2.4），面板关了也不挪回。
- 一件就按它的形状画在落点上（`ItemPainter.draw_item`，和棋盘同一套画法、同一个格子尺寸，所以「放下去是什么样就是什么样」）；~~允许重叠，后放的在上~~ → 不重叠，相遇弹开（180 §2.2）；
- 悬停出悬浮窗、双击快速置入棋盘（现有 `quick_move` 的路）、左键拿起进 `DragLayer`（从地上拿走 = 从 stash 移除）；
- 没有框、没有标题、没有滚动条；东西多了就是满地。

`StashView` 删掉；`inventory_panel` 右下那块留给棋盘和提示。

### 2.4 拖拽：放手在哪就落在哪

`DragLayer`：放手时底下没有容器视图 → 进当前 stash，落点 = 放手点（归一化）。落在**面板上**（背包面板、按钮栏、战利品框之类不是容器的地方）也算地上，但落点往面板外最近的空处推一下，免得东西被面板盖住看不见。从地上拿起又放回地上 = 改落点。

残影在棋盘外时不再画「插入线」，就是跟手。

### 2.5 每个节点一片地

已经是（`NodeStorageModule`）。补两处：
- 地图屏是叠层栈的底，地在它下面也照画，所以玩家走到一个存过东西的点，一进屏就看见地上有东西，不用先开背包；开背包、开战利品、进战前准备，看到的还是同一片地、同一些东西在同一个位置。
- 节点存着东西的标记照旧；离开时的提示照 109（不弹）。

### 2.6 不变的

撤离 / 结算（「地上还有 n 件没背出来」）、脱落 / 顶出 / 替换包进地上、`InventoryService.transfer_*` 的签名、`ItemStash` 作为列表容器的全部接口、按点存档。所有现有 stash 测试应原样通过。

## 四、待定（按推荐即执行）

| # | 问题 | 推荐 |
|---|---|---|
| 1 | 名字 | **地上**（「拖出背包 = 放在地上」一句话讲清） |
| 2 | 允许重叠吗 | **180 起不允许，相遇弹开**（画面层解算，核心层仍不碰撞）。原定：允许（后放的在上、拿得起），只在初始铺放和被面板盖住时自动推开；不做整理按钮，不做碰撞 —— 守住 3.4 的「不发明整理玩法」 |
| 3 | 落点存不存档 | **存**（归一化坐标），不然每次读档满地重排 |
| 4 | 地是每屏一份还是每节点一份 | **每节点一份**（作者已定）：由导演持有，各屏只是布局 |
