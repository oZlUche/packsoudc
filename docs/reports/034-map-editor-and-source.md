# 034 · 地图编辑器、地图来源、路线同步生长

> 阶段 4 · M3 ｜ 架构文档 5.3.1（新）、5.4（v1.33）｜ 计划外插入，记在[报告 027](archive/027-m3-plan.md) 的 M3-3a

## 目标

作者提的四件事：

1. 一个开发者也能用的地图编辑器：先按参数随机生成，再手动改；
2. 每局的地图配置里能选「随机生成」还是「载入预设」；
3. 四环地图为了高危区要重试太多次 → 高危区可选，且要五环以上才有；
4. 路线不要一条走到底再走下一条，而是从最外环上几个相隔至少 X 个槽位的出生点**同步**向内长，
   这样能实时确认剩余空间。

## 编辑器不认识任何具体的生成器

左侧的参数表单不是为 `RingMapConfig` 手写的 —— 它问生成器要一份 `default_config()`，
再用道具编辑器那个 `PropertyForm` 把导出属性反射出来。中间怎么画问 `MapLayout`
（按 `graph.layout_kind` 取，和生成器注册表同一个套路），连「哪里还能加点」也是布局回答的。

所以第二章换一种拓扑时：登记一行生成器、一行布局，编辑器一行不改。

操作：左键选点；空位上左键加点；选中后 Shift+左键另一点连 / 断；右键一条路断开；Delete 删点。
右栏改类型、危险等级、所属高危区、出生点 / 终点。每个动作都是公开方法，鼠标只是调它们 ——
测试也直接调，不伪造输入事件。

**校验分两档**：通用规矩（连得上、有出生点、到得了终点）不过就不能当预设用，红字；
形态自己的规矩（高危区单入口、换乘点……）只是提醒，黄字。后者是**给生成器的约束，不是给作者的**，
手绘的图有权不守。`MapSource` 载入预设时也只问前一档。

**删点不动路线标注**。路线是一串有意义的节点，删掉中间一个之后怎么接是作者的决定；
替他接上或整条删掉都是越权。校验会说「路线断了」，右栏有个「清空路线标注」。

## 预设定死地形，不定死内容

预设图固定的是点、路、类型。节点里具体刷出什么由 `content_seed` 决定，
`MapSource.reroll_content_seeds`（默认开）让它每局按对局种子重掷 ——
同一张手绘地图，每次进去敌人和战利品不同。关掉就连内容也原样照搬（教程关、固定挑战用）。

## 路线同步生长

每一环上所有路线一起落子。落子之前各条路线的位置都在手上，所以：

- **候选最少的先挑**。先让选择多的挑，可能正好把别人唯一的落点占掉；
- 合流之前，与这一环上已落的子保持间距 —— `entry_min_gap` 以最外环槽位为单位，按环长等比缩小；
- 挤不开先退到「不重合」，再退到合流。

出生点：大致均分、在余量内抖动、避开空白区；贪心从一个起点排不下就换下一个起点。
`出生点数 × 间隔 > 槽位数` 是配置错误，`build_note` 会直说，而不是一句「没能造出图」。

顺带发现 `route_drift` 也该用同一把尺：原来它是「± 2 个槽位」不分环，内环只有六个槽位时
那就是 ±120°，截图里路线横着穿过半张图。现在同样按环长缩。

## 统计揪出三个被重试掩盖的缺陷

写 `tools/map_stats.gd` 本来只是想看改完之后重试次数降没降。它按规则汇总失败原因，
第一次跑出来是这样：

```
5 环 | 平均 3.11 次 | zone_missing 55, isolated 81, reachable 80, zone_connected 69, zone_gate 12
```

`zone_missing` 是配置层面的（高危区没地方长），其余四条**不该出现** —— 那是算法没做对，
靠换种子碰出一张恰好没事的图：

1. **高危区沿「空间相邻」生长，候选边却按「次序最近的若干个」建**，两者对不上时区内根本没边相连。
   → 生长时走过的每一步记下来，建边之后补齐并保护。
2. **区外的点如果向内的边全通进了高危区，隔离时一并被删光**，只剩同环的弧，而弧随后还要按概率断。
   → 隔离后给它重连一条通向区外内环点的边。
3. **gate 那条边没受保护**，是切向边的话会被断边步骤断掉，整片区进不去。
   → 保护。

修完之后（各 64 个种子）：

| 环数 | 成功 | 平均尝试（033） | 平均尝试（现在） | 剩下的失败原因 |
|---|---|---|---|---|
| 3 | 64/64 | — | 1.00 | 无 |
| 4 | 64/64 | 5.11 | 1.00 | 无（没有高危区了） |
| 5 | 64/64 | 2.89 | 1.50 | 只有 `zone_missing` |
| 6 | 64/64 | 2.20 | 1.19 | 只有 `zone_missing` |
| 7 | 64/64 | — | 1.16 | 只有 `zone_missing` |

033 里我把四环的 5.11 次归因于「高危区能落脚的环只有一个」。**那只对了一部分** ——
大头其实是上面三个缺陷。教训：重试次数高的时候先看 `failure_tally` 里是哪条规则，
「换种子重来」会把算法缺陷和配置拥挤混成同一个数字。

新增 / 改动的测试：

- 环形生成器：出生点间隔进了 64 种子的不变式；2 / 3 / 4 / 6 环各 16 个种子过全部不变式；
  高危区门槛（从配置读 `min_rings`，不写死 5）与可选；间隔拉到理论上限放得下、多一格放不下且说得出原因；
  32 个种子里没有一次提前合流。
- `MapGraph.remove_node`。
- `MapSource` / `MapPreset`：存读逐字节相同；读回来的图过得了环形校验（JSON 的字典键变成字符串）；
  重掷内容种子；走不通的图拒绝载入。
- 编辑器：改类型、连断、空位加点、删点、zone 同步、存了再载入、`MapSource` 载得进编辑器存的预设；
  类型名单与配色表互相覆盖；每个登记的生成器都有对应布局。

## 遗留

- 没有撤销。现在误删只能重新生成或重新载入。
- 环形布局是朴素版（角度 = 槽位 / 槽位数），径向边不严格垂直于切线，M3-6 解。
- 编辑器不能改环数 / 槽位数这类 `layout_meta`，要改就改参数重新生成。
- 参数表单把「类型分配（M3-3c）」那组字段也摆出来了，现在改了没效果。
- 节点 `content`（敌人、战利品）还编辑不了，等 M3-3c / M4 有了内容再说。
