## 一、逐条

### 1. 「敌人的耐力没有正常消耗」

**排查**：写了探针对每个教程敌人真打一场、数敌方 `stamina` 的扣费事件 —— **机制没坏**：每个敌人都在扣（序章一的劫掠者 5 次、守卫 12 次……）。问题在**数据**：序章二的游兵我给了 `max_stamina 120 / regen_stamina 20`，三把匕首每秒花 15、回 20，条永远满着，看起来就是「不消耗」；别的敌人回复 4、上限 50，几秒的战斗只掉几点，也几乎看不出。
**改**：游兵改成 `max_stamina 60 / regen_stamina 8`（`data/maps/tutorial2.json`）—— 探针里一场 4 秒掉到 29 / 60，看得见；克制矩阵（塔盾 5/5、板甲 0/5）不变。别的敌人没动：它们的回复本来就压不住消耗，只是战斗太短。

### 2. 「搜索界面的回到地图选项点击后不代表结束事件，只是最小化窗口」

**排查**：搜索屏的「收起（回地图）」走的就是 `GameFlow.hide_overlay` = 最小化（084 作者定：会话开着、没拿的还在、「回到这个点」原样放回），测试 `frame_minimize_and_window` 一直验着这条。**行为没错，按钮文字没说清**。
**改**：按钮改成「回到地图（不结束：回到这个点接着搜）」。

### 3. 「合成是只要相邻就会在进入下一个节点时自动发生的，去掉拖上去的功能」

**改**：合成不再有「拖到一起 / 配对」这一步。`RunState.craft_pairs()` 随时报出棋盘上**四邻相接、有配方**的对子（每件只进一对，uid 升序先配到的算，顺序稳定）；`resolve_crafts` 在踩上下一个点时（暂存区清完之后）把每一对合掉：产物落在 uid 小的那件的位置（它的朝向），放不下试另一件的位置、再自动找位，再不行进暂存区并提醒；`craft_done` 与结果屏照旧。
`pending_crafts` / `queue_craft` / `craft_queued` 与存档里的配对表全删（相邻本身就是状态，不用另存）。拖拽层删掉 `_craft_target` / `_stash_partner` / `_craft_into` / `queue_craft`，只留 `craft` 回调**用于高光**：拿起一件时能和它合成的那几件亮一圈，提醒放到旁边。背包面板：相邻的两件都画「合」，新挨上一对提示一句「走到下一个点时合成 X」。序章二的教程文字改成「放到匕首旁边（挨着）」。

### 4. 「道具的颜色代表了稀有度，从高到低：红色、金色、紫色、蓝色、绿色、白色」

**改**：`ItemPainter.RARITY_COLORS` 六档：0 白 / 1 绿 / 2 蓝 / 3 紫 / 4 金 / 5 红；名字六个（普通 / 优良 / 稀有 / 史诗 / 传说 / **神话**）。按稀有度下标的表都补到六档：掉落率 `base_chance` 加 0.02、商店权重加 0.5、揭示耗时加 3.0（`SearchRules` 与 `LootView` 的默认表、两份节点规则）；珍宝权重改成 `{"4": 3, "5": 1}`（金、红）。现有道具最高稀有度 4（灰白色金属碎片），自然成了金。

### 5. 「力量护符的给武器增益效果没有直接显示在背包的 dps 统计上，检查是没有生效还是 dps 统计不是实时计算的」

**排查**：统计是实时的（拖一下重编译）。**两件事叠在一起**：
- 力量的符号的血怒是**信力一阶**才解锁的（`faith_bonuses[0].tier = 1`，暴力之神阈值 3 —— 打三场才有）；没过阈值它什么都不给，这是 082 的规则，不是 bug。
- 过了阈值也看不见：血怒是「开战时给自己上一个 buff（增伤 +10%）」，而预估 DPS 只按道具自己的属性算，buff 是战斗里才施加的东西 —— **统计没算它**。
**改**：`CombatantSpec.opening_mods()` 收集「开战时 + 必然 + 给自己上 buff」的属性修饰（blood_rage 这类），`estimated_dps_of(item)` 把它们并进道具属性再算，`rough_dps()` 与道具悬浮窗的 DPS 都走它。测试：匕首 + 符号，信力一阶的预估 DPS 比零阶高（血怒 +10%）。有时长的 buff 也按全程算 —— 只是预估。

### 6. 商店重做

**改**（`ui/game/shop_screen.gd` 重写；`ShopSession` 加货架棋盘）：
- **左店右包**：右边是 [InventoryPanel]（棋盘 + 暂存区），左边四个**栏位**（`ShopSession.shelves`：每格一块小棋盘，至少 3×4，商品更大就跟着大），商品是真的 `ItemInstance` 摆在 (0,0)，底下写价与尺寸。同一层拖拽盖着全部。
- **买**：把商品拖进自己的棋盘 / 暂存区 = 买，放手时 `pay_for(i)` 收钱、记卖掉；钱不够 `drop_filter` 拦住（东西弹回栏位）并提示「金币不足：X 要 N 币，你有 M」。双击商品 = 买（`buy(i)` 自己找位：先包、放不下进暂存区），钱不够双击没反应、同一句提示。
- **卖**：把包里 / 暂存区里的东西拖进「出售区」（`sell_box`，3×4）= 卖，回**定价的一半**（`EconomyRules.shop_sell_ratio = 0.5`，`sell_price_of`）。自己的东西放不到栏位上；商品放不进出售区。
- 店里 `drop_outside_to_stash` 关着：放到外面 = 放回原处，不算买也不算卖。刷新、收起、离开照旧。
- `bought(def, price, inst)` 多了 `inst`：双击 / 按钮买的由会话交出实例（RunState 先试进包、放不下进暂存区）；拖着买的已经在玩家手里，inst 为 null。

### 7. 「战斗中增加一个 buff 栏……每个用一个图标（目前暂时用一个字）表示，鼠标移动到对应图标上时可以悬浮显示这个 buff 的具体效果」

**改**：[CombatantPanel] 的层数条改成**图标**：名字的第一个字 + ×层数，减益红框、增益蓝框，鼠标压上去发 `buff_hovered(id, at)`；[BattleView] 接住开 [HoverTip]，正文是 [Glossary.describe_buff]（增益 / 减益、叠层、时长、每层的属性、自带规则、上身 / 到期效果）。定义从双方的战斗单位里收集（`Glossary.buffs_in_spec`，战斗屏在 `play` 之后 `set_buff_defs`）。

### 8. 「道具的效果指向特定名词或关键词时……在悬浮窗侧边给每个关键词展示一个对应的详细说明窗口（这套显示逻辑在未来的正式渲染后也要保留）」

**改**：新类 [Glossary]（`core/text/glossary.gd`）：
- **固定词条** `TERMS`：自发 / 开战时 / 出手时 / 冷却 / 急速 / 护甲 / 护盾 / 耐力 / 耗耐力 / 永续 / 叠层 / 休眠 / 信力 / 合成 / 增益槽 / 受益槽 / 中毒 / 流血……
- **buff 词条**：从道具的规则里收集到的 `BuffDef`（自己的、信力加成的、buff 自带规则里再施加的），说明按定义生成（`describe_buff`）—— 数据改了文字跟着改。
- `terms_in(text, extra)` 找文字里出现的词条（按出现顺序），`mark` 把它们标成紫色下划线。
- **主文字只写名词**：`ApplyStatus.describe()` 改成「施加中毒」「获得血怒」，不再写永续 / 层数 / 时长；力量的符号的 note 改成「第一阶：开战时血怒」。「伤害 +10%」在血怒的侧窗里。
- [ItemTooltip.describe_full] 返回 `{text, terms}`；[HoverTip] 在主面板右边（放不下就左边）竖着开一列小窗，一个词条一块。**逻辑与渲染分开**：词条是数据，怎么画是 HoverTip 的事，将来换正式渲染保留这套「主文字 + 侧边词条」。
- `Glossary.mod_text` 统一了属性修饰的中文（「伤害 +10%」「护甲 +4」），道具悬浮窗、buff 侧窗、包体加成都用它。

### 9. 「武器道具要写耐力消耗，另外，没有主武器的概念，包里的所有武器都会发挥作用，不要假设存在什么装备栏」

**改**：武器的每条规则后面写「耗耐力 N」（`ResourceCost` 的面板数或属性值）。**排查「主武器」**：全项目没有这个假设 —— `CompiledItem` / `OnItemFired` 的注释早写着「本作没有主武器」，编译器对每件武器各自出规则，悬浮窗也是每条规则一行；这次在悬浮窗里加了一句注释确认。

### 10. 「信仰道具可能会拥有通用效果，也就是即使不处于激活信仰下也能发挥的效果，比如盾牌提供的固定减伤，武器本身的攻击力，护符可以彻底失去效果」

**改**：休眠（别的信仰激活着）的信仰道具**保留自己的战斗定义**（`combat`：基础属性 + 自己的规则 + 包体加成 = 通用效果），只丢**信力加成、邻接（不给不收）、套装计数**。新字段 `ItemDef.dormant_keeps_combat`（默认 true）：写 false 就彻底不参战；没有 `combat` 的道具（力量的符号这类护符）本来就没有通用效果 —— 休眠即彻底失效，不用改数据。`FaithState.keeps_combat_when_dormant(def)` 把这条写明；编译器里休眠的记在 `dormant` 表、跳过 4b（信力）与邻接。悬浮窗写「信仰道具：别的信仰激活时休眠（保留通用效果 / 彻底失效）」。

### 11. 「击败 BOSS 后保底掉落一个金色道具，然后直接撤离结算」

**改**：
- `DropRule.boss_rarity = 4`（金；-1 = 不保底）：核心点打赢时 `DropResolver.roll(..., boss = true)` 先塞一件 —— 这个稀有度里先挑带珍宝标签的，没有挑任何非包道具，还没有往低一档找；**不看它身上有没有**（作者定的保底是给玩家的奖励，不是掉落规则的例外）。
- `NodeRules.boss_extracts = true`：`NodeEvents` 打赢核心点发 `boss_defeated`，`RunState.boss_cleared` 记着（跟存档）；战利品屏标题写「BOSS 的战利品　收起就直接撤离结算」，收起（`hide_overlay`）= 不要剩下的 → `extract_after_boss()`（不看站在哪、不付费，`end_reason = boss`）→ 结算屏「击败了核心的 BOSS，直接撤离」。规则关掉就还是普通的收起。
