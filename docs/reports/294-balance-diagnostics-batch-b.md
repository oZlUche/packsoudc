### 2.2 扫表实验目录（§6.1、§6.3）

`core/run/calibration/balance_experiment.gd`（`BalanceExperiment`）+ `balance_report.gd`（`BalanceReport`）：

```
godot --headless --path . --script res://tools/bench_matrix.gd -- <木桩> <池> <难度> <每格场数> <种子> --out-dir=<目录> [--mode=coverage|frequency|bare_node] [--maps=20] [--chapter=<id>]
```

不加 `--out-dir` 时还是旧的四张表，结果和以前一样。加了就写 `<目录>/<实验 id>/`：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 批次 A 的实验元数据（来源 `synthetic`、构建、引擎、内容摘要、木桩集合摘要、参数） |
| `seeds.json` | 种子规则 + 每场的种子和开打前随机数状态 |
| `cases.jsonl` | 一场一行：case / 格 / 配对 / 序号、来源、木桩键、流派、段、角色、预算、档、敌人摘要（id、档、件数、内容摘要）、节点（类型、地形种类、危险度；频率测试还有第几张图第几个点）、种子与状态、结果与 §2.1 的指标、有效性。造不出来的也写一行，带原因 |
| `summary.json` | 全体一份、每格一份 `summarize()`；兵刃变体对兵刃的配对差；频率测试的总体（图上的点按档、地形、危险度、敌人计数） |
| `summary.csv`、`report.md` | 都从 `summary.json` 印出来，不各算一遍（测试读回 `summary.json` 重印，逐字一样） |
| `diagnostics/` | 只给平局、超时、无效的场存完整诊断包，最多 20 份 |

三种抽样，报告分开写：

| 抽样 | 敌人从哪来 | 能说明什么 |
|---|---|---|
| `coverage` 覆盖测试 | 池里每个敌人 × 每一档显式枚举，不看节点条件 | 找一边倒的对局；不代表一局里遇到的频率 |
| `frequency` 频率测试 | 照正式开局（`RunState.start`，带难度）生成几张图，取图上真的战斗点和它身上已经定好的敌人，按档抽；点出现得多就抽得多 | 修报告 292 #1：真实点带地形种类与危险度。随机点、搜索遭遇是揭开时现造的，不在图上，没算进来 |
| `bare_node` 假节点 | 沿用旧扫表那个没有地形、危险度 0 的点 | 对照用；报告里写明不能当真实地图难度 |

同一档同一序号的敌人和随机源只看（种子, 档, 序号）（覆盖测试再加敌人），各路木桩共用：敌人造一次，连同造完时随机源的状态记下，每路接着那个状态开打。测试核过：假节点的一格和旧 `BalanceMatrix.cell` 逐场一样。结果是旧扫表 419 秒的量，现在 58 秒。

### 2.3 猎手同格式

`tools/bench_hunters.gd -- <猎手> <每档场数> <木桩> … --out-dir=<目录>`：同一种实验目录（假节点抽样），`summary.json` 多一节每段的 `wanted`（现在的规则给的档）和 `best`（有效场里胜率离五成最近的档）以及那一档的区间；`HunterBench.wanted_of()` 从原来的 `run()` 里拆出来，两条路共用。

### 2.4 参考配装合法性检测（§7）

`core/run/calibration/scenario_check.gd`（`ScenarioCheck`）+ `tools/check_balance_scenarios.gd`：

```
godot --headless --path . --script res://tools/check_balance_scenarios.gd -- [木桩] [--pool=…] [--difficulty=…] [--character=…] [--allow-dropped] [--out=<报告>]
```

- 每份：道具都认得（改过名的按别名认）、按记的落点摆得回去（和数据审计同一个函数）、独一的不重复、声明的核心件（`core`，没写按生成器挑中的 `picked`）都在棋盘上、生成器丢掉的件（`left`）报出来、超没超声明的预算（`budget`：格子 / 重量 / 价值）和角色负重。
- 预算记件数、包数、物品占格 / 棋盘格、重量、价值；不拿待校准的战力估计当等成本的定义。
- 五路流派木桩按同样的池、段位、种子重造一份逐份比。
- 退出码：0 全合法；1 用法或读写错误；2 有不合法的（丢件默认也算，`--allow-dropped` 降为提示）。
