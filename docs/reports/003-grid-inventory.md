# 003 · GridInventory 容器核心与原子移动

对应架构文档：3.2 节「一个类服务所有容器」、3.3 节「跨容器移动必须原子化」。

## 目标

实现网格容器本体与跨容器移动服务，使「玩家背包／尸体／商店／仓库／装备栏」能够共用同一套实现，并保证移动失败时物品绝不丢失。

| `tests/run_tests.gd` | 增加防挂死兜底与 `run_*` 子套件自动发现 |

## 关键决策

### 1. 容器带 `changed` 信号，而不是依赖全局 EventBus

`RefCounted` 可以声明 signal，所以容器自己就能通知表现层，`core/` 无需依赖任何 autoload。架构原则 1.1「逻辑层零 Node 依赖」因此得以保持，也省掉了一个目前还没有其他用途的 `EventBus` autoload。

### 2. 批量操作把中间态藏起来

`begin_batch()` / `end_batch()` 成对使用，区间内的多次改动合并成一次 `changed`。

跨容器移动必须用它包住：否则 UI 会在「已从源移除、尚未放入目标」这一瞬间收到信号并据此重建视图。虽然同帧内最终状态正确，但让表现层观察到不一致的中间态是个隐患，不如从源头掐掉。

测试里有专门一组断言，验证一次移动在源与目标各只发一次信号，回滚时同样只发一次。

### 3. `place` 是先校验后写入的全有全无操作

这是回滚能成立的前提：`place` 失败时一个格子都没碰过，所以 `InventoryService.move` 在目标放不下时，一定能把物品原样放回源容器。这个不变式写进了 `move` 的注释，改动 `place` 时不能破坏它。

回滚仍然做了失败检查并 `push_error`，因为一旦这个不变式被破坏，容器状态就损坏了，必须立刻暴露而不是静默继续。

### 4. `transfer_all` 按占格数从大到小搬

先安置大件，小件更容易见缝插针，总装入量明显优于随机顺序。测试用「2x2 背包 + 一件 2x2 与两件 1x1」验证了这一点：结果必须是那件大的被装走。

这个顺序将来直接服务于搜刮界面的「全部拾取」。

### 5. 新增 `tools/test.sh`

踩了两次同一个坑：新增带 `class_name` 的脚本后不重跑 `--import`，全局类缓存不更新，测试会以 `Identifier "GridInventory" not declared` 失败。

脚本每次都先 `--import` 再跑测试，并过滤掉引擎与插件的噪声输出。用 `GODOT=...` 可覆盖引擎路径。

```bash
bash tools/test.sh
```

### 6. 测试入口增加防挂死兜底

GDScript 的运行时错误会中断 `_initialize`，导致 `quit()` 永远执行不到，无头进程一直挂着 —— 这次就因此卡了一次 120 秒超时，而且因为 stdout 被管道缓冲，连错误信息都看不到。

现在 `_process` 会在第一帧检查完成标志，未完成则打印提示并以退出码 2 退出。退出码语义：0 通过，1 有断言失败，2 测试自身崩了。

```

```

输出中会夹带 5 条 `WARNING`（重复 id、无效定义、未知 def id ×2、重复 place），全部由负向用例触发，是预期行为。

### 覆盖到的关键路径

- 重叠、越界、标签不匹配、同一实例重复放入 —— 全部拒绝且不改变容器状态
- 原地旋转：成功时旧格释放新格写入，被挡时 `rotation` 与占用表都不变
- 封禁格支持非矩形容器；已占据的格子不能封禁
- `can_place` 的 `ignore_uid`：忽略自身时同位置判为可放（原地旋转与自移动依赖它）
- 自动装填：优先左上、优先原朝向；禁止旋转时 1x3 放不进 3x1，允许旋转时可以
- 邻接查询：四邻有效、斜角无效、多点相接的同一物品只计一次
- 序列化：往返后 id／尺寸／标签／封禁格／锚点／旋转／状态全部保留；二次序列化字节一致；经 `JSON.stringify` → `parse_string` 往返不变；定义缺失时丢弃该件、其余正常加载

### 三条被测试抓出来的错误，全部出在测试自身

| 失败断言 | 原因 |
|---|---|
| 「旋转后会撞上 blocker，应被拒绝」 | 用例复用了前一轮已被转成横向的容器，挡路者两次都因落点被占而没放进去，实际根本没有挡路者。改用干净容器重写 |
| 「旋转被拒后 rotation 不变」 | 同上，连带失败 |
| 「失败后目标容器不应有残留」 | 断言写成了 1 件，但目标容器此时本就持有先前移入的一件加挡路者共 2 件。改为断言件数不变，并补一条「目标不应持有被移动的 uid」 |

实现代码未因此改动。三条都是断言写错，被测试自己挡下来了。

## 遗留

- `resize()` 尚未实现。可扩容背包属于架构文档第 12 节列出的扩展机制，当前 `size` 在构造后固定。真要加时需要处理「缩小后原有物品放不下」的情形。
- `InventoryService.move` 只返回 `bool`，不返回失败原因。UI 目前靠 `can_place` 自己算高亮，够用；若将来要显示「背包不接受此类物品」之类的具体提示，需要改成返回结构体。
- 尚无物品交换（拖 A 到 B 上时互换位置）。是否需要取决于手感测试。
- `data/items/` 仍为空，所有测试用代码构造定义。
