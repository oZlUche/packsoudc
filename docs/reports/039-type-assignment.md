## 步骤

0 高危区内容 → 路线末端 → a 风格 mix → b 环权重 → c 配额 → d 覆盖 → e 邻接 → f 撤离点 → g 校准。
细节在 5.4 步骤 5。实现里定下来的几条：

**覆盖不算高危区里的点。** 第一版把高危区里的点也算超标，而那里按规则不放休息区，
一片 9 个点的区深处必然超标，于是一直重试。进高危区就是知道没得歇。

**覆盖修正与撤离点都不盖掉已经是必须型的节点。** 第一版覆盖修正放商店时，
候选里有休息区（旧类型 rest 的配额下限是 0，改掉不违规），于是先放好的休息区被商店盖掉，
`coverage` 一路红。改成默认不动必须型；只有配额超了、撞上禁止相邻时才允许改掉一个必须型。
撤离点同理 —— 出口吃掉休息区，玩家就没地方喘气了。

**校准换进来的精英只限 mix 里列了它的路线。** 校准第一版只在非必须型之间换。
偏战斗的路线要抬风险，最有效的是加精英，可精英是必须型不让换，于是它抬不上去，
校准只能把别的路线往下压 —— 偏混合的路线被压成一串事件点（统计里 mixed 每条平均 2.6 个事件）。
放开精英当目标之后，偏搜索的路线又被塞了精英去拉平性价比。最后定为：精英能换进来，
但只限 mix 里有它的路线。

**分数记成整数。** 路线的 `risk` / `reward` 第一版是浮点，`11.0` 过一遍 JSON 变成 `11`，
「同一张图永远导出同样的字节」当场红了三处。改成 `risk_x100` / `reward_x100`，百分之一为单位。

`sample()` 里的全是占位，请按手感改。测试从配置读期望值，改数不红。

| 覆盖 | rest 4 步, shop 6 步 |
| 禁止相邻 | elite–elite, shop–shop |

| 环数 | 落进档位 | 性价比离散（平均 / 最大） | combat 风险 / 收益 | search | mixed |
|---|---|---|---|---|---|
| 5 | 119/144 | 0.16 / 0.26 | 6.9 / 10.0 | 2.3 / 3.7 | 5.5 / 8.9 |
| 8 | 139/144 | 0.21 / 0.25 | 8.9 / 12.4 | 3.5 / 6.1 | 7.5 / 11.8 |

5 环落进档位的少一些：combat 每 2 环一个中途撤离点，5 环的路线上有 2～3 个撤离点（0 风险），
自己抬不高，只能压别人。这是数值问题，不是算法问题 —— 小图把 `bailout_every_rings` 调成 3 就好。

生成成功率与重试次数与 038 持平（5 环 1.10，8 环 1.19）。

## 验证

```
bash tools/test.sh
通过  2582 项断言，28 个套件（69 秒）
```

- 48 个种子逐条查图自身的规矩：配额（从配置读）、覆盖（高危区外，死胡同也在内）、
  喘气型不进高危区、不许相邻、高危区内容、被吸收的路线节点不是必须型、每 N 环一个撤离点、
  `type_rules` 在图上。
- 路线：去撤离点的末端是撤离点；有 bailout 的沿路有撤离点；记账的分数与重算一致；
  趋势 —— 每种风格独占节点累计起来，mix 最重的类型在可换类型里最多；多数路线落进档位；
  平均风险的高低与档位顺序一致。
- 配置自相矛盾（配额把休息区限死为 0、覆盖却要 4 步一个）在 6 次内干净失败，原因指向 `coverage`；
  权重里没有搜索点，高危区照样凑够。
- 校验从图上读：过一遍 JSON、手上没有配置照样查；两个精英挨着 → `adjacent`；商店塞满 → `quota`；
  手绘图没有 `type_rules` 一条不查。
- 同种子逐字节相同。

测试从 38 秒涨到 69 秒：每张图多了 40～50 毫秒的类型分配，全套测试要生成六七百张图。
`tools/test.sh` 的超时从 120 秒放到 240 秒。

## 遗留

- 手绘图不跑分配器：作者画的类型就是类型。5.4.2 说的「手绘图按最短路推几条路线只用于 HUD」还没做。
- `random` 类型的风险收益是按平均值给的占位；它进入时才掷骰，M4 定了概率表再算。
- `tier` 不进分数（5.4.2 的决定），但内容层（M4）会按 tier 缩放敌人 —— 到时候看要不要进。
- 编辑器里改类型不会重算路线分数（那是标注）。
