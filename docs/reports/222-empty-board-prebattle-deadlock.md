# 空手出发卡死在战前准备（222）

> 架构 thread，2026-10-21。来源：测试 thread 冒烟报告（`/mnt/project-files/testing/2026-10-21-smoke/report.md` 第 2 条）。协调者转来要一份给作者挑的短方案。

## 一、现象与原因

复现：开局屏第二页默认「不带预设」（`preset_index = -1`），棋盘上只有两个空包；一路「继续」出发；第一步走到战斗点或精英点。战前准备屏只有「开战」一个按钮且灰着（`pre.no_attacker`：「棋盘上一件会出手的东西都没有」），这一屏按设计是**必须过的**（不能收起回地图，见 `prebattle_screen.gd` 头注），唯一的两条退路 —— 「脱身」技能（只有安德烈乌斯带，且 166 补充一后主动技能对玩家隐藏）和烟雾弹（商店才有）—— 新手都没有。进点时已经自动存档，所以「继续」读回来还是这一屏：**这份存档的这一局永远走不下去**，只能删档。

查过的事实：

- 开局屏的 `depart()` 只查角色和出生点，不查棋盘上有没有会出手的东西。
- 「开局那套」（`grant_first_kit`）只在仓库为空的第一局发；打完三张序章的玩家仓库里有信物和带回来的东西，不再发。所以「不带预设 + 仓库里没武器」是真会出现的状态，不只是测试脚本点出来的。
- 空棋盘不止出发时会有：局中被猎手撵上、搜索点撞上遭遇，都是**强制开打**；玩家把武器全扔在地上、或唯一一把武器被耗尽，同样会走到这一屏。所以只拦出发堵不住。

## 二、三种做法

| | 做法 | 堵得住哪种 | 大小 |
|---|---|---|---|
| 甲 拦出发 | 开局屏「出发」时编一次玩家规格，`active_items()` 为空就不出发，按钮旁提示一句接应者的话：「包里一件能出手的都没有，这样进去等于送。挑一套预设，或从仓库拖一件武器上来。」 | 新手空手出发 | 小 |
| 乙 战前兜底 | 战前准备屏在「开战」灰着、又没有脱身 / 烟雾弹可用时，多出一个按钮「打不了，退开」：走 `skip_pending_battle()` 那条路（点算用过、没有战利品、不扣体力），和脱身一样回地图。脱身拦着的点（核心点）退不开，那里改成「认输」：按打输结算（扣体力、被赶跑），一局继续或照规则结束 | 出发、猎手、遭遇、扔光、耗尽 —— 所有情形 | 中 |
| 丙 甲 + 乙（**推荐**） | 两样都做：新手在开局屏就被拦住，知道为什么；局中真到了打不了的地步，有一条不丢存档的路 | 全部 | 中 |

不推荐的：把默认预设从「不带」改成「强攻」。它只盖住新手那一种情形，又改了老玩家的默认选择。

## 三、细节（丙）

- 甲的提示走 `say` 通知（`notice.*` 键，中英都写），不弹窗；按钮不灰，点了才提示（灰掉的按钮玩家不知道为什么）。
- 乙的按钮只在 `can_start() != ""` 且 `slip_reason() != ""` 时出现，正常情况下战前屏还是只有「开战」。「退开」不是脱身：不消耗技能、不记次数，就是「这场打不起来，走人」。核心点上的「认输」复用打输那条结算，不另写规则。
- 测试：开局屏空棋盘出发被拦且有提示、放一把刀后能出发；战前屏空棋盘出现「退开」、点后回地图、点算用过、不扣体力；核心点空棋盘出现「认输」、按打输结算；有武器时两个按钮都不出现。

## 五、补充一：作者定了第四种（2026-10-21 13:05）

作者：「出发前有提示，空手也可以进战斗，就是正常结算（纯挨打）」。甲乙丙都不用，改成：

1. **出发只提示、不拦。** 开局屏棋盘上没有会出手的东西时，「出发」按钮旁常显一行接应者的话（`say` 通知键，中英都写）：「包里一件能出手的都没有，进去就是挨打。」棋盘一有武器这行就消失；「出发」照常一次点就走。不做二次确认。
2. **空手也能开战。** `PrebattleScreen.can_start()` 去掉 `active_items().is_empty()` 那一条（`pre.no_attacker` 键随之不再灰按钮；可以留作战前屏上的一行提醒，不拦）。开战就按正常流程打：玩家不出手、只挨打，体力归零输掉，走已有的打输结算（普通点扣体力、核心点 `boss_lost`、必死场 `fatal_loss`、体力归零 `vitality_depleted`），不写新规则。
3. **不加任何退路**：不做「退开」「认输」；脱身 / 烟雾弹照旧。
4. 顺带查一下 `BattleSim`：一方完全不出手时，另一方照常打到对方归零，不会走到「再没有任何事会发生」的提前结束；如果敌方也打不动（理论上不该有），维持现有的平局处理。

测试改成：开局屏空棋盘有提示行、放一把刀提示消失、空棋盘能出发；战前屏空棋盘「开战」可点；空手对拾荒者模拟一场，玩家输、按打输结算扣体力；原来断言「开战」灰掉的测试改过来。

## 六、落地（执行，2026-10-21，v3.70）

按 §五 补充一落了，甲乙丙都没做。

1. **开局屏**：`SetupScreen.unarmed()` 编一次棋盘（`BattleCompiler.compile_board`），没有会出手的道具时，「出发」上面那一行（原来写开不了的原因的 `_status`）常显 `setup.unarmed`「包里一件能出手的都没有，进去就是挨打。」，中英都有。第二、三页都显示，第一页（选角色）不显示。有开不了的原因时，原因优先。放上武器后提示消失。「出发」照常一次点就走。
2. **战前屏**：`can_start()` 去掉空手那一条，只在没有待打的仗时拦。空手时 `_why` 那一行写 `pre.no_attacker` 作为提醒，「开战」不灰。新加 `PrebattleScreen.unarmed()`。
3. **结算**：没写新规则，走已有的打输结算。测试里空手打精英点，结果是输了、记一场败，并扣了体力或用掉一次免罚（`free_losses`）。
4. **BattleSim**：查过了。一方不出手时，另一方照常出手打到对方归零。提前结束只发生在「再没有任何事会发生」时，敌方在出手就不会走到那一步。
5. 测试：新套件 `test_unarmed_222`。覆盖以下几点：开局屏不带预设时有提示，换一套带武器的预设提示消失，第三页也显示；空手出发；走到最近的战斗或精英点；战前屏 `can_start()` 为空、「开战」不灰、只提醒一句；开战后输掉、不是平局、记败。原来没有测试断言「开战」会灰掉，所以不用改。
