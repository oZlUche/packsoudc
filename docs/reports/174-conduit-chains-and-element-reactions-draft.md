# 174 · 讨论稿：少量元件、组合成链 —— 本作的 Noita / 以撒式核心组合机制

> 作者 2026-10-14 22:10：「参考 noita 和以撒的结合类似的核心设计，就是多个不同元素组合在一个链条上可以产生巨大变化，且这些元素因为可以随意组合所以有很高的灵活性和拓展性，用较少的初始数量就能达成多种阵容，我们的游戏可否也有一个类似的机制？因为当前的机制还是太简单了」。作者 22:15 补充：「也许可以像卡牌游戏，比如游戏王那样注重【时机】？攻击前，攻击后，施加 buff 时？不过我们好像已经在做类似的事了……也许可以设计不同的组件，比如矿石类代表攻击，铜矿石就是攻击前，然后组合搭配藤蔓材料，其效果为【为敌人施加】，接着组合骨质品，效果为【流血】，最后达成一个【每次攻击前为敌人施加流血】的 buff？但是如何才能让这些道具组合呢？单纯用增益槽之类的镶嵌吗？好像太粗暴，也不符合游戏给玩家带来的直觉。」性质：架构 · **讨论稿**，等作者挑方向后再写正式方案与数据模型。关联 108（附加）、130（流血 / 中毒反应件）、132（受益规则）、133（乘算加算）、148 / 171（晶石供给 → 装载槽）、152（buff 轴）、165（敌人棋盘的邻接组）、170（悬浮窗）。

## 1. 那两款游戏的「组合」到底是什么

| | Noita（法杖） | 以撒（泪弹） |
|---|---|---|
| 元件 | 法术：投射物 / 修饰符 / 触发器 / 多重施放，各自只做一件事 | 道具：给泪弹加一个旗子（追踪、穿透、分裂、毒……） |
| 组合算子 | **顺序**：法杖上从左到右读，修饰符作用于「下一个」，触发器把后面的法术挂到命中那一刻 | **集合**：旗子全叠在同一发泪弹上，部分旗子两两有特判 |
| 二阶效应 | 材料反应（油遇火、水遇电），和法术链相互独立 | 旗子间的特判（硫磺火 + 分裂 = 多道光束） |
| 可读性 | 法杖面板按顺序排开，一眼看出链 | 泪弹外观变化 |

共同点，也是「少量元件 → 大量阵容」的来源：

1. **元件少而正交**，每个只改一件事（种类、数量、时机、方向），不是「+10% 伤害」这种数值件；
2. 有一个**组合算子**把元件合成一个结果 —— 顺序链或旗子集合，元件之间不需要互相认识；
3. 元件之间有**二阶效应**（反应表），组合的结果是**种类变化**，不是数值相加；
4. 结果**可读可预测**，玩家能在摆的时候算出来。

## 2. 本作现在的组合层（审计）

| 层 | 做什么 | 组合性 | 内容量 |
|---|---|---|---|
| 邻接 增益 / 受益（`AdjacencyProfile`） | 挨着满足标签的邻居就给数值或一条规则 | 一跳，加法 | 8 件写了过滤 |
| 附加（108） | 配件把一条「出手时……」规则挂到宿主武器 | 一跳，种类变化但不可再组合 | 毒箭、日神附魔 |
| 供给 → 装载槽（148 / 171） | 晶石改法杖伤害类型、耗次数 | 一跳，一次 | 火焰魔晶石等 |
| 状态反应（130） | 施加流血 / 中毒时转化、条件增伤、剧毒 | **二阶**，但手写两条线 | 4 件 |
| buff 轴（152）、乘算 / 加算（133） | 数值 | 加法 | — |
| 套装（`SetDatabase`） | 凑齐 id 列表给整单位加成 | 清单 | 0 份数据 |
| 信仰 / 祭坛 / 科技 | 整局数值 | 加法 | — |

110 件道具、19 把武器、8 种伤害类型、9 个 buff，可是：**全是「A 给 B 加一点」或「A 给 B 一条规则」**，没有「A 的产物流经 B、C 再出去」；没有顺序；二阶效应只有流血 / 中毒两条手写线。所以阵容像清单（凑齐这几件），不像配方（这几件按这个顺序会变成另一种东西）。作者说的「太简单」就是缺第 2、3 条。

## 3. 方案：两层叠加 —— 「传导链」是组合算子，「元素反应」是二阶效应

两层各自成立，叠起来才有 Noita 的味道。先讲元素，因为它复用的最多。

### 3.1 元素：五个印

火、冰、雷、毒、血（物理没有元素）。五个都**已经存在**：`fire / ice / lightning` 是伤害类型，`poison / bleed` 是状态。新概念只有一个：**元素印**（`ElementMark`）—— 任何带元素的伤害或状态命中目标，就在目标身上盖一个该元素的印（有层数，几秒后衰减）。印是「等反应的燃料」。

元素从哪来：武器本身的伤害类型；晶石装载（171 的转类型）；附加（108 的「出手时施加中毒」）；下面传导链的「转元素」件。**现有 19 把武器一件不改**就分出五类燃料。

### 3.2 反应表：十对，每对一种「种类变化」

两个不同元素的印碰上（目标身上已有甲，这一下带乙）就触发反应，**两印都消耗**（防止永动），效果由反应定义给，走现有规则内容（`deal_damage / apply_status / shift_axis / change_resource`），**不加新效果类型**。草案（名字和数值都是占位，给作者看方向）：

| 组合 | 反应 | 效果（一句话） |
|---|---|---|
| 火 + 毒 | 爆燃 | 吃掉毒层，按层数一次火伤，再盖灼烧 |
| 火 + 冰 | 淬裂 | 对方护甲碎掉（护甲清零）+ 固定伤 |
| 火 + 雷 | 过载 | 自己下一次出手伤害翻倍 |
| 火 + 血 | 封口 | 对方几秒内治疗无效 + 固定伤 |
| 冰 + 雷 | 超导 | 对方几秒内受伤倍率上升（破绽层） |
| 冰 + 毒 | 凝毒 | 毒伤延迟累积，印消失时一次结清 |
| 冰 + 血 | 冻疮 | 对方几秒内出手间隔拉长 |
| 雷 + 毒 | 电解 | 中毒升阶为剧毒（130 已有转化件） |
| 雷 + 血 | 激荡 | 自己下一次攻击必定暴击 |
| 毒 + 血 | 溃烂 | 每层流血补一层中毒（130 的桥，收编进表） |

同元素再碰 = 加深一层，不反应。十对反应、五个元素，就把 19 把武器 × 晶石 × 配件的组合从「数值不同」变成「做的事不同」。

数据：`data/authoring/reactions/<甲>_<乙>.json`，`{elements, consume, effects[]}`，内容编辑器加一页「反应」；结算在伤害管线第 5 步之后（`ReactionResolver`，以攻击方为来源发一条临时规则）。

### 3.3 传导链：棋盘上的「法杖」

Noita 的法杖是一行格子按顺序读；本作的棋盘本来就是格子，顺序由**方向**给：

- 每把武器定义一个**出口**（`exit`：哪一边，随旋转转，默认右边）。
- 从出口格起，沿直线连续排着的**导管**（新一类道具，标签 `conduit`）组成这把武器的**链**，最长四件。
- 每次出手，伤害包从武器出来，**按顺序流经每一节导管**，每节改一件事，最后打到对方。顺序有意义：先「分裂」再「增幅」，每一片都增幅（也每片都付耐力）；先「增幅」再「分裂」，只增幅一次。

导管一期七种（元件少，各做一件事）：

| 导管 | 改什么 | 像 Noita 的 |
|---|---|---|
| 转元素（五种各一件，可由晶石兼任） | 伤害包换元素 | 修饰符 |
| 分裂 | 一包变 N 片，每片几成伤害，各自盖印（反应更容易凑） | 多重施放 |
| 回响 | 这一包过一会再放一次 | 延迟触发 |
| 引信 | **下一节**的效果不在出手时做，改在命中那一刻做（拿命中当扳机） | 触发器 |
| 增幅 | 伤害加成，耐力消耗也加 | 伤害修饰 |
| 虹吸 | 命中回自己耐力 / 血 | 吸血 |
| 棱镜 | 一包同时带两个元素 → 命中时自己就凑成反应 | 双元素法术 |

导管只服务**离它最近的那把武器**（出口直接顶着它的）；链靠占格子付代价，越长越占地、越耗耐力，正好接上本作的空间与耐力经济。编译期静态生成（和邻接一样，`_chain_of(weapon)` → `CompiledItem.chain`），出手时 `DealDamage` 把包交给 `ChainRunner` 走一遍再进管线。

敌人同样用：165 的邻接组里写一条链，对阵屏（157）看得见，玩家开战前能读。

### 3.7 作者的补充：材料当词，链当句子（时机是现成的）

作者问的「时机」我们**已经有了**：架构 4.4 一条规则 = 时机 · 频率 · 消耗 · 内容，时机现有十二种（出手时、受伤前、受伤后、施加状态时、状态消失时、战斗开始、按节拍、资源低于、层数达到……）；146 还把填好数值的零件做成了**构件库**（`RulePartDef`，`data/authoring/rule_parts/`：`on_item_fired`、`apply_status_bleed`、`cooldown_1s`、`uses_1`……），规则里写 `@<id>` 引用。作者说的「铜矿石 = 攻击前、藤蔓 = 为敌人施加、骨 = 流血」，就是**把构件库里的零件印到材料上**，再让玩家在棋盘上把零件拼成一条规则。实现上几乎是现成的：

- 道具加一个字段 `word: @<构件 id>`（一件材料 = 一个词）。词分四类，恰好对应规则的四个槽位再加一个「名词」：**时机词**（矿石类：铜 = 攻击前、铁 = 攻击后、银 = 施加状态时、金 = 战斗开始）、**对象 / 效果词**（藤蔓 = 为敌人施加 ×、树根 = 为自己施加 ×、苔 = 为相邻武器 ×；效果里留一个空）、**名词**（填那个空：骨 = 流血、毒腺 = 中毒、兽皮 = 护甲、晶石 = 五元素之一）、**修饰词**（频率 / 消耗：蜂蜡 = 每两秒一次、粗盐 = 耗一次使用、树脂 = 耗耐力）。现有 40 件材料按自然 / 工艺 / 魔法三类正好分得开，不用新造多少东西。
- **怎么组合 —— 不用镶嵌，用 3.3 的链当句子**：从武器出口起沿直线排词，**读的顺序就是语法**：时机词 → 对象 / 效果词 → 名词（→ 修饰词）。「铜矿石 · 藤蔓 · 骨」排在一把剑右边 = 这把剑获得「每次攻击前，为敌人施加流血」。编译器把词按序喂给一个小解析器，拼成一条 `AbilityRule`，再走 108 的 `_attach(weapon, rule, origin)` 挂到那把武器上 —— 108 的附加、171 的装载槽、3.3 的导管、这里的词，**都是同一条链上的词**，只是词性不同（导管 = 效果词的一种，晶石 = 名词）。
- 句子不完整就没有规则，悬浮窗（170）直接写缺什么：「缺少对象」「缺少效果」；完整了写成一句话，玩家摆的时候就能读到结果。「挨着放 = 一起用、从左往右读」是本作已经教过玩家的直觉（邻接、阅读顺序），比槽位自然。
- **试 → 定**：摆在棋盘上的句子随时拆改，是「试」；在工坊 / 休息点可以把一句完整的句子**铸**成一枚一格的符牌（现有配方系统，9 份配方那一套，消耗这几件材料），是「定」—— 省格子、不可再拆。既保留 Noita 式的现场拼装，又给以撒式的「拿到一件就定了」留出口。
- 和 3.1–3.2 的关系：元素反应是名词层的二阶效应（名词是晶石时盖印）；和 3.3 的关系：导管就是效果词。三节合起来一句话：**棋盘上的一条直线是一句话，词是材料，句子挂在武器上，名词之间会起反应**。

### 3.4 可读性（否则组合再多也是黑箱）

- 棋盘上从武器出口起画一条**发光的线**穿过各节导管（和增益 / 受益格图标同一套 170 的格位标记）。
- 武器悬浮窗（170 版式）写**最终结果**而不是零件：「每 X 秒：两发 火 Y，命中时 引爆」。
- 战斗回放里反应弹字（「爆燃！」），百科加「反应表」一页，触发过的才点亮（图鉴式）。
- 流派仍不命名（架构 3.8），只命名反应。

### 3.5 和现有层的关系

| 现有 | 之后 |
|---|---|
| 增益 / 受益 | 不动，仍是数值层 |
| 171 装载槽里的晶石 | 就是「转元素」导管的一种，法杖的装载槽 = 法杖自带的一节链 |
| 108 附加 | 收编为「附加状态」导管（出手时盖印） |
| 130 的流血 / 中毒件 | 毒、血两个元素的来源；「溃烂之刃」收进反应表 |
| 133 乘算加算 | 增幅导管用它 |

### 3.6 规模与成本

- 内容：7 种导管（转元素 5 + 其余 6 = 11 件）+ 10 份反应 + 5 个印定义；现有武器零改动。11 件导管 × 顺序 × 长度 ≤ 4 × 10 反应，阵容数量级是现在的几十倍，而且**每种都做不同的事**。
- 代码：编译器加链（和邻接同模式）、`ChainRunner`、`ReactionResolver` 挂管线第 5 步、`ElementMark` 存在 `CombatantRuntime`、棋盘画线、悬浮窗句子、回放弹字、百科页、编辑器两页。金样有意重录。
- 风险：数值平衡（用耐力当总闸：每节导管都加耗耐）；回放可读性（反应弹字 + 170 的图标）。

## 4. 给作者的三条路

| | 做什么 | 得到 | 代价 |
|---|---|---|---|
| A | 只做元素反应（3.1–3.2） | 现有武器 + 晶石 + 配件立刻有「种类变化」；像以撒 | 小，无新道具类 |
| B | 只做传导链（3.3） | 顺序与空间的组合感；像 Noita，但没有二阶效应就只是「数值流水线」 | 中 |
| C | 两层都做，先 A 后 B | 完整的「少元件 → 多阵容」 | 大，分两期 |
| **D** | **C + 3.7 词链**：导管与词是同一条链，反应先做，再做链与词 | 作者两条消息合一：时机可拼、材料有用、顺序可读、元素会反应 | 大，分三期（反应 → 词链 → 导管 / 铸牌） |

**推荐 D，先做反应**：反应复用的全是现成东西，先让 19 把武器分出五味；词链接上去时构件库、附加入口、链的读法都已经在，等于把三份现成零件接通；导管与铸牌放最后。
