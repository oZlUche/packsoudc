# 387 仓库占用空间调查与精简方案（只调查，未改动）

## 目标

作者问：git 仓库占了多少空间，旧文档能不能压缩。本报告只做测量和方案，**没有删除、转换任何文件，也没有改写历史**。要动手的部分列在最后，等作者拍板。

测量对象：2026-11-23 的 main（`cc6c9f09`，2921 个提交）全新克隆。

## 总量

| 部分 | 大小 | 说明 |
|---|---|---|
| `.git`（全部历史） | **516 MB** | 已打包成一个包，没有可回收的散对象，`git gc` 在全新克隆上省不了空间 |
| 工作区（当前文件） | **216 MB** | 8955 个文件 |
| 合计 | 约 730 MB | 本地 `G:\oziuc\背包搜打撤` 另有 Godot 的 `.godot/` 导入缓存，不在 git 里，不算在内 |

`.git` 里 153 MB 是当前版本文件本身，**356 MB 是历史旧版本**（同一张图、同一个字体被改过多次，每一版都永久留在历史里）。

结论：**大头是美术素材的反复修改，不是文档**。文档（含测试截图）在历史里约 60 MB。

## 压缩能省多少（实测估算）

| 对象 | 现在 | 无损重压 png | 转 webp（质量 85） |
|---|---|---|---|
| `docs/` 下全部截图（250 张） | 50 MB | 基本不变 | **15 MB** |
| 其中 `testing/images` | 35 MB | — | 8.5 MB |
| `assets/maps/` | 38.5 MB | 不变 | 1 MB（有损，原画质量下降） |
| `assets/ui/` | 48 MB | 44 MB | 3.4 MB（有损） |

注意：只改当前文件，**`.git` 不会变小**，反而先多出一份新版本；旧版 png 仍留在历史里。想让 `.git` 变小只能改写历史。

## 方案

| 编号 | 做法 | 省多少 | 代价 / 风险 |
|---|---|---|---|
| 1 | 文档截图转 webp（`docs/reports/` 下的 png/jpg，md 里的链接同步改） | 工作区约 −35 MB | 低。截图是给人看的，质量 85 肉眼无差。历史不变小 |
| 2 | 以后的测试截图不再进仓库，放 `/mnt/project-files/testing/<日期>-<版本>/`，报告里只写路径（报告本身仍在仓库） | 止住每轮测试约 1～3 MB 的增长 | 本地仓库里看不到截图，要去项目文件夹看 |
| 3 | 字体子集不要每次加字就提交：攒一批再生成，或一次性放入完整常用字集 | 止住每次约 0.5 MB 的增长 | 完整字集会让工作区多几 MB |
| 4 | 游戏美术源文件（地图、界面背景）转有损 webp | 工作区约 −80 MB | **不推荐**：原画质量永久下降，Godot 导出包大小由导入设置决定，源文件变小并不会让游戏变小 |
| 5 | 改写历史（`git filter-repo` 去掉旧版地图、旧字体、已删的 `handoff/art-review` 等） | `.git` 估计 516 → 约 150～200 MB | **高**：要强推 main；本地仓库、所有云端会话、未合并的分支和 PR 都要重新克隆或重建；提交号全部变化，报告里引用的提交号失效。做之前必须暂停所有线程 |
| 6 | Git LFS 管大图 | 新提交的大图不进普通历史 | 不推荐：GitHub 免费 LFS 只有 1 GB 存储 + 每月 1 GB 流量，云端会话每次克隆都会消耗流量，很快用完 |

## 建议

- 推荐做 **1 + 2 + 3**：风险低，工作区少约 35 MB，并减缓以后的增长。
- **5（改写历史）先不做**。516 MB 在 GitHub 的建议范围内（官方建议单仓库 1 GB 以内、最多不超过 5 GB），日常也只是首次克隆慢一些。真要做，建议挑一个所有线程都空闲的时间一次做完。
- **4、6 不做。**

## 遗留

等作者确认上面 1～6 各做不做；确认后再开实施 PR。
