# 031 · 体力：一个不知道任何数值的资源

> 阶段 4 · M3 旁支 ｜ 架构文档 7.1（v1.30）

## 起因

7.1 的体力表里原本写着「普通战斗失败 −1、精英 −2、休息区 +1（待定）」。作者的要求是：

> 休息区回多少不要写死，只要给体力留一个公用方法以便调用就行。

## 做法

`core/run/vitality.gd`。一句话概括：**本类不知道任何游戏数值。**

```gdscript
vitality.spend(cost, &"battle_lost")   # cost 来自节点内容
vitality.restore(amount, &"rest")      # amount 来自休息区配置
```

扣多少、回多少、上限是多少，一律由调用方传进来。`Vitality` 只管边界与信号。

| 谁定这个数 | 什么数 |
|---|---|
| 节点内容与章节配置 | 战斗失败扣多少、休息区回多少 |
| `ErosionSchedule`（5.7） | 侵蚀浅层惩罚扣多少 |
| 角色定义（将来） | 初始与上限 |

数值写进本类的话，调一次就要改一次代码；而且不同角色、不同章节、甚至不同的休息区
都可能给不同的数，到那时改起来就是把同一个常量从三个地方各挖一遍。

## 三个值得记的决定

### 1. 一个方法真正动手，另外两个是它的读法

`change(delta, reason)` 是唯一改值的地方，`spend` / `restore` 都走它。
一处改动、一处信号，不会出现「某条路径忘了发 `changed`」。

`spend` 与 `restore` 存在的理由只是**可读性**：`spend(2)` 比 `change(-2)` 少一次心算，
而调用处几乎总是知道自己在扣还是在回。两者都对参数取绝对值 ——
传了负数仍按语义走，不会反向生效。

### 2. 返回**实际**变化量，不是请求量

「这一下该扣 3 点」和「实际扣掉了 1 点（只剩 1 点了）」是两回事。
结算界面、日志、成就关心的通常是后者，所以 `change` / `spend` / `restore` 都返回实际量，
`changed` 信号里带的也是实际量。

这条抄的是 `ResourcePool.change` 的约定（4.4）—— 同一个项目里同一种语义只该有一种，
不然调用方每次都要回去翻一遍这个返回值到底是哪个。

**没变就不发信号**：已经满了还去 `restore`，实际变化 0，不发 `changed`。
界面不该为一次无事发生闪一下。

### 3. 它不知道「战败」是什么

归零只发 `depleted(reason)`，由 `GameDirector` 判定结局。

BOSS 输了直接战败那条例外也在调用方：战斗结算时看一眼「这个节点是不是 `core`」，
是就直接走 `DeathResult`，连 `spend` 都不用调。把它写进 `Vitality` 的话，
这个类就得认识地图节点类型 —— 一个管数字的东西没理由知道地图长什么样。

## 角色系统：只留占位，不建

`PLACEHOLDER_MAX = 5`，一个常量。`Vitality` 从构造参数拿上限，所以角色系统落地时
**本类与所有调用方一行不改** —— 只是 `RunState` 构造它时从角色定义读。

这与 `CombatantBaseline`（战斗侧的角色占位，报告 021）是同一种做法。两者将来会挂到
同一份角色定义上：战斗基线管「开局多少血多少耐力」，体力管「这一局还剩几条命」。

**刻意不建 `CharacterDef`**：现在只有两个占位点，建出来也是个空壳，还得维护它的
导入导出与编辑器表单。等真有第三样东西要按角色变，那时三个一起收进去，
比现在猜着建一个再改两次便宜。

## 验证

```
godot --headless --path . --script tests/run_tests.gd
通过  1465 项断言，22 个套件
```

`tests/test_vitality.gd` 里**一个游戏数值都没有** —— 没有「普通战斗 −1」这种断言，
那是内容，改它不该让测试变红。测的是边界行为：截断、实际变化量、归零信号只发一次、
上限涨落、存取往返、以及「不给上限时用的是那个占位常量，没有第二处写死」。

## 遗留

- 谁来听 `depleted` → `GameDirector`（M6）。
- 扣多少回多少的那些数，写在节点内容与章节配置里 → M4 / M5。
- `RunState` 里的字段已从 `hp: int` / `max_hp: int` 改成 `vitality: Vitality`，但 `RunState`
  本身还没实现（M5）。
