# 124 方案：常用道具的上位版本（口粮、纱布、伤药、解毒包三阶梯），并用合成把低阶升高阶

> 架构 · 提议（2026-10-05）。作者：「增加一些当前道具的上位版本，比如口粮、纱布」。

## 一、现状（已核实）

- 四件基础消耗 / 补给（全部 1 格）：**口粮** `ration`（白，被动 耐力上限 +40、每秒回耐力 +2）、**纱布** `bandage`（白，按冷却清一层流血）、**伤药** `salve`（绿，生命低于 40% 时回 25，一次）、**解毒包** `antidote_kit`（绿，按冷却清一层中毒）。每件都只有一档，玩家从外环到核心背的是同一件。
- 合成（114）只有一条配方（匕首 + 毒药瓶）。122 刚加了二十八件材料，材料目前只有「卖钱」和「交科技」两个去处。
- 可用构件足够：触发 `on_schedule` / `on_resource_below(percent)`，节奏 `cooldown(seconds)` / `always`，消耗 `uses(max_uses)`，效果 `change_resource(amount)` / `remove_status(buff_id, stacks)`，被动 `base_stats`。不用加新构件。

## 二、设计原则

- **上位 = 同一件事做得更好，再多一点点**：不换功能，不换标签（`food` / `remedy` 照旧，自然之神、信力行为照收），这样教程里学的「口粮回耐力」在后期仍然成立。
- **三阶**：白 → 绿 → 蓝。二阶同尺寸更强，三阶更强但多占一格 —— 「更好的东西要地方」是本作的核心取舍。
- **每一阶都能合成出来**：两件低阶 + 一件 122 的材料 → 一件高阶。材料因此有了第三个去处，而且是局内就能用的。搜索池里高阶也直接出，合成只是路径之一。
- 数值全是占位，照 ItemValue 公式不填 `value`。

## 四、合成的三件输入

现在 `RecipeDef.inputs` 是两件、`CraftingModule.craft(a, b_uid)` 是拖一件到另一件上。三件输入要改交互，不值。**改成两步两件**：先「口粮 + 口粮 → 一份双口粮（中间态）」太啰嗦；所以把材料并进第二步：

- 配方写成 **两件**：`口粮 + 粗盐块 → 腌肉干`、`腌肉干 + 蜂蜡块 → 行军军粮`，以此类推（上表「合成」列里去掉重复的那件）。
- 这样每一阶 = 一件低阶 + 一件材料。强度上比「两件低阶」便宜，用稀有度与材料的稀有度把门：三阶配方用的材料本身是绿 / 蓝（蜂蜡块绿、水晶簇绿、琥珀原石蓝）。

`RecipeDef` 与 `CraftingModule` 零改动。

## 五、搜索池与敌人

- 新道具不带 `treasure`，按稀有度正常进搜索池；敌人的 `item_tags` 里带 `remedy` / `food` 的（拾荒者等）也会背到，受 `rarity_cap` 约束，外环不会背出蓝色药剂。
- 百科的「合成」页 `see_items` 加 `salted_meat`、`bandage_roll`，让玩家在页里看到「还能这么合」。
