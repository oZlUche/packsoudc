# 259 节点生成权重：路旁的点跟路线走，休息点收口（架构方案）

作者 2026-10-27 12:50：「检查一下节点生成的权重，目前即使是战斗路线上搜索节点的数量也过多了」；12:58：「整体来说休息节点也偏多，甚至常出现两个休息节点连接的情况（如图所示）」（截图：一小片里四个休息点，其中两个直接相连）。

## 二、原因

1. **路线外的点不认路线。** 一张图 28～47 个点里 10～21 个（约四成）不在任何路线上，它们由所在环的 `type_weights` 抽：battle 3 / search 3 / event 3 / random 2 / elite 1 / chest 1（`ring_type_assigner.gd` `_assign_by_weights` → `_weights_for`）。这张表全环一样、不看旁边是哪条路线，搜索天然占 3/13，再加宝箱与随机折算到 30%。
2. **高危区只从战斗 / 常规路线岔出**（搜索路线 `spawns_zones = false`），每片至少 2 搜索 + 1 精英、小型一片只有 3～4 个点 —— 等于给战斗路线旁边固定挂两个搜索点。这是 053 的「诱惑」设计，本身没错，但和第 1 条叠在一起。
3. **路线自己的点被喘气处吃掉一半。** 战斗路线独占 7.5 个点里，出生 1 + 商店 0.9 + 休息 1.6 + 撤离 0.3 占 3.8，`mix` 只分到 3.7 个点，战斗感本来就薄。
4. **休息点有四个来源在叠加**：① 每环配额 `rest: [1, 2]` —— **每环至少一个**，5 环就至少 5 个（114 定的，`free_mode.json` 六个环与 `ring_template` 都是这个数；代码里的 `sample()` 与机关沙漏都是 `[0, 1]`）；② 每条路线中点放一个（`haven_at`，小型 0.5 / 中型 ⅓）；③ 覆盖 `coverage.rest = 3`，任何点三步内要有休息，不够就贪心补；④ 随机点揭出休息 1/11。`no_adjacent` 只禁精英—精英、商店—商店，**没有休息—休息**，所以 ① 的「本环必须有」挨着 ② 的「路线中点」就是截图那样。

## 三、方案

三个旋钮，各管一件事，沙盒里都试过（同一脚本、同 96 种子，数字见 §3.4）：

### 3.1 路旁的点跟路线走（管「战斗路线旁边为什么是搜索」）

`_weights_for`：不在任何路线上、也不在高危区里的点，先找**最近的路线**（沿边走，最多 4 步，第一次碰到路线点为止）；只碰到一种风格就用那条路线的 `mix` 当权重，`random` 与 `chest` 这两种「不确定」类型保留环权重；碰到两种风格（两条路线之间的夹缝、换乘区）或 4 步内没碰到路线，照旧用环权重。配额、覆盖、禁止相邻、校准一个都不改 —— 只是换了抽签用的权重表。顺手把「最近路线风格」写进 `node.layout.near_style`，图的 JSON 跟着带，编辑器与将来的随机点揭示都能用。高危区不动（2 搜索 + 1 精英是它的定义）。

效果：战斗路线旁边长的是战斗 / 精英，搜索路线旁边长的是搜索，三条路线终于从旁边就看得出区别。**但全图搜索总数不变** —— 它只是把搜索挪到搜索路线那一侧，所以单靠它解决不了「整体搜索多」。

### 3.2 全局权重下调（管「整张图搜索多」）

六个环与 `ring_template` 的 `type_weights`：battle 3 → 4、search 3 → 2（event 3 / random 2 / elite 1 / chest 1 不动）；`node_rules/standard.json` 的 `random_weights.search` 3 → 2。两处数字。路线 `mix`（战斗 5 / 1 / 1，搜索 4 / 1 + 八成保底）不动，搜索路线还是搜索路线。

### 3.3 休息点三改（管「休息多、休息挨着休息」）

- `free_mode.json` 六个环与 `ring_template` 的 `rest` 配额 `[1, 2]` → `[0, 1]`（和 `sample()`、机关沙漏一致）：不再「每环必有」，每环最多一个。
- `coverage.rest` 3 → 4（机关沙漏就是 4）。路线中点那一个照放，覆盖只补真正的空档。
- `no_adjacent` 加 `["rest", "rest"]`。休息旁有商店是合理的歇脚处，不禁。
- 随机点：揭开时若相邻已有休息点，`rest` 权重按 0 算（`NodeEvents.reveal` 传一个排除表给 `random_pick`）。沙盒数字不含这一条（它在运行时）。

### 3.5 推荐

**A = 3.1 + 3.2 + 3.3 一起做**（推荐）。三个旋钮互不打架：3.1 定「旁边长什么」，3.2 定「全图各占几成」，3.3 定「休息几个、不挨着」。

## 四、改动清单（给执行，按 A）

1. `core/map/generators/ring_type_assigner.gd`：`_weights_for` 增加「路线外的点取最近路线的 mix」；新增 `_nearest_style(id)`（BFS ≤ 4 步，返回唯一风格或 null）；`_assign_by_weights` 把 `near_style` 写进 `node.layout`。`MapGraph.normalize` 若有字段白名单，加上它。
2. `data/authoring/chapters/free_mode.json`：六个环 + `ring_template` 的 `type_weights` battle 4 / search 2，`quota.rest` → `[0, 1]`；`coverage.rest` → 4；`no_adjacent` 加 `["rest", "rest"]`。`data/authoring/node_rules/standard.json`：`random_weights.search` 2。都是手写 JSON，按导出器格式（键序、默认值省略），改完 `import_content` 重导 .tres。
3. `core/run/node_events.gd` `reveal` + `core/run/node_rules.gd` `random_pick(rng, exclude)`：相邻已有休息点时不揭出休息（商店同理不必，商店没有相邻问题）。
4. `tools/map_stats.gd`：加「路旁一步」那张表（本报告的脚本已有，直接并入），作者以后要看就跑一次。
5. 测试 `tests/map/test_ring_type_assigner.gd`：① 48 种子里没有一条休息—休息边（从 `no_adjacent` 读，不写死）；② 战斗路线旁一步的点里 battle + elite 的平均数 ≥ search + chest（趋势检查，和 mix 那条同一档：尽力而为，查趋势）；③ 搜索路线旁一步 search ≥ battle；④ 配额、覆盖那些现成断言照跑。`test_free_mode`（若有章节级断言）休息配额改读新值。
6. 存档：图是生成时定的，老存档的图不变、不需要 IdAliases。

## 五、不做的 / 另议

- 机关沙漏（格子生成器）：`type_weights` battle 3 / search 3 / event 2 / random 2 / elite 1 / chest 1、`rest [0, 1]`、覆盖 4，没有路线概念；作者玩过觉得搜索多再按 B 的办法拧它那份权重。
- 高危区的 2 搜索 + 1 精英不动。
- 不改 `mix` 本身（战斗 5 / 精英 1 / 事件 1 等）。

## 六、待定（默认按推荐）

1. A 三样一起做（推荐）；备选 B 只改数字；C 只改风格与休息。
2. 最近路线找几步：4 步（推荐，够着换乘区边缘就停）；备选 2 步（更保守，剩下的仍走环权重）。
3. `coverage.rest` 4（推荐）；备选 保持 3（休息会比现在少得少）。
4. 随机点相邻休息时不揭休息（推荐）；备选 `random_weights.rest` 直接 0（随机点永远不是休息）。
5. 休息—商店相邻：不禁（推荐）。
