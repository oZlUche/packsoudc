## 一、现在的代码离方案有多远

| 方案要的 | 代码现状 | 位置 |
|---|---|---|
| 六个一级页签：出征、仓库、科技、委托、后勤、书架 | 五个：出征、委托、仓库、后勤、书架；科技是书架里的一格和一颗小键 | `ui/game/meta_screen.gd` 的 `TABS`、`SUB_TABS`、`SHELF_CELLS` |
| 声望五档 0 / 10 / 25 / 50 / 100 | 四档 0 / 2 / 5 / 9 | `data/authoring/factions/*.json`、`core/meta/commissions/commissions.gd` |
| 三个初始阵营：后勤部队、魔法师协会、灰灯互助会；后续：地图协会、河滩垦户社 | 五方：军团接应队、协会、灰灯、使团、猎盟 | `data/authoring/factions/` |
| 剧情单常驻、不占位；常规单走告示栏 | 委托簿三张原型单，最多同时接两份；告示栏未开工 | `commission_book.gd`、`ui/game/commission_panel.gd` |
| 铁匠铺、科技、集市由各方首单开放 | 三处都不受声望控制，教程后直接可用 | `meta_screen.gd`、`GameFlow` |
| 出征：选章节后有「本次准备」页 | 三页：角色、携带、地图 | `ui/game/setup_screen.gd` |
| 材料倾向 | v5.28 整层删掉了；产物表 `p_produce` 和材料节点 `p_only` 还在 | `core/run/search_session.gd` 的 `draw_items` |
| 苗圃、食堂 | 没有 | — |

存档版本：局外 `MetaState.SAVE_VERSION` 5，局内 `RunState.SAVE_VERSION` 6。本规格两边都要升。

结论：这份方案不能从地图协会和垦户社直接开工，要先换导航，再换声望地基。

## 三、分批

每批独立 PR、全量测试通过后合并，合并后通知本地同步和游戏测试。B2 和 B3 结束时各请作者试玩一次。

### B1 科技升为一级页签（可立刻做，不依赖声望）

- `TABS` 改成出征、仓库、科技、委托、后勤、书架。科技页直接放现有的科技面板（`tech_panel.gd`），默认打开上次浏览的那棵树。
- 书架：去掉科技格和那颗小键，空出的一格先放静物，重新排版交 UI设计 出样张。
- 所有旧入口转过去：`show_tab` 的旧名 `tech` 留作别名；教程导览、结算的见识奖励按钮、追踪科技的入口、快捷键逐个核对。
- 页签可见规则不变（委托页签仍看 `GameFlow.commissions_visible`）。六项要在英文、大字号、最窄分辨率下不遮住【开始探索】，用 334 留下的探针脚本过一遍矩阵；手柄和键盘焦点顺序跟着新顺序。
- 试玩切片档案：按切片清单保留它原有的页签集合，只跟着换顺序。
- 这一批不加门控：科技页签对所有已有科技入口的存档照常显示。门控在 B2 一起加。

### B2 声望地基与委托三子页

1. **五档声望**：门槛写进阵营定义，等级名用方案的暂定称谓（初识、熟面、受托、信赖、代言）。「累计达标」和「对应剧情已完成」两个条件分开存、分开显示。迁移按第二节。
2. **委托页三个子页**：剧情、常规、声望。默认剧情，记住上次选择。
   - 剧情：分阵营列出，出现后一直留到完成，不占常规位，不到期。
   - 常规：就是报告 341 的告示栏（钉位、到期、补位、保底），池子先用第十一节的三类数量模板加限次交付。阵营没到 25 并完成许可单时，这一方不出纸条，并写明差哪份剧情。
   - 声望：每方一行，累计值、当前档、下一门槛、已开和未开的功能、所需剧情，可点到对应剧情或设施。
3. **三份初始剧情与设施门控**：《领炉牌》开铁匠铺，《第一份勘察记录》开科技，《认一认秤》开集市，各 +10。教程结束直接定位到剧情子页，三份自动接取。
   - 三份都要在营地一步办完（和对应 NPC 说一次话或点一次确认），不需要出征。这样新档第一次回营就能把三处都打开。
   - 门控只对「教程结束后才建的新进度」生效。教程已过的旧档：三处保持开放，首次回营补发三份引导单并直接记为可领（领了拿 +10），重复进入不重发。
   - 没开放的设施：后勤里那颗键和科技页签照常显示，但点进去是一张说明板，写明找谁办哪份单，并有一颗键直达那份剧情。不藏入口，免得玩家不知道有这东西。
   - 试玩切片档案不加门控。
4. **后续剧情到 25**：每方两份基础剧情各 +5，加一份许可单 +5。W1 的三张原型单改挂到这里：《照抄也要做得出》对应后勤或协会的「用铁匠铺打造一次」，《无人署名的信》对应灰灯的《一封回信》，《两条回路》改给地图协会留到 B3。其余几份按声望稿的候选（查验材料、领取工具、辨认矿样、登记产地、送收条、核对药包）由执行线程起草，原话列在落地报告里请作者过目。
5. **结算**：委托那一段加上各方声望增量和新开放的入口。
6. 告示栏的界面占位、样张流程照 341；小牌上「手头」的常规单沿用现有追踪牌。

出口：新档教程后三条线各办完首单，三处设施打开；一方做完三份后续剧情到 25，只有这一方的常规纸条开始出现；旧档读进来设施一处不少、声望按表折算、不重复发奖。

B2 较大，执行时可以拆成两个 PR：先 1 到 3 加 5（声望、子页、门控），再做 2 的常规池和 4 的后续剧情。

### B3 地图协会与河滩垦户社（同一批）

**引入**：教程后第一次正式探索结算时，营地同时收到《把路画回来》和《第一畦》两份常驻剧情，各 +10，互不依赖。《把路画回来》登记这一局实际到过的一处地形，败退也算；《第一畦》领一包试种种苗并种下。到 25 之前每方三份后续剧情（校对旧图、核实矿脉、提交路标；试种、收获、登记留种）。

**材料倾向（地图协会 10 开放）**

- 位置：出征流程在地图页之后加「本次准备」页。玩家还没解锁任何准备项时这一页整页跳过，流程和现在一样。已解锁时默认「无倾向」，不选也能直接出发。
- 选项：无倾向、矿物（`mineral`）、草木（`plant`）。工艺材料那一项等非战斗道具表出来、确认标签够用再加。
- 判定位置：`SearchSession.draw_items` 里，只在普通搜索、这一件已经落到材料类别之后，对合法材料候选重分相对权重（目标系乘倍率，其他保持 1，再归一到原来的材料总权重）。材料总出现率、稀有度、件数都不变。材料节点、敌人掉落、首领保底、宝箱、商店、事件奖励不走这条路。实现上和现有的产物表 `p_produce` 并列一个参数，不要叠在产物表上，免得两者相乘失控。
- 可选性：按所选章节算候选。某方向在这一章没有候选、或候选全是同一系（选了也不改变分布）时标为不可选并写原因。换章节重新校验；出发后锁定到本局结束。
- 存档：`RunState` 加本局倾向字段，局内版本升一；旧档缺字段按无倾向；读档不重抽。
- 倍率先不定：做一个配对试验工具（同种子、同路线，对比无倾向、1.25、1.5），按章节出四个数：每局目标材料带出数、普通材料总量、稀有度分布、专属材料点访问率。结果进落地报告，作者定倍率。定之前游戏内先用 1.5。
- 50 档（准备页显示受益的分区和节点类型）与 100 档（标一处本来就生成的材料点）留到本批之后，等倍率定了再做。

**苗圃（垦户社 10 开放）**

- 位置：后勤加子页「苗圃」。后勤现在是两颗小键（集市、铁匠铺）；加到四五项后改成方案说的页内设施列表，保留键盘焦点和上次访问项。「出售」页 268 已经并掉了，这次不恢复，除非作者要。
- 状态：`MetaState` 加田块列表（每畦：作物、播种时的局号、还差几局、是否成熟）和「最后并账的局号」。局外版本升一，旧档为空。
- 推进：一次有实际探索的正式出征结算推进一格，胜败都算。和这一局的其他结果同一次并入（`MetaState.absorb`，靠 `settled_runs` 防重复）；重载、没走出起点的空跑不推进。教程局、试玩切片不推进。
- 收获：成熟后留在地里；仓库放得下才能收，放不下就留着。扣种、入库、清畦在一次操作里做完，中途失败整体回滚，不会多给也不会吞。
- 回营提示：只在后勤页签上挂一个「可收获」的标记，不弹窗。
- 首批作物（建议初值）：苦叶草两局收两份、绳麻三局收一束。香根等食堂（B4）一起投。作物具体对应现有哪件材料、种苗从哪来、成本多少，等非战斗道具表出来后选，优先启用现在没有用途的材料。新作物如果需要新道具，说明文字留空给作者写。
- 产量上界：不超过同样局数主动采集的产量，用现有的材料供给统计工具对一下，结果进报告。

出口：真实新档走通「选矿物、播种、正式探索、回营收获、打开科技」；换图、败退、库满、结算重试各测一次；两份首单都能从新档完成。

### B4 灰灯食堂（单独一批，B3 之后）

灰灯 25 并完成《开伙》后开放。三道菜、每局一餐、后勤里预订、出征确认页显示菜名、实价和实际效果、开局成功才扣费、结算清除。两处点餐入口共用同一份订单。上线前不显示可操作的空店。菜的效果要改局内规则（耐力、超载移动、休息），动手前单独出一页效果与边界的说明给作者过目。
