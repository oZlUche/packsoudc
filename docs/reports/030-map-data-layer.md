# 030 · M3-1 地图数据层

> 阶段 4 · M3 ｜ 架构文档 5.2（v1.29）｜ 计划见[报告 027](027-m3-plan.md)

## 目标

拓扑无关的三个类：`MapNode`、`MapEdge`、`MapGraph`，加存取。计划里给这一步定的验收是三条：
存取不丢字、邻接关系对称、**不认识任何地图形状**。

## 产出

| 文件 | 职责 |
|---|---|
| `core/map/map_node.gd` | 一个点：类型、危险等级、区域、tier、侵蚀分档、内容种子、**内容**、走没走过、布局载荷 |
| `core/map/map_edge.gd` | 一条路：两端、是否单向、画法提示、行动消耗、布局载荷；`other` / `passable_from` |
| `core/map/map_graph.gd` | 点与路的容器，出生点、终点、区域表、**路线表**；构建、邻接查询、确定性存取 |
| `tests/test_map_graph.gd` | 三组：构建与邻接 / 存取不丢字 / 不认识任何地图形状 |

三个类都是纯 `RefCounted`，`core/` 里零 `Node` 依赖这条没破。

## 关键决策

### 1. 「不认识任何形状」写成会红的检查

第 13 节把地图形态硬编码列为已知风险。对策不是一句注释，是两道检查：

- 三个类的**属性名**里不许出现 `ring` / `angle` / `radius` / `floor`
- 三个文件的**源码**里也不许出现，**连注释都不行** —— 注释里出现，说明写的人脑子里已经在
  按某种形状想了，下一步就是写进代码

命中就把文件名、行号、那一行打出来。靠人记住的约束，到第二章开工时必然已经没人记得。

写的时候这条检查当场起了一次作用：`normalize` 最初用 `floorf` 判断整数值，
虽然按词边界匹配不会命中，还是换成了 `float(int(f)) == f` —— 擦边的东西不留。

### 2. 过一遍 JSON，字节不变

真正的存档要过 JSON，而 JSON 没有整数：`{"order": 3}` 读回来是 `3.0`。类型化的字段用 `int()`
接住就行，麻烦在**自由字典**（`layout`、`content`、`routes`、区域表）—— 数据层不解读它们，
自然也不知道哪个值该是整数。

不处理的话，存一次读一次 `to_dict()` 的结果就变了，「同一张图永远导出同样的字节」不再成立，
而存档比对、回放、「同种子同一张图」的测试全靠这条。

`MapGraph.normalize` 把读回来的自由字典里**值为整数的浮点数还原成整数**。代价是真正的 `2.0`
也会变成 `2` —— 约定：自由字典里要小数就别写成整数值。测试里 `reward: 1.25` 确认真小数不被误伤。

区域表以 id 为键，JSON 的键只能是字符串，所以存成按 id 升序的数组，读回来还原成整数键。

### 3. 导出顺序与加入顺序无关

节点按 id 升序导出，并提供 `node_ids()`（升序）作为**一切遍历的入口**。
字典的迭代顺序取决于插入顺序，而生成器以后会按各种顺序加点；
任何一处直接 `for id in nodes` 都可能让「同种子同一张图」在某次重构后悄悄失效。
测试里把同一张图换个顺序建一遍，断言导出的字节相同。

### 4. `edges_of` 不论方向，`neighbors` 才问走不走得通

`edges_of(id)` 返回挨着这个点的全部路；单向路走不走得通由 `MapEdge.passable_from` 回答，
`neighbors` 已经替调用方过滤好了。分开是因为两种问题都有人问：
画图要全部的路（单向路也得画出来），移动只要走得通的。

### 5. 两处与 5.2 原文不同，已回写

- `seed` → **`content_seed`**：`seed` 会遮住 GDScript 的全局函数 `seed()`。
- `MapEdge` 多了 `layout`：手绘图里「连续的 `|` 是一步跨过一个环的路」（5.4.1），
  跨了几层得有地方记，而它是形状相关的信息，只能进布局载荷。

### 6. 坏数据在门口拒绝

`add_node` 拒绝重复 id；`add_edge` 拒绝自环和两端不存在的路；`from_dict` 遇到两端对不上的路
丢弃并告警，不留一条悬空的边 —— 悬空的边会让后面每一个遍历都得判空。

## 这一步新定的设计

**章节 BOSS 失败直接战败**（作者定，7.1）。别的战斗输了节点变空白、人还能走；
核心变空白了这一局就没有终点。所以打 BOSS 是押上整局的决定 ——
这也让偏搜索路线「尽头是撤离点、可以不打 BOSS」成了一条真正的退路。

## 遗留

- 连通性、可达性这类**图算法**不在这一步：通用校验属于 M3-2（`MapGenerator.validate`），
  步数表属于 M3-4（`MapNavigator.distance_map`）。
- `content` 目前只是个槽位。里面装什么（敌人是谁、背包长什么样）是 M4 的事（5.10）。
- `routes` 里 `risk` / `reward` 是生成器算好写进来的快照，数据层不重算也不校验 ——
  「摘要与图对得上」这条不变式在 M3-3c 测。
