## 二 关键决策（作者要点头的几条）

| # | 决策 | 为什么这么定 |
|---|---|---|
| 2.1 | **战败保钱的底是「战败那一刻 wallet 里剩的钱」，不是「带进来的原始金额」** | 按原始金额退，等于中途花掉的钱也跟着退（带 200 花 150、战败退 30% = 60 > 身上剩的 50），**凭空造钱**。按余额退才是纯风险减免 |
| 2.2 | 「不参战」给的是**「有战斗定义的东西」**（武器、护甲、会出手的器官），不只是武器 | 你说的痛点是「用不到的装备扔地上」，护甲同样在背包外找不到；材料 / 珍宝 / 包本来就不参战，给了没意义 |
| 2.3 | **信物不给这颗按钮** | 标了信物会让 `FaithState.active_tag` 跳过它 → 信仰整个熄掉。那是另一件事，不该藏在「不参战」里 |
| 2.4 | 铜章「按下并在铜章里松开」才算，拖出去不认；「开战」灰着 / 铜章已交给战斗屏时都不接点击 | 和按钮语义一致，避免误触和重复触发 |
| 2.5 | 带入现金**默认 0**、每次进开局屏重置 | 「不带」是安全默认；不至于玩家没注意就带走了全部家当 |
| 2.6 | 扣款时机 = **建局成功之后**（地图生成失败不扣） | `RunState.start()` 返回 null 时不扣，玩家不会白亏一笔 |

## 六 这个分支落地要注意的三件事

1. **`docs/techs.xlsx` 是科技表的唯一来源**，改了它必须跑两步再提交：`tools/techs_xlsx_to_json.gd` → `tools/import_content.gd`。本分支**已经把生成物一起提交**（`data/techs/pack.tres`、`data/run_buffs/tech_pack_1..3.tres`、`docs/techs.md`），所以 `check_content` 直接绿，不需要额外动作。
2. **说明文字里不能出现阿拉伯数字**（`TextLint`，一个数只能有一个来源）。所以行囊三档的静态说明写成「两成 / 三成 / 一半」，真正的百分数由 `KeepOnDeath.describe()` 生成。
3. **注释里也不能用字集外的字**（168 字体检查）。这轮踩到「赚」，改成「回」。

还有一个**和本分支无关的既有抖动**：`tests/ui/test_pawn_184.gd` 的「回来了：小棋子收起」那条依赖重绘时机，单跑三次过一次两次，全套里偶发撞上。它测的是地图屏，与本批改动无关 —— 但如果 CI 红在那条，别怪这个分支。
