## 一、五条提议

### 1. 节点层：进节点、处理、回地图

原话要点：设想是「地图移动进入节点、处理节点事宜、结束后跳回地图」，问能不能把处理节点的屏当成一个新层叠在地图屏上。

我的理解：一个节点一层。这一层里把这个节点的事从头到尾处理完（回放、拾取、搜索……），关掉就回地图。

与现状的差别：**现在就是叠层** —— 战斗回放、战利品、搜索、商店、事件、休息都叠在地图上，地图和镜头都留着。差别只在「一步之内连着几件事」怎么组织：
现在是 flow 排队，每件事一个叠层换着上；提议是一层里翻页。玩家看到的一样，区别是有没有一个共用的外框。

### 2. 开局预选：角色 + 从仓库带入（有限制）

原话要点：增加开局预选界面，选角色（未来导入，现在占位）、从局外仓库带入物品；带入有数量和格子限制，具体规则占位，先按 3×3 的格子上限和 3 件的数量上限，
未来还有稀有度上限，不要写死。

我的理解：带入的东西得**摆得进一块 3×3 的格子**（按形状，不是数格子之和）、至多 3 件、将来稀有度不超过某档；三个数都是数据。角色现在只有一个占位角色。

与现状的差别：M6-3 的开局屏已经能勾仓库里的东西，但没有任何限制；没有角色。

### 3. 暂存区按节点清空，离开时分层提示

原话要点：结算逻辑没问题；暂存区跨节点不保留，理解为每次搜索或打完时暂时腾出的空间；只在离开节点时，如果暂存区有道具或贵重道具才提示；
未来设置里加开关并分层：有道具就提醒 / 只提醒特定稀有度以上 / 只提醒价值 N 以上 / 完全不提醒。

我的理解：暂存区的生命周期从「一局」缩到「一个节点」。走出这个点（下一步）暂存区连东西一起清空；走之前按设置里的档位提示。
这就把 15 节第 7 项定了：不是「进下一关消失」也不是「结算才清」，是**每走一步**。

与现状的差别：现在暂存区整局保留、跟着存档，只在撤离时消失。商店买的、事件给的、拾取的、开局放不下的、被顶出来的都先进暂存区。

### 4. 仓库与图鉴两个系统

原话要点：仓库以格子储存，不需要背包道具（所有格子默认有包）；背包道具以列表储存；未来可能删掉「背包」这个媒介，不要写死它的存在；带入就失去，合理保留。
图鉴：带出过的物品点亮、统计累计带出数量，不代表物品被储存；未来制作系统可以花货币把点亮的道具放进仓库。

我的理解：局外两张表。**仓库**是一块格子（大小是数据），非包道具按形状摆进去；包另放一个列表；「什么进列表」是一条将来可以删掉的规则。
**图鉴**按道具 id 记「带出过几次」，点亮 = 至少一次；它是将来制作系统的输入，也第一次给了局外货币一个用处。

与现状的差别：现在仓库是一个列表（什么都往里放），没有图鉴。

### 5. 搜索：耗时随稀有度，未搜的能拖，只看两件

原话要点：搜索耗时和稀有度成正比（和体积无关）；未搜索的物品也可以被拖动，可能影响搜索顺序，但已经处于搜索中的道具不受影响；
一个长度为 2 的搜索列表，只知道当前搜谁和下一个搜谁；不需要按光标距离。

我的理解：揭示不再是一批一条时间线，而是**一件一件来**：当前这件按它的稀有度耗时，搜完了按栏位顺序挑下一件；
玩家可以挪没搜的东西改变「下一个」，但打不断当前这件。

与现状的差别：现在一批一条 Tween、每件固定 0.3 秒、没亮的抓不起来、顺序只看栏位。

## 二、性价比与矛盾

| 条 | 改动量 | 收益 | 主要矛盾 / 风险 | 建议 |
|---|---|---|---|---|
| 1 节点层 | 小 | 中 | 无；搜索与商店是交互式会话，不能自动翻页 | 做成共用的「节点外框」，flow 的队列不动 |
| 2 开局预选 | 中 | 高 | 7.1 说过「先不建 CharacterDef」—— 现在有了第三样按角色变的东西，该建了；包能不能带入、开局装备表怎么摆要定 | 做，优先 |
| 3 暂存区按节点 | 小～中 | 高 | 改的是 M1～M5 已定的行为；商店 / 事件 / 休息屏得能开背包；穿行也算一步 | 做，**第一个做** |
| 4 图鉴 | 小 | 中 | 无 | 做 |
| 4 仓库格子化 | 中～大 | 现在低 | 仓库容量与「满了怎么办」没定；存档版本升 2 | 等容量规则定了再做 |
| 5 搜索 | 中 | 中高 | 耗时泄露稀有度；未搜的拖到哪；搜索中的能不能拖 | 做，先定三个问题 |

### 1. 节点层

现状已经满足「进节点、处理、回地图」。值得做的是一个共用的外框：叠层顶上一行写这个点的名字、类型、这是这一步的第几件事（回放 1/2、战利品 2/2），
底下是各屏原来的内容。flow 的队列不动 —— 队列记的是「发生了什么」，外框管的是「怎么给人看」，两者分开才好测。改动量小，收益是一致的观感。
矛盾没有；只是搜索、商店这两层由玩家决定什么时候走，外框上不能有「自动继续」。

### 2. 开局预选与带入限制

7.1 写过「现在刻意不建 `CharacterDef`：只有两个占位点，等真的有第三样东西要按角色变时再说」。带入限制就是第三样（搜索速度是第四样），可以建了：

```
CharacterDef（内容种类 characters，data/authoring/characters/*.json）
  id / display_name / description
  baseline: CombatantBaseline   开局多少血多少耐力（4.2，收掉 15 节第 8 项）
  vitality_max: int              体力上限（7.1）
  board: Vector2i                棋盘尺寸（收掉 15 节第 5 项）
  carry: CarryRules              带入规则：board 3×3、max_items 3、rarity_cap -1（= 不限）
  search_speed: float            揭示耗时的倍率（第 5 条）
  loadouts: Array[StringName]    这个角色可选的开局装备
```

带入检查用一块真的 3×3 `GridInventory`（不要求包）逐件 `try_add`：「格子上限」按形状算，两把长条枪在 3×3 里能不能同时放下由形状说了算，
不是数格子之和 —— 这是数据模型里的约束，不是运行时兜底。三个数在 `CarryRules` 里，稀有度上限先填 -1，界面按它灰掉不合格的。
存档：`RunState` 多存一个角色 id。

矛盾与要定的：
- **包能不能带入**？建议能：占一件、按形状占格（皮革包 2×3 放得进 3×3）。
- **开局装备表和角色的关系**：建议装备表保留为内容，角色列出自己可选的几套；一个占位角色 `default` 列出现在三套。
- 角色系统落地前只有一个角色，界面上就一张卡，但结构先立住。

### 3. 暂存区按节点清空

改动本身小：`RunState.step_to` 前清空暂存区（清掉的算「遗落」，进日志），走之前按设置档位弹提示。提示档位是设置项，放 `user://settings.json`，
档位是枚举（有就提 / 稀有度 ≥ X / 价值 ≥ N / 不提）、阈值是数，不写死；撤离确认里已有的那句遗落提示并进同一套。

影响面比改动大，要一起改的：
- 商店买的、事件给的现在直接进暂存区（M4-5 / M4-4）；按节点清空之后，玩家得在走之前把它们放进棋盘，否则没了。这是有意的张力，
  但**商店 / 事件 / 休息屏得能开背包**（战利品屏已经有棋盘在旁边，这三屏没有）。
- 开局放不下的进暂存区：三套装备现在都放得下，将来加装备要守住这一条，或者出生点上给一次提示。
- 顶替被挤出来的东西进暂存区（M1），也一样走之前得放回去。
- 「穿行」用过的点也是一步，也清。
- 存档签名测试、沙盒的假设要跟着改；3.4 与 15 节第 7 项改成定稿。

矛盾：无原则性的。节奏上每一步都要收拾一次背包，玩家动作变多；提示分层就是为这个准备的。

### 4. 仓库与图鉴

**图鉴**小：`MetaState.codex` 是 id → 累计带出次数，`absorb()` 撤离时每件加一；局外屏加一页列全部道具，点亮的写次数，没点亮的灰剪影。
制作系统将来读它。这一条顺手把「局外货币有什么用」回答了一半：花钱把点亮的道具放进仓库。

**仓库格子化**中到大：`MetaState.warehouse` 从列表改成一块格子（大小是数据，先占位 10×8）加一个「列表里的东西」；分流规则只写一处 `stores_in_list(def)`，
现在是 `def.is_bag`，将来删掉包就删这一个分支，存档格式两段都留着。局外屏用 `InventoryView` + 拖拽整理；开局屏从格子里挑带入的。
存档版本升到 2，旧的 meta 要么迁移（列表里的东西逐件 `try_add` 进格子）要么作废 —— 现在只有开发期的存档，作废最省。

矛盾与要定的：
- **仓库有大小就有满的时候。** 撤离带回来的放不下怎么办：丢掉、自动扩一行（像 `LootPacker`）、只点亮图鉴不进仓库、或者容量本身是局外成长的一项。
  没定之前格子化没有意义，所以建议图鉴先做、格子化等这条定了再做。
- 现在 `GridInventory` 里的包有承载语义（放进格子会变成「包里能放东西」），所以包另放列表是对的。

### 5. 搜索

改动中等：揭示循环从「一批一条 Tween」改成「当前一件 + 下一件」：当前这件按稀有度计时，到点亮出来，按栏位顺序挑下一件；
每档稀有度的秒数放 `SearchRules`（内容，先占位 [0.3, 0.5, 0.8, 1.2, 2.0]），角色的 `search_speed` 是倍率。视图上当前那件画进度环、下一件画个标记。
去掉「按光标距离」。

矛盾与要定的：
- **耗时随稀有度会泄露信息**：搜得久的就是好东西。三角洲也这样，玩家学会「读时间」是手感的一部分还是漏洞，你定；我认为是前者，等待本身就是张力。
- **未搜索的拖到哪**？拖出容器到棋盘就等于不用搜，揭示形同虚设。建议只能在容器内挪位置（改「下一个」是谁），拖出去要等亮了。
- **搜索中的那件**：按你说的不受影响 —— 当前那件锁住，抓不起来；下一件可以换。
- 拖拽层现在只有「能不能抓」一道门，要加「能不能放到那儿」一道（容器内可以、容器外不行），是 M1 拖拽层的一个小扩展。

## 三、建议的顺序与要作者拍板的

顺序：**3 暂存区按节点 → 2 开局预选（含 CharacterDef）→ 5 搜索 → 4 图鉴 → 1 节点外框 → 4 仓库格子化**。
3 定节奏、改动小、影响所有屏，先做免得后面的屏各做一遍；2 收掉三个占位；5 是手感；图鉴便宜；外框是观感；格子化等规则。

要拍板的：
1. 带入限制归角色（`CharacterDef.carry`）还是独立一份规则；包能不能带入。
2. 开局装备表与角色的关系（角色列出可选的几套？）。
3. 暂存区：穿行也清？提示的默认档位（建议「稀有度 ≥ 稀有 或 价值 ≥ 100」）？
4. 仓库满了怎么办；开发期的旧 meta 作废可以吗。
5. 未搜索的能否拖出容器（建议不能）；耗时泄露稀有度是否接受（建议接受）。
6. 节点外框要不要做。

答了就按顺序开做，每条一份报告。

## 四、作者的回应与修订（第二轮）

作者对第三节的问题答了八条。逐条记下，并把第二节的评估改过来。

| # | 作者的回应 | 落到设计上 |
|---|---|---|
| 1 | 搜索速度不做成属性：搜索在战斗外、不是实时的，同一稀有度快慢只有负面体验 | `CharacterDef` 不带 `search_speed`；每档稀有度的秒数只在 `SearchRules` 里 |
| 2 | 问「穿行也清」是什么意思 | 见下面的解释；按「每走一步都清」定 |
| 3 | 图鉴计数在原有基础上累加；同一次撤离带出多件各计一次；只点亮一次 | `codex[id] += 件数`；点亮 = 计数 > 0，本来就幂等 |
| 4 | 稀有度影响耗时是正向体验的一部分；未搜索的拖不出容器没问题 | 按第二节第 5 条做 |
| 5 | 开局的限制**通过包实现**：开局只有一个 2×2 的包或两个小包，能带的道具自然受限（初始包量随局外成长提升）；这样包就没必要带出，但有的包自带小增益，怎么定先备注；目前**包只能带出、不能带入**，但可以点亮图鉴 | 带入的检查不再是独立的 3×3，就是**初始包的空间**：开局屏摆好初始包，从仓库往包里拖，放得进的就是带的。件数 / 稀有度上限保留为数据字段，默认不限 |
| 6 | 仓库也是局外成长的一部分 | 仓库大小是数据（`MetaRules` 占位），随成长变；「满了」是常态而不是异常 |
| 7 | 撤离出来不直接进仓库：保留整个背包格子，在结算屏选择「一键置入」，仓库满了或没能全装下就中途停下提示 | 结算屏 = 玩家的棋盘 + 仓库格子 + 一键置入；`absorb()` 只记账（图鉴、价值、钱），入库是结算屏上的交互 |
| 8 | 问「节点外框」是什么 | 见下面的解释；只是观感，可以不做 |

### 「穿行」是什么

地图上每走一步都是「离开当前点、踩上下一个点」。踩上一个**用过的点**（打过的、搜过的、走过的）什么都不会发生，只是路过 —— 沙盒和日志里叫它「穿行」。
「穿行也清」问的是：暂存区是在「离开发生过事的点」时清，还是**每走一步**都清（包括只是路过的那一步）。
按作者对暂存区的定义（搜索或打完时暂时腾出的空间），最自然的是每走一步都清：走出任何一个点，暂存区就没了，路过的点上顶出来的东西也一样。这样规则只有一条，不用记「这个点发生过事没有」。

### 「节点外框」是什么

现在叠在地图上的战斗回放、战利品、搜索、商店各是一块独立的面板，长得各不一样。「外框」指给它们套一个共用的壳：顶上一行写「点 12 · 战斗 · 这一步的第 1 / 2 件事」，
按钮位置统一，底下才是各屏自己的内容。玩家看起来就是「进了这个点的一层、里面翻了两页、关掉回地图」。它不改任何逻辑，只是让一步之内的几件事看起来是同一层。可做可不做。

### 修订后的设计

**开局预选（第 2 条）**：角色占位一个（`CharacterDef`：基线、体力上限、棋盘尺寸、初始包、可选件数 / 稀有度上限，**没有搜索速度**）。
开局屏左边挑角色、中间是棋盘（初始包已经摆好）、右边是仓库格子：从仓库往包里拖，放得进的就是带的；包不能带入。
现在的三套开局装备含武器，按新想法它们退化为「初始包的配置」；**仓库是空的第一局带什么**要定 —— 建议保底一套（数据），或者装备表保留为「仓库空时的默认清单」。

**暂存区（第 3 条）**：每走一步清空，走之前按设置档位提示。

**结算（第 7 条）**：撤离后 `RunState` 的棋盘原样留到结算屏；结算屏画棋盘和仓库格子，拖或「一键置入」（按栏位顺序逐件 `try_add`，放不下就停在那一件、提示还剩几件）。
图鉴与价值在撤离那一刻按棋盘上的记，与入没入库无关。离开结算屏时棋盘上还剩的东西怎么办要定 —— 建议提示后丢弃。
带出的包：计图鉴、计价值；进不进仓库（列表）等「卖」或「包的增益」定了再说，数据模型里那段列表留着。

**仓库（第 4 / 6 条）**：格子，大小是 `MetaRules` 里的数（占位 10×8），随局外成长；不需要包；分流规则 `stores_in_list(def)` 只写一处。
图鉴：id → 累计带出件数，同一次带出多件各计一次，点亮 = 计数 > 0。

**搜索（第 5 条）**：当前一件 + 下一件；每档稀有度的秒数在 `SearchRules`；未搜的只能在容器内挪位；搜索中的锁住；去掉光标距离。

### 修订后的顺序与还要拍板的

顺序：**3 暂存区 → 4 仓库格子化 + `MetaRules` → 7 结算屏置入 → 4 图鉴 → 2 开局预选（含 CharacterDef）→ 5 搜索 → 1 外框（可选）**。
仓库格子化提前，因为结算屏的「一键置入」和开局屏的「往包里拖」都要它。

还要拍板的：
1. 初始包空间之外，件数 / 稀有度上限还要不要（建议留成数据字段，默认不限）。
2. 仓库是空的第一局带什么（保底一套 / 装备表当默认清单）。
3. 离开结算屏时没置入的东西怎么办（建议提示后丢弃）。
4. 带出的包进不进仓库（建议先只计图鉴和价值）。
