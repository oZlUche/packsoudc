## A：悬浮回调生命周期（B01）

**根因（已证实）**：背包面板把一个闭包装进悬浮窗的 `hover_quiet`，闭包里读面板自己的 `fuse_note`、`_quiet_uid`，还套着前一个回调 `prev`。自己的窗跟着面板一起释放，没有问题；但地上那块（`GroundLayer`）是导演建的、跨面板常驻，它的窗在第一次开合成确认窗时也装上了这层闭包，面板关掉后没有人撤。之后再停到地上的道具上，就会调用已释放面板上的闭包。

在 v6.15 代码上用最小步骤复现：开面板 → 开合成确认窗 → 关窗 → 释放面板 → 调地上窗的条件，得到 `SCRIPT ERROR: Attempt to call function '<anonymous lambda>' on a null instance`。实际游戏里那块内存可能已被别的对象复用，于是表现为报告里的「`is_open` in base `Vector2`」与 `slot >= slot_max` 对象查询错误。每开一块面板还会在地上的窗上多套一层 `prev`，旧面板一直被引用。

**修复**：
- `HoverTip` 的单个 `hover_quiet` 回调改成按登记者存的表：`quiet_on(owner, fn)` / `quiet_off(owner)`，同一登记者再登记是替换，不叠加。
- 背包面板在 `setup` 时给自己的窗登记，`_attach_ground` 时给地上的窗登记，离开场景树时撤销（和原来解绑拖拽层放在同一处）。条件改成面板的方法 `_quiet_check`，不再用闭包套闭包。
- 防线：查询时发现登记者已释放却没撤销，就丢掉那条并报警告，不调用它。正常路径不会走到这里；走到了说明还有别处生命周期写错，警告会出现在日志里，不会被吞掉。
- 交互不变：确认窗开着不弹，关窗后鼠标还停在被压那件上先不弹，挪到别的道具再恢复（v6.12 的行为，`test_fusion_279` 照旧通过）。

**测试**（`tests/ui/test_slice_v614.gd`）：三块面板共用一块地；确认窗开着时地上的窗也不弹，且不重复登记；中间那块先释放、其余逆序释放后一条不剩，之后照常弹；开关 100 次，登记数不增长；登记者释放却未撤销的那条在查询时被丢掉。

**没覆盖**：没有在真机长序列（商店 → 背包 → 合成 → 挤出 → 调试抽屉 → 地面回收）和导出包上复测。请游戏测试按方案 §2.3 再走一遍。

## B：开局入口（B02、U02、反馈 1、反馈 2）

**B02 预设**：
- 章节可以点名自己的预设（`ChapterDef.presets`）。点了名就只列这几套；没点名的章节照旧按档位列，但不列标了 `chapter_only` 的切片专用预设。
- 切片加两套专用预设，只用清单里的东西：
  - **强攻**：匕首、磨刀石、药膏。能和补给的匕首合出双刀，或和磨刀石合出淬火匕首。
  - **坚守**：皮甲、磨刀石、药膏。
- 预设说明是作者可改的一句话，不是道具说明。
- 后端兜底：`GameFlow.start_refusal` 在出发前再查一遍，以下情况都拒绝出发（报警告，不开局）：
  - 预设不属于这一章；
  - 不许携入的章节里，多出预设和补给以外的东西；
  - 补给标多了。
- 审计（`slice_audit`）改成按开局屏同一份枚举跑三个入口：不带预设、强攻、坚守。开局带了清单外的东西会报「开局带的 X 不在清单里」。20 个种子 × 3 个入口：0 个问题。

**U02 补给上棋盘**：
- 章节补给（匕首、纱布、口粮）在整备页就摆在棋盘上，只能在棋盘上挪，进不了仓库。
- 切预设时补给不重复摆：A→B→A 之后，棋盘上是补给加一套预设，各一份。
- 出发时补给按「摆了哪些」记账（`RunState.supply_left`）：摆了的不再另发，没摆进去的才照章补发，所以出发后背包加地上和预览一样。
- 棋盘放不下时会说一句。

**反馈 1 仓库**：不许携入的章节，整备页藏起仓库框，换成一张纸条说明「这一章只带预设和补给」。没选预设时的悬浮说明也改成同样的意思，不再写「其余从仓库拖」。

**反馈 2 预设引导**：第一次进整备页的预设那一页，说一句预设是什么、怎么换，只说一次。

**强度**（`slice_bench`，20 种子，各敌人单挑）：
- 两套都能稳赢屠夫；
- 蛮兵要先合出淬火匕首才稳；
- 盾卫：强攻 0%，坚守合成后 65%；
- 守卫：两套都打不过，要靠路上的东西。

试过给坚守带剁刀，打守卫 100%，太强，没有用。

**测试**（`tests/ui/test_slice_v614.gd`）：
- 切片只列两套、正式章节不列；
- 后端拒绝别章预设、多带长剑、补给标多；
- 审计三个入口都过；带长剑会报；
- 整备页：补给三件在棋盘上、进不了仓库；A→B→A 不叠；出发后背包和预览一样；仓库框换成纸条。

**没覆盖**：坚守打不过守卫是否合适，要等真人试玩再定。

## C：合成引导（反馈 3、U01）

**首次能合成时说一句**：
- 章节新开关 `fuse_hint`，只有切片开着。
- 背包面板在棋盘或地上一有变动（摆好之后，等这一帧走完）就查一遍有没有能合的一对。查的方式和拖放合成同一套：两件都许拿去合、没锁、不是随身之物。
- 有就给两件标上小锤，说一句「拿起一件，拖到有小锤的搭档上，确认后合成」。只标、只说，不替玩家挪东西，也不说成品是什么。
- 几对都能合时，先挑两件都在棋盘上的，再挑一件在地上的，同一档按先拿到的。
- 不说的情况：
  - 手上拿着东西、或确认窗开着：等下一次变动再看；
  - 这个存档已经说过、合成过，或认识任何配方。
- 存档里分开记两件事：「说过」和「合过」。「合过」只有真合成了才记，只说过不算。
- 想再看：说明页「拖放与旋转」本来就写着小锤和拖上去合成，没另加帮助页。

**U01 压两件**：拖着的东西压了两件以上，而且光标正对着一件搭档，算「想合成」，不再按挤出处理：
- 预览变红，残影旁边写「还压到其他物品，请换一侧或反向拖动」。
- 松手弹回原处，所有东西都不动，再说一遍同一句。
- 压到两件搭档时说「压到两件能合的道具，请只对准一件」，不自动挑一件。
- 光标对着的不是搭档（比如对着熏鱼）：照旧挤出，普通摆放不受影响。
- 只压一件搭档：照旧开确认窗。

**测试**（`tests/ui/test_slice_v614.gd`）：
- U01：亚麻布卷压纱布加熏鱼、对准熏鱼照常挤出、压两块纱布、只压一块开确认窗。
- 首次引导：
  - 只有一把匕首时不说；手上拿着时不说；
  - 两把都在棋盘上、一把在地上一把在棋盘上，都能标出来；
  - 说一次之后不再说，换一块面板也不说；
  - 合成后记「合过」；
  - 认识配方、章节没开、这一屏不许合（商店的货），都不说。

**没覆盖**：
- 搜索、战利品的揭示动画有没有等完：现在是等变动后的那一帧，没有挂到动画结束的信号上。
- 存过档、重开之后不再说：靠的是存档旗标，没有做存档往返的测试。
- 真人能不能看懂这一句，要游戏测试或试玩来看。

## D：路线、事件和说明（D01、D02、反馈 4）

**D01 绕过盾卫**（按地图连线和对打表算，没有做带状态的路线工具）：

| 路线 | 走法 | 移动 | 原地搜索 | 风险 |
|---|---|---|---|---|
| 正面 | 出生 → 拾荒者 → 搜索一（两次） → 蛮兵 → 盾卫 → 搜索二 → 歇脚 → 担架 → 守卫 → 终点 | 9 | 3 | 盾卫是精英，输了扣 2 点体力；强攻 0%，坚守合成后 65% |
| 绕行 | …蛮兵 → 商店 → 补衣人 → 歇脚 → 搜索二 → 回歇脚 → 担架 → 守卫 → 终点 | 11 | 3 | 不打盾卫；多走两步，路上还能逛商店、找补衣人 |
| 提前撤离 | 两条都能在歇脚旁边的免费撤离点走 | — | — | — |

结论：
- 步数上限 20，绕行只多两步，所以绕行几乎全面占优。
- 商店本来就卖毒药瓶和圆盾，「打赢盾卫才拿得到」这条从来不成立。313 写的「盾卫之后」是说错了，已经改成「在盾卫和歇脚之间，回头也能到」。
- 按方案没有加「先赢盾卫才开搜索二」的锁：坚守要先拿到毒药和圆盾才打得过盾卫，加了锁就成了循环。
- 要不要给盾卫一点独有的收益，是改玩法的事，交给作者定。

**D02 补衣人**：
- 切片地图换用一份切片专用的补衣人（`event_refugee_weaver_slice`），只有「交出亚麻布卷」和「保留材料」两项。
- 正式版的补衣人不动。
- 审计新加一条：地图上的事件有选项要清单外的道具，就报出来。拿正式版补衣人代入时，会报熟皮革拿不到。
