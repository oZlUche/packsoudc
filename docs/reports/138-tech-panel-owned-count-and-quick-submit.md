- 作者原话：「在科技的上交界面，除了已交和需求外，也加入当前拥有数量，拥有大于0时可以快速置入」

## 一、现状（`ui/game/tech_panel.gd`，110 / 118）

右板「费用」区每种材料一行 `Label`：「名称　已交 n / 需要 m　✓」（`_refresh`，第 290 行附近）。上交只有两条路：
折叠的仓库格子里**双击一件**（`submit(uid)` → `GameFlow.submit_tech` → `TechService.submit`：从仓库移除、`tech_deposits` 计数 +1、存 meta），
或**拖进上交区**（`_on_zone_changed` → `TechService.deposit`）。要交三块钢锭得在仓库里找三次、双击三次；仓库折叠着时还看不到自己有没有。

## 二、改成

材料行从 `Label` 换成一行 `HBoxContainer`：

```
钢锭　已交 1 / 需要 3　拥有 5　[交 2]
```

- **「拥有 n」** = 仓库里这个 `item_def.id` 的件数（`MetaState.warehouse.items()` 按 `def.id` 数，一次遍历给所有材料行用；仓库只有局外物品，没有堆叠，一件一个）。拥有为零时灰字「拥有 0」。
- **【交 k】按钮**：k = min(还差的, 拥有的)（还差的 = `TechService.needed`）。拥有为零或已交齐时不显示按钮（已交齐那行本来就打 ✓）。前置没点亮时整行照旧只是文字（上交区本来就灰着）。
- 按下：取仓库里前 k 件该 id 的 uid，逐件走现有的 `_flow.submit_tech(def.id, uid)`（每件都是同一条「上交即消耗」的路，`TechService.submit` 自己查 `can_submit`，交满自动停）；成功后 `_line.text = "交了 k 件「钢锭」"`，`changed.emit()`，`_refresh()`。`submit_tech` 每件存一次 meta，k 最多三五件，不值得加批量接口（待定 1）。
- 仓库格子视图：仓库折叠着时按钮一样可用；展开时交完的格子空出来，`InventoryView` 已经听仓库的变化信号，不用另刷。
- 不改 `TechService`、`MetaState`、存档。

## 三、文案与数字

界面行里的数字是读数（已交 / 需要 / 持有 本来就是裸数字），不受「玩家文案不许阿拉伯数字」约束；按钮文字「交 %d」同理。

## 五、测试

- 仓库有五块钢锭、下一级要三块、已交一块 → 行文字含「拥有 5」、按钮「交 2」；按下后 `deposited == 3`、仓库剩三块、按钮消失、行打 ✓、meta 存了。
- 仓库有一块、还差三块 → 按钮「交 1」，按下后还差两块、按钮消失（拥有 0）。
- 仓库没有 → 「拥有 0」灰字、无按钮。
- 前置没点亮 → 无按钮。
- 满级 → 费用区只有「已满级」，没有材料行。

## 六、待定（按推荐）

1. **要不要给 `GameFlow` 加批量 `submit_tech_many`（存一次 meta）**。推荐：**不加**，逐件调现有接口，少一条路。
2. **按钮上写「交 k」还是「全部交」**。推荐：**「交 k」**，一眼看出会扣几件。
