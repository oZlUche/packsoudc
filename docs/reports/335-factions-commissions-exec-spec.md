# 335 阵营与委托：落地规格（架构设计按方案整理，交执行线程）

> 日期：2026-11-19。作者 2026-11-19 20:24（架构设计线程）：查看[阵营与委托方案](../plans/2026-11-19-factions-and-commissions.md)（含「委托内容、奖励与入口的执行规格」一节），按理解落实并让执行线程执行。
> 基线：main `74c8a3b`，v6.55。本报告只有文档，没有改代码。
> 方案里的组织、台词、任务、数值都是拟案；本报告把它们落成工程上能直接开工的形状。凡写「建议初值」的，作者没回音就照做，改了再跟。

## 一、我对方案的理解

1. 营地多一本**委托簿**：五个组织各一页，每方五份具名委托（两份入门 +1、两份调查 +2、一份结案 +3），声望 0 / 2 / 5 / 9 四级，共 25 份；另有三种可重复模板。
2. 委托有三种完成地点：营地当场办完、局内现场交付（交了就算，之后败退也算）、要带回营地（遗失就重做这一步）。**任务卡必须分别写清接取、完成、领奖在哪。**
3. 声望只管「这方愿意把多重要的事交给你」，开放的是服务、案卷和后续选择；金币付成本，见识仍只来自单局结算，信力不受影响。正常战败不扣声望。
4. 出征最多带两份正式委托；局内另可遇到一次即时的现场请求，不占槽。
5. 先做三张原型单验证整套流程，再补齐军团、协会、灰灯三方（15 单），最后做使团和猎盟（10 单）。

## 三、数据与状态

**内容（走内容管线，`data/authoring/` → `.tres`）**

- `factions/<id>.json`：名字、四级名称（陌生 / 熟面 / 受托 / 代言）、阈值 `[0, 2, 5, 9]`、每级开放的服务 id、联系人 NPC。
- `commissions/<id>.json`：所属阵营、档位（入门 / 调查 / 结案 / 模板）、声望值、前置（声望级、前置委托、章节 / 配方可用）、阶段列表、报酬、互斥组、原话与卡面字段。
- 每个阶段写：目标类型与参数、在哪完成（营地 / 现场 / 带回）、托付算不算数、要不要本人成功撤离。

**目标类型**按批次增加，每种对应一个真实事件，不靠界面按钮自报完成：

| 批次 | 目标类型 | 触发源 |
|---|---|---|
| 原型 | 查验不同的撤离点 N 处 | 撤离点事件里新增的「查验」选项 |
| 原型 | 接单后在基地真的打造一次指定范围内的配方 | `Smithy.forge` 成功 |
| 原型 | 把任务信交到指定种类的接应点 | 撤离点事件里新增的「交信」选项 |
| 第二批 | 从仓库交付符合条件的物品（可等效替代）；在两类材料点各采样一次；带任务物成功撤离或托付；营地核对（选一项） | 仓库交付页、材料点交互、`extract` / `SafeModule.closed`、委托簿内的选择 |
| 第三批 | 足迹点依次调查、击败指定敌人取证、听证与裁决 | 新的点内交互、`battle_finished`、委托簿内的选择 |

**局外状态（进 `MetaState`，走 `MetaMigrations`，旧档默认全空）**：各方声望；每份委托的状态（未见 / 可接 / 已接 / 某阶段 / 已结）与阶段进度；已登记的线索；互斥案件的归属；回执列表（谁收到了什么、还差什么）。

**局内状态（新 `CommissionModule`，照保险箱的样子做）**：出征时把已追踪的至多两份委托拍个快照带进局；监听上表的事件记进度；进度跟这一局的存档走。结算时和这一局的其他结果**同一次**并入局外（`MetaState.absorb`，靠 `settled_runs` 防重复）：

- 写明「现场交付」的阶段，失败也并入（和配方发现同一条路）。
- 写明「带回」的阶段，只在成功撤离或托付成功时并入；否则这一步重做，已归档的阶段保留。
- 同一物证、同一节点、读档重进都只记一次：进度按「委托 id + 阶段 + 节点 id 或实例 uid」去重。

**任务道具**：带 `commission` 标签的道具（信、名册、封签样本）。占格；不能卖、不能献祭、不进随机来源、不被赐福、不参与合成；放弃委托时收回。出征时发进背包，放不下落地并在出征页提示。按项目规则，说明文字留空给作者写。

## 四、三张原型单的具体做法

| 委托 | 接取 | 完成 | 领奖 | 要改的地方 |
|---|---|---|---|---|
| **两条回路**（军团，调查 +2） | 委托簿 | 同一局里在两个不同的撤离点各点一次「查验」，第二次点完当场成立；之后败退也算 | 回营委托簿 | `extract_default` 事件加「查验」选项（带着这份委托且这个点没查过才出现）。付费撤离点查验不收钱。标准图本来就是一处免费加一处付费撤离点，不用改地图生成；出征页核对所选章节撤离点不足两处时提示换章节 |
| **照抄也要做得出**（协会，入门 +1） | 委托簿，接单时从「已解锁且当前材料够」的铁匠配方里选一张 | 接单之后在铁匠铺真的打造一次那张配方，成品归玩家 | 委托簿当场 | 监听 `Smithy.forge`；没有可选配方时卡面写明缺什么，不让接。只补劳动报酬，不再发一份成品价值 |
| **无人署名的信**（灰灯，入门 +1） | 委托簿，出征时发一封占 1 格的信 | 在任一免费撤离点点「交信」，信消失，当场显示「已送达」；之后败退也保留 | 回营看回信 | 撤离点事件加「交信」选项；信是任务道具。带着信死在半路 = 信遗失，回营重领再送 |

原型阶段的验收就是方案里的那个循环：同时接《两条回路》和《无人署名的信》，交完信、查了一处出口后失败；回营看到灰灯回执已成立、军士还在等第二处出口；结算分别列出「已送达」和「还差什么」。

## 五、界面（建议初值）

- **委托簿**：基地加第五个页签「委托」，排在「出征」之后。左侧五方（首版三方，另两方不显示，不留「待开放」占位），右侧任务卡。每方只展开推荐的下一步，其余折叠。
- **任务卡**固定五栏：替谁办、做什么、在哪完成、带不带回、报酬。互斥案件在接取前就显示两种后果。
- **追踪**：出征页显示已选的两份；局内地图角上一块小牌列当前目标，完成一项划掉一项。
- **结算**：加一段「委托」，逐条写谁收到了什么、哪一步保留、哪一步要重做。
- **现场请求**：就是一屏普通事件，写清收货人、交哪件、当场回报；拒绝不扣声望。
- 委托簿、任务卡、小牌、回执都是新面板：先用现有书页和纸条素材占位，样张请 UI设计 出给作者挑；遵守无裸文字、面板声明明暗、金币用图标、非矩形样张这些既有规则。
- 统一教程没走完的存档不显示「委托」页签；试玩切片档案不显示。

## 六、报酬与校准（数值都是候选）

- 声望：入门 +1、调查 +2、结案 +3；重复模板最多把一方推到 2。
- 金币与实物：出一个核对工具，逐单列出「放弃的可卖价值 / 最低购料成本 / 绕路行动数 / 占格」对「报酬」，重复单不允许买入即交有净利。首版三张原型单的酬金由执行线程按这张表给候选值，写进报告。
- 完成委托本身不发见识。
- 永久服务（军团的约定会合点、协会的手记与选题、灰灯的匿名寄存等）随各方结案批次做，原型不做。
