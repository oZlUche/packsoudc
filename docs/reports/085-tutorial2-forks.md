## 二、新机制

- **合成**（15 节第 5 项落地；作者定：**不是立刻的**）：新内容种类 `recipes`（`RecipeDef`：两件输入 → 一件产物，顺序无关；导入器查道具库）。拖着 a 压到恰好一件 b 上、放不进空位时先问配方（预览画绿）—— 有就**配对**：`RunState.queue_craft(a, b)` 保管 a、b 留在棋盘上画「合」记号、提示「走到下一个点时合成」；没有配方才顶替。
  **走到下一个点**（`_on_arrive`：清暂存区之后、节点的事之前）`resolve_crafts`：b 消失、产物落在 b 的位置，放不下自动找位，再不行进（刚清空的）暂存区并提醒「背包装不下，放进了暂存区」；b 不在了（被丢了）就把 a 放进暂存区。每桩发 `craft_done`，GameFlow 排成一页结果屏先给看，地图日志也记。配好的对**跟存档**。`DragLayer` 没给 `queue_craft` 回调时（沙盒 / 测试）仍是立刻合的老路。第一条配方：匕首 + 毒药瓶 → 涂毒匕首。
- **章节收起与顶上**：`ChapterDef.hidden_by_unlock` —— 拿到那个解锁就不再列（序章通关收起、序章二通关收起），于是「新的一局」时只剩下一张教程图、`skip_setup` 直接开；第一章要 `prologue2_done`。`ChapterDef.vitality_bonus`：这一章多给体力（序章二 +2，两场都输也死不了）。
- **`line` 布局认 `row`**：同一列上下错开画岔路，行居中。
- **节点内容 `base_stats`**（084 已有）在这里大量用：四个敌人的血 / 甲 / 耐力回复 / 回血都按教程需要写死，不跟全局敌人数值一起涨。

## 三、新内容

道具七件：塔盾（`on_before_damage` → `modify_damage flat -4`）、板甲（`max_shield 45`，开战自动满）、毒药瓶（素材）、涂毒匕首（匕首 + 中毒 buff：每秒每层 2 点 `poison` 伤害，无视护甲与护盾）、战锤、护身符（`max_shield 60` + 每秒 `change_resource shield +7`）、解毒包（每 0.8 秒 `remove_status` 中毒与流血）。
敌人四种：游兵、重击手、持符者、药师（都带皮革包，道具全在包里）。事件十四份（`tut2_*`）。

## 三·五、作者试玩后的修正

- **固定减伤减过头会回血**（塔盾 -4 挨 3 点的匕首显示「回复」）：伤害管线里 `flat` 加完没钳零，负数落到血上成了治疗。修：减到头就是 0，变治疗只有 `invert` 一条路（`DamageResolver`，补了管线测试）。
- **普通匕首去掉流血**：作者定它就是典型的高频低伤；流血留给弯刀 / 剁刀。游兵三把匕首对塔盾于是一点打不进。
- **毒药瓶自己也能下毒**（四秒一层，慢）；合成涂毒匕首后借匕首的快手一刀一层。
- **序章二开局发一把匕首**：`ChapterDef.starting_items`（章节发的道具，在角色初始包之上）。
- 口粮的 `regen_stamina` 战斗里本来生效，是耐力评估只读了基线：改成读单位级（基线 + 道具），悬浮窗还写耐力上限。
- 序章一第二次搜到的贴身内甲只会给别的护具加甲、自己没用：换成皮甲（3 甲）；内甲留给教邻接槽的那一段（086 提案）。
- 敌人的包必掉（`DropRule.bags_always_drop`，默认开）且不占 `min_drops` 的保底名额；保底数是数据。

## 三·七、作者第三轮（持符者、合成没触发、配对高光）

- **持符者只叠盾**：护身符改成每秒给自己叠一层「护符结界」buff（层数不限、到战斗结束），每层 `max_shield +8` —— 资源上限涨多少当前值涨多少（v1.0 定的规则），所以就是「每秒 +8 点护盾、没有上限」；去掉了 `regen_hp`，也不再预置 `max_shield`。毒伤害不吃护盾，仍只有涂毒匕首能赢；长剑 7.5 DPS 追不上 8/s 的盾。
- **毒没叠层**：作者打持符者时用的应是没合成的毒药瓶（四秒一层、六秒过期，最多一两层）—— 根子在合成没触发。
- **合成为什么没触发**：配对原来只认**棋盘上**被压的那件；匕首在暂存区里时，把毒药瓶放到它那一行只是插进列表。现在暂存区里也能配对（拖到那一行上），被压的那件一起从暂存区拿出来由一局保管（暂存区一挪步就清，留着会丢），到下一个点产物找地方进包。反过来拿匕首压毒药瓶也一样。
- **配对高光**：拖起一件，所有登记视图里能和它合成的那几件亮一圈（棋盘上脉动的绿框、暂存区那一行绿框），放下 / 取消就熄。

## 三·八、永续（作者定）

规矩：**可叠层的 buff 永续，不可叠层的可以过期**。可叠层的往往简单（发生 A：中毒、流血、结界、兴奋剂），叠上就一直在，直到被清除或战斗结束；
不可叠层的（`max_stacks == 1`）往往复杂（满足 X 条件时获得 ABC：标记、血怒、偏转），可以有时长。
`BuffDef.is_stackable()` / `is_permanent()` / `duration_text()` 把概念写明，`BuffInstance` 按 `is_permanent()` 判过期；**导入器拦**：可叠层的填了时长报错（独立 buff 文件与道具里内联的都查）。
内容：中毒、流血、兴奋剂去掉时长；标记（8 秒）、血怒（10 秒）、偏转（8 / 4 秒）保留。道具说明里写「施加「中毒」（永续，至多 5 层）」。

## 三·九、叠层不设上限 + Buff 制作器 + 界面语言（作者定）

- **叠层上限通常没有**：`max_stacks 0 = 不限`（`BuffInstance.add_stacks` 只在 > 0 时钳），中毒（毒药瓶、涂毒匕首）与流血（弯刀、切肉刀）去掉「至多 5 层」；兴奋剂保留 3 层作「有上限」的例子。
- **Buff 制作器** `ui/buff_editor`：和道具 / 事件编辑器同一条原则（同一条通路的另一个入口）。字段：id、名字、是减益；**叠层**（可叠层勾选 + 上限 SpinBox，0 = 不限）；**时长**（永续勾选 + 秒数）—— 可叠层时永续锁死、秒数不可编辑（写着「可叠层的 buff 一律永续」），取消可叠层 → 上限 1，可以取消永续、给默认 5 秒；**效果**由 `PropertyForm` 反射 `BuffDef` 生成（mods / rules / on_apply / on_expire，构件类型下拉来自注册表 = 「从预设里挑」），旁边一个 **JSON 代码编辑器**可直接改再「套用」；校验走导入器（含永续规矩）；保存 = `data/authoring/buffs/<id>.json` + `data/buffs/<id>.tres`；草稿缓存与放弃改动同事件编辑器。道具里按 id 引用 `"buff": "<id>"`。启动选择器里多了它一张卡。
- **界面语言** `UiText`（`core/text/ui_text.gd`）：键 → {zh, en} 的表，`t(key)` 按 `UiText.lang` 取；`GameSettings.language`（存盘，不认识的回落 zh）；主菜单一个「语言」按钮点一下切并原地重建；导演读设置后 `UiText.apply`，编辑器 `_ready` 也读。现在只有主菜单与 buff 制作器走它，别的屏仍是写死的中文，逐屏换成 `UiText.t()` 就跟着切。

## 三·十、「新的一局」为什么开到了序章二（作者问）→ 「新的一局」与「继续」并列（作者定）

不是主菜单的代码错，是两条规矩叠在一起：序章通关给 `prologue_done`，序章的 `hidden_by_unlock` 就是它（教程收起）；收起之后能选的只剩序章二，
它又 `skip_setup`，于是 `new_run` 不经开局屏直接开（084 那条）。作者的局外存档里已经有 `prologue_done`（之前通关过序章一），所以一点「新的一局」就是序章二。

作者定的规矩：**新的一局 = 从头开始；已有存档就并列显示「继续」。**

- `GameFlow.new_run_target()`：教程没全通就是第一张教程（不管前面几张通没通）；教程全通了看还能选的，只剩一章又 skip_setup 才直接开，否则开局屏（随机一局）。按钮写「新的一局 · 序章：废墟边缘」。
- `GameFlow.continue_target()` / `continue_run()`：有局内存档 → 读档（按钮「继续上次」）；没有存档但教程打到中途 → 下一张没通关的教程（按钮「继续 · 序章二：岔路」）；两样都没有主菜单不显示「继续」。
- `tutorial_chapters()` / `tutorials_done()`：教程章 = 带 `hidden_by_unlock` 的章。
- 局外屏的「局外解锁」占位开关也列章节通关给的解锁（`prologue_done` / `prologue2_done`），标着「通关：序章」「开放：序章二」，作者要清进度在这儿关。

## 四、没做的 / 留给作者

- 大型规模是占位（配置说明就写着「占位」），生成不出图时开局屏会报「这一章生成不出图」；环数现在取规模档的最少环，作者要「规模里再选环数」再加一个数。
- 合成只有「拖到一起」一条路，没有配方界面、没有多件合成；配方悬浮窗提示靠事件文字（`RecipeDef.note` 还没画到道具悬浮窗上）。配好的对不能解除（要解除得等作者说怎么解：再拖一次？）。
- 第二张图的敌人不掉专属道具，掉的是身上的（按 084 的规则）；作者要「奖励」再加。
- 克制关系用五个种子的模拟验：游兵 5/5 vs 0/5、重击手血量差 37、持符者 5/5 vs 0/5、药师 5/5 vs 0/5。真人手感等作者试。
