# 298 拼接配方进悬浮窗、配方里的名字可停留查看、升级前后两窗并排（279 / 286 补充）

> 作者 2026-11-11 13:10（架构设计线程）：「目前关于基础道具的合成，也就是两件白色品质武器邻接后变为另一种武器的设定，似乎还没有在悬浮窗里记录配方，能否加上？并且让配方内的名字以可查看信息的方式显示。另外，关于武器的升级，在铁匠铺或者局内铁砧里，能否加上明确对比武器升级前后的两个信息窗并排设计？」直接指派：待定按推荐派执行。

## 〇 一句话

三件事：① 道具悬浮窗加一行「可拼为」，列出这件贴着谁能拼成什么（14 张拼接配方全进）；② 配方里出现的每个道具名都改成**道具词**，停上去开那件道具的整段悬浮窗（拼接的搭档、286 配方子窗「要」那行的武器和魔晶）；③ 砧和铁匠铺里，升级配得上时并排摆两块信息窗：左 = 现在这把，右 = 锤完那把，右边和左边不一样的行左侧加一条金线。

## 一、现状（读码）

- 拼接（279）：`data/authoring/recipes/fuse_*.json` 14 张，`adjacent: true`，两件贴着时接缝上浮铜徽（`Fusion.pairs`）。悬浮窗里**完全没提**：`ItemTooltip.upgrades_line` 只查 `Anvil.upgrades_for`（砧配方），拼接配方不在里面。v5.43 起停在铜徽上也不弹窗，所以玩家不试就不知道能拼什么。
- 14 张里有 5 张的一边不是武器而是材料：磨刀石（手斧 / 短剑 / 伐木斧 / 小刀）、鞣皮（粗弓）、燧石（木棍）。材料那一边的悬浮窗同样该写。
- 配方词（286）：`[url=recipe:<id>]` 只包砧配方的**出件名**；子窗里「要　这把 + 【金属】≥ 绿」的武器名、魔晶名是死文本。`HoverTip` 只认 `term:` 和 `recipe:` 两种前缀。
- 砧（`ui/game/anvil_column.gd`）：两槽配上后 `preview()` 给出件，面板里用几行字写出件的简述（`ItemTooltip.describe`）；没有和原件的对照。铁匠铺（`smithy_panel.gd`）点开配方只有配方卷轴，也没有对照。

## 二、做法

### 2.1 「可拼为」一行

- 新 `ItemTooltip.fusions_line(def)`：扫全部 `adjacent` 配方，凡是这件占一边的各出一段，接在「可升为」那行上面。写法：

  `可拼为：+ 小刀 → 双刀　+ 木棍 → 短矛　+ 磨刀石 → 淬火匕首`

  搭档名是**道具词**（2.2），出件名是**配方词**（`recipe:fuse_*`，按稀有度上色、下划线）。自己拼自己（小刀 + 小刀）照样写「+ 小刀」。
- 拼接的配方子窗：出件整段悬浮窗（品质 0）+ 一行「要　小刀 + 木棍」（两个都是道具词）。不写「贴着放、点锤」的操作说明 —— 铜徽和金虚线已经在说（奥卡姆）；要加再加（待定 3）。
- 材料那边（磨刀石、鞣皮、燧石）同一行、同一写法。
- 只写「能拼成什么」，不在出件上反写「由什么拼成」（待定 2）。

### 2.2 道具词：配方里的名字都能停上去看

- 新前缀 `[url=item:<道具 id>]`，`HoverTip` 和 `term:` / `recipe:` 走同一条路：停 `TERM_SEC` 开子窗，子窗 = 那件道具的整段悬浮窗（品质 0），可钉、可再开，深度照 `MAX_DEPTH` 3 封顶。
- 用在三处：拼接行的搭档名；拼接与砧配方子窗「要」那行的武器名；魔晶配方的魔晶名。材料**类**（【金属】≥ 绿）不是一件具体道具，保持原样。
- 286 的钉住例外（没钉住的窗、鼠标从道具直接进窗不收）扩到带道具词的窗；别的窗照旧。

### 2.3 升级前后两窗并排

- 新小部件 `UpgradeCompare`：两块悬浮窗样式的信息窗并排（就用 `ItemTooltip.describe_full` 的排版和悬浮窗的皮，不要新图），中间不加箭头和字，左旧右新的次序本身就够。
  - 左 = 现在这把（真实例：带它自己的品质和附魔）。
  - 右 = 锤完那把（`Anvil.result` 的预览件：品质按材料档数算好，数值是最终值）。
  - 右窗里**和左窗对不上的行**左侧加一条金线（逐行比字符串：改了数的句子、新添的句子都会亮；名字和稀有度那两行不标）。不写「+3」这类差值，数字两边都在，自己能比。
- 砧（休息点铁炉屏左上）：武器和材料都放上、配得上时显示两窗，替掉现在面板里那几行出件简述；配不上或没放齐，照旧是 286 的提示句，不显示两窗。
- 铁匠铺：点开一张**升级类**配方（吃一把武器 + 材料的那些）时显示两窗。左 = 仓库里会被吃掉的那把；仓库里没有这把，左窗按品质 0 画并整窗压暗。普通配方（不吃武器的）不显示。
- 位置由执行按两屏的空位摆（砧：铁板右侧或下方的空处；铁匠铺：舞台区配方卷轴旁），两窗不能盖住槽和锤键；摆完请 UI设计 过一眼。
- 两窗是常驻的信息窗，不是悬浮窗：不用停、不会收；窗里的关键词、配方词、道具词照样能停上去开子窗。

## 三、改动清单（执行）

1. `ItemTooltip.fusions_line` + 进悬浮窗正文（「可升为」上面）；`recipe_full` 认拼接配方（「要　甲 + 乙」）。
2. `HoverTip` 认 `item:`，开整段道具子窗；钉住例外扩到带道具词的窗。
3. 286 子窗「要」行的武器名、魔晶名包成道具词。
4. `UpgradeCompare`（两窗并排 + 不同行金线）；砧配上时显示、替掉出件简述；铁匠铺升级类配方点开时显示。
5. `UiText` 新键：「可拼为：%s」「+ %s → %s」「要　%s + %s」（拼接用，中英）。
6. 测试：小刀的悬浮窗有三段可拼；磨刀石也有；搭档词开道具子窗、出件词开配方子窗、到 3 层停；砧配上显示两窗且右窗有金线行、拿走材料两窗消失；铁匠铺升级配方有两窗、普通配方没有、仓库没这把时左窗压暗。

## 四、待定（没回音按推荐）

| # | 事 | 推荐 |
|---|---|---|
| 1 | 拼接行写法 | 「可拼为：+ 搭档 → 出件」一行排开，搭档是道具词、出件是配方词 |
| 2 | 出件上要不要反写「由 甲 + 乙 拼成」 | 不写，先少再多 |
| 3 | 拼接子窗要不要写操作（贴着放、点锤） | 不写，铜徽自己会说 |
| 4 | 两窗的差别怎么标 | A 不同的行左侧一条金线（推荐）；B 什么都不标；C 写差值（+3） |
| 5 | 没配上时要不要也显示两窗 | 不显示，只在配得上时出现 |
| 6 | 铁匠铺仓库里没这把 | 左窗按品质 0 压暗显示 |
