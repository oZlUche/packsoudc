# 230 · 方案：道具悬浮窗加功能按钮 —— 一套「道具操作」供给层，按容器与屏给按钮；新增【锁定】

> 架构设计线程，2026-10-21。作者原话（18:41）：「考虑给道具的悬浮窗加上功能按钮，比如对局中的【锁定】，仓库中的【出售】【出售同类】【锁定】【锁定同类】之类的按钮，具体哪些可以参考类似游戏的右键菜单或者常见功能」。
> 本文只做方案，不实施。承接 084 / 170 / 193（悬浮窗）、099（右键）、109（双击 = 快速置入）、226（悬浮窗是控件，字可以落在上面）。

## 〇 一句话

悬浮窗底下加一排小按钮，**按钮由「这件东西此刻在哪个容器、哪一屏」决定**：一处供给层 `ItemActions` 统一出按钮，悬浮窗只管画和点；现在散在双击、右键、拖拽里的动作（置入、拾取、买、卖、献祭、奉为主信仰……）都从这一层出，再加一个新状态 **锁定**（锁住的东西不卖、不丢、不献祭、不当材料，一键出售跳过它）。右键一件 = 立刻钉住悬浮窗（省掉等一秒多），信物的右键切换改成按钮。

## 一、现状（v3.80 核过）

- **悬浮窗** `HoverTip`（084 / 170 / 193）：跟着鼠标，深底白字 360 宽，头 / 正文 / 脚注三块；鼠标离开道具 0.15 秒内进窗就留下；停够 0.5 + 0.6 秒钉住（黄铜线绕一圈），钉住后可以进窗、点词条开子窗、「百科 >」。窗本身挡鼠标（`MOUSE_FILTER_STOP`），**已经能点** —— 只是现在窗里没有能点的东西。
- **道具的动作**今天分散在三种输入里：
  - 双击（109）= 「快速置入」：地上 → 棋盘、仓库 ↔ 棋盘、战利品 → 棋盘、商店货架 = 买、神坛台 / 保险箱 / 铸炉槽 = 取回、基地仓库按页签 = 置入 / 卖 / 上交。
  - 右键（099）= `item_context` 信号，只有两处接：棋盘上的信物 → 奉为主信仰（局内背包窗、开局屏）。
  - 拖拽：卖（商店出售区）、献祭（祭品台）、进保险箱、丢地上、铸炉槽、上交区（229 删）。
- **没有「锁定」**：`GridInventory.is_locked` 是 207 的「扎根」（生长到顶的东西动不了），不是玩家锁；`ItemInstance.state` 是一个随存档走的字典，可以放新旗。
- **同类游戏的右键菜单 / 常见功能**（作者让参考的）：塔科夫 —— 检视、使用、装备、打开、丢弃、投保、折叠、卸弹、按此物筛选、钉住 / 锁定（锁住不卖不丢）、标记容器；三角洲行动 —— 快速出售、锁定（防误卖误丢）、丢弃、拆分、使用、检视；暗区突围 —— 锁定、快速出售、丢弃、移入安全箱、使用；暗黑四 —— 标记为垃圾 / 收藏（收藏的不被批量分解出售）；背包乱斗 / 背包英雄 —— 只有卖（拖到垃圾桶 / 双击）、没有锁。共同点：**锁定 + 快速出售 + 丢弃 + 移到某处 + 使用** 五类；「锁定」几乎都是防误操作（可移动、不可卖 / 丢），不是防系统。

## 二、设计

### 2.1 一处供给层：`ItemActions`

`core/inventory/item_actions.gd`（纯数据 + 回调）：

```
class ItemAction:  id: StringName   # &"lock" &"sell" ...
                   label: String    # 「出售 35 币」「锁定同类 ×3」
                   enabled: bool    # 灰着时 reason 写进按钮悬浮窗
                   reason: String
                   danger: bool     # 真 = 两步确认（见 2.4）
                   run: Callable
```

每一屏在建视图时登记一个供给函数：`view.actions_for = func(uid) -> Array[ItemAction]`（放在 `ContainerView` 上，像 `item_double_clicked` 一样随视图走）。`HoverTip.show_item` 开窗时调它，拿到按钮列表就在脚注下面画一行。**双击仍是「第一颗按钮」的快捷键**（`actions[0]` = 该容器的默认动作，就是今天双击做的事），右键 = 立刻钉住并展开按钮；这样三种输入指向同一份逻辑，以后加动作只加一处。

### 2.2 哪件在哪，给什么按钮

按钮顺序 = 默认动作 → 搬运类 → 锁 → 危险类。灰按钮也画（原因在它的悬浮窗里），免得玩家猜。

| 容器 / 屏 | 按钮（默认动作加粗） |
|---|---|
| **局内 · 棋盘**（背包窗 / 商店 / 神坛 / 保险箱 / 铸炉 / 战前） | **放到地上**；锁定 / 解锁；奉为主信仰（信物，替掉右键）；放进保险箱（保险箱屏开着时）；出售 N 币（商店屏）；献祭（神坛屏，`accepts_offering`）；放进铸炉（铸炉屏，收它的槽亮着时） |
| **局内 · 地上** | **放进背包**；锁定 / 解锁 |
| **战利品 / 宝箱 / 事件收获** | **拾取**（进包，放不下到地上） |
| **商店 · 货架** | **购买 N 币**（钱不够灰） |
| **商店 · 出售区**、**神坛 · 祭品台**、**保险箱**、**铸炉槽** | **取回** |
| **基地 · 仓库**（仓库页 / 出售页 / 科技页 / 开局第二页 / 结算第二页都是同一块） | 出售 N 币；出售同类 ×n 得 M 币；锁定 / 解锁；锁定同类 ×n / 解锁同类；**带上**（开局页：放上棋盘）；**上交**（科技页，选中节点要它时）；收进包架（包，225） |
| **带回的棋盘**（结算第二页 / 基地仓库页） | **置入仓库**；锁定 / 解锁；收进包架（包） |
| **图鉴格**、**敌人棋盘**（战前 / 地图纸签） | 不给按钮（只看） |

「出售同类」「锁定同类」的「同类」= 同一个 `def.id`（不是同标签），范围 = 这一块容器（仓库全页）。

### 2.3 锁定

- **存**：`ItemInstance.state["locked"] = true`，随 `to_dict` 走，撤离 `_adopt` 时跟着进仓库；读法 `inst.is_locked_by_player()`（别碰 207 的 `GridInventory.is_locked` = 扎根）。
- **管什么**：锁住的东西 **可以拖、可以放**（锁不是钉），但 —— 不能卖（商店出售区 / 基地 `sell_item` 拒收，`sell_where` 一键出售跳过并在回话里写「跳过 N 件锁定的」）、不能丢到地上（局内拖到地上 / 「放到地上」灰）、不能献祭、不能进铸炉槽、不能「取消置入」丢弃；「一键置入」「全部拾取」「整理」照常搬它。
- **不管什么**：事件 `lose_item`、侵蚀磨损、战败丢棋盘 —— 锁是防自己手滑的，不是护身符（同类游戏也都这么做）。
- **画**：格子左上角一枚小锁角标（`ItemPainter` 新 `draw_lock`，同 208 耐久角标那套位置规则，图找 UI替换美术，16 px）；悬浮窗副行末尾加「· 已锁定」。
- **同类锁**：对仓库全页同 id 的每件写旗；按钮字「锁定同类 ×3」/ 已全锁时变「解锁同类 ×3」。

### 2.4 防误点

- `danger` 的按钮（出售、出售同类、献祭、放到地上）**两步**：第一下按钮字变「再点一次」（2.2 读档屏删除那套），两秒不点回弹；锁住的东西这些按钮直接灰、原因「已锁定」。
- 悬浮窗没钉住时按钮**也能点**（进窗就留下），但点完窗立刻收（动作做了，东西多半已经不在原处）；钉住的窗点完留着、内容刷新（比如锁定 → 解锁）。
- 右键立即钉住：`item_context` 改由 `HoverTip` 统一接（钉住 + 展开），各屏不再各接；信物切换成按钮后 099 的两处连线删。

### 2.5 样子

按钮一行放在脚注下面（虚线之下），每颗高 28、字 14、~~横排自动换行，最多两行~~（排法改见 §2.6）；悬浮窗是深底（D2 皮革），按钮用 **深底上的小石签**：问 UI替换美术要一枚深色版小按钮（`kit` 的 `chip_*` 是浅纸上的，深底不合）—— 常态 / 悬停 / 按下 / 灰 四态 + 「危险」态一枚（朱红边，用在「再点一次」）。小锁角标同一批。英文按钮字短，宽度按字算。

### 2.6 排版（作者 19:19 补：「每行可以左右对齐」）

作者 19:19 在 UI替换美术 原话：「按钮的排版要设计一下，现在毫无对齐的样子太丑了，每行可以左右对齐」。替掉 §2.5 的「横排自动换行，最多两行」：

- 每行占满悬浮窗内容宽 360（和分隔线同宽）；一行最多两颗、**等宽**（各 177，间 6），字居中；一颗独占时满宽。宽度不按字算。
- 行序照 §2.2（默认 → 搬运 → 锁 → 危险），两两并行；行间 6，第一行顶 = 脚注下 6。
- 成对的永远同一行不拆：「锁定 | 锁定同类」（解锁同理）、「出售 | 出售同类」。单颗后面紧跟一对、或单颗落在最后 → 独占一行。
- 一行两颗时任一颗字宽 + 16 超过半宽（英文长字）→ 这一行拆成两行各占满，不缩字。
- 通常一到两行；仓库开局页带包时最多三行（带上 | 收进包架、锁定 | 锁定同类、出售 | 出售同类）。
- 规格与样稿：`/mnt/project-files/art/ui/kit/out/tip/layout.json` 的 `tipbtn.row_layout`，`mocks/tipbtn_rows.png`；UI替换美术 已交执行。「再点一次」= §2.4 的两步防误点，由 UI替换美术 向作者解释。

## 三、改动点

- `ui/inventory/container_view.gd`：`actions_for: Callable`；`inventory_view.gd` 右键不再发给屏，发给悬浮窗（或悬浮窗自己 `watch` 时接 `item_context`）。
- `ui/inventory/hover_tip.gd`：`show_item(full, at, actions)` 画按钮行；`pin_now()`；按钮点击 → `run.call()` → 刷新或收窗；两步确认计时在 `tick` 里。
- `core/inventory/item_actions.gd`（新）+ `ItemInstance.is_locked_by_player / set_locked`。
- 各屏登记供给函数：`inventory_panel`（棋盘 / 地上）、`shop_screen`、`altar_screen`、`safe_screen`、`forge_screen`、`container_screen` / `chest` / `event_screen` 收获行、`setup_screen`（棋盘 / 地上 / 仓库）、`warehouse_panel`（仓库 / 带回棋盘）、`meta_screen`（按页签给仓库的按钮：出售页给卖、科技页给上交）、`result_screen`。双击改成调 `actions[0]`，各屏的 `quick_move / quick_buy / take_back` 留作动作的实现。
- 锁的守门：`MetaState.sell_item / sell_where / _sellable`、`ShopSession` 卖、`AltarScreen._allow_drop`、`ForgeScreen` 槽过滤、`DragLayer` 落地上的过滤（局内）—— 五处读旗。
- `ItemPainter.draw_lock`；`UiText`：十来个按钮字（中英，短）+ 「已锁定」「跳过 N 件锁定的」「再点一次」复用。帮助页 `anchor_and_right_click.json` 改「右键 = 立刻钉住悬浮窗、按钮里奉为主信仰」；新帮助页 `item_actions.json`（锁定管什么不管什么）。
- 测试：`test_hover_tip`（按钮行、右键即钉、两步确认）、`test_item_actions`（每屏供给的按钮集 = 上表）、`test_lock`（卖 / 丢 / 献祭 / 一键出售跳过 / 置入照搬 / 存档来回）、英文键齐。
